# 15-2. COUNT (개수를 세는 쿼리) 는 어떻게 동작하나요? COUNT(1), COUNT(*), COUNT(column) 의 동작 과정에는 차이가 있나요?

# 1. **COUNT(1) 의 동작 원리**

1. 데이터 추출

> Note 

  - 데이터베이스 엔진이 레코드(행)를 하나씩 읽을 때마다 괄호 안의 상수 1을 해당 행의 임의 값으로 부여하고 이를 셉니다.

  - 이때, 행을 발견할 때마다 상수 1이 NULL인지 판단합니다. 숫자 1은 절대 NULL이 아니므로 결국 행이 존재하는 횟수만큼 전부 세게 됩니다.

1. 내부 변환

> Note 

  - 사용자가 1, 2, 3 혹은 어떤 상수를 넣더라도, 현대의 옵티마이저는 실행 계획을 세우는 단계에서 이를 완전히 무시하고 COUNT(*) 와 100% 동일한 방식으로 변환하여 동작시킵니다.

  - 이는 과거의 유산일 뿐 현재는 두 구문의 동작 과정에 아무런 차이가 없습니다.

---

# 2. **COUNT(*) 의 동작 원리**

1. 데이터 추출

> Note 특정 컬럼의 값을 파고들어 읽지 않습니다. 단순히 행이 있다는 사실만 확인합니다.

1. NULL 처리

> Note 레코드 내부의 데이터가 무엇이든, 전부 NULL이더라도 행 자체가 존재하므로 무조건 개수에 포함합니다.

1. 최적화

> Note 옵티마이저는 굳이 실제 데이터가 담긴 무거운 데이터 블록을 읽지 않고, 사용 가능한 세컨더리 인덱스들 중 가장 크기가 작은 인덱스를 훑어서 빠르게 행 개수만 파악하는 방식으로 동작합니다.

---

# 3. COUNT(컬럼명) 의 동작 원리

1. 데이터 추출

> Note 

  - 데이터베이스 엔진이 각 레코드에서 명시된 특정 컬럼의 실제 값을 메모리로 가져와 하나씩 검사합니다.

  - 행의 존재 유무가 아니라, 괄호 안에 지정된 그 컬럼의 데이터를 일일이 열어봅니다.

1. NULL 처리

> Note 꺼내온 데이터가 유효한 값인지, 비어있는 값(NULL)인지 매번 확인합니다. 값이 존재할 때만 카운트를 올리고, NULL이면 세지 않고 넘어갑니다.

1. 최적화 제약

> Note 지정된 컬럼에 인덱스가 걸려있지 않다면, 옵티마이저는 해당 컬럼의 값이 NULL인지 판단하기 위해 디스크에서 테이블 전체를 읽어와야 하므로 무거운 I/O 작업이 동반됩니다.

---

# 4. 요약

| **쿼리 구문** | **집계 기준** | **NULL 포함 여부** | **특징 및 성능** |
| --- | --- | --- | --- |
| COUNT(1) | 테이블 전체 행 | 포함하여 집계 | 내부적으로 COUNT(*)와 100% 동일하게 동작. 성능 이점 없음 |
| COUNT(*) | 테이블 전체 행 | 포함하여 집계 | SQL 표준. 가장 크기가 작은 인덱스를 자동 스캔하여 성능 최적화 |
| COUNT(컬럼명) | 특정 컬럼의 유효 값 | 제외하고 집계 | 컬럼에 인덱스가 없으면 Table Full Scan 발생 위험 높음 |
