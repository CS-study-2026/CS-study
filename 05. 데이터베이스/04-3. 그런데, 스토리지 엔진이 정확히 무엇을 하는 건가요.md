# 4-3. 그런데, 스토리지 엔진이 정확히 무엇을 하는 건가요?

> 💡 

## 0. 사전 지식: MySQL 아키텍처와 WAL 원칙 / Undo, Redo

MySQL 2계층 아키텍처

  1. 사용자 요청을 분석하는 **상위 계층인 MySQL 엔진**

  1. 실제 데이터를 디스크/메모리에 다루는 **하위 계층인 스토리지 엔진**

이 두 가지가 철저히 분리되어 동작

---

> 

WAL (Write-Ahead Logging) 원칙

디스크의 임의 위치에 데이터를 바로 쓰는 `랜덤 I/O(Random I/O)`는 성능 비효율 매우 큼

따라서 `InnoDB`는 데이터를 직접 디스크  파일에 저장하기 전에, 변경 이력을 순차적 **I/O(Sequential I/O)로 로그 파일에 먼저 빠르게 기록**하는 WAL 매커니즘을 채택

---

> 

Undo / Redo

## 1. Undo 영역 (Undo Log)

### 개념

데이터가 변경되기 직전의 이전 데이터(Before Image)를 백업해 두는 메모리 및 디스크 공간입니다.

---

## 2. Redo 영역 (Redo Log)

### 개념

데이터 변경 사항이 디스크 데이터 파일에 최종 반영되기 전, 변경 이력 자체(After Image)를 순차적으로 기록해 두는 로그(WAL, Write-Ahead Logging) 파일입니다.

## 4-3. 스토리지 엔진이 정확히 무엇을 하는 건가요?

### 개념 정의

`스토리지 엔진`은 물리적인 저장 매체(디스크, 메모리 등)에서 **데이터를 실제로 저장, 조회, 수정, 삭제(CRUD)하는 역할**을 직접 담당하는 하위 실행 모듈입니다.

MySQL은 **여러 종류의 스토리지 엔진**을 선택하여 사용할 수 있는 플러그인 아키텍처(Pluggable Storage Engine) 구조를 가지고 있습니다.

### MySQL 엔진 vs 스토리지 엔진 역할 분담

| **구분** | **MySQL 엔진 (두뇌 역할)** | **스토리지 엔진 (손발 역할)** |
| --- | --- | --- |
| 담당 영역 | 접속 클라이언트 관리, SQL 파싱, 쿼리 최적화 | 디스크/메모리 데이터 입출력, 인덱스 관리 |
| 주요 구성 요소 | SQL Parser, Preprocessor, Optimizer, Executer | InnoDB, MyISAM, Memory, RocksDB 등 |
| 주요 기능 | 문법 검사, 실행 계획 수립, 테이블 단위 잠금 | 트랜잭션 처리, 행 단위 잠금(Row-level Lock), MVCC |

<details>
<summary>행 단위 잠금(Row-level Lock)</summary>

## 행 단위 잠금 (Row-level Locking)

테이블 전체가 아니라, 실제로 변경(INSERT, UPDATE, DELETE)하려는 특정 행(Row)에 대해서만 락(Lock)을 거는 방식입니다.

  - **핵심 효과**: 동시성(Concurrency)의 극대화입니다.

  - **비교**: 과거 MyISAM 엔진은 한 행만 수정해도 테이블 전체를 잠그는 테이블 단위 잠금(Table-level Lock)을 사용해서 다른 사용자의 접근을 막았습니다. 반면 InnoDB의 행 단위 잠금은 A 사용자가 1번 행을 수정 중이어도, B 사용자가 2번 행을 동시에 수정하거나 읽을 수 있게 해줍니다.
</details>

<details>
<summary>MVCC</summary>

## MVCC (Multi-Version Concurrency Control, 다중 버전 동시성 제어)

하나의 레코드에 대해 **여러 버전의 데이터(스냅샷)를 동시에 유지**하여, 잠금 없이도 읽기와 쓰기 작업을 동시에 처리하는 기술입니다.

  - **동작 원리**:

    1. 특정 트랜잭션이 데이터를 수정하면, 변경되기 전의 옛날 데이터는 **Undo 로그**로 복사됩니다.

    1. 이때 다른 트랜잭션이 해당 데이터를 조회하면, 수정 중인 락을 기다리는 것이 아니라 Undo 로그에 보관된 **과거 버전의 데이터를 읽어갑니다.**

  - **핵심 효과**: "읽기는 쓰기를 막지 않고, 쓰기는 읽기를 막는다"는 원칙을 달성합니다. 락으로 인한 대기 시간을 없애서 데이터베이스의 조회 및 수정 성능을 대폭 끌어올립니다.
</details>

> 요약하자면

  - **행 단위 잠금**: "다른 행을 작업하는 사용자끼리 서로 방해하지 않게 만드는 기술"

  - **MVCC**: "같은 행을 다루더라도 읽는 사람과 쓰는 사람이 서로 방해하지 않게 만드는 기술"

### 대표적인 스토리지 엔진 종류

- InnoDB

  - MySQL 5.5 버전부터 기본 스토리지 엔진으로 채택되었습니다.

  - 트랜잭션(ACID) 지원, 행 수준 잠금(Row-level Lock), 외래키(Foreign Key) 지원이 핵심입니다.

  - 대규모 트랜잭션 처리가 필요한 OLTP 시스템의 글로벌 표준입니다.

- MyISAM

  - 과거 기본 스토리지 엔진이었으나 트랜잭션을 지원하지 않습니다.

  - 테이블 수준 잠금(Table-level Lock)을 사용하여 쓰기 작업 시 전체 테이블이 락에 걸립니다.

  - 구조가 단순하여 읽기 전용 작업에 빠르다는 장점이 있었으나, 현재는 거의 사용되지 않습니다.

- Memory

  - 모든 데이터를 RAM에 보관하여 극도의 처리 속도를 제공합니다.

  - 전원이 꺼지면 데이터가 사라지는 휘발성이므로 임시 테이블 용도로만 제한적으로 활용됩니다.
