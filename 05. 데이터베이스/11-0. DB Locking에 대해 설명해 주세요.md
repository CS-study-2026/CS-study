# 11-0. DB Locking에 대해 설명해 주세요.

DB Locking은 **여러 트랜잭션이 동시에 같은 데이터에 접근할 때 데이터의 일관성과 무결성을 유지하기 위해 접근을 제어하는 방법**입니다.

예를 들어 계좌에 10만 원이 있는데 A와 B가 동시에 출금한다고 해보겠습니다.

```plain text
현재 잔액 = 100,000원

Transaction A             Transaction B
     ↓                          ↓
100,000원 조회              100,000원 조회
     ↓                          ↓
30,000원 출금              50,000원 출금
     ↓                          ↓
70,000원 저장               50,000원 저장
```

두 트랜잭션이 같은 값을 읽고 각각 수정하면 한쪽 변경사항이 사라지는 **Lost Update**가 발생할 수 있습니다.

Lock을 사용하면 특정 데이터에 대한 동시 접근을 제한하여 이런 문제를 방지할 수 있습니다.

### Shared Lock / Exclusive Lock

DB Lock의 대표적인 형태로 **Shared Lock(S Lock)**과 **Exclusive Lock(X Lock)**이 있습니다.

**Shared Lock은 읽기를 위한 Lock**입니다.

```plain text
        Row
      🔒 S Lock
      ↙      ↘
     A        B
   READ     READ
```

여러 트랜잭션이 동시에 Shared Lock을 획득할 수 있지만, 일반적으로 해당 데이터에 대한 Exclusive Lock과는 충돌합니다.

**Exclusive Lock은 쓰기를 위한 Lock**입니다.

```plain text
        Row
      🔒 X Lock
        ↑
        A
     UPDATE

        B
        ↓
      대기...
```

한 트랜잭션이 X Lock을 획득하면 다른 트랜잭션이 충돌하는 S/X Lock을 획득할 수 없으며 Lock이 해제될 때까지 기다리게 됩니다.

대표적으로 다음과 같은 SQL이 있습니다.

```sql
SELECT *
FROM account
WHERE id = 1
FOR UPDATE;
```

`FOR UPDATE`를 사용하면 조회한 데이터를 이후 수정할 목적으로 잠그며, 다른 트랜잭션의 충돌하는 접근을 제한할 수 있습니다.(해당 데이터에 **자물쇠(Lock)**를 채움)

### Lock의 설정 범위(Level)

Lock은 **어느 범위의 데이터를 잠그느냐**에 따라서도 구분할 수 있습니다.

| 범위 | 설명 |
| --- | --- |
| Database Lock | 데이터베이스 전체를 대상으로 Lock |
| Table Lock | 테이블 전체를 대상으로 Lock |
| Page Lock | 데이터가 저장된 Page 단위로 Lock |
| Row Lock | 특정 Row를 대상으로 Lock |

```plain text
Database
   ↓
 Table
   ↓
 Page
   ↓
 Row
```

Lock의 범위가 크면 관리해야 할 Lock의 수가 적어 관리 비용은 줄어들지만, 다른 트랜잭션이 동시에 접근할 수 있는 데이터의 범위도 줄어들어 **동시성이 낮아질 수 있습니다.**

반대로 Row Lock처럼 범위가 작으면 서로 다른 Row에 여러 트랜잭션이 동시에 접근할 수 있어 **동시성이 높아지지만**, DB가 관리해야 할 Lock의 수가 많아집니다.

```plain text
Lock 범위 ↑ → 관리 비용 ↓ / 동시성 ↓
Lock 범위 ↓ → 관리 비용 ↑ / 동시성 ↑
```

DBMS에 따라 지원하는 Lock의 범위와 실제 동작은 다를 수 있습니다.

### Lock은 언제까지 유지될까?

일반적으로 트랜잭션에서 획득한 Lock은 **트랜잭션이 ****`COMMIT`**** 또는 ****`ROLLBACK`****될 때 해제**됩니다.

```plain text
BEGIN
  ↓
데이터 접근
  ↓
Lock 획득 🔒
  ↓
조회 / 수정
  ↓
COMMIT 또는 ROLLBACK
  ↓
Lock 해제 🔓
```

따라서 Lock과 Transaction은 관련이 깊지만 같은 개념은 아닙니다.

> **Transaction은 여러 작업을 하나의 논리적인 작업 단위로 묶는 것이고, Lock은 여러 트랜잭션 사이의 동시 접근을 제어하는 방법입니다.**

### Blocking과 Lock Wait

한 트랜잭션이 보유한 Lock 때문에 다른 트랜잭션이 필요한 Lock을 획득하지 못하고 작업이 진행되지 않는 현상을 **Blocking**이라고 합니다.

이때 Blocking된 트랜잭션이 기존 Lock이 해제되기를 기다리는 상태를 **Lock Wait**이라고 합니다.

```plain text
Transaction A
X Lock 획득 🔒
      ↓
    작업 중
      │
      │ Blocking
      ↓
Transaction B
X Lock 요청
      ↓
획득할 수 없음
      ↓
  Lock Wait
      ↓
A COMMIT / ROLLBACK
      ↓
Lock 해제 🔓
      ↓
B Lock 획득 → 작업 진행
```

즉,

```plain text
Blocking
→ 다른 트랜잭션의 Lock 때문에 작업이 막히는 현상

Lock Wait
→ Blocking으로 인해 Lock이 해제되기를 기다리는 상태
```

Blocking과 Lock Wait 자체는 Lock을 이용한 동시성 제어 과정에서 정상적으로 발생할 수 있습니다.

하지만 Lock을 보유한 트랜잭션의 작업이 길어지면 다른 트랜잭션의 대기 시간도 증가하여 **응답 시간이 길어지고 전체 처리량이 감소**할 수 있습니다.

또한 일정 시간 이상 Lock을 획득하지 못하면 DBMS의 설정에 따라 **Lock Wait Timeout**이 발생할 수 있습니다.

### Deadlock

Lock으로 인해 발생할 수 있는 또 다른 문제로 **Deadlock(교착 상태)**이 있습니다.

Deadlock은 두 개 이상의 트랜잭션이 **서로 상대방이 가지고 있는 Lock이 해제되기를 기다리면서 어느 쪽도 진행하지 못하는 상태**입니다.

```plain text
Transaction A              Transaction B

Row 1 🔒                   Row 2 🔒
   ↓                          ↓
Row 2 Lock 필요            Row 1 Lock 필요
   ↓                          ↓
B가 가지고 있음            A가 가지고 있음
   ↓                          ↓
   대기 ←──────────────→ 대기

          Deadlock
```

일반적인 Blocking과 Deadlock은 다음과 같은 차이가 있습니다.

```plain text
[일반적인 Blocking]

A : Row 1 🔒
       ↓
B : Row 1 필요 → Lock Wait

A COMMIT
   ↓
Lock 해제
   ↓
B 실행 가능

→ Lock을 가진 트랜잭션이 끝나면 해결


[Deadlock]

A : Row 1 🔒 → Row 2 기다림
                    ↑
                    ↓
B : Row 2 🔒 → Row 1 기다림

→ 서로 상대방의 Lock을 기다림
→ 그대로는 진행할 수 없음
```

DBMS는 일반적으로 Deadlock을 감지하면 트랜잭션 중 하나를 선택하여 **Rollback**하고 Lock을 해제함으로써 교착 상태를 해결합니다.

### Lock의 단점

Lock은 여러 트랜잭션이 동일한 데이터에 접근할 때 데이터의 정합성을 유지할 수 있다는 장점이 있지만 다음과 같은 비용이 발생합니다.

- **Blocking**: 다른 트랜잭션의 작업이 진행되지 못할 수 있음

- **Lock Wait**: Lock 해제를 기다리면서 응답 시간이 증가할 수 있음

- **Lock Wait Timeout**: 일정 시간 이상 Lock을 획득하지 못하면 작업이 실패할 수 있음

- **Deadlock**: 여러 트랜잭션이 서로의 Lock을 기다리며 진행하지 못할 수 있음

- **동시 처리량 감소**: Lock 경쟁이 많아질수록 동시에 처리할 수 있는 작업이 줄어들 수 있음

따라서 Lock은 데이터의 정합성을 보장하는 데 유용하지만, **정합성과 동시 처리 성능 사이의 균형을 고려하여 사용해야 합니다.**

### 한 번에 답한다면

> **DB Locking은 여러 트랜잭션이 동일한 데이터에 동시에 접근할 때 발생할 수 있는 동시성 문제를 방지하고 데이터의 일관성을 유지하기 위해 접근을 제어하는 방법입니다. 대표적으로 읽기를 위한 Shared Lock과 쓰기를 위한 Exclusive Lock이 있으며, Lock은 일반적으로 트랜잭션이 Commit 또는 Rollback될 때 해제됩니다. Lock을 통해 Lost Update와 같은 동시성 문제를 방지할 수 있지만, Lock 대기로 인한 성능 저하나 Deadlock이 발생할 수 있기 때문에 적절하게 사용해야 합니다.**
