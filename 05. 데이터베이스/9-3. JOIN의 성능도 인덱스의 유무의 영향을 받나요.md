# **9-3. JOIN의 성능도 인덱스의 유무의 영향을 받나요?**

JOIN의 성능은 인덱스의 영향을 크게 받을 수 있습니다.

JOIN은 보통 한 테이블의 행과 다른 테이블의 행을 조건에 맞게 연결하는 연산입니다.

예를 들어 다음과 같은 JOIN이 있다고 하겠습니다.

```plain text
SELECT *
FROM orders o
JOIN users u
  ON o.user_id = u.id;
```

이 쿼리는 주문 테이블의 `user_id`와 회원 테이블의 `id`가 같은 행을 찾아 연결합니다.

```plain text
orders.user_id = users.id
```

이때 `users.id`나 `orders.user_id`에 인덱스가 있는지에 따라 성능이 크게 달라질 수 있습니다.

---

## 1. 인덱스가 없는 경우

인덱스가 없다면 DBMS는 조건에 맞는 행을 찾기 위해 많은 데이터를 직접 확인해야 할 수 있습니다.

예를 들어 `orders` 테이블의 각 행마다 `users` 테이블을 전부 확인해야 한다면 비용이 매우 커질 수 있습니다.

```plain text
orders 1번 행
→ users 전체 탐색

orders 2번 행
→ users 전체 탐색

orders 3번 행
→ users 전체 탐색
```

개념적으로는 다음과 같은 비효율이 발생할 수 있습니다.

```plain text
orders 행 수 = 1,000,000
users 행 수 = 100,000

각 orders 행마다 users를 많이 탐색
→ 매우 큰 비용 발생 가능
```

물론 실제 DBMS는 항상 이렇게 단순하게만 실행하지는 않고, Hash Join 같은 다른 방식을 선택할 수도 있습니다.

하지만 적절한 인덱스가 없으면 선택할 수 있는 효율적인 실행 계획이 줄어들 수 있습니다.

---

## 2. 인덱스가 있는 경우

JOIN 조건에 사용되는 컬럼에 인덱스가 있으면, DBMS는 필요한 행을 더 빠르게 찾을 수 있습니다.

예를 들어 `users.id`에 인덱스가 있다면:

```plain text
orders의 user_id 값을 확인
→ users.id 인덱스에서 해당 id를 빠르게 탐색
→ 일치하는 회원 행 찾기
```

흐름은 다음과 같습니다.

```plain text
orders.user_id = 10
→ users.id 인덱스에서 10 검색
→ 해당 users 행 찾기
```

이렇게 하면 전체 테이블을 매번 훑는 것보다 훨씬 효율적일 수 있습니다.

---

## 3. 어떤 컬럼에 인덱스가 중요할까?

JOIN 성능에서 중요한 인덱스는 보통 **JOIN 조건에 사용되는 컬럼**입니다.

```plain text
SELECT *
FROM orders o
JOIN users u
  ON o.user_id = u.id;
```

이 경우 주요 컬럼은 다음입니다.

```plain text
orders.user_id
users.id
```

특히 참조되는 쪽의 기본키나 유니크 키에는 인덱스가 있는 경우가 많습니다.

```plain text
users.id
→ 기본키
→ 보통 인덱스 존재
```

하지만 외래키 컬럼에는 DBMS에 따라 자동으로 인덱스가 생성되지 않을 수 있습니다.

```plain text
orders.user_id
→ 외래키 컬럼
→ JOIN에서 자주 사용된다면 인덱스 고려
```

따라서 `orders.user_id`처럼 JOIN에 자주 사용되는 외래키 컬럼에는 인덱스를 두는 것이 성능에 유리할 수 있습니다.

---

## 4. 인덱스가 있다고 항상 빠른 것은 아니다

인덱스가 있으면 JOIN 성능에 도움이 될 수 있지만, 항상 무조건 빠른 것은 아닙니다.

옵티마이저는 다음 요소를 함께 고려합니다.

```plain text
테이블 크기
조건의 선택도
읽어야 하는 row 수
인덱스를 타고 다시 테이블을 조회하는 비용
JOIN 순서
통계 정보
```

예를 들어 조건에 맞는 데이터가 너무 많다면 인덱스를 타는 것보다 테이블을 순차적으로 읽는 것이 더 나을 수 있습니다.

```plain text
전체 데이터의 90%를 읽어야 함
→ 인덱스를 통해 하나씩 찾는 것보다
   전체 스캔이 더 효율적일 수 있음
```

따라서 인덱스는 JOIN 성능에 영향을 주지만, 실제 사용 여부는 실행 계획을 통해 확인해야 합니다.

---

## 5. 인덱스가 오히려 부담이 되는 경우

인덱스는 조회 성능에는 도움이 될 수 있지만, 쓰기 작업에는 부담이 됩니다.

```plain text
INSERT
UPDATE
DELETE
```

가 발생하면 테이블 데이터뿐 아니라 인덱스도 함께 갱신해야 하기 때문입니다.

따라서 JOIN에 거의 사용되지 않는 컬럼에 무분별하게 인덱스를 추가하면 오히려 전체 성능에 부담이 될 수 있습니다.

중요한 기준은 다음입니다.

```plain text
자주 JOIN되는 컬럼인가?
조건 검색에도 자주 사용되는가?
선택도가 충분한가?
쓰기 비용을 감당할 만큼 조회 이점이 큰가?
```

---

## 6. 질문에 대한 최종 답변

> JOIN의 성능은 인덱스의 유무에 큰 영향을 받을 수 있습니다. JOIN은 한 테이블의 값과 다른 테이블의 값을 비교해 연결하는 작업이므로, JOIN 조건에 사용되는 컬럼에 인덱스가 있으면 일치하는 행을 더 빠르게 찾을 수 있습니다. 예를 들어 `orders.user_id = users.id`로 JOIN한다면 `users.id`나 `orders.user_id`에 인덱스가 있을 때 탐색 비용을 줄일 수 있습니다.

다만 인덱스가 있다고 해서 항상 사용되는 것은 아닙니다. 조건에 맞는 데이터가 너무 많거나, 옵티마이저가 전체 스캔이 더 효율적이라고 판단하면 인덱스를 사용하지 않을 수도 있습니다. 따라서 JOIN 성능을 판단할 때는 인덱스 유무뿐 아니라 실행 계획을 확인해서 실제로 인덱스를 사용하는지, JOIN 순서와 예상 row 수가 어떻게 되는지 함께 봐야 합니다.

## 핵심 요약

```plain text
JOIN 성능
= 인덱스 영향을 크게 받을 수 있음

중요한 인덱스
= JOIN 조건에 사용되는 컬럼

예시
= orders.user_id
= users.id

인덱스가 있으면
= 일치하는 행을 빠르게 찾을 수 있음

인덱스가 없으면
= 더 많은 row를 스캔해야 할 수 있음

주의
= 인덱스가 있어도 항상 사용하는 것은 아님
= 실행 계획으로 실제 사용 여부를 확인해야 함
```
