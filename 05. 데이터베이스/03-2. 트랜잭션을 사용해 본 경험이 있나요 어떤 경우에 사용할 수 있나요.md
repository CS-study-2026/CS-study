# 3-2. 트랜잭션을 사용해 본 경험이 있나요? 어떤 경우에 사용할 수 있나요?

제가 We-Trip 에서 사용한 것은요  

---

### 1. 환전 체결

원화를 외화로 환전할 때는 다음 작업이 함께 수행됩니다.

```plain text
원화 잔액 차감
→ 외화 잔액 증가
→ 거래내역 및 원장 저장
→ 주문 상태 변경
```

이 작업들은 하나의 환전이라는 동일한 업무에 속하기 때문에 모두 함께 처리되어야 합니다.

예를 들어,

```plain text
원화 잔액 차감 성공
→ 외화 잔액 증가 성공
→ 거래내역 저장 실패
```

와 같은 상황이 발생하면 실제 돈은 이동했지만 거래내역은 남지 않습니다.

또는

```plain text
잔액 변경 성공
→ 주문 상태 변경 실패
```

라면 환전은 완료됐지만 주문은 계속 `PENDING` 상태로 남아 동일한 주문이 다시 실행될 수도 있습니다.

이를 방지하기 위해 환전 체결 메서드에 `@Transactional`을 적용해 모든 작업이 함께 성공하거나 함께 롤백되도록 구현했습니다.

```java
@Transactional
public ExchangeOrder executeExchange(...) {
    // 잔액 변경
    // 거래내역 저장
    // 주문 상태 변경
}
```

### 2. 동시 환전 요청

공동 계좌에 10만 원이 있을 때 8만 원 환전 요청이 동시에 두 건 들어온다고 가정해 보겠습니다.

락이 없다면 두 요청 모두 잔액이 충분하다고 판단해 총 16만 원이 차감될 수 있습니다.

```plain text
요청 A : 잔액 10만 원 확인
요청 B : 잔액 10만 원 확인
→ 총 16만 원 차감 가능
```

이를 방지하기 위해 계좌 조회 시 비관적 락(Pessimistic Lock)을 사용했습니다.

```plain text
요청 A가 Lock 획득
→ 요청 B 대기
→ A 처리 후 Commit
→ B가 변경된 잔액 확인
```

락은 트랜잭션이 종료될 때까지 유지되기 때문에, 잔액 조회부터 실제 차감까지 하나의 트랜잭션으로 처리했습니다.

---

### 3. 실패 이력 저장

예약 환전이 잔액 부족으로 실패하더라도 실패 이력은 남겨야 했습니다.

하지만 일반 트랜잭션을 사용하면 상위 트랜잭션이 롤백될 때 실패 이력도 함께 사라질 수 있습니다.

이를 방지하기 위해 실패 이력 저장에는 `REQUIRES_NEW`를 적용했습니다.

```java
@Transactional(propagation = Propagation.REQUIRES_NEW)
public ExchangeTransaction recordFailure(...) {
    return exchangeTransactionRepository.save(...);
}
```

기존 트랜잭션과 별도의 트랜잭션을 생성하기 때문에 환전은 실패하더라도 실패 이력은 정상적으로 저장할 수 있었습니다.

## `REQUIRES_NEW`란?

### `REQUIRES_NEW`란?

`REQUIRES_NEW`는 **기존 트랜잭션이 있더라도 이를 잠시 중단하고, 새로운 트랜잭션을 생성하여 독립적으로 실행하는 전파(Propagation) 옵션**이다.

## Transaction Propagation(전파)

트랜잭션 전파는 **트랜잭션이 실행 중인 메서드에서 또 다른 트랜잭션 메서드를 호출할 때, 기존 트랜잭션에 참여할지 새로운 트랜잭션을 생성할지를 결정하는 옵션**이다.

    - **`Propagation.REQUIRED`**** (기본값)**

      - 기존 트랜잭션이 있으면 참여하고, 없으면 새로 생성한다.

      - 여러 작업을 하나의 트랜잭션으로 처리할 때 사용한다.

    - **`Propagation.REQUIRES_NEW`**

      - 기존 트랜잭션이 있어도 잠시 중단하고 새로운 트랜잭션을 생성한다.

      - 상위 트랜잭션이 롤백되어도 반드시 저장되어야 하는 작업(로그, 감사 이력, 실패 이력 등)에 주로 사용한다.

우리 프로젝트에서는 예약 환전이 실패했을 때 실패 이력을 반드시 남기기 위해 사용했다.

```java
@Transactional(propagation = Propagation.REQUIRES_NEW)
public ExchangeTransaction recordFailure(...) {
    return exchangeTransactionRepository.save(...);
}
```

예를 들어,

```plain text
환전 체결 시작 (기존 트랜잭션)
→ 잔액 부족으로 예외 발생
→ 실패 이력 저장 (REQUIRES_NEW)
→ 실패 이력 Commit
→ 기존 트랜잭션 Rollback
```

일반 `@Transactional`이었다면 상위 트랜잭션이 롤백될 때 실패 이력도 함께 롤백된다.

반면 `REQUIRES_NEW`는 별도의 트랜잭션으로 실행되므로, 환전은 실패하더라도 실패 이력은 정상적으로 저장할 수 있다.

즉, **상위 작업의 성공 여부와 관계없이 반드시 저장되어야 하는 작업(로그, 감사 이력, 실패 이력 등)** 에 주로 사용된다.
