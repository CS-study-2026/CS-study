# 10-0. B-Tree와 B+Tree에 대해 설명해 주세요.

> 

B-Tree와 B+Tree는 데이터베이스에서 인덱스를 구현할 때 사용하는 대표적인 균형 트리 자료구조입니다.

둘 다 하나의 노드에 여러 개의 키를 저장할 수 있어 트리의 높이를 낮게 유지하고, 디스크 I/O를 줄이는 데 목적이 있습니다.

**B-Tree는 내부 노드에도 실제 데이터가 저장될 수 있는 반면, B+Tree는 내부 노드에는 검색을 위한 키만 저장하고 실제 데이터는 리프 노드에만 저장합니다.**

또한 B+Tree의 리프 노드는 서로 연결되어 있어 범위 검색에 유리합니다.

따라서 데이터베이스에서는 디스크 I/O를 줄이고 범위 검색을 효율적으로 처리할 수 있는 B+Tree가 인덱스 구조로 많이 사용됩니다.

## 1️⃣ B-Tree란?

### 📌 정의

**B-Tree(Balanced Tree)**는 하나의 노드에 **여러 개의 키와 자식 포인터**를 저장하는 균형 잡힌 다방향 탐색 트리이다.

일반적인 BST와 비교하면:

```plain text
BST

        10
       /  \
      5    20
```

하나의 노드가 최대 2개의 자식을 가짐

⬇️

```plain text
B-Tree

       [10 | 20]
      /    |    \
    ...   ...   ...
```

하나의 노드에 여러 개의 키를 저장하고,
키 사이의 여러 구간을 자식 노드가 담당한다.

---

## 2️⃣ B-Tree의 핵심 특징

### 🔹 1. 하나의 노드에 여러 개의 키 저장

예를 들어

```plain text
[10 | 20 | 30]
```

이라는 노드가 있다면,

```plain text
        [10 | 20 | 30]
       /    |    |    \
     <10  10~20 20~30  >30
```

처럼 여러 개의 자식 서브트리를 가질 수 있다.

➡️ **다방향 탐색(Multi-way Search)**

---

### 🔹 2. 항상 균형을 유지

B-Tree는 모든 리프 노드가 **같은 레벨**에 존재한다.

```plain text
          [20]
        /      \
     [10]     [30 | 40]
     / \       / | \
   ... ...   ... ... ...
```

따라서 특정 데이터만 지나치게 깊은 곳에 위치하는 것을 방지한다.

➡️ 트리 높이를 낮게 유지

➡️ 탐색 성능을 안정적으로 유지

---

### 🔹 3. 노드가 가득 차면 분할(Split)

삽입 과정에서 노드가 허용된 키 개수를 초과하면

```plain text
        [10 | 20 | 30]
```

노드를 분할하고 가운데 키를 부모로 올린다.

```plain text
          [20]
         /    \
      [10]    [30]
```

이 과정을 통해 트리의 균형을 유지한다.

---

### 🔹 4. 노드가 너무 비어 있으면 병합(Merge)

삭제 과정에서 노드의 키가 부족해지면

- 형제 노드에서 키를 빌리거나

- 형제 노드와 병합

하여 최소 키 개수 조건을 유지한다.

➡️ **삽입: Split**

➡️ **삭제: Borrow / Merge**

---

## 3️⃣ B+Tree란?

### 📌 정의

**B+Tree는 B-Tree를 기반으로 데이터베이스와 파일 시스템의 인덱스에 적합하도록 변형한 구조**이다.

가장 큰 차이는 **데이터가 저장되는 위치**이다.

### B-Tree

```plain text
          [20]
        /      \
   [10 | 15]  [25 | 30]
    ↑ DATA     ↑ DATA
```

내부 노드에서도 데이터에 접근할 수 있다.

### B+Tree

```plain text
          [20]
        /      \
   [10 | 15]  [20 | 25 | 30]
       ↓             ↓
     DATA          DATA
```

내부 노드는 **탐색을 위한 키와 자식 포인터** 중심으로 구성하고,

실제 데이터는 **리프 노드에만 저장**한다.

---

## 4️⃣ B+Tree의 추가적인 특징

### 🔗 리프 노드 연결

B+Tree의 리프 노드는 일반적으로 서로 연결되어 있다.

```plain text
[10 | 15] → [20 | 25] → [30 | 35] → [40 | 45]
```

따라서 특정 범위를 찾은 뒤에는
다음 리프 노드로 이동하면서 데이터를 순차적으로 확인할 수 있다.

예:

```sql
WHERE age BETWEEN 20 AND 40
```

➡️ 20을 찾은 뒤

➡️ 연결된 리프 노드를 따라가며

➡️ 40까지 순차적으로 탐색

---

## 5️⃣ B-Tree vs B+Tree

| 구분 | B-Tree | B+Tree |
| --- | --- | --- |
| 데이터 저장 | 내부 노드 + 리프 노드 | **리프 노드** |
| 내부 노드 | 키 + 데이터/포인터 | **키 + 자식 포인터** |
| 리프 노드 연결 | 일반적으로 없음 | **연결 리스트 형태** |
| 단일 값 탐색 | 빠름 | 빠름 |
| 범위 검색 | 상대적으로 불리 | **유리** |
| 순차 접근 | 상대적으로 불리 | **유리** |
| DB 인덱스 | 사용 가능 | **널리 사용** |

---

## 6️⃣ 왜 DB에서 B+Tree가 많이 사용될까?

DB의 데이터는 대부분 메모리가 아니라 **디스크/SSD**에 저장된다.

따라서 중요한 것은 단순히 비교 연산 횟수가 아니라

> **디스크에서 얼마나 적은 횟수로 데이터를 읽어오는가?**

이다.

B-Tree 계열은 하나의 노드에 여러 키를 저장하여
트리의 높이를 낮출 수 있다.

```plain text
BST

높음
 ↓
   O
  / \
 O   O
 ...
```

```plain text
B-Tree / B+Tree

낮음
 ↓
        [10|20|30|40|50]
       /  |  |  |  |  \
     ...
```

➡️ 트리 높이 감소

➡️ 디스크 I/O 감소

➡️ 대규모 데이터 탐색에 유리

---

## 📌 핵심 정리

- **B-Tree**: 여러 키를 가진 다방향 균형 탐색 트리

- **B+Tree**: B-Tree의 변형으로, 실제 데이터를 리프 노드에 집중

- B+Tree의 **리프 노드는 연결**되어 범위 검색과 순차 접근에 유리

- 두 구조 모두 균형을 유지하여 일반적으로 **O(log N)** 탐색 가능

- 데이터베이스 인덱스에서는 **디스크 I/O를 줄이고 범위 검색을 효율적으로 수행할 수 있어 B+Tree가 널리 사용됨**

---

## 🎯 예상 꼬리 질문

### Q. Red-Black Tree와 B+Tree의 차이는?

**Red-Black Tree는 균형 이진 탐색 트리이고, B+Tree는 여러 개의 자식과 키를 가질 수 있는 다진 탐색 트리입니다.**

Red-Black Tree는 주로 메모리 자료구조에서 사용하고, B+Tree는 한 노드에 많은 데이터를 저장해서 **트리의 높이와 디스크 I/O를 줄일 수 있기 때문에 DB 인덱스에 주로 사용됩니다.**

또 B+Tree는 리프 노드들이 연결되어 있어서 **범위 검색에도 유리합니다.**

---

### Q. Hash Index와 B+Tree Index의 차이는?

**Hash Index는 해시 함수를 이용해서 특정 키를 빠르게 찾는 데 유리하고, B+Tree Index는 정렬된 구조를 유지하기 때문에 범위 검색에 유리합니다.**

그래서 `WHERE id = 10`같은 **동등 비교에는 Hash가 적합**하지만,

`id BETWEEN 10 AND 20`이나 `ORDER BY`처럼 **범위나 정렬이 필요한 경우에는 B+Tree가 적합합니다.**

일반적인 DB 인덱스에서는 이런 이유로 B+Tree가 많이 사용됩니다.

---

### Q. B+Tree에서 삽입/삭제가 발생하면 어떻게 균형을 유지하는가?

**삽입할 때 노드가 가득 차면 노드를 분할하고, 필요한 경우 부모로 키를 올려서 트리의 균형을 유지합니다.**

반대로 삭제로 인해 노드의 키가 최소 개수보다 부족해지면 **인접한 노드에서 키를 빌리거나, 인접 노드와 병합**합니다.

이런 과정을 통해 **모든 리프 노드가 같은 깊이에 있도록 유지**하기 때문에 B+Tree는 항상 균형 잡힌 구조를 유지합니다.
