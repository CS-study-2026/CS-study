# 5-2. 앞 꼬리질문에 대해, 그렇다면 인덱스에서 사용하지 않겠다고 선택한 값은 위 정책을 그대로 따라가나요?

# 1. 일반적인 인덱스는 "특정 값만 사용 안 함"이 아님

예를 들어:

```sql
CREATE INDEX idx_age
ON users(age);
```

라고 하면 일반적인 B+Tree 인덱스에서는 `age` 컬럼의 인덱스 대상 엔트리들이 관리됨

```plain text
users

id | age
---|----
1  | 20
2  | 30
3  | 40

===========
idx_age
===========
20 → row 1
30 → row 2
40 → row 3
```

여기서 갑자기

> "30이라는 값은 인덱스에서 사용하지 않겠습니다."

라는게 아님

**Partial/Filtered Index **처럼 조건을 걸어서 일부 행만 인덱싱하는 기능은 O

예를 들어 PostgreSQL이라면:

```sql
CREATE INDEX idx_active_user
ON users(email)
WHERE active=true;
```

이 경우에는 `active = false`인 행들이 해당 인덱스에서 제외됨

---

# 2. **Partial Index 또는 특정 값을 제외하는 인덱스**

예를 들어:

```sql
CREATE INDEX idx_status
ON orders(status)
WHERE status!='DONE';
```

라고 할 때,

주문이:

```plain text
order_id | status
---------|---------
1        | WAIT
2        | WAIT
3        | DONE
4        | DONE
5        | DONE
```

이라면 인덱스에는 조건을 만족하는 행만 들어감

```plain text
Index

WAIT → order 1
WAIT → order 2

DONE → 인덱스 대상 아님
```

그러면 `DONE` 행들은 **이 인덱스에서 관리할 필요가 X**

그래서 해당 인덱스 관점에서는 저장 공간과 유지 비용을 줄일 수 O

---

# 3. **Partial Index를 사용할 수 없다**는 것은 반드시 Full Table Scan을 한다는 뜻은 아니다.

다른 적절한 인덱스가 있다면 그걸 사용할 수도 있고, DB 옵티마이저가 다른 실행 계획을 선택할 수도 있음

즉:

```plain text
Partial Index 사용 불가능
        ↓
다른 Index 사용 가능?
    /          \
   O            X
다른 Index    Seq Scan 등이
사용 가능      선택될 수 있음
```

---

# 4. UPDATE - 기존 인덱스 엔트리 제거

예를 들어:

```sql
CREATE INDEX idx_status
ON orders(status)
WHERE status!='DONE';
```

에서

```sql
UPDATE orders
SET status='DONE'
WHERE order_id=1;
```

하면

기존에는:

```plain text
WAIT → 인덱스에 존재
```

했는데 `DONE`으로 바뀌면서 Partial Index 조건에서 벗어남

따라서:

```plain text
WAIT
Index O
  ↓
UPDATE
  ↓
DONE
Index X

→ 기존 인덱스 엔트리를 제거해야 함
```

즉 **UPDATE 비용이 아예 사라지는 것도 X**

반대로 이미 `DONE`인 행에서 **인덱스와 무관한 컬럼**만 수정하는 경우라면 해당 Partial Index의 유지 비용을 줄이는 효과가 있을 수 O

---

# 5. 면접용 답변

> 일반적인 인덱스는 특정 값만 임의로 제외하는 방식이 아니라, 인덱스로 지정한 컬럼의 값을 대상으로 관리합니다. 다만 Partial Index나 Filtered Index를 사용하면 특정 조건을 만족하는 행만 인덱스에 포함할 수 있습니다.


예를 들어 `status != 'DONE'`인 데이터만 인덱싱한다면 `DONE`인 행은 해당 인덱스에서 관리하지 않기 때문에 인덱스의 크기와 유지 비용을 줄일 수 있습니다.

다만 UPDATE로 인해 `WAIT`에서 `DONE`처럼 인덱스 조건을 벗어나게 되면 기존 인덱스 엔트리를 삭제해야 하고, 반대로 `DONE`에서 `WAIT`로 변경되면 새로운 인덱스 엔트리를 추가해야 하므로 인덱스 유지 비용이 완전히 없어지는 것은 아닙니다.

또한 Partial Index의 조건에 해당하지 않는 데이터를 조회한다고 해서 반드시 Full Table Scan이 발생하는 것은 아니며, 옵티마이저가 다른 인덱스나 적절한 실행 계획을 선택할 수 있습니다.

**한 줄 핵심**

> **Partial Index는 일부 행을 인덱스에서 제외해 저장 공간과 유지 비용을 줄일 수 있지만, 데이터 변경으로 인덱스 포함 여부가 바뀌면 여전히 인덱스 갱신 비용이 발생합니다.**
