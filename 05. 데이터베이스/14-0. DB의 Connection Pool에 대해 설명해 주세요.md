# 14-0. DB의 Connection Pool에 대해 설명해 주세요.

> **DB의 Connection Pool(커넥션 풀)**은 쉽게 말하면 DB와의 연결(Connection)을 미리 여러 개 만들어 두고, 필요할 때 빌려 쓰고 다시 반납하는 방식

### 1. 왜 필요한가요?

애플리케이션이 DB에 접근할 때마다 매번 이렇게 하면:

```plain text
요청 발생
   ↓
DB 연결 생성
   ↓
SQL 실행
   ↓
DB 연결 종료
```

DB 연결을 만드는 과정에는 네트워크 연결, 인증, 세션 생성 등이 필요해서 생각보다 비용이 크다.

그래서 실제로는:

```plain text
           Connection Pool
        ┌───────────────┐
요청 1 →│ Connection 1  │
요청 2 →│ Connection 2  │
요청 3 →│ Connection 3  │
        └───────────────┘
                ↕
               DB
```

처럼 **미리 DB Connection을 만들어 둔다.**

---

### 2. 동작 과정

예를 들어 Pool에 Connection이 3개 있다고 해보자.

```plain text
Pool

C1 : 사용 가능
C2 : 사용 가능
C3 : 사용 가능
```

사용자 A의 요청이 오면:

```plain text
A → C1 빌림
```

사용자 B도 요청:

```plain text
B → C2 빌림
```

SQL 실행이 끝나면 Connection을 실제로 끊는 게 아니라:

```plain text
A 작업 완료
↓
C1을 Pool에 반납
```

한다.

즉,

> **Connection 생성 → 종료**가 아니라

**Connection 빌림 → 사용 → 반납 → 재사용**

하는 구조이다.

---

### 3. 장점

가장 중요한 것은 **성능 향상이**다.

DB Connection을 매번 새로 만드는 작업을 줄일 수 있어서 응답 시간이 빨라지고, 동시에 많은 요청이 들어오는 웹 서버에서 특히 유리하다. 또한 Connection의 최대 개수를 제한해서 DB에 너무 많은 연결이 생성되는 것도 막을 수 있다.

예를 들어:

```plain text
Connection Pool 최대 = 10

동시 요청 100개
```

라고 해도 실제 DB Connection은 최대 10개만 사용하고 나머지 요청은 Connection이 반환되기를 기다리는 식으로 관리할 수 있다.

---

### 4. Pool이 꽉 차면?

여기가 시험에서도 중요하다.

```plain text
maximumPoolSize = 10

10개의 Connection이 모두 사용 중
↓
11번째 요청 발생
```

그러면 바로 새로운 Connection을 무한정 만드는 게 아니라 **Connection 하나가 Pool로 돌아올 때까지 기다린다.**

일정 시간 동안 Connection을 얻지 못하면 **Timeout**이 발생한다.

대표적인 Java Connection Pool인 HikariCP에서도 `maximumPoolSize`까지 Connection을 사용 중이고 idle Connection이 없으면 `getConnection()` 호출이 `connectionTimeout`까지 대기한 뒤 실패하도록 되어 있다.

---

### 5. 중요한 설정값

Spring Boot에서 많이 쓰는 **HikariCP** 기준으로 보면 다음 정도만 기억하면 된다.

| 설정 | 의미 |
| --- | --- |
| `maximumPoolSize` | Pool에서 만들 수 있는 최대 Connection 수 |
| `minimumIdle` | 최소한으로 유지할 Idle Connection 수 |
| `connectionTimeout` | Connection을 기다릴 최대 시간 |
| `idleTimeout` | 사용하지 않는 Connection을 유지하는 시간 |
| `maxLifetime` | Connection 하나의 최대 생존 시간 |

특히:

```plain text
maximumPoolSize = 10
```

이면

> DB에 동시에 연결할 수 있는 Connection을 최대 10개까지 Pool에서 관리한다.

### 요약

```plain text
Connection Pool
= DB 연결을 미리 만들어 놓는 저장소

요청
→ Connection 빌림
→ SQL 수행
→ Connection 반납
→ 다른 요청이 재사용
```

### 구현 방법

> **DB Connection은 보통 눈에 보이는 "파일" 형태가 아니라, 애플리케이션 안에서 객체(Object) 형태로 다룬다.** 그 객체가 실제로는 DB 서버와의 네트워크 세션을 잡고 있다.

Java 기준으로 보면 보통 이렇게 생긴다.

```java
Connectionconn=DriverManager.getConnection("jdbc:mysql://localhost:3306/testdb","user","password"
);
```

여기서 `conn`이 바로 **DB Connection 객체**입니다.

내부적으로는 대략 이런 구조입니다.

```plain text
Java Application
      │
      │ Connection 객체
      ▼
 JDBC Driver
      │
      │ TCP 연결
      ▼
 Database Server
      │
      └─ DB Session
```

즉 Connection은 단순한 변수 하나처럼 보이지만, 실제로는 **DB 서버와 통신할 수 있는 연결 상태를 나타내는 객체이**다.

예를 들어 이 Connection을 이용해서 SQL을 실행한다.

```java
Connectionconn= ...;PreparedStatementps=conn.prepareStatement("SELECT * FROM user");ResultSetrs=ps.executeQuery();
```

흐름을 보면:

```plain text
Connection
   ↓
PreparedStatement
   ↓
SQL 실행
   ↓
ResultSet
```

이라고 볼 수 있다.

Connection Pool을 사용하면 이 `Connection` 객체들을 여러 개 만들어서 관리한다.

```plain text
Connection Pool

[Connection 1]
[Connection 2]
[Connection 3]
[Connection 4]
[Connection 5]
```

요청이 들어오면:

```plain text
Connectionconn=dataSource.getConnection();
```

처럼 Pool에서 하나를 빌린다.

그리고

```plain text
conn.close();
```

를 호출하더라도 Connection Pool을 사용하는 환경에서는 보통 **실제 DB 연결을 끊는 게 아니라 Pool에 반납된**다.

이 부분이 중요하다.

```plain text
일반 Connection

close()
 ↓
DB 연결 종료
```

반면

```plain text
Connection Pool

close()
 ↓
Pool에 반납
 ↓
다른 요청이 재사용
```

이라고 이해하면 된다.

한마디로 정리하면 **DB Connection = 애플리케이션과 DB 서버 사이의 통신 세션을 나타내는 객체이**다. Java에서는 대표적으로 `java.sql.Connection` 인터페이스로 다룬다.

### HikariCP

Java/Spring에서 많이 쓰는 **DB Connection Pool 구현체이**다. 즉,  “Connection을 미리 여러 개 만들어 두고 빌려주고 반납받는 역할”을 실제로 해주는 라이브러리이다.

흐름은 이렇게 보면 된다.

```plain text
Spring 애플리케이션
        ↓
     HikariCP
 ┌───────────────┐
 │ Connection 1  │
 │ Connection 2  │
 │ Connection 3  │
 │ ...           │
 └───────────────┘
        ↓
       DB
```

예를 들어 요청이 들어오면 HikariCP에서 Connection 하나를 빌립니다.

```plain text
Connectionconn=dataSource.getConnection();
```

SQL 작업이 끝나고

```plain text
conn.close();
```

를 하면, 일반적으로 HikariCP 환경에서는 DB 연결 자체를 끊어버리는 게 아니라 **Pool로 반납**해서 다른 요청이 재사용할 수 있게 한다.

특히 중요한 설정은 이런 것들이다.

```plain text
spring.datasource.hikari.maximum-pool-size=10
spring.datasource.hikari.connection-timeout=30000
```

여기서 `maximumPoolSize=10`이면 HikariCP가 관리하는 실제 DB Connection의 최대 개수가 10개라는 뜻이다. 10개를 전부 사용 중인데 새로운 요청이 들어오면, Connection이 반납될 때까지 기다리고 `connectionTimeout`을 넘기면 예외가 발생한다. HikariCP 공식 문서 기준 기본 `maximumPoolSize`는 10, `connectionTimeout`은 30초이다.

핵심 관계만 외우시면:

```plain text
Connection
= DB와 실제로 연결된 하나의 통신 세션

Connection Pool
= 여러 Connection을 모아서 관리하는 개념

HikariCP
= Connection Pool을 실제로 구현한 Java 라이브러리
```

즉 **HikariCP 자체가 Connection은 아니고, Connection들을 관리하는 관리자**라고 생각하시면 가장 정확하다.

### 사용 예시

> **DB에 자주 접근하는 애플리케이션**, 특히 **여러 사용자의 요청을 동시에 처리하는 서버**에서 사용한다.

1. **웹 서버 / API 서버**

Spring Boot 같은 서버에서 사용자 요청이 계속 들어오는 경우

```plain text
GET /users
POST /login
GET /products
POST /orders
```

각 요청에서 DB를 조회해야 하니까 Connection Pool을 사용하면 효율적이다.

1. **동시에 여러 사용자가 DB를 사용하는 경우**

예를 들어 서버에 동시에 100명이 접속했다고 해서 DB Connection을 무조건 100개 만드는 대신,

```plain text
Connection Pool = 10개
```

정도로 만들어 두고 요청들이 순차적으로 빌려 쓰게 할 수 있다.

1. **DB 조회가 반복적으로 발생하는 장시간 실행 애플리케이션**

```plain text
서버 실행
↓
수천~수백만 번 DB 접근
↓
서버 종료
```

같은 프로그램에서는 Connection을 계속 새로 만드는 것보다 Pool을 사용하는 것이 훨씬 효율적이다.

반대로 **단 한 번 DB에 접속하고 끝나는 간단한 프로그램**이라면 Connection Pool의 필요성이 크지 않다.

```plain text
DB연결↓SELECT 한 번
↓
프로그램 종료
```

이런 단순 스크립트라면 그냥 Connection 하나 만들어 사용해도 된다.

핵심은 이렇게 기억하시면 된다.

> **Connection Pool = DB 연결이 반복적으로 필요한 서버 환경에서 Connection 생성 비용을 줄이고, 동시에 사용할 DB 연결 수를 관리하기 위해 사용한다.**

실무 흐름으로 연결하면:

```plain text
사용자 요청
    ↓
Spring Server
    ↓
HikariCP에서 Connection 빌림
    ↓
SQL 실행
    ↓
Connection 반납
    ↓
다음 요청이 재사용
```

즉 **웹 백엔드 개발에서는 거의 기본적으로 사용한다고 생각하시면 된다.**

> 💡 Spring Boot에서 `spring-boot-starter-jdbc` 또는 `spring-boot-starter-data-jpa`로 DB를 사용했고, 별도로 다른 Connection Pool을 설정하지 않았다면 보통 HikariCP를 사용한다.
