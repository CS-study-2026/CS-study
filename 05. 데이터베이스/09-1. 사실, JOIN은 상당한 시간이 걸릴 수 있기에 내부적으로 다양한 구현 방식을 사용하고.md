# 9-1. 사실, JOIN은 상당한 시간이 걸릴 수 있기에 내부적으로 다양한 구현 방식을 사용하고 있습니다. 그 예시에 대해 설명해 주세요.

# 0. 왜 Join이 시간이 많이 걸릴까?

> Note JOIN은 두 개 이상의 독립적인 테이블을 연결해 하나의 결과로 만들어내는 과정에서 데이터베이스의 **CPU 연산량**과 **메모리, 디스크 I/O 자원**을 극도로 많이 소모합니다.

1. 연산 횟수의 기하급수적 증가 (시간 복잡도 O(N × M))

> Note 최악의 경우, 데이터베이스는 조인 조건을 확인하기 위해 A 테이블의 모든 행과 B 테이블의 모든 행을 각각 일일이 비교해야 합니다.

  - A 테이블에 1만 건, B 테이블에 1만 건의 데이터가 있다면, 조인 기준을 잡아줄 인덱스가 없을 경우 최대 1억 번(10,000 × 10,000)의 탐색과 비교 연산이 발생합니다.

  - 데이터 규모가 커질수록 알고리즘의 시간 복잡도처럼 처리 시간이 곱연산으로 폭증하게 됩니다.

1. 무작위 디스크 I/O (Random Disk Access) 폭증

> Note 데이터베이스의 실질적인 데이터는 메모리(RAM)가 아닌 물리적인 저장장치에 블록 단위로 흩어져 저장되어 있습니다.

  - 두 테이블의 데이터를 매칭하기 위해 디스크의 여기저기를 탐색하며 읽어 들이는 **랜덤 I/O**가 대량으로 발생합니다.

  - 컴퓨터 시스템 구조상 디스크 장치에 접근하여 데이터를 읽고 쓰는 작업은 CPU 연산이나 메모리 접근보다 압도적으로 느린 병목 구간입니다.

1. 메모리 고갈 및 임시 디스크 공간(Temp Space) 사용

> Note 데이터베이스 엔진은 Sort-Merge나 Hash Join 같은 작업을 빠르게 수행하기 위해 데이터를 메모리(Buffer Pool)로 끌어올려 정렬하거나 해시 맵을 구성합니다.

  - 하지만 조인해야 할 데이터 셋이 너무 거대해서 할당된 메모리 용량을 초과하게 되면, 데이터베이스는 하드 디스크에 임시 작업 공간(Temp Tablespace)을 만들어 데이터를 썼다 지웠다 하며 억지로 연산을 이어갑니다.

  - 가장 빠른 작업장(메모리)을 놔두고 가장 느린 창고(디스크)에서 연산을 수행하게 되면서 쿼리 속도가 급격히 추락합니다.

---

# 1. Nested Loop Join (중첩 루프 조인)

> Note 프로그래밍의 **중첩 반복문(이중 for문)** 구조와 똑같이 작동하는 가장 기본적인 조인 방식입니다.

기준이 되는 외부 테이블(Driving Table)의 행을 하나씩 읽으면서, 연결할 내부 테이블(Driven Table)을 검색하여 조건에 맞는 데이터를 찾습니다.

특징:

> Note 

  1. 인덱스 의존도

  - 내부 테이블의 조인 컬럼에 인덱스가 구성되어 있을 때 매우 빠른 속도를 냅니다.

  1.  사용 환경

  - 소량의 데이터를 처리하거나, 인덱스가 완벽하게 설계된 온라인 트랜잭션 처리(OLTP) 환경에서 주로 선택됩니다.

  1. 치명적 단점

  - 인덱스가 없다면 외부 테이블을 읽을 때마다 내부 테이블 전체를 풀 스캔(Full Scan)해야 하므로 데이터량이 많아질수록 시간 복잡도가 O(N x M)으로 기하급수적으로 증가합니다.

---

# 2. Sort-Merge Join (정렬 병합 조인)

> Note 조인할 두 테이블의 데이터를 조인 키를 기준으로 각각 정렬(Sort)한 뒤, 두 집합을 순차적으로 훑어 내려가며 조건에 맞는 데이터를 병합(Merge)하는 방식입니다.

투 포인터(Two Pointer) 알고리즘과 유사한 방식으로 데이터를 매칭하여 처리합니다.

특징:

> Note 

  1. 인덱스 무관

  - 조인 컬럼에 인덱스가 없어도 사용할 수 있습니다.

  1. 연산 범위

  - 동등 조인(=)뿐만 아니라 비등가 조인(>, <, >=, <=)에서도 활용이 가능합니다.

  1. 오버헤드

  - 데이터 정렬 과정 자체에서 CPU와 메모리를 다량 소모하므로, 정렬해야 할 데이터가 너무 거대할 경우 메모리 공간 부족이나 디스크 I/O 병목이 발생할 수 있습니다.

---

# 3. Hash Join (해시 조인)

> Note 조인할 두 테이블 중 크기가 더 작은 테이블을 메모리에 올려 해시 테이블(Hash Table)을 생성(Build)하고, 나머지 큰 테이블을 순차적으로 스캔하면서 해시 함수를 통해 매칭되는 값을 찾아가는(Probe) 방식입니다.

특징:

> Note 

  1. 탐색 속도

  - 해시 함수를 거쳐 주소를 직접 찾아가기 때문에 탐색 속도가 O(1)에 수렴할 정도로 매우 빠릅니다.

  1. 사용 환경

  - 대규모 데이터 웨어하우스나 통계 처리, 데이터 분석(OLAP) 등 거대한 테이블을 빠르게 조인해야 할 때 최적의 성능을 자랑합니다.

  1. 제한 사항

  - 해시 함수의 특성상 값이 정확히 일치해야만 주소를 찾을 수 있으므로 동등 조인(=) 조건에서만 작동합니다. 부등호 연산에서는 사용할 수 없습니다.

| --- | --- | --- | --- |
| Nested Loop Join | 소량 데이터 조회

| Sort-Merge Join | 비등가 조인(>, <, >=, <=)

| Hash Join | 대규모 데이터 웨어하우스

통계 및 데이터 분석(OLAP)

인덱스가 없는 거대한 두 테이블 결합 | 무거운 정렬 과정 없이 해시 함수를 통해 주소를 다이렉트로 찾아가므로 대규모 매칭 시 압도적으로 빠릅니다. | 값이 정확히 일치하는 동등 조인(=)에서만 사용이 가능하며, 해시 테이블 생성 시 메모리를 다량 차지합니다. |
