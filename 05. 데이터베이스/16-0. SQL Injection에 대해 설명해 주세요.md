# 16-0. SQL Injection에 대해 설명해 주세요.

> 

SQL Injection은 사용자가 입력한 값이 SQL 문장의 일부로 해석되도록 만들어, 공격자가 의도하지 않은 SQL을 실행시키는 공격입니다.

예를 들어 로그인 과정에서 사용자 입력을 문자열로 SQL에 직접 이어 붙이면, 공격자가 조건식을 조작해서 인증 절차를 우회할 수 있습니다.

대표적인 방어 방법은 **사용자 입력을 SQL 문법과 분리하는 것**입니다. 이를 위해 Prepared Statement나 Parameterized Query를 사용합니다. 이렇게 하면 입력값이 SQL 문법이 아니라 단순한 데이터로 처리되기 때문에 공격자가 SQL 구문을 주입하기 어렵습니다.

따라서 SQL Injection의 핵심 원인은 **신뢰할 수 없는 사용자 입력을 SQL 문장에 직접 결합하는 것**이고, 가장 기본적인 대응 방법은 **파라미터 바인딩을 사용하는 것**입니다.

---

## 1️⃣ SQL Injection이란?

### 📌 정의

**SQL Injection**은 악의적인 SQL 구문을 입력값에 포함시켜,
애플리케이션이 의도하지 않은 SQL을 실행하도록 만드는 공격이다.

즉,

```plain text
사용자 입력
   ↓
SQL 문장에 직접 결합
   ↓
SQL 문법으로 해석
   ↓
의도하지 않은 쿼리 실행
```

이 발생하는 것이 핵심이다.

---

## 2️⃣ 어떻게 발생하는가?

예를 들어 로그인 기능이 있다고 가정한다.

### ❌ 취약한 코드

```java
String sql =
    "SELECT * FROM users " +
    "WHERE id = '" + userId + "' " +
    "AND password = '" + password + "'";
```

사용자가 정상적으로 입력하면

```plain text
id       = user01
password = 1234
```

다음과 같은 SQL이 만들어진다.

```sql
SELECT *
FROM users
WHERE id = 'user01'
AND password = '1234';
```

정상적인 경우에는 문제가 없다.

---

## 3️⃣ 악의적인 입력이 들어온다면?

공격자가 입력값에 SQL 문법을 넣을 수 있다.

예를 들어 비밀번호에

```plain text
' OR '1'='1
```

과 같은 값을 입력한다고 가정한다.

그러면 애플리케이션이 만드는 SQL이 의도와 다르게 구성될 수 있다.

```sql
SELECT *
FROM users
WHERE id = 'user01'
AND password = '' OR '1'='1';
```

⬇️

```sql
(id = 'user01' AND password = '')
OR
('1' = '1')
```

여기서 `'1'='1'`은 항상 참이다.

따라서 원래 의도했던

```plain text
아이디 + 비밀번호가 일치하는가?
```

라는 조건이 공격자의 입력에 의해 변조될 수 있다.

➡️ **사용자 입력이 SQL 문법으로 해석된 것이 문제**

---

## 4️⃣ SQL Injection의 핵심 원인

### ❌ 문자열 연결(String Concatenation)

```java
String sql =
    "SELECT * FROM users WHERE id = '" + userId + "'";
```

이 방식에서는

```plain text
SQL 코드
+
사용자 입력
```

이 하나의 문자열로 합쳐진다.

따라서 DB 입장에서는

```plain text
어디까지가 SQL이고
어디부터가 데이터인지
```

구분하기 어렵다.

---

## 5️⃣ 대표적인 공격 유형

### 🔹 인증 우회

로그인 SQL의 조건을 조작하여
정상적인 비밀번호 검증을 우회

---

### 🔹 데이터 조회

공격자가 SQL을 조작하여
원래 접근할 수 없는 데이터를 조회

```plain text
사용자 정보
비밀번호 관련 정보
개인정보
```

등이 노출될 수 있다.

---

### 🔹 데이터 수정 / 삭제

애플리케이션 계정에 충분한 DB 권한이 있다면

```sql
UPDATE ...
DELETE ...
```

등의 의도하지 않은 SQL 실행으로 이어질 수 있다.

> ⚠️ 실제 피해 범위는 애플리케이션의 DB 계정 권한과 DB 설정 등에 따라 달라진다.

---

## 6️⃣ 가장 중요한 방어 방법

### 🛡️ Parameterized Query

SQL 문장과 사용자 입력을 분리한다.

```java
String sql =
    "SELECT * FROM users WHERE id = ? AND password = ?";

PreparedStatement pstmt =
    connection.prepareStatement(sql);

pstmt.setString(1, userId);
pstmt.setString(2, password);
```

이 경우

```plain text
SQL 구조
    ↓
SELECT ... WHERE id = ? AND password = ?
```

와

```plain text
사용자 입력
    ↓
userId
password
```

가 분리된다.

사용자가 SQL 문법을 입력하더라도
해당 값은 **SQL 코드가 아니라 하나의 데이터 값**으로 처리된다.

---

## 7️⃣ 방어 방법 정리

| 방법 | 설명 |
| --- | --- |
| **Parameterized Query** | SQL과 입력값을 분리 |
| **Prepared Statement** | 파라미터를 바인딩하여 SQL Injection 방지 |
| ORM 사용 | 쿼리 생성 과정에서 파라미터 바인딩 활용 |
| 입력값 검증 | 예상되는 형식인지 검증 |
| 최소 권한 | DB 계정에 필요한 권한만 부여 |
| 오류 메시지 제한 | DB 구조나 SQL 정보를 외부에 노출하지 않음 |

### ⭐ 핵심

가장 중요한 방어 원칙은

> **"사용자 입력을 SQL 문법으로 해석되지 않도록 한다."**

이다.

---

## 📌 핵심 정리

```plain text
SQL Injection
      ↓
사용자 입력이 SQL 문법으로 해석
      ↓
의도하지 않은 SQL 실행
      ↓
인증 우회 / 데이터 조회 / 데이터 변경 등
```

따라서

```plain text
문자열 연결 ❌

Parameterized Query
Prepared Statement
파라미터 바인딩 ✅
```

을 사용하여 **SQL 코드와 데이터를 분리**하는 것이 핵심적인 방어 방법이다.
