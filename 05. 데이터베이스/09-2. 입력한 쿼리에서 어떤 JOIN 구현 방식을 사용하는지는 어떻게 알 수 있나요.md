# 9-2. **입력한 쿼리에서 어떤 JOIN 구현 방식을 사용하는지는 어떻게 알 수 있나요?**

입력한 쿼리에서 DBMS가 어떤 방식으로 JOIN을 수행하는지는 **실행 계획, Execution Plan**을 확인하면 알 수 있습니다.

사용자가 SQL을 작성하면 DBMS는 그 SQL을 그대로 순서대로 실행하지 않습니다.

먼저 옵티마이저가 여러 실행 방법을 비교한 뒤, 비용이 낮다고 판단한 실행 계획을 선택합니다.

```plain text
SQL 입력
→ 파싱
→ 옵티마이저가 실행 계획 생성
→ 선택된 실행 계획대로 실행
```

이때 실행 계획에는 다음과 같은 정보가 포함됩니다.

```plain text
어떤 테이블을 먼저 읽는지
어떤 인덱스를 사용하는지
각 테이블에서 몇 건 정도 읽을 것으로 예상하는지
JOIN 순서가 어떻게 되는지
JOIN 알고리즘이 무엇인지
임시 테이블이나 정렬이 필요한지
```

실행 계획을 확인하는 대표적인 명령은 `EXPLAIN`입니다.

```plain text
EXPLAIN
SELECT *
FROM orders o
JOIN users u
  ON o.user_id = u.id;
```

DBMS에 따라 더 자세한 실제 실행 결과를 보고 싶다면 `EXPLAIN ANALYZE`를 사용할 수도 있습니다.

```plain text
EXPLAIN ANALYZE
SELECT *
FROM orders o
JOIN users u
  ON o.user_id = u.id;
```

`EXPLAIN`은 DBMS가 예상한 실행 계획을 보여주고,

`EXPLAIN ANALYZE`는 실제로 쿼리를 실행한 뒤 실제 수행 시간과 실제 처리한 row 수까지 함께 보여줍니다.

다만 MySQL, PostgreSQL, Oracle 등 DBMS마다 출력 형식은 다릅니다.

예를 들어 MySQL에서는 실행 계획에서 다음 항목들을 볼 수 있습니다.

```plain text
type
→ 테이블 접근 방식

possible_keys
→ 사용할 수 있었던 인덱스 후보

key
→ 실제 선택된 인덱스

rows
→ 읽을 것으로 예상되는 행 수

Extra
→ 추가 실행 정보
```

PostgreSQL에서는 다음과 같은 형태로 JOIN 방식이 더 직접적으로 표시될 수 있습니다.

```plain text
Nested Loop
Hash Join
Merge Join
```

즉, JOIN 구현 방식을 확인하려면 단순히 SQL 문장만 보는 것이 아니라, DBMS가 선택한 실행 계획을 확인해야 합니다.

예를 들어 같은 JOIN 쿼리라도 데이터 양, 인덱스 유무, 통계 정보, 조건절에 따라 실행 방식이 달라질 수 있습니다.

```plain text
데이터가 적음
→ 단순한 Nested Loop가 선택될 수 있음

JOIN 컬럼에 적절한 인덱스 있음
→ 인덱스를 활용한 Nested Loop가 선택될 수 있음

큰 테이블끼리 조인
→ Hash Join이나 Merge Join이 선택될 수 있음
```

따라서 질문에 대한 답은 다음과 같이 정리할 수 있습니다.

> 입력한 쿼리에서 어떤 JOIN 구현 방식을 사용하는지는 실행 계획을 확인하면 알 수 있습니다. DBMS는 옵티마이저를 통해 여러 실행 방법 중 비용이 낮다고 판단한 계획을 선택하며, `EXPLAIN`이나 `EXPLAIN ANALYZE`를 사용하면 JOIN 순서, 사용 인덱스, 예상 row 수, JOIN 알고리즘 등을 확인할 수 있습니다. 단, 실행 계획의 형식과 표시되는 정보는 DBMS마다 다를 수 있습니다.

## 핵심 요약

```plain text
JOIN 구현 방식 확인
= 실행 계획을 확인한다

대표 명령
= EXPLAIN
= EXPLAIN ANALYZE

확인할 것
= JOIN 순서
= 사용 인덱스
= 테이블 접근 방식
= 예상 row 수
= 실제 실행 시간
= JOIN 알고리즘

주의
= SQL만 보고 확정하지 말고 실행 계획을 봐야 한다
```

straight join → opt 강제로 join 순서가 뭔지 알려주는 방식 (mysql)
