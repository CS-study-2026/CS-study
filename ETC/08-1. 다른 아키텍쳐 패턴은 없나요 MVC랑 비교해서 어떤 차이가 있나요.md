# 8-1. 다른 아키텍쳐 패턴은 없나요? MVC랑 비교해서 어떤 차이가 있나요?

## 다른 아키텍처 패턴과의 비교 (MVP, MVVM)

MVC 외에도 UI와 로직의 결합을 분리하기 위해 파생된 대표적인 패턴들

### 1. MVP 패턴 (Model-View-Presenter)

- **특징**: 컨트롤러 대신 프레젠터(Presenter)가 존재

- **차이점**: 뷰와 모델이 서로를 알지 못하며, 프레젠터가 1:1로 뷰의 인터페이스를 직접 조작

### 2. MVVM 패턴 (Model-View-ViewModel)

- **특징**: 뷰모델(ViewModel)과 **데이터 바인딩(Data Binding)** 기술을 사용

- **차이점**: 뷰는 뷰모델의 데이터 상태를 관찰(Observer)하고 있다가, 상태가 바뀌면 코드로 화면을 직접 렌더링하지 않아도 **자동으로 UI 갱신** (모던 프론트엔드/모바일 표준)

### 📊 아키텍처 패턴 비교 요약 테이블

| **구분** | **MVC (Spring MVC 등)** | **MVP (Model-View-Presenter)** | **MVVM (Model-View-ViewModel)** |
| --- | --- | --- | --- |
| **중재자 역할** | Controller (프론트 컨트롤러 포함) | Presenter | ViewModel |
| **View와 Model의 관계** | 뷰가 모델을 직접 참조할 수 있음 | 완전히 분리됨 (프레젠터가 중재) | 완전히 분리됨 (데이터 바인딩 사용) |
| **UI 갱신 방식** | 컨트롤러/서블릿이 뷰를 지정해 렌더링 | 프레젠터가 뷰 인터페이스를 직접 호출 | 뷰모델의 상태 변화를 뷰가 감지하여 자동 갱신 |
| **주요 사용처** | 웹 서버 사이드 렌더링 (Spring MVC) | 레거시 데스크톱/모바일 앱 | 모던 웹 프론트엔드 (Vue.js, React 상태 구조) |
