# 8-0. MVC 패턴이 무엇인가요?

## 0. 사전 지식: 관심사의 분리 (Separation of Concerns)

> 소프트웨어의 구성 요소를 역할에 따라 나누어, 코드의 유지보수성, 확장성, 테스트 용이성을 극대화하기 위한 설계 원칙

## 8. MVC 패턴이 무엇인가요?

### 개념 정의

애플리케이션을 세 가지 핵심 구성 요소인 모델(Model), 뷰(View), 컨트롤러(Controller)로 나누어 설계하는 가장 대표적인 소프트웨어 아키텍처 패턴

- **Model (모델)**: 데이터와 비즈니스 로직을 담당(DB 연동, 데이터 상태 관리)

- **View (뷰)**: 사용자에게 보이는 인터페이스(UI) 화면을 담당

- **Controller (컨트롤러)**: 사용자의 입력(요청)을 받아 모델을 조작하고, 그 결과를 뷰에 전달하는 중재자

### 💡 기본 MVC 패턴 구현 코드 예시 (Java 기준)

개념을 직관적으로 이해할 수 있는 클래스 기반의 간단한 구현 예시

```java
// 1. Model (데이터와 비즈니스 로직 담당)
class UserModel {
    private String name;
    private int age;

    // 생성자를 통해 데이터 초기화 (JS의 constructor 역할을 담당)
    public UserModel(String name, int age) {
        this.name = name;
        this.age = age;
    }

    // Getter & Setter
    public String getName() {
        return name;
    }

    public void setName(String name) {
        this.name = name; // 전달받은 새 이름으로 필드 값을 변경
    }

    public int getAge() {
        return age;
    }

    public void setAge(int age) {
        this.age = age;
    }
}

// 2. View (화면 렌더링/출력 담당)
class UserView {
    public void printUserDetails(String name, int age) {
        System.out.println("[화면 갱신] 이름: " + name + ", 나이: " + age);
    }
}

// 3. Controller (중재자: 사용자의 요청을 받아 Model과 View를 조율)
class UserController {
    private UserModel model;
    private UserView view;

    public UserController(UserModel model, UserView view) {
        this.model = model;
        this.view = view;
    }

    // 사용자의 이름 변경 액션이 들어왔을 때 호출되는 메서드
    public void setUserName(String name) {
        model.setName(name); // 1. Model의 데이터 변경
        updateView();        // 2. 변경된 데이터를 View에 전달하여 갱신
    }

    public void updateView() {
        view.printUserDetails(model.getName(), model.getAge());
    }
}

// --- 실행 클래스 ---
public class MvcDemo {
    public static void main(String[] args) {
        // 1. 모델 초기화 (기본 데이터 설정)
        UserModel model = new UserModel("홍길동", 25);

        // 2. 뷰 생성
        UserView view = new UserView();

        // 3. 컨트롤러 생성 (모델과 뷰를 연결)
        UserController controller = new UserController(model, view);

        // 초기 상태 화면 출력
        controller.updateView();

        System.out.println("--- 사용자가 이름을 '김철수'로 변경 요청 ---");

        // 사용자의 액션 발생 (컨트롤러가 개입)
        controller.setUserName("김철수");
    }
}
```

## 스프링에서의 MVC (Spring MVC)

웹 개발에서 MVC 패턴을 가장 완성도 높게 구현한 프레임워크가 바로 **Spring MVC.**

스프링은 DispatcherServlet(디스패처 서블릿)이라는 프론트 컨트롤러를 중심으로 MVC 구조를 동작.

### 🔄 Spring MVC의 핵심 요청 처리 흐름 (Lifecycle)

1. 클라이언트가 요청을 보내면 **DispatcherServlet**이 가장 먼저 요청을 가로채어 받습니다.

1. DispatcherServlet은 **HandlerMapping**에게 요청 URL을 처리할 컨트롤러를 찾아달라고 위임합니다.

1. 찾은 컨트롤러를 실행할 수 있는 **HandlerAdapter**를 통해 실제 Controller의 메서드를 호출합니다.

1. **Controller**는 비즈니스 로직을 처리한 뒤 Model에 데이터를 담고, 반환할 View의 이름을 리턴합니다.

1. **ViewResolver**가 뷰 이름을 실제 화면 파일(HTML, Thymeleaf 등) 경로로 변환합니다.

1. 최종 렌더링된 화면(또는 JSON 데이터)이 클라이언트에게 응답됩니다.

### 💻 Spring MVC 구현 코드 예시 (Java / Spring Boot)

```java
@Controller // 이 클래스가 Spring MVC의 Controller임을 명시
public class UserController{

    @GetMapping("/user")
    public String getUserProfile(Model model){
        // 1. Model에 데이터를 담습니다 (데이터 전달)
        model.addAttribute("name", "홍길동");
        model.addAttribute("age", 25);

        // 2. 렌더링할 View의 이름을 리턴합니다 (예: userProfile.html)
        return "userProfile";
    }
}
```

- _참고_: 최근 REST API 서버를 개발할 때는 `@Controller` 대신 `@ResponseBody`(또는 `@RestController`)를 사용하여 View를 거치지 않고 Model 데이터를 직접 JSON으로 반환하는 구조를 주로 사용합니다.
