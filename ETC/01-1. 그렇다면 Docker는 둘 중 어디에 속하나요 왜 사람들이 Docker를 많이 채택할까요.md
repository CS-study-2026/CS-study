# 1-1. 그렇다면 Docker는 둘 중 어디에 속하나요? 왜 사람들이 Docker를 많이 채택할까요?

# 1-1. Docker는 가상화와 가상머신 중 어디에 속할까? 왜 많이 사용할까?

## 1. Docker는 어디에 속할까?

[Docker](https://www.docker.com/?utm_source=chatgpt.com)는 **가상머신(VM)이 아니다.**

Docker는 **컨테이너(Container) 기술을 사용하여 애플리케이션의 실행 환경을 격리하는 플랫폼**이다.

넓게 보면 **OS 수준 가상화(OS-level Virtualization)**에 해당한다.

관계를 정리하면 다음과 같다.

```plain text
가상화
│
├── 하드웨어 수준 가상화
│     └── Virtual Machine(VM)
│
└── OS 수준 가상화
      └── Container
            └── Docker ← 컨테이너를 생성·실행·관리하는 플랫폼
```

따라서 정확하게는 **Docker 자체가 가상머신이나 컨테이너인 것도 아니며, 컨테이너를 쉽게 만들고 실행하고 관리할 수 있도록 해주는 플랫폼/도구**라고 이해하면 된다.

---

## 2. VM과 Docker Container는 무엇이 다를까?

가장 중요한 차이는 **각 실행 환경이 독립적인 OS Kernel을 가지느냐**이다.

### Virtual Machine

```plain text
┌─────────────┐  ┌─────────────┐
│    App A    │  │    App B    │
├─────────────┤  ├─────────────┤
│ Guest OS    │  │ Guest OS    │
│  + Kernel   │  │  + Kernel   │
└─────────────┘  └─────────────┘
        │               │
        └───────┬───────┘
                ▼
         ┌────────────┐
         │ Hypervisor │
         └────────────┘
                │
         ┌────────────┐
         │  Hardware  │
         └────────────┘
```

VM 하나하나가 **독립적인 Guest OS와 Kernel**을 가진다.

예를 들어 VM을 3개 생성하고 각각 Linux를 설치했다면 각 VM이 자신의 Linux Kernel을 가지고 실행된다.

### Docker Container

```plain text
┌─────────────┐  ┌─────────────┐  ┌─────────────┐
│ Container A │  │ Container B │  │ Container C │
│    App A    │  │    App B    │  │    App C    │
│ + Libraries │  │ + Libraries │  │ + Libraries │
└─────────────┘  └─────────────┘  └─────────────┘
        │               │               │
        └───────────────┼───────────────┘
                        ▼
                 ┌─────────────┐
                 │ Host Kernel │
                 └─────────────┘
                        │
                 ┌─────────────┐
                 │  Hardware   │
                 └─────────────┘
```

컨테이너는 VM처럼 각각 완전한 OS Kernel을 가지지 않고 **Host의 Kernel을 공유**한다.

대신 프로세스, 파일 시스템, 네트워크 등의 환경을 서로 격리하여 각 컨테이너가 독립적인 환경처럼 동작하게 한다.

이 차이가 Docker의 여러 장점으로 이어진다.

---

## 3. Docker를 많이 사용하는 이유

### ① VM보다 가볍다

VM은 각각 Guest OS를 실행해야 하지만 Docker Container는 Host Kernel을 공유한다.

```plain text
VM
App
↓
Guest OS + Kernel
↓
Hypervisor
↓
Host

Container
App + 필요한 라이브러리
↓
공유 Kernel
↓
Host
```

따라서 일반적으로 컨테이너가 VM보다 **필요한 저장공간과 메모리가 작고 빠르게 시작할 수 있다.**

---

### ② 개발 환경을 동일하게 만들기 쉽다

Docker의 매우 큰 장점 중 하나다.

예를 들어 개발자 A의 환경이 다음과 같다고 하자.

```plain text
Java 17
MySQL 8
Redis 8
특정 라이브러리
특정 환경설정
```

다른 개발자가 프로젝트를 실행하려면 같은 환경을 일일이 구축해야 한다.

이 과정에서 흔히 발생하는 문제가

> "내 컴퓨터에서는 잘 되는데?"

라는 **환경 차이 문제**다.

Docker에서는 필요한 실행 환경을 **Dockerfile 등의 설정으로 정의하고 이미지(Image)로 만들어 배포**할 수 있다.

```plain text
Dockerfile
   │
   │ build
   ▼
Docker Image
   │
   ├── 실행 → Container A
   ├── 실행 → Container B
   └── 실행 → Container C
```

같은 이미지를 사용하면 개발 환경, 테스트 환경, 운영 환경 사이의 차이를 크게 줄일 수 있다.

---

### ③ 배포가 편리하다

Docker에서는 애플리케이션과 실행에 필요한 의존성을 **Image**라는 형태로 패키징할 수 있다.

```plain text
Application
+ Runtime
+ Library
+ Configuration
       │
       ▼
  Docker Image
       │
       ▼
┌─────────────────┐
│ Docker Container│
└─────────────────┘
```

서버에 필요한 프로그램을 하나씩 설치하기보다 Docker가 설치된 환경에서 이미지를 받아 컨테이너를 실행하는 방식으로 배포할 수 있다.

이러한 특성 때문에 **CI/CD와도 잘 어울린다.**

---

### ④ 여러 애플리케이션을 서로 격리할 수 있다

하나의 서버에서도 서로 다른 환경을 가진 애플리케이션을 실행하기 쉽다.

```plain text
Server
│
├── Container A
│     └── Java App
│
├── Container B
│     └── Node.js App
│
├── Container C
│     └── Redis
│
└── Container D
      └── Nginx
```

각각의 컨테이너가 격리되어 있기 때문에 애플리케이션별 환경을 관리하기 편리하다.

---

## 4. VM과 Docker 비교

| 구분 | Virtual Machine | Docker Container |
| --- | --- | --- |
| 가상화 방식 | 하드웨어 수준 가상화 | OS 수준 가상화 |
| Kernel | VM마다 별도 Kernel | Host Kernel 공유 |
| Guest OS | 필요 | 완전한 Guest OS 불필요 |
| 크기 | 상대적으로 큼 | 상대적으로 작음 |
| 시작 속도 | 상대적으로 느림 | 빠름 |
| 격리 수준 | 강함 | 프로세스 수준의 격리 |
| 자원 사용량 | 상대적으로 많음 | 상대적으로 적음 |
| 대표적인 용도 | 서로 다른 OS 환경, 강한 격리 | 애플리케이션 실행·배포 |

단, **Docker가 VM보다 무조건 좋은 것은 아니다.** 서로 목적이 다르다.

VM은 독립적인 Kernel을 가지고 있기 때문에 서로 다른 OS를 실행하거나 더 강한 격리가 필요한 상황에 적합하다. 컨테이너는 같은 Kernel을 공유하는 대신 훨씬 가볍고 빠르게 실행 환경을 구성할 수 있다는 장점이 있다.

---

## 5. 한 가지 주의할 점: Mac/Windows의 Docker

앞에서 Docker Container는 **Host Kernel을 공유한다**고 설명했는데, 여기서 의문이 생길 수 있다.

> "그러면 macOS나 Windows에서 Linux Docker Container는 어떻게 실행하지?"

Linux 컨테이너는 Linux Kernel 기능을 사용하기 때문에 macOS에서 Linux Kernel을 직접 공유할 수 없다.

그래서 [Docker Desktop](https://www.docker.com/products/docker-desktop/?utm_source=chatgpt.com)은 macOS 등에서 **경량 Linux VM을 두고 그 안에서 Linux 컨테이너를 실행하는 방식**을 사용한다.

```plain text
Mac Hardware
      │
    macOS
      │
┌───────────────────┐
│  Linux VM         │
│                   │
│  Linux Kernel     │
│       │           │
│  ┌────┴─────┐     │
│  ▼          ▼     │
│ Container  Container
│    A          B   │
└───────────────────┘
```

따라서 **컨테이너 자체가 VM인 것은 아니지만**, 실행하는 운영체제에 따라 Docker가 내부적으로 VM을 활용할 수 있다.

---

## 핵심 정리

> **Docker는 VM이 아니라 컨테이너를 생성하고 실행·관리하는 플랫폼이다.**

VM은 하드웨어를 가상화하여 각각의 Guest OS와 Kernel을 실행하는 반면, Docker Container는 **OS Kernel을 공유하면서 애플리케이션 실행 환경을 격리**한다.

이 때문에 컨테이너는 일반적으로 VM보다 **가볍고 시작이 빠르며**, 애플리케이션과 의존성을 Image로 패키징할 수 있어 **개발 환경 통일과 배포 자동화에 유리하다.**

이러한 특징이 Docker가 개발 및 서버 배포 환경에서 널리 사용되는 주요 이유다.
