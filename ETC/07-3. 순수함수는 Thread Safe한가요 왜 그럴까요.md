# 7-3. 순수함수는 Thread Safe한가요? 왜 그럴까요?

## 면접 답변

> 순수함수는 **같은 입력에 항상 같은 결과를 반환**하고, **외부에서 관찰 가능한 부수효과가 없는 함수**입니다. 
공유 가변 상태에 의존하거나 이를 변경하지 않으므로 **여러 스레드가 동시에 호출해도 호출 간 간섭이 없어 Thread Safe**합니다. 
다만 자바에서는 인자로 전달한 가변 객체가 다른 스레드에 의해 변경되는 경우까지 고려해야 합니다.

---

## 1. 순수함수의 두 조건

- **동일한 입력값 → 동일한 결과:** 
현재 시간, 난수, 변경 가능한 전역변수 등 외부 상태에 결과가 의존하지 않음

- **관찰 가능한 부수효과 없음:** 
전역변수나 전달받은 객체를 수정하거나 파일·DB·콘솔 등에 쓰지 않음

예를 들어 square(3)은 언제 호출하든 9를 반환하고 외부 상태를 바꾸지 않음

```java
class PureFunctions {
    static int square(int x) {
        return x * x;
    }
}
```

---

## 2. 왜 Thread Safe한가?

`Thread Safe`하다 = 
여러 스레드가 같은 코드나 객체를 동시에 사용해도, 그 코드가 약속한 올바른 동작을 유지한다는 뜻
**하지만 스레드 안전성이 모든 호출의 결과가 같거나 실행 순서가 고정된다는 뜻은 아님**

순수함수는 변경 가능한 공유 상태를 읽거나 갱신하지 않습니다. 각 호출이 자신의 입력값을 바탕으로 계산하므로 다른 호출이 실행 중인 값을 덮어쓰거나, 공유 상태의 변경 시점에 따라 결과가 달라지는 문제가 없습니다.

| 스레드 | 입력 | 계산 | 결과 |
| --- | --- | --- | --- |
| A | 3 | square(3) | 9 |
| B | 5 | square(5) | 25 |

**스레드 A: 3 → 자신의 계산 → 9
스레드 B: 5 → 자신의 계산 → 25서로 변경할 공유 상태가 없으므로 실행이 겹쳐도 간섭하지 X**

따라서 순수한 계산 자체에는 공유 상태를 보호하기 위한 락이 필요하지 않습니다. Oracle도 불변 객체는 상태를 변경할 수 없어 스레드 간 간섭으로 상태가 손상되지 않는다고 설명합니다.

---

## 3. 반례: 공유 상태를 변경하는 함수

```java
class UnsafeCounter {
    private int count = 0;

    int increment() {
        return ++count;
    }
}
```

여러 스레드가 같은 `UnsafeCounter` 객체를 사용하면 문제가 생길 수 있습니다.

++count는 한 줄이지만 개념적으로 ‘읽기 → 더하기 → 저장하기’로 나뉘며, 전체가 원자적인 연산이 아님

| 순서 | 스레드 A | 스레드 B | 공유 count |
| --- | --- | --- | --- |
| 1 | count를 읽음: 0 | — | 0 |
| 2 | — | count를 읽음: 0 | 0 |
| 3 | 1을 계산해 저장 | — | 1 |
| 4 | — | 1을 계산해 저장 | 1 |

두 번 증가했는데 최종값은 2가 아닌 1입니다. 한 스레드의 갱신이 다른 스레드의 저장으로 사라지는 상황입니다. 순수함수는 이러한 공유 상태 갱신을 하지 않기 때문에 이 문제가 생기지 않습니다.

---

## 4. Thread Safe하다고 모두 순수함수는 아니다

```java
import java.util.concurrent.atomic.AtomicInteger;

class SafeCounter {
    private final AtomicInteger count = new AtomicInteger();

    int increment() {
        return count.incrementAndGet();
    }
}
```

incrementAndGet()은 증가 연산을 원자적으로 수행하여 위의 갱신 손실 문제를 해결합니다. 그러나 호출할 때마다 내부 상태가 변하고 반환값도 달라지므로 순수함수는 아닙니다.

| 예시 | 순수함수인가? | 동시 호출 안전성 |
| --- | --- | --- |
| square(int) | 예 | 안전 |
| UnsafeCounter.increment() | 아니요 | 같은 객체를 공유하면 안전하지 않음 |
| SafeCounter.increment() | 아니요 | 이 카운터의 증가 연산은 안전 |

Thread Safe는 동시 실행의 올바름에 대한 성질
순수성은 입력·출력과 부수효과에 대한 성질

---

## 5. 자바에서 주의할 점: 가변 객체 인자

‘이 메서드는 인자를 수정하지 않으니 무조건 안전하다’고 판단하면 부족합니다.

```java
static int sum(int[] values) {
    int result = 0;
    for (int value : values) {
        result += value;
    }
    return result;
}
```

이 메서드는 배열을 직접 수정하지 않습니다. 하지만 실행 중 다른 스레드가 같은 배열 요소를 바꾸면 일관된 입력값에 대한 합을 보장할 수 없습니다. 단지 같은 배열 참조를 전달했다는 사실만으로 입력값이 동일하게 유지되지는 않습니다.

- 순수성을 판단할 때는 공유된 가변 입력의 내용이 계산 중 안정적으로 유지되는지도 확인

- 가능하면 불변 데이터 또는 해당 호출만 소유하는 데이터를 사용합니다. 공유된 가변 데이터를 복사할 때도 일관된 스냅샷을 얻는 과정이 안전해야

- final int[]는 참조의 재할당만 막습니다. 배열 요소는 여전히 변경할 수 있습니다.

- 지역변수라고 해도 그 변수가 참조하는 객체가 공유되어 있다면 별도 검토가 필요합니다.

위 sum()의 result처럼 호출 안에서만 사용되는 지역변수를 변경하는 것 자체는 외부에서 관찰 가능한 부수효과가 아닙니다. ‘변수를 전혀 변경하지 않는다’가 순수함수의 정의는 아닙니다.

---

## 6. 예상 꼬리 질문

- **순수함수이면 synchronized가 필요한가요?** 
→ 순수한 계산 자체는 공유 가변 상태를 보호할 필요가 없으므로 필요하지 않지만, 
    계산 결과를 공유 컬렉션에 저장하는 주변 코드는 별도로 검토해야 합니다.

- **static 메서드이면 Thread Safe한가요?** 
→ static은 객체 생성 없이 호출할 수 있다는 의미이며, 공유 가변 상태에 접근하는지와 동기화 방식에 따라 안전성이 달라집니다.

- **Thread Safe하면 같은 입력에 같은 결과인가요?** 

→ X. 원자적 카운터처럼 안전하게 상태를 변경하면서 호출마다 다른 결과를 반환할 수 있습니다.

- **불변성과 순수성은 같은가요?** 
→ X. 불변성은 값이나 객체의 상태가 바뀌지 않는 성질이고, 순수성은 함수의 결과와 부수효과에 대한 성질임

불변 데이터는 순수함수를 작성하는 데 도움이 된다
