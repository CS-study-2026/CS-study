# 1-0. 가상화가 무엇이고, 이것이 가상머신과 어떠한 차이가 있는지 설명해 주세요.

# 1-0. 가상화란 무엇이고, 가상머신과 어떤 차이가 있을까?

## 1. 가상화(Virtualization)란?

> **가상화(Virtualization)**란 CPU, 메모리, 디스크, 네트워크 같은 **물리적인 컴퓨터 자원을 논리적으로 나누거나 추상화하여 여러 개의 독립적인 환경처럼 사용할 수 있게 만드는 기술**이다.

예를 들어 물리적인 서버가 한 대 있다고 하자.

```plain text
가상화 적용 전

┌─────────────────────────────┐
│         Application         │
├─────────────────────────────┤
│       Operating System      │
├─────────────────────────────┤
│ CPU │ Memory │ Disk │ Network│
└─────────────────────────────┘
          물리 서버 1대
```

일반적으로 하나의 컴퓨터에서는 하나의 OS가 하드웨어 자원을 관리한다.

하지만 가상화 기술을 사용하면 하나의 물리 서버를 여러 개의 독립적인 컴퓨터처럼 사용할 수 있다.

```plain text
가상화 적용 후

┌──────────┐ ┌──────────┐ ┌──────────┐
│  VM #1   │ │  VM #2   │ │  VM #3   │
│  Linux   │ │ Windows  │ │  Linux   │
│ App A    │ │ App B    │ │ App C    │
└──────────┘ └──────────┘ └──────────┘
      │           │           │
      └───────────┼───────────┘
                  ▼
        ┌──────────────────┐
        │    Hypervisor    │
        ├──────────────────┤
        │ Physical Hardware│
        │ CPU / RAM / Disk │
        └──────────────────┘
```

실제로 CPU와 메모리가 3세트 존재하는 것은 아니다.

**하나의 실제 하드웨어 자원을 가상화 기술을 통해 여러 환경이 나누어 사용하는 것**이다.

---

## 2. 하이퍼바이저(Hypervisor)

가상머신을 이해하려면 **하이퍼바이저**라는 개념도 알아야 한다.

하이퍼바이저는 **물리적인 하드웨어 자원을 여러 가상머신에 할당하고, 각각의 가상머신을 관리하는 소프트웨어 계층**이다.

예를 들어 실제 서버에 다음과 같은 자원이 있다고 하자.

```plain text
CPU    : 8 Core
Memory : 32 GB
Disk   : 1 TB
```

하이퍼바이저가 이를 다음처럼 VM에 할당할 수 있다.

```plain text
Physical Server
CPU 8 Core / RAM 32GB

        │
        ▼

     Hypervisor
        │
   ┌────┼────┐
   ▼    ▼    ▼

 VM 1   VM 2   VM 3
2 Core  4 Core  2 Core
8 GB    16 GB   8 GB
Linux   Linux   Windows
```

대표적인 가상화 기술/제품으로는 **VMware ESXi, Microsoft Hyper-V, KVM** 등이 있다.

---

## 3. 그렇다면 가상머신(VM)이란?

- **가상머신(Virtual Machine)**은 가상화 기술을 이용해 만들어진 **가상의 컴퓨터 환경**이다.

즉,

> **가상화 = 기술 또는 개념**

**가상머신 = 그 기술을 이용하여 만들어진 가상의 컴퓨터**

라고 구분하면 된다.

비유하면 다음과 비슷하다.

```plain text
가상화(Virtualization)
        │
        │ 기술
        ▼
┌───────────────────┐
│ Virtual Machine 1 │
├───────────────────┤
│ Virtual Machine 2 │
├───────────────────┤
│ Virtual Machine 3 │
└───────────────────┘
```

가상머신은 실제 컴퓨터처럼 **가상 CPU(vCPU), 가상 메모리, 가상 디스크, 가상 네트워크 인터페이스** 등을 가지며 그 위에 독립적인 운영체제를 설치할 수 있다.

예를 들어 macOS를 사용하는 Mac에서 가상머신을 생성하고 그 안에 Linux를 설치할 수도 있다.

```plain text
Mac

┌───────────────────────────────┐
│            Linux VM           │
│                               │
│  Linux OS                     │
│  ├─ Application A             │
│  └─ Application B             │
├───────────────────────────────┤
│      Virtual Hardware         │
├───────────────────────────────┤
│        Hypervisor             │
├───────────────────────────────┤
│         Mac Hardware          │
└───────────────────────────────┘
```

Linux 입장에서는 자신이 실제 컴퓨터 위에서 실행되는 것처럼 동작하지만, 실제로는 하이퍼바이저가 제공한 **가상의 하드웨어 환경** 위에서 실행되고 있다.

---

## 4. 가상화와 가상머신의 차이

| 구분 | 가상화(Virtualization) | 가상머신(Virtual Machine) |
| --- | --- | --- |
| 의미 | 물리 자원을 추상화하는 **기술/개념** | 가상화 기술로 만들어진 **실행 환경** |
| 역할 | CPU, 메모리 등의 자원을 논리적으로 분리 | 독립된 컴퓨터처럼 동작 |
| OS | 특정 OS 자체를 의미하지 않음 | 일반적으로 각 VM에 독립적인 Guest OS 설치 |
| 관계 | VM을 만들 수 있게 하는 기반 기술 | 가상화의 대표적인 결과물 |

따라서 **가상화와 가상머신은 서로 대립되는 개념이 아니다.**

```plain text
가상화 기술
   │
   ├── 가상머신(VM)
   │
   ├── 가상 네트워크
   │
   ├── 가상 스토리지
   │
   └── 기타 가상화 기술
```

가상화는 VM보다 더 넓은 개념이다.

## 가상 네트워크와 가상 스토리지

가상화는 가상머신(VM)뿐만 아니라 **네트워크와 저장장치에도 적용**할 수 있다.

### 1. 가상 네트워크(Virtual Network)

**물리적인 네트워크 장비를 소프트웨어적으로 추상화하여 만든 네트워크**다.

실제 환경에서는 스위치, 라우터, 랜카드 같은 장비가 필요하지만, 가상화 환경에서는 이들의 일부 기능을 소프트웨어로 구현할 수 있다.

```plain text
실제 네트워크

PC ── 랜카드 ── 스위치 ── 라우터 ── Internet


가상 네트워크

VM 1 ─┐
VM 2 ─┼── Virtual Switch ── Physical NIC ── Internet
VM 3 ─┘
```

예를 들어 하나의 물리 서버 안에 VM 3개가 있다면 **가상 스위치(Virtual Switch)**를 만들어 VM끼리 통신하게 할 수 있다.

즉, **실제 네트워크 장비의 기능을 소프트웨어적으로 구현하는 것**이라고 이해하면 된다.

---

### 2. 가상 스토리지(Virtual Storage)

**물리적인 HDD, SSD 등의 저장 공간을 추상화하여 논리적인 저장 공간으로 제공하는 기술**이다.

예를 들어 실제 서버에 여러 개의 디스크가 있더라도 이를 하나의 큰 저장공간처럼 묶어서 제공하거나, 반대로 하나의 물리 디스크를 여러 개의 논리적인 저장공간으로 나누어 제공할 수 있다.

```plain text
Physical Storage

SSD 1 ─┐
SSD 2 ─┼── Storage Virtualization
SSD 3 ─┘
              │
       ┌──────┼──────┐
       ▼      ▼      ▼
     100GB  200GB   500GB
      VM 1   VM 2    VM 3
```

VM 입장에서는 자신에게 **100GB짜리 디스크가 실제로 존재하는 것처럼 보이지만**, 실제 저장 공간이 물리적으로 정확히 그렇게 분리되어 있을 필요는 없다.

---

### 한 번에 정리하면

| 종류 | 무엇을 가상화하는가? | 결과 |
| --- | --- | --- |
| **가상머신(VM)** | CPU, 메모리 등 컴퓨터 자원 | 가상의 컴퓨터 |
| **가상 네트워크** | 스위치, 라우터, NIC 등의 네트워크 기능 | 가상의 네트워크 |
| **가상 스토리지** | HDD, SSD 등의 저장 공간 | 가상의 저장장치 |

결국 **가상화의 핵심은 물리적인 자원을 그대로 노출하지 않고 소프트웨어를 통해 논리적인 자원으로 만들어 제공하는 것**이라고 이해하면 된다.

## 5. 왜 가상화를 사용할까?

가장 큰 이유는 **물리적인 자원을 효율적으로 사용하면서 서로 독립된 실행 환경을 만들 수 있기 때문**이다.

예를 들어 서버 세 대가 필요하다고 해서 반드시 물리 서버 세 대를 구입할 필요는 없다.

```plain text
물리 서버를 각각 사용하는 경우

Server A → Linux → Web Server
Server B → Linux → DB Server
Server C → Windows → Application Server
```

충분히 성능이 좋은 서버 한 대가 있다면 가상화를 이용해 다음처럼 구성할 수도 있다.

```plain text
Physical Server
        │
   Hypervisor
        │
 ┌──────┼──────┐
 ▼      ▼      ▼
VM 1   VM 2   VM 3
Linux  Linux  Windows
 Web    DB      App
```

이렇게 하면 **하드웨어 활용률을 높일 수 있고**, VM별로 OS와 프로그램이 분리되어 있기 때문에 **격리성(Isolation)**도 확보할 수 있다.

다만 여러 VM이 같은 물리 서버의 자원을 공유하기 때문에 자원 경합이 발생할 수 있고, 물리 서버 자체에 장애가 발생하면 그 서버 위의 여러 VM이 함께 영향을 받을 수 있다는 점도 고려해야 한다.

## 핵심 정리

> **가상화(Virtualization)**는 하나의 물리적인 컴퓨터 자원을 추상화하여 여러 독립적인 환경에서 사용할 수 있도록 만드는 **기술**이다.

**가상머신(Virtual Machine)**은 이러한 가상화 기술을 이용해 생성된 **가상의 컴퓨터**이다.

따라서 `가상화 = VM`이 아니라, **가상화라는 더 큰 개념 안에 가상머신이 존재한다**고 이해하는 것이 정확하다.

**참고 자료:** IBM의 Virtualization 개요 및 Red Hat의 Virtualization 설명에서 가상화를 물리 컴퓨터의 자원을 여러 가상 환경에 분배할 수 있도록 하는 기술로 설명하고 있으며, VM은 이러한 가상화된 환경의 대표적인 형태로 설명한다.
