# 7-1. Side Effect가 무엇인가요? 이를 모두 없애는 프로그래밍이 이상적이라고 할 수 있을까요?

> **Side Effect(부수 효과)는 함수나 연산이 값을 반환하는 것 외에, 외부 상태를 바꾸거나 외부와 상호작용하는 것**을 말한다. 

여기서 ‘부수’는 의도하지 않았다는 뜻은 아니다. 파일 저장처럼 꼭 필요한 작업도 포함된다.

예를 들어 다음 함수는 계산한 값을 반환할 뿐, 외부 상태를 바꾸지 않는다.

```java
int add(int a, int b) {
    return a + b;
}
```

반면 다음 함수는 외부 변수 `count`를 변경하므로 부수 효과가 있다.

```java
int count = 0;

int add(int a, int b) {
    count++;       // 외부 상태 변경 → 부수 효과
    return a + b;
}
```

대표적으로 **전역 변수·객체의 필드 변경, 전달받은 객체 수정, 파일 저장, DB 갱신, 화면 출력, 네트워크 요청** 등이 부수 효과에 해당한다.

**그렇다고 부수 효과를 모두 없애는 것이 이상적인 것은 아니다.** 실제 프로그램은 결과를 화면에 보여주고 데이터를 저장해야 하므로 부수 효과가 필요하다. 은행 앱에서 송금 금액을 계산하는 것만으로는 부족하고, 실제 잔액을 갱신해야 하는 것과 같다.

따라서 좋은 방향은 **계산 로직에서는 부수 효과를 줄이고, 필요한 부수 효과는 명확히 분리해 관리하는 것이**다.

| 구분 | 송금 기능의 예 |
| --- | --- |
| 계산 로직 | 수수료와 송금 후 잔액 계산 |
| 부수 효과를 수행하는 로직 | DB에 잔액 반영, 거래 내역 저장, 알림 전송 |

이렇게 분리하면 계산 로직을 쉽게 테스트할 수 있고, 데이터가 언제 어디서 변경되는지도 파악하기 쉬워진다.

**1. 부수 효과가 없다고 무조건 순수 함수는 아니다**

순수 함수는 다음 두 조건을 모두 만족해야 한다.

- **같은 입력에는 항상 같은 결과**를 반환한다.

- **외부에서 관찰할 수 있는 부수 효과**가 없다.

```java
static int rate = 10;

static int calculate(int price) {
    return price * rate;
}
```

이 함수는 외부 값을 변경하지는 않지만, `rate`가 바뀌면 같은 `price`에도 결과가 달라진다. 따라서 순수 함수가 아니다. 다음처럼 필요한 값을 매개변수로 받으면 외부 상태에 대한 의존성을 없앨 수 있다.

```java
static int calculate(int price, int rate) {
    return price * rate;
}
```

**2. 매개변수로 받은 객체를 수정하는 것도 부수 효과이다**

전역 변수만 생각하기 쉽지만, **호출한 쪽이 가진 객체를 변경하는 것**도 포함된다.

```java
static int sum(List<Integer> numbers) {
    numbers.add(100);  // 호출한 쪽의 리스트까지 변경됨
    return numbers.stream().mapToInt(Integer::intValue).sum();
}
```

`sum()`이라는 이름만 보고 호출했는데 원본 리스트까지 바뀌면, 다른 코드에서 예상하지 못한 문제가 생길 수 있다.

**3. 왜 문제가 되는지 구체적으로 알아야 한다**

| 문제 | 예시 |
| --- | --- |
| 실행 순서에 의존 | A 함수가 공유 값을 바꾸면 B 함수의 결과도 달라짐 |
| 테스트가 복잡해짐 | 테스트마다 전역 변수나 DB 상태를 준비·복구해야 함 |
| 동시성 오류 가능 | 여러 스레드가 같은 값을 수정하다 갱신을 누락함 |
| 재실행 시 중복 처리 | 결제 요청을 다시 실행해 중복 결제가 발생할 수 있음 |

특히 **공유되는 변경 가능한 상태**가 많으면 병렬 처리가 어려워진다.

**4. 불변성과 부수 효과의 관계도 구분하면 좋다**

불변성은 **만든 데이터를 변경하지 않는 성질이**다. 원본을 수정하는 대신 새로운 결과를 만들면, 상태 변경으로 인한 부수 효과를 줄일 수 있다.

다만 **불변 데이터를 사용한다고 모든 부수 효과가 사라지는 것은 아니다.** 불변 문자열을 화면에 출력해도 출력이라는 부수 효과는 발생한다.

그리고 Java의 `final`은 객체 자체를 불변으로 만들지 않는다.

```java
final List<Integer> numbers = new ArrayList<>();
numbers.add(1);  // 가능: 리스트 내부는 변경할 수 있음
// numbers = new ArrayList<>(); // 불가능: 다른 객체로 재대입
```
