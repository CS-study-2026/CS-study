# 4-2. 다형성이 무엇인지 설명하고, 동적 다형성과 정적 다형성이 무엇인지 설명해 주세요.

> 

다형성이란 하나의 인터페이스나 부모 타입을 통해 여러 형태의 객체를 다룰 수 있는 성질입니다. Java에서는 주로 상속과 인터페이스를 통해 구현합니다.

정적 다형성은 컴파일 시점에 어떤 메서드를 호출할지 결정하는 방식으로 대표적으로 오버로딩이 있고, 동적 다형성은 실행 시점에 실제 객체의 타입을 기준으로 어떤 메서드를 호출할지 결정하는 방식으로 오버라이딩이 있습니다.

즉, 정적 다형성은 컴파일 시점에, 동적 다형성은 실행 시점에 호출할 메서드가 결정된다는 차이가 있습니다.

---

## 1️⃣ 다형성이란?

**다형성(Polymorphism)**은 말 그대로

> **하나의 형태가 여러 형태로 동작할 수 있는 성질**

을 의미한다.

객체지향 프로그래밍에서는 보통 **부모 타입이나 인터페이스 하나로 여러 자식 객체를 다룰 수 있는 것**을 의미한다.

예를 들어 동물이라는 부모 클래스가 있다고 하자.

```java
class Animal {
    void sound() {
        System.out.println("동물이 소리를 냅니다.");
    }
}

class Dog extends Animal {
    @Override
    void sound() {
        System.out.println("멍멍");
    }
}

class Cat extends Animal {
    @Override
    void sound() {
        System.out.println("야옹");
    }
}
```

그러면 다음과 같이 사용할 수 있다.

```java
Animal animal1 = new Dog();
Animal animal2 = new Cat();

animal1.sound();
animal2.sound();
```

실행 결과:

```plain text
멍멍
야옹
```

변수의 타입은 둘 다 `Animal`이지만 실제 객체는 각각 `Dog`, `Cat`이다.

```plain text
Animal
   ↑
 ┌─┴──────┐
Dog      Cat
```

따라서 **부모 타입 하나로 서로 다른 객체의 동작을 호출할 수 있다.**

---

# 2️⃣ 정적 다형성

**정적 다형성(Static Polymorphism)**은

> **컴파일 시점에 어떤 메서드를 호출할지 결정되는 다형성**

이다.

대표적인 예가 **오버로딩(Overloading)**이다.

```java
class Calculator {

    int add(int a, int b) {
        return a + b;
    }

    double add(double a, double b) {
        return a + b;
    }
}
```

호출할 때 전달되는 인자의 타입을 보고 컴파일러가 어떤 메서드를 호출할지 결정한다.

```java
Calculator calculator = new Calculator();

calculator.add(1, 2);       // int 버전
calculator.add(1.5, 2.5);   // double 버전
```

즉,

```plain text
add(1, 2)
     ↓
컴파일러가 인자 타입 확인
     ↓
add(int, int) 선택
```

따라서 **오버로딩 = 대표적인 정적 다형성**이라고 볼 수 있다.

---

# 3️⃣ 동적 다형성

**동적 다형성(Dynamic Polymorphism)**은

> **실행 시점에 실제 객체의 타입을 기준으로 어떤 메서드를 호출할지 결정되는 다형성**

이다.

대표적인 예가 **오버라이딩(Overriding)**이다.

```java
class Animal {
    void sound() {
        System.out.println("동물 소리");
    }
}

class Dog extends Animal {

    @Override
    void sound() {
        System.out.println("멍멍");
    }
}

class Cat extends Animal {

    @Override
    void sound() {
        System.out.println("야옹");
    }
}
```

다음과 같이 부모 타입으로 참조할 수 있다.

```java
Animal animal = new Dog();

animal.sound();
```

변수의 선언 타입은 `Animal`이지만 실제 객체는 `Dog`다.

```plain text
Animal animal
      │
      ▼
   new Dog()
```

따라서 실행 시점에는 `Dog.sound()`가 호출된다.

```plain text
animal.sound()
      ↓
실제 객체 확인
      ↓
Dog 객체
      ↓
Dog.sound()
```

이것이 **동적 다형성**이다.

---

# 4️⃣ 왜 실행 시점에 결정될까?

다음 코드를 생각해 보자.

```java
Animal animal;

if (condition) {
    animal = new Dog();
} else {
    animal = new Cat();
}

animal.sound();
```

컴파일하는 시점에는 `animal`이 실제로 어떤 객체를 가리킬지 확정되지 않을 수 있다.

실행 결과에 따라

```plain text
condition == true
      ↓
new Dog()
      ↓
Dog.sound()
```

또는

```plain text
condition == false
      ↓
new Cat()
      ↓
Cat.sound()
```

가 될 수 있다.

따라서 실제 객체의 타입을 기준으로 메서드가 선택되는 것을 **동적 바인딩(Dynamic Binding)**이라고 한다.

---

# 5️⃣ 정적 다형성과 동적 다형성 비교

| 구분 | 정적 다형성 | 동적 다형성 |
| --- | --- | --- |
| 결정 시점 | 컴파일 시점 | 실행 시점 |
| 대표적인 방법 | 오버로딩 | 오버라이딩 |
| 판단 기준 | 메서드 이름 + 매개변수 | 실제 객체의 타입 |
| 상속 필요 | 반드시 필요하지 않음 | 일반적으로 상속/인터페이스 사용 |
| 대표 개념 | Method Overloading | Method Overriding |
| Java 예시 | `add(int, int)` / `add(double, double)` | `Animal animal = new Dog()` |

---

# 6️⃣ 다형성의 장점

다형성을 사용하면 **구체적인 객체의 종류를 코드에서 일일이 구분하지 않아도 된다.**

예를 들어 다음과 같은 코드가 있다고 하자.

```java
void makeSound(Animal animal) {
    animal.sound();
}
```

이 메서드는 `Dog`인지 `Cat`인지 알 필요가 없다.

```java
makeSound(new Dog());
makeSound(new Cat());
```

각 객체의 `sound()`가 알아서 실행된다.

```plain text
makeSound(Dog)
      ↓
Animal 타입으로 받음
      ↓
Dog.sound()

makeSound(Cat)
      ↓
Animal 타입으로 받음
      ↓
Cat.sound()
```

따라서 새로운 동물 클래스를 추가하더라도 기존 `makeSound()`를 수정할 필요가 없다.

```java
class Bird extends Animal {

    @Override
    void sound() {
        System.out.println("짹짹");
    }
}
```

```java
makeSound(new Bird());
```

이처럼 **구현체보다 추상화된 타입에 의존하는 구조**를 만들 수 있다는 것이 다형성의 중요한 장점이다.

## 📌 핵심 정리

```plain text
다형성
│
├── 정적 다형성
│     └── 컴파일 시점에 결정
│           └── 오버로딩
│
└── 동적 다형성
      └── 실행 시점에 결정
            └── 오버라이딩
```

- **다형성** → 하나의 부모 타입/인터페이스로 여러 구현체를 다룰 수 있는 성질

- **정적 다형성** → 컴파일 시점에 메서드 결정

- **동적 다형성** → 실행 시점에 실제 객체를 기준으로 메서드 결정

- **오버로딩** → 정적 다형성의 대표적인 예

- **오버라이딩** → 동적 다형성의 대표적인 예

- 동적 다형성에서는 **동적 바인딩**을 통해 실제 객체의 메서드가 호출된다.
