# **5-0. 프레임워크와 라이브러리의 차이에 대해 설명해 주세요.**

## 5. 프레임워크와 라이브러리의 차이에 대해 설명해 주세요.

### 개념 정의

- **라이브러리 (Library)**

개발자가 애플리케이션을 개발할 때 필요한 특정한 기능(예: 날짜 계산, JSON 파싱, 암호화 등)을 수행하기 위해 미리 만들어 둔 **도구 및 함수들의 집합**입니다.

- **프레임워크 (Framework)**

애플리케이션의 전체적인 데이터 흐름과 생명주기(Lifecycle)를 관리하는 뼈대이자 실행 환경(아키텍처)입니다.

### 핵심 차이점: 제어의 역전 (Inversion of Control, IoC)

두 개념을 나누는 가장 결정적인 기술적 기준은 "전체 프로그램의 흐름을 누가 주도하고 제어하는가"라는 제어의 역전 유무

- **라이브러리를 사용할 때 (개발자가 주도)**

  - 개발자가 직접 작성한 애플리케이션 코드가 주체

  - 필요할 때마다 특정 라이브러리의 함수를 **직접 호출** (능동적으로 도구를 가져다 씀)

- **프레임워크를 사용할 때 (프레임워크가 주도)**

  - 프레임워크가 애플리케이션의 전체 실행 흐름을 가짐

  - 개발자는 프레임워크가 정해둔 규칙과 규격(인터페이스, 어노테이션 등)에 맞춰 코드 조각만 채움

  - 프레임워크가 적절한 시점에 개발자의 코드를 대신 호출(Callback)

### 프레임워크 vs 라이브러리 비교

| **구분** | **라이브러리 (Library)** | **프레임워크 (Framework)** |
| --- | --- | --- |
| **제어 주도권** | 개발자의 코드 (Application) | 프레임워크 (Framework) |
| **제어의 역전 (IoC)** | 적용되지 않음 | 적용됨 (핵심 동작 원리) |
| **애플리케이션 흐름** | 개발자가 흐름을 직접 제어함 | 프레임워크가 전체 생명주기를 관리함 |
| **자유도 및 제약** | 원하는 부분만 선택적으로 쉽게 교체 가능 | 프레임워크가 정한 아키텍처 규칙을 엄격히 따라야 함 |
| **대표적인 예시** | Python NumPy, Jackson, Lodash, Axios | Spring Boot, Django, Ruby on Rails, NestJS |

### 💡 면접/발표용 요약 정리

> "프레임워크와 라이브러리의 가장 큰 차이는 **제어의 역전(IoC)**에 있습니다.

라이브러리는 개발자가 필요할 때 직접 호출해서 사용하는 **도구**인 반면,

프레임워크는 애플리케이션의 전체적인 틀과 생명주기를 주도하며 개발자가 작성한 코드를 능동적으로 불러와 실행시키는 **뼈대**입니다."
