# 7-0. 순수함수가 무엇인지를 함수형 프로그래밍 매커니즘과 연관지어 설명해 주세요.

## 1. 함수형 프로그래밍(Functional Programming)이란?

함수형 프로그래밍은 **함수를 중심으로 프로그램을 구성하고, 가변 상태와 부수 효과를 최소화하는 프로그래밍 패러다임**이다.

명령형 프로그래밍이 데이터를 어떻게 변경할 것인지에 집중한다면, 함수형 프로그래밍은 입력 데이터를 어떤 결과로 변환할 것인지에 집중한다.

| 구분 | 명령형 프로그래밍 | 함수형 프로그래밍 |
| --- | --- | --- |
| 핵심 관점 | 어떻게 처리할 것인가? | 무엇을 계산할 것인가? |
| 상태 관리 | 가변 상태를 적극 활용 | 불변 데이터 선호 |
| 처리 방식 | 반복문, 변수 변경 등 | 함수 조합, 데이터 변환 |
| 부수 효과 | 일반적으로 허용 | 최소화하고 분리 |
| 대표적인 Java 코드 | `for`, 변수 누적 | `stream`, `map`, `filter` |

함수형 프로그래밍에서 중요한 개념 중 하나가 **순수함수(Pure Function)** 이다.

## 2. 순수함수(Pure Function)란?

순수함수란 다음 두 가지 조건을 모두 만족하는 함수다.

1. **동일한 입력에 대해 항상 동일한 결과를 반환한다.**

1. **부수 효과(Side Effect)가 없다.**

### 2-1. 동일한 입력 → 동일한 출력

```plain text
public int add(int a, int b) {
    return a + b;
}
```

`add(3, 5)`는 언제 호출하더라도 항상 `8`을 반환한다.

반면 다음 함수는 순수함수가 아니다.

```plain text
int bonus = 10;

public int addBonus(int value) {
    return value + bonus;
}
```

`bonus`라는 외부의 가변 상태에 따라 결과가 달라질 수 있기 때문이다.

### 2-2. 부수 효과(Side Effect)가 없어야 한다

부수 효과란 함수가 결과를 반환하는 것 외에 외부에서 관찰할 수 있는 상태 변경이나 동작을 일으키는 것을 의미한다.

대표적으로 다음과 같은 작업이 있다.

- 외부 변수 또는 객체의 상태 변경

- 파일이나 데이터베이스에 데이터 저장

- 콘솔 출력 및 네트워크 요청

```plain text
int total = 0;

public int add(int value) {
    total += value;
    return total;
}
```

위 함수는 외부 변수 `total`을 변경하므로 순수함수가 아니다.

반면 다음과 같이 작성하면 순수함수가 된다.

```plain text
public int add(int total, int value) {
    return total + value;
}
```

외부 상태를 변경하지 않고, 입력값만으로 결과를 계산하기 때문이다.

## 3. 순수함수와 함수형 프로그래밍의 관계

함수형 프로그래밍은 순수함수를 활용해 **데이터를 변경하는 대신 새로운 결과를 계산하고, 여러 함수를 조합하여 프로그램을 구성하는 방식**을 지향한다.

### 3-1. Java Stream API 예시

```plain text
List<Integer> numbers = List.of(1, 2, 3, 4, 5);

List<Integer> result = numbers.stream()
        .filter(n -> n % 2 == 0)
        .map(n -> n * 2)
        .toList();
```

**동작 과정**

1. 원본 데이터: `[1, 2, 3, 4, 5]`

1. `filter()`: 짝수만 선택 → `[2, 4]`

1. `map()`: 각 요소를 2배 → `[4, 8]`

1. 최종 결과: `[4, 8]`

여기서 `filter`와 `map`에 전달한 람다식은 순수함수의 조건을 만족한다.

또한 원본 리스트는 변경되지 않는다.

### 3-2. 순수함수가 함수형 프로그래밍에 유리한 이유

| 특징 | 설명 |
| --- | --- |
| 참조 투명성 | 함수 호출을 결과값으로 대체해도 프로그램의 의미가 변하지 않음 |
| 테스트 용이성 | 외부 상태에 의존하지 않아 입력과 출력만으로 검증 가능 |
| 병렬 처리 용이성 | 공유 상태 변경이 없어 데이터 경합 위험을 줄일 수 있음 |
| 예측 가능성 | 동일한 입력에서 동일한 결과가 나오므로 동작을 이해하기 쉬움 |
| 함수 합성 | 여러 순수함수를 조합해 복잡한 로직을 구성하기 쉬움 |

**참조 투명성(Referential Transparency)**

참조 투명성이란 표현식을 그 결과값으로 대체해도 프로그램의 동작이 달라지지 않는 성질이다.

예를 들어 `add(3, 5)`가 순수함수라면 해당 호출을 `8`로 대체해도 프로그램의 의미가 달라지지 않는다.

이러한 특성 덕분에 함수의 동작을 예측하고 테스트하기 쉬워진다.

### 3-3. 함수형 프로그래밍의 모든 함수가 순수함수일까?

**아니다. 함수형 프로그래밍에서 사용하는 모든 함수가 순수함수인 것은 아니다.**

실제 프로그램에서는 다음과 같은 부수 효과가 반드시 필요한 경우가 있다.

- 데이터베이스에 데이터 저장

- 서버에 HTTP 요청 전송

- 파일 읽기 및 쓰기

- 로그 출력

따라서 함수형 프로그래밍은 부수 효과를 무조건 금지하는 것이 아니라, **순수한 계산 로직과 부수 효과가 발생하는 로직을 분리하여 관리하는 것**을 지향한다.

## 4. 면접 답변 정리

순수함수란 동일한 입력에 대해 항상 동일한 결과를 반환하고, 외부 상태를 변경하는 등의 부수 효과가 없는 함수입니다.

함수형 프로그래밍은 이러한 순수함수를 중심으로 데이터 변환과 함수 조합을 수행하고, 가변 상태와 부수 효과를 최소화하는 프로그래밍 패러다임입니다.

순수함수는 외부 상태에 의존하지 않으므로 예측과 테스트가 쉽고, 공유 상태로 인한 문제를 줄여 병렬 처리에도 유리합니다.

Java에서는 Stream API의 `map`, `filter` 등에 순수한 람다식을 전달하여 함수형 프로그래밍의 특징을 활용할 수 있습니다.

**핵심 정리**

- **순수함수:** 동일한 입력 → 동일한 출력 + 부수 효과 없음

- **함수형 프로그래밍:** 순수함수와 함수 조합을 활용하고 가변 상태 및 부수 효과를 최소화하는 프로그래밍 패러다임

- **참조 투명성:** 함수 호출을 결과값으로 대체해도 프로그램의 의미가 변하지 않는 성질

- **Java에서의 활용:** Stream API, 람다식, 함수형 인터페이스

- **주의:** 함수형 프로그래밍은 부수 효과를 완전히 금지하는 것이 아니라 분리하고 관리하는 것을 지향한다.
