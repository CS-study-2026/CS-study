# 4-3. 오버로딩과 오버라이딩의 차이에 대해 설명해 주세요.

> 

오버로딩은 같은 클래스에서 같은 이름의 메서드를 여러 개 정의하되 매개변수의 개수나 타입을 다르게 하는 것입니다. 어떤 메서드를 호출할지는 컴파일 시점에 결정되므로 정적 다형성에 해당합니다.

반면 오버라이딩은 부모 클래스의 메서드를 자식 클래스에서 같은 시그니처로 재정의하는 것으로, 실행 시점에 실제 객체의 타입에 따라 호출되는 메서드가 결정되기 때문에 동적 다형성에 해당합니다.

즉, 오버로딩은 같은 이름의 메서드를 여러 형태로 제공하는 것이고, 오버라이딩은 상속받은 메서드의 동작을 자식 클래스에 맞게 재정의하는 것입니다.

---

## 1️⃣ 오버로딩(Overloading)이란?

**같은 이름의 메서드를 여러 개 정의하는 것**이다.

단, 매개변수의 **개수 또는 타입이 달라야 한다.**

```java
class Calculator {

    int add(int a, int b) {
        return a + b;
    }

    int add(int a, int b, int c) {
        return a + b + c;
    }

    double add(double a, double b) {
        return a + b;
    }
}
```

사용할 때 전달하는 인자를 기준으로 적절한 메서드가 선택된다.

```java
Calculator calculator = new Calculator();

calculator.add(1, 2);
calculator.add(1, 2, 3);
calculator.add(1.5, 2.5);
```

---

## 2️⃣ 오버로딩의 조건

오버로딩은 **메서드 이름은 같지만 매개변수 목록이 달라야 한다.**

### ✅ 가능

```java
void print(int value) {
}

void print(String value) {
}
```

```java
void print(int value) {
}

void print(int value, int value2) {
}
```

### ❌ 불가능

반환 타입만 다른 경우에는 오버로딩이 아니다.

```java
int add(int a, int b) {
    return a + b;
}

// 컴파일 오류
double add(int a, int b) {
    return a + b;
}
```

왜냐하면 메서드를 호출할 때

```java
add(1, 2);
```

어떤 메서드를 호출해야 하는지 반환 타입만으로 구분할 수 없기 때문이다.

따라서 **반환 타입은 오버로딩의 기준이 아니다.**

---

# 3️⃣ 오버라이딩(Overriding)이란?

**부모 클래스에서 정의한 메서드를 자식 클래스가 자신의 목적에 맞게 재정의하는 것**이다.

```java
class Animal {

    void sound() {
        System.out.println("동물 소리");
    }
}

class Dog extends Animal {

    @Override
    void sound() {
        System.out.println("멍멍");
    }
}
```

이제 다음 코드를 실행하면

```java
Animal animal = new Dog();

animal.sound();
```

결과는

```plain text
멍멍
```

이다.

변수의 타입은 `Animal`이지만 실제 객체는 `Dog`이기 때문이다.

---

# 4️⃣ 오버라이딩의 조건

오버라이딩에서는 부모 메서드와 **같은 메서드 시그니처**를 사용해야 한다.

```java
class Parent {

    void hello(String name) {
        System.out.println("Hello " + name);
    }
}

class Child extends Parent {

    @Override
    void hello(String name) {
        System.out.println("Hi " + name);
    }
}
```

여기서

```plain text
메서드 이름: hello
매개변수: String name
```

이 동일하다.

반면 매개변수가 다르면 오버라이딩이 아니라 **오버로딩**이 된다.

---

# 5️⃣ 오버로딩 vs 오버라이딩

| 구분 | 오버로딩 | 오버라이딩 |
| --- | --- | --- |
| 의미 | 같은 이름의 메서드를 여러 개 정의 | 부모 메서드를 자식이 재정의 |
| 관계 | 같은 클래스에서 주로 발생 | 부모-자식 관계 필요 |
| 메서드 이름 | 같음 | 같음 |
| 매개변수 | 달라야 함 | 같아야 함 |
| 반환 타입 | 반환 타입만 달라서는 불가능 | 호환되는 반환 타입 사용 |
| 결정 시점 | 컴파일 시점 | 실행 시점 |
| 다형성 | 정적 다형성 | 동적 다형성 |
| 목적 | 다양한 입력 형태 지원 | 자식 클래스에 맞는 동작 구현 |

---

# 6️⃣ 가장 쉽게 구분하는 방법

### 오버로딩

> **"같은 이름인데 매개변수가 다르다."**

```java
add(int, int)
add(int, int, int)
add(double, double)
```

```plain text
같은 메서드 이름
       +
다른 매개변수
       ↓
   오버로딩
```

---

### 오버라이딩

> **"부모의 메서드를 자식이 다시 구현한다."**

```java
class Animal {
    void sound() {}
}

class Dog extends Animal {
    @Override
    void sound() {}
}
```

```plain text
부모
Animal.sound()
      ↓
자식
Dog.sound()
      ↓
오버라이딩
```

---

# 7️⃣ 호출 시점의 차이

## 오버로딩

```java
Calculator calculator = new Calculator();

calculator.add(1, 2);
```

컴파일러가 매개변수를 확인한다.

```plain text
add(1, 2)
   ↓
(int, int)
   ↓
add(int, int) 선택
```

따라서 **컴파일 시점에 결정**된다.

---

## 오버라이딩

```java
Animal animal = new Dog();

animal.sound();
```

실행할 때 실제 객체를 확인한다.

```plain text
animal
  ↓
실제 객체 = Dog
  ↓
Dog.sound()
```

따라서 **실행 시점에 결정**된다.

---

# 8️⃣ `@Override`는 왜 사용하는가?

Java에서는 오버라이딩할 때 `@Override`를 붙이는 것을 권장한다.

```java
@Override
void sound() {
    System.out.println("멍멍");
}
```

`@Override`는 컴파일러에게

> "이 메서드는 부모 클래스의 메서드를 재정의하려는 것이다."

라고 알려준다.

만약 메서드 이름이나 매개변수를 잘못 작성하면 컴파일러가 오류를 알려준다.

```java
class Dog extends Animal {

    @Override
    void souund() {  // 오타
    }
}
```

이 경우 부모의 `sound()`를 정상적으로 오버라이딩한 것이 아니므로 컴파일 오류가 발생한다.

따라서 `@Override`는 **오버라이딩 의도를 명확히 하고 실수를 방지하는 역할**을 한다.

---

## 9️⃣ 헷갈리기 쉬운 포인트

### ❗ 오버로딩은 반환 타입만 다르게 할 수 없다.

```java
int method(int x) {
    return x;
}

// ❌ 불가능
double method(int x) {
    return x;
}
```

---

### ❗ 오버라이딩은 접근 제어자를 더 좁게 만들 수 없다.

```java
class Parent {

    public void hello() {
    }
}

class Child extends Parent {

    // ❌ public → protected로 축소 불가능
    protected void hello() {
    }
}
```

자식 클래스의 오버라이딩 메서드는 부모 메서드보다 **접근 범위를 좁힐 수 없다.**

---

### ❗ `private` 메서드는 오버라이딩할 수 없다.

```java
class Parent {

    private void hello() {
    }
}

class Child extends Parent {

    // 이것은 오버라이딩이 아님
    private void hello() {
    }
}
```

부모의 `private` 메서드는 자식 클래스에서 직접 접근할 수 없기 때문이다.

---

## 📌 핵심 정리

```plain text
오버로딩
→ 같은 이름
→ 다른 매개변수
→ 컴파일 시점 결정
→ 정적 다형성

오버라이딩
→ 부모 메서드 재정의
→ 같은 메서드 시그니처
→ 실행 시점 결정
→ 동적 다형성
```

### 🎯 암기 포인트

> **오버로딩 = 이름은 같게, 매개변수는 다르게**

**오버라이딩 = 부모의 메서드를 자식이 다시 정의**

| 질문 | 답 |
| --- | --- |
| 같은 이름 + 다른 매개변수? | **오버로딩** |
| 부모 메서드를 자식이 재정의? | **오버라이딩** |
| 컴파일 시점 결정? | **오버로딩** |
| 실행 시점 결정? | **오버라이딩** |
| 정적 다형성? | **오버로딩** |
| 동적 다형성? | **오버라이딩** |
