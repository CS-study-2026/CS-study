# 00. QueryDSL

# 🔍 QueryDSL 개념부터 실전 활용까지

## 1️⃣ QueryDSL이란 무엇인가

### 📌 정의

QueryDSL은 **타입 안전성을 보장하는 쿼리 생성 라이브러리**이다.

👉 문자열이 아닌 **자바 코드로 쿼리를 작성**할 수 있다.

---

### 📌 기존 방식 (JPQL)

```java
@Query("SELECT n FROM Note n WHERE n.title = :title")
List<Note> findByTitle(String title);
```

### 문제점

- 문자열 기반 → **컴파일 시점 검증 불가**

- 오타 발생 시 런타임 에러

- 복잡한 쿼리 작성 어려움

---

### 📌 QueryDSL 방식

```java
QNote note = QNote.note;

queryFactory
    .selectFrom(note)
    .where(note.title.eq(title))
    .fetch();
```

---

### 핵심 특징

- 타입 안전성 (Type-safe)

- IDE 자동완성 지원

- 컴파일 시점 오류 검출

---

# 5️⃣ 동적 쿼리 처리

## 📌 문제

검색 조건이 다양할 경우

- 키워드 있을 수도 있음

- 사용자 필터 있을 수도 있음

---

## ❌ 기존 방식

```java
if (keyword != null) {
    // 조건 추가
}
```

→ 코드 복잡

---

## ✅ QueryDSL 방식 (BooleanBuilder)

```java
BooleanBuilder builder = new BooleanBuilder();

if (keyword != null) {
    builder.and(note.title.contains(keyword));
}

if (userId != null) {
    builder.and(note.userId.eq(userId));
}

queryFactory
    .selectFrom(note)
    .where(builder)
    .fetch();
```

---

### 효과

- 조건 조합 유연

- 코드 가독성 향상

## 📌 적용 내용

```java
builder.and(note.visibility.eq(PUBLIC));

```

---

## 📌 결과

# 7️⃣ 장점과 단점

## ✅ 장점

- 타입 안전성

- 동적 쿼리 작성 용이

- 가독성 향상

- 유지보수성 증가

---

## ⚠️ 단점

- 초기 설정 복잡

- 학습 비용 존재

- 코드 길어질 수 있음

---

# 8️⃣ 언제 사용하는 것이 좋은가

✔️ 검색 조건이 많은 경우

✔️ 동적 쿼리가 필요한 경우

✔️ 유지보수가 중요한 프로젝트

✔️ JPA 기반 프로젝트

---

# 9️⃣ 한 줄 정리

👉 **“QueryDSL은 타입 안전성과 동적 쿼리를 해결하기 위한 쿼리 생성 라이브러리”**

---

# 📌 핵심 요약

- QueryDSL은 코드 기반 쿼리 작성 도구

- QClass를 통해 타입 안전성 제공

- BooleanBuilder로 동적 쿼리 해결

- 프로젝트에서 검색 기능 구현에 활용
