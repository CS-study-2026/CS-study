# Docker

## 1. 도커가 등장한 이유

- **문제점:** 개발자의 컴퓨터에서는 잘 돌아가던 프로그램이 서버나 다른 동료의 컴퓨터에서는 설정 차이(OS, 라이브러리 버전 등)로 인해 작동하지 않는 문제 발생.

- **해결책:** 프로그램 실행에 필요한 코드, 런타임, 시스템 도구, 설정 등을 하나로 묶어 **컨테이너**화하여 어디서든 동일하게 실행되도록 보장.

## 2. 주요 개념

- 이미지 (Image)

  - **정의:** 컨테이너를 실행하기 위한 모든 파일과 설정값이 담긴 설계도(템플릿).

  - **특징:** 불변성(Immutable). 한 번 만들어진 이미지는 변하지 않으며, 이를 통해 일관성을 유지함.

- 컨테이너 (Container)

  - **정의:** 이미지를 실행한 실제 인스턴스.

  - **비유:** 붕어빵 틀이 '이미지'라면, 그 틀에서 구워진 '붕어빵'이 컨테이너. 하나의 이미지로 여러 개의 격리된 컨테이너를 실행 가능.

## 3. 왜 Docker를 더 선호할까?

| **비교 항목** | **가상 머신 (VM)** | **도커 컨테이너 (Docker)** |
| --- | --- | --- |
| **구조** | 하이퍼바이저 위에 Guest OS 설치 | 호스트 OS의 커널 공유 (Docker Engine 위 실행) |
| **무게** | GB 단위 (매우 무거움) | MB 단위 (매우 가벼움) |
| **속도** | 분 단위 (느린 부팅) | 초 단위 (매우 빠른 실행) |
| **효율성** | 자원 할당이 고정적임 | 필요한 만큼 자원을 유연하게 사용 |

- 두 가지 모두 격리된 환경을 제공하는 것은 같지만 방식과 효율성에서 엄청난 차이가 존재한다.

- 구조와 무게

  - VM: 하이퍼바이저 위에 하드웨어를 가상화하고, 그 위에 Guest OS를 매번 새로 설치해야 한다. 윈도우 위에 리눅스를 깔면, 리눅스 OS 자체가 차지하는 용량과 메모리가 낭비될 수 있다.

  - Docker: 호스트 컴퓨터의 OS 커널을 공유한다. 컨테이너 안에는 내 프로그램을 실행하는 데 딱 필요한 라이브러리와 설정 파일만 들어있다.

- 속도

  - VM: OS가 부팅되어야 하므로 분 단위의 시간이 걸린다.

  - Docker: 컨테이너는 이미 켜져 있는 OS 위에서 프로세스만 실행하는 격이라 **초 단위**로 켜진다.

## **4. 도커의 주요 장점**

- **환경 일관성:** 개발, 테스트, 운영 환경을 완전히 동일하게 유지.

- **확장성 및 이식성:** 컨테이너를 복제하여 쉽게 확장할 수 있고, 어떤 클라우드나 서버로도 쉽게 이동 가능.

- **격리성:** 각 컨테이너는 독립된 공간에서 실행되어 서로 영향을 주지 않음.

## 5. Docker Hub

- 정의: 도커에서 운영하는 공식 클라우드 이미지 레지스트리로 코드를 공유할 때 **GitHub**을 쓰듯, 도커 이미지를 공유할 때는 **Docker Hub**를 사용한다.

- 특징

  - 공식 이미지: 도커 팀이나 해당 소프트웨어 개발사(예: Nginx, Python, Oracle, MySQL, Ubuntu)에서 직접 관리하는 신뢰할 수 있는 이미지들을 사용할 수 있다.

  - 자동 빌드: GitHub과 연동해두면, 코드가 업데이트될 때마다 도커 허브가 알아서 새로운 이미지를 생성해준다.
