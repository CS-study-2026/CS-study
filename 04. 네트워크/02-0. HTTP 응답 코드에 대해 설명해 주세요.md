# 2-0. HTTP 응답 코드에 대해 설명해 주세요.

# 1. HTTP 응답 코드란?

- HTTP 응답 코드는 웹 브라우저(클라이언트)가 웹 서버에 무언가를 요청했을 때, 서버가 그 결과를 세 자리 숫자로 요약해서 보내주는 '통신 상태 보고서'.

- 즉, 클라이언트가 서버에 어떠한 요청을 하여 응답을 받았을 때, 해당 응답이 어떠한 상태인지 간단하게 보여주는 것입니다.

# 2. HTTP 응답 코드의 5가지 범주

- 1xx (정보 제공): 요청을 받았으며 작업을 계속 진행 중임을 의미.

- 2xx (성공): 클라이언트의 요청이 성공적으로 처리되었음을 의미.

- 3xx (리다이렉션): 요청을 완료하기 위해 클라이언트가 추가적인 조치를 취해야 함을 의미. (주소 이동 등)

- 4xx (클라이언트 오류): 클라이언트의 요청에 잘못된 문법이나 권한 문제 등 오류가 있음을 의미.

- 5xx (서버 오류): 클라이언트의 요청은 유효했으나, 서버가 성능 저하나 버그 등으로 인해 요청을 처리하지 못했음을 의미.

# 3. 1xx 응답 코드(정보 제공)

- 이 대역의 코드들은 클라이언트의 요청이 서버에 접수되어 현재 "작업이 진행 중"임을 알리는 임시 응답입니다.

- 최종 응답(200, 404 등)이 오기 전에 주고받는 프로토콜 수준의 신호이기 때문에, 실제 웹 화면을 개발하거나 일반적인 API를 만들 때는 마주칠 일이 거의 없습니다.

- 100 Continue (계속 진행)

  - 클라이언트가 요청의 일부분을 보냈고, 서버가 그것을 확인했으니 나머지 요청을 계속 보내도 좋다는 신호입니다.

  - 클라이언트가 대용량 파일을 업로드하기 전에 `Expect: 100-continue`라는 헤더를 먼저 보냅니다.

  - 서버가 상태를 보고 "업로드해도 괜찮다"고 판단하면 100 Continue를 보내고, 그때 클라이언트가 진짜 본문(파일 내용)을 전송합니다.

  - 거부될 요청이라면 대용량 데이터를 전송하기 전에 미리 차단할 수 있어 네트워크 낭비를 막아줍니다.

- 101 Switching Protocols (프로토콜 전환)

  - 클라이언트가 요청 헤더를 통해 통신 규약(프로토콜)을 바꾸자고 제안했고, 서버가 이를 수락하여 프로토콜을 전환하겠다는 의미입니다.

  - 일반적인 HTTP 통신을 하다가, 실시간 양방향 통신을 위해 웹소켓(WebSocket)으로 연결을 업그레이드할 때 가장 흔하게 사용합니다.

- 102 Processing (처리 중 - WebDAV)

  - 서버가 요청을 접수하여 수신했으며 처리 중이지만, 최종 응답을 보내기까지 시간이 다소 걸리고 있음을 의미합니다.

  - 서버가 작업을 수행하는 데 시간이 너무 오래 걸릴 경우, 클라이언트가 "연결이 끊어졌나?" 하고 먼저 연결을 끊어버리는 타임아웃(Timeout) 오류를 방지하기 위해 임시로 보내는 신호입니다.

- 103 Early Hints (사전 힌트)

  - 서버가 최종 응답을 준비하는 동안, 브라우저가 필요한 자원(CSS, JavaScript 파일 등)을 미리 다운로드(Preload)할 수 있도록 힌트를 주는 코드입니다.

  - 웹페이지 로딩 속도를 최적화하기 위해 사용합니다.

# 4. 2xx 응답 코드(성공)

- 클라이언트가 보낸 요청을 서버가 아무런 문제 없이 "성공적으로 잘 처리했다"는 신호입니다.

- 200 OK (성공)

  - 요청이 성공적으로 처리되었으며, 요청에 대한 결과 데이터가 응답 본문(Body)에 포함되어 전송합니다.

  - 웹사이트 주소를 입력해 메인 페이지를 읽어오거나(GET), 일반적인 게시글 목록을 조회할 때 가장 기본적으로 반환되는 성공 신호입니다.

- 201 Created (작성됨)

  - 요청이 성공적이었으며, 그 결과로 서버에 새로운 리소스가 생성되었음을 의미합니다.

  - 회원가입을 완료하여 새로운 유저 정보가 DB에 저장되었을 때, 혹은 게시판에 새로운 글을 작성(POST)하여 등록에 성공했을 때 주로 사용합니다.

- 202 Accepted (접수됨)

  - 요청이 접수되었으나, 아직 실제 처리는 완료되지 않은 상태입니다.

  - 주로 비동기 처리를 할 때 사용합니다.

  - "내일까지 1,000만 명에게 대량 단체 메일을 발송해 줘"라는 요청을 보냈을 때, 서버가 그 자리에서 다 보낼 수 없으므로 우선 "요청은 잘 받았으니 순차적으로 처리할게" 하고 먼저 이 코드를 내려줍니다.

- 204 No Content (콘텐츠 없음)

  - 요청은 성공적으로 처리되었으나, 클라이언트에게 **보내줄 데이터(본문)가 없다**는 의미입니다.

  - 특정 게시글이나 회원 정보를 '삭제(DELETE)'했을 때가 대표적입니다.

  - 삭제가 끝났으니 굳이 되돌려줄 데이터가 없으므로 "요청대로 잘 지웠고, 보여줄 본문은 없어"라는 뜻으로 보냅니다.

<summary>자주 사용되지 않는 200번대 응답 코드</summary>

- 203 Non-Authoritative Information (비인증 정보)

    - 요청은 성공적으로 처리되었지만, 응답 헤더에 담긴 메타데이터가 원본 서버(Origin Server)에서 직접 온 것이 아니라 중간에 있는 프록시 서버 등에 의해 수정되거나 가공된 정보임을 클라이언트에게 알리는 코드입니다.

    - 클라이언트가 어떤 데이터를 요청했는데, 중간에 있는 캐시(Cache) 서버나 보안 프록시 서버가 "원본 서버가 준 데이터랑 똑같긴 한데, 헤더 정보는 내가 우리 네트워크 환경에 맞게 조금 수정했어"라고 알려주며 데이터를 넘겨줄 때 발생합니다.

  - 205 Reset Content (콘텐츠 재설정)

    - 요청이 성공적으로 완료되었고 서버가 처리를 마쳤으니, 클라이언트에게 현재 화면에 있는 입력 폼(Form)을 모두 초기화(Reset)하라고 지시하는 코드입니다.

    - 사용자가 웹사이트에서 설문조사를 작성하거나 연속으로 회원 정보를 등록하는 화면이 있다고 가정해 보겠습니다. 사용자가 등록 버튼을 누르면 서버가 데이터를 DB에 잘 저장한 뒤, 205번 코드를 내려보내 브라우저가 화면의 모든 입력창을 자동으로 깨끗하게 비우고 다음 입력을 받을 준비를 하도록 만들 때 사용합니다.

  - 206 Partial Content (부분 콘텐츠)

    - 클라이언트가 요청한 전체 리소스 중에서 지정한 일부분(Range)만 성공적으로 전송했다는 의미입니다.

    - 클라이언트가 헤더에 `Range`를 지정해 요청하면, 서버는 이 코드와 함께 `Content-Range` 헤더를 붙여 데이터의 어느 조각인지를 명시하여 보냅니다.

    - 유튜브나 넷플릭스 같은 **비디오 스트리밍 서비스**에서 2시간짜리 영화를 한 번에 다 다운로드하면 대역폭 낭비가 심하므로, 사용자가 시청하는 구간만큼만(예: 0~10MB, 그다음 10~20MB) 쪼개서 요청하고 응답받을 때 사용합니다.

# 5. 3xx 응답 코드(리다이렉션)

- 클라이언트가 요청한 리소스의 주소가 바뀌었거나 위치가 이동되었으니, "새로운 주소로 다시 찾아가라"고 지시하는 코드입니다.

- 백엔드 개발 시 주소가 변경된 구버전 API를 처리하거나, 보안(HTTP -> HTTPS) 적용, 혹은 웹 브라우저의 로그인 후 페이지 이동 등을 구현할 때 매우 자주 사용됩니다.

- 301 Moved Permanently (영구 이동)

  - 요청한 리소스의 주소가 영구적으로 완전히 변경되었음을 의미합니다.

  - 브라우저는 이 응답을 받으면 새로운 주소를 기억(캐싱)해 둡니다. 다음부터 사용자가 옛날 주소로 접속하려고 해도 브라우저가 알아서 새로운 주소로 바로 연결해 줍니다. 검색엔진(SEO)도 이 코드를 보면 옛날 주소의 점수를 새로운 주소로 온전히 이전시킵니다.

  - 사이트 도메인을 완전히 새로 바꿨을 때(예: `old-site.com` -> `new-site.com`), 또는 보안을 위해 `http://...`로 들어온 요청을 `https://...` 주소로 강제로 영구 이동시킬 때 사용합니다.

- 302 Found / Moved Temporarily (일시적 이동)

  - 요청한 리소스의 주소가 일시적으로 변경되었음을 의미합니다.

  - 301번과 달리 주소가 '잠깐' 바뀐 것이기 때문에, 브라우저가 새로운 주소를 기억하지 않습니다. 다음번 요청 때도 일단 원래 주소로 확인을 요청해야 합니다.

  - 로그인하지 않은 사용자가 마이페이지(` /mypage`)에 접근했을 때, 로그인 페이지(` /login`)로 잠시 이동시켰다가 로그인이 완료되면 다시 마이페이지로 돌려보낼 때 아주 흔하게 사용됩니다. 또는 이벤트 기간에만 메인 페이지를 이벤트 페이지로 임시 교체할 때도 쓰입니다.

- 304 Not Modified (수정되지 않음)

  - 클라이언트가 요청한 리소스가 마지막으로 확인했을 때와 비교해 전혀 수정되지 않았다는 것을 알려주는 코드입니다.

  - 서버는 "너가 이미 가지고 있는 파일이 최신 버전이니까 그걸 그대로 써"라고 알려주며, 본문(Body) 데이터를 전송하지 않습니다. 클라이언트는 자신의 컴퓨터에 저장되어 있던 캐시(Cache) 데이터를 그대로 화면에 띄웁니다.

  - 웹사이트의 로고 이미지, CSS, 자바스크립트 파일처럼 자주 바뀌지 않는 자원들을 매번 네트워크를 통해 새로 다운로드하면 속도가 느려지므로, 네트워크 대역폭을 아끼고 웹사이트 로딩 속도를 획기적으로 높이기 위해 사용됩니다.

- 307 Temporary Redirect (임시 리다이렉트)

  - 302번과 마찬가지로 일시적인 이동을 의미하지만, 한 가지 강력한 제약 조건이 추가된 코드입니다.

  - 리다이렉트할 때 클라이언트가 보낸 HTTP 메서드(GET, POST 등)와 본문(Body) 데이터를 그대로 유지해서 새 주소로 보내야 합니다. (참고로 옛날에 만들어진 302번은 POST 요청을 받아도 새 주소로 이동할 때 GET 요청으로 멋대로 바꾸는 문제가 있어서, 이를 명확하게 고치기 위해 307번이 등장했습니다.)

  - 사용자가 결제 요청(POST)을 보냈는데, 서버가 일시적인 점검이나 다른 결제 게이트웨이 서버로 해당 결제 요청 데이터(금액, 카드 정보 등)를 그대로 유지한 채 안전하게 이정표만 바꾸어 넘겨주어야 할 때 사용합니다.

<details>
<summary>자주 사용되지 않는 300번대 응답 코드</summary>

- 300 Multiple Choices (여러 선택항목)

    - 클라이언트가 요청한 리소스에 대해 **두 개 이상의 응답(선택지)이 존재**하므로, 마음에 드는 것을 선택하라고 알려주는 코드입니다.

    - 하나의 주소에 여러 언어 버전(한국어, 영어, 일본어)의 페이지가 있거나, 동영상 파일의 포맷(mp4, avi)이 여러 개일 때 서버가 이 목록들을 선택지로 내려줍니다. 하지만 실무에서는 서버가 클라이언트의 헤더 정보(Accept-Language 등)를 보고 알아서 가장 적절한 페이지를 골라 200 OK로 보내주는 방식을 주로 쓰기 때문에 거의 사용되지 않습니다.

  - 303 See Other (다른 위치 보기)

    - 요청에 대한 결과물이 다른 주소에 있으니, 무조건 GET 메서드를 사용하여 새로운 주소로 이동하라고 지시하는 코드입니다.

    - 사용자가 게시판에 글을 작성하고 [등록] 버튼을 누르면 서버로 POST 요청이 날아갑니다. 서버는 글을 DB에 잘 저장한 뒤 303 코드를 주며 "글이 잘 등록되었으니, 새로 생성된 글 보기 페이지(GET)로 이동해!"라고 브라우저에게 명령합니다. 이렇게 하면 사용자가 글 보기 화면에서 '새로고침'을 누르더라도 똑같은 글이 중복 등록(POST)되는 대참사를 원천 차단할 수 있습니다. (백엔드 설계의 중요 패턴인 POST-Redirect-GET 패턴의 핵심 코드입니다.)

  - 305 Use Proxy (프록시 사용 - 현재는 폐기됨)

    - 요청한 리소스에 접근하려면 서버가 지정한 **프록시(Proxy) 서버를 거쳐서 다시 요청해야 한다**고 알려주는 코드입니다.

    - 이 코드는 브라우저가 자동으로 프록시 설정을 바꾸도록 유도하기 때문에, 악의적인 해커가 가짜 프록시 서버로 유저의 트래픽을 가로채는 보안 취약점(보안 리스크)이 있었습니다. 이 때문에 현대 웹 표준과 최신 브라우저에서는 안전상의 이유로 이 코드를 완전히 무시하며, **더 이상 사용하지 않는 폐기(Deprecated)된 코드**입니다.

  - 308 Permanent Redirect (영구 리다이렉트)

    - 301번과 마찬가지로 주소가 **영구적으로 변경**되었음을 의미하지만, 한 가지 규칙이 더 추가된 코드입니다.

    - 리다이렉트할 때 클라이언트가 보낸 HTTP 메서드와 본문(Body) 데이터를 절대로 변경하지 않고 그대로 유지해서 새 주소로 보내야 합니다. (옛날에 만들어진 301번이 POST 요청을 GET으로 바꾸어 버리는 고질적인 문제가 있어서, 이를 명확하게 규정하기 위해 307번과 함께 새로 추가된 현대적인 표준 규격입니다.)

    - 구버전 회원가입 API 주소(`POST /v1/signup`)가 신버전 주소(`POST /v2/signup`)로 영구 변경되었을 때, 사용자가 입력한 아이디와 비밀번호 데이터(POST 본문)를 그대로 유지한 채 새 주소로 안전하게 넘겨주어야 할 때 사용합니다.
</details>

# 6. 4xx 응답 코드(클라이언트 오류)

- 백엔드 개발자가 API를 설계할 때 유효성 검사(Validation)나 권한 검증을 통과하지 못하면 가장 적극적으로 활용하는 대역입니다.

- 클라이언트 개발자에게 "당신들이 코드를 이렇게 수정해야 합니다"라고 명확히 소통하는 기준이 되기 때문에 실무에서 비중이 매우 높습니다.

- 400 Bad Request (잘못된 요청)

  - 서버가 요청 문법을 이해할 수 없거나, 필수적으로 보내야 하는 데이터가 누락/형식이 잘못되었을 때 반환합니다.

  - 백엔드 유효성 검사(Validation) 단계에서 에러가 발생하면 가장 기본적으로 던지는 코드입니다.

- 401 Unauthorized (인증되지 않음)

  - 해당 리소스에 접근하기 위해서는 로그인이나 토큰 인증이 필요함을 의미합니다. (이름은 '권한(Authorization)'이지만 실제로는 '인증(Authentication)'이 누락되었을 때 씁니다.)

  - 로그인하지 않은 상태로 마이페이지를 조회하려고 하거나, API 호출 시 헤더에 Bearer 토큰(JWT)을 누락하고 보냈을 때 사용합니다.

- 403 Forbidden (거부됨/권한 없음)

  - 서버가 클라이언트가 누구인지는 알고 있으나(인증은 됨), 해당 리소스에 접근할 수 있는 권한(Role)이 없음을 의미합니다.

  - 일반 회원이 관리자 전용 페이지(` /admin`)에 접근하려고 할 때, 혹은 다른 사용자가 작성한 비공개 글을 수정하려고 할 때 차단하는 코드입니다.

- 404 Not Found (찾을 수 없음)

  - 클라이언트가 요청한 URI에 해당하는 리소스를 서버에서 절대 찾을 수 없다는 의미입니다. 가장 대중적으로 유명한 에러 코드입니다.

  - 주소창에 오타를 입력해 없는 주소로 접근했을 때(` /not-found-page`), 또는 없는 게시글 번호(` /posts/999999`)를 조회하려고 했을 때 서버가 던지는 응답입니다.

- 409 Conflict (충돌)

  - 서버의 현재 상태와 클라이언트의 요청이 충돌을 일으켰을 때 사용합니다. 데이터 무결성을 지키기 위해 필수적인 코드입니다.

  - 이미 가입된 이메일 주소로 또다시 회원가입을 시도할 때(아이디 중복), 또는 동일한 아이디로 동시에 두 번 등록 요청이 들어와 데이터가 꼬일 위험이 있을 때 사용합니다.

<details>
<summary>자주 사용되지 않는 400번대 응답 코드</summary>

- 405 Method Not Allowed (허용되지 않은 메서드)

    - 요청한 URL 주소는 존재하지만, 클라이언트가 보낸 HTTP 메서드(GET, POST, PUT, DELETE 등)를 해당 주소에서 지원하지 않는다는 의미입니다.

    - 특정 게시글을 읽는 주소(`GET /posts/1`)는 열려있는데, 누군가 악의적으로나 실수로 해당 주소에 삭제 요청(`DELETE /posts/1`)을 보냈을 때 서버가 "그 주소에서 그 행위는 허용되지 않는다"며 차단할 때 씁니다.

  - 406 Not Acceptable (수용할 수 없음)

    - 클라이언트가 요청 헤더(`Accept-*`)를 통해 "나는 이런 형식의 데이터만 받을 수 있어"라고 요구했으나, 서버가 그 형식에 맞는 데이터를 만들어 줄 수 없을 때 반환합니다.

    - 브라우저가 헤더에 `Accept-Language: ko`를 보내 "무조건 한국어 페이지로 줘"라고 요청했는데, 서버에 영어와 일본어 데이터밖에 없을 때 "너가 원하는 언어로 맞춰줄 수 없어"라며 이 코드를 보냅니다. (다만 실무에서는 406번을 엄격하게 내리기보다 기본 언어(영어)로 200 OK를 주는 경우가 많습니다.)

  - 412 Precondition Failed (사전 조건 실패)

    - 클라이언트가 요청 헤더에 지정한 **사전 조건(Precondition)을 서버가 만족하지 못했을 때** 발생합니다.

    - 주로 데이터가 중간에 다른 사람에 의해 수정되었는지 검증할 때(동시성 제어) 쓰입니다. 클라이언트가 "내가 가진 데이터 버전이 최신 버전(`If-Match: 버전1`)이 맞으면 수정해 줘"라고 보냈는데, 그새 다른 사람이 데이터를 수정해서 서버의 버전이 변경되었다면 412 에러를 내며 요청을 거부합니다.

  - 413 Content Too Large (요청 엔티티가 너무 큼)

    - 클라이언트가 보낸 요청 본문의 크기(파일 용량 등)가 서버가 허용하는 한계치를 초과했을 때 발생합니다.

    - 서버 설정(Nginx, 톰캣 등)에서 첨부파일 업로드 제한을 10MB로 해두었는데, 사용자가 1GB짜리 대용량 영상을 첨부하여 전송하려고 할 때 서버가 요청을 즉시 차단하며 이 코드를 반환합니다.

  - 415 Unsupported Media Type (지원되지 않는 미디어 타입)

    - 클라이언트가 보낸 데이터의 미디어 형식(포맷)을 서버가 처리할 수 없다는 의미입니다.

    - 서버는 오직 JSON 형식(`application/json`)의 데이터만 받아서 처리하도록 설계되어 있는데, 클라이언트가 실수로 XML 형식이나 텍스트 파일 형식으로 데이터를 쏘았을 때 "우리 서버는 이 파일 형식을 읽을 줄 모른다"며 거부할 때 사용합니다.

  - 429 Too Many Requests (너무 많은 요청)

    - 클라이언트가 **짧은 시간 동안 서버가 허용하는 횟수를 초과하여 너무 많은 요청**을 보냈을 때 반환합니다. DDOS 공격을 방어하거나 API 사용량 제한(Rate Limiting)을 구현할 때 필수적인 코드입니다.

    - 특정 IP에서 1초에 500번씩 연달아 조회를 요청하면, 서버는 시스템 과부하를 막기 위해 "요청 횟수가 너무 많으니 잠시 후 다시 시도하라"며 요청을 차단합니다.
</details>

# 7. 5xx 응답 코드(서버 오류)

- 이 코드가 발생했다는 것은 내 소스코드에 버그가 있거나, 데이터베이스가 다운되었거나, 서버 인프라에 불이 켜졌다는 뜻입니다.

- 실무에서 에러 로그를 분석할 때 가장 먼저 파헤쳐야 하는 핵심 대역이기도 합니다.

- 500 Internal Server Error (서버 내부 오류)

  - 서버에 요청이 전달되어 처리하던 중, 서버 내부에서 예상하지 못한 에러나 예외(Exception)가 발생하여 작동이 중단된 상태입니다. 500번대 중 가장 광범위하고 흔하게 발생하는 코드입니다.

  - 자바(Java) 코드를 짤 때 가장 흔하게 발생하는 `NullPointerException`이나 데이터베이스 조작 에러(SQL 예외) 등을 백엔드 로직에서 적절하게 예외 처리(Try-Catch)하지 못하고 그대로 밖으로 터져 나갔을 때 브라우저가 이 코드를 받게 됩니다.

- 502 Bad Gateway (불량 게이트웨이)

  - 게이트웨이나 프록시 서버(Nginx, Apache, AWS ALB 등)가 중간에서 요청을 받아 실제 백엔드 애플리케이션 서버(Tomcat, Spring Boot 등)로 넘겨주었는데, 백엔드 서버로부터 잘못된 응답을 받았거나 연결에 실패했을 때 발생합니다.

  - 스프링 부트 서버가 어떤 버그로 인해 프로세스가 완전히 죽어버렸거나, 새로운 코드를 반영하기 위해 서버를 재배포하는 아주 잠깐의 공백 사이에 사용자가 요청을 보내면 중간에 서 있던 Nginx가 "뒤에 있는 서버가 대답을 안 하네?"라며 이 코드를 던집니다.

- 503 Service Unavailable (서비스 이용 불가)

  - 서버가 현재 요청을 처리할 수 없는 임시적인 상태임을 뜻합니다. 주로 서버 과부하 상태이거나 유지 보수(점검) 중일 때 반환됩니다.

  - 수강신청, 명절 기차표 예매, 인기 콘서트 티켓팅 때 수백만 명의 사용자가 동시에 몰려 서버 자원(CPU, 메모리)이 한계에 도달하면, 서버는 시스템이 아예 뻗어버리는 것을 막기 위해 대기열을 걸거나 "죄송합니다. 현재 이용자가 많아 처리할 수 없습니다"라는 안내와 함께 이 코드를 보냅니다.

- 504 Gateway Timeout (게이트웨이 시간 초과)

  - 502번과 마찬가지로 중간 프록시 서버와 관련된 에러입니다. 백엔드 서버로 요청을 전달하는 것까지는 성공했으나, 백엔드 서버가 지정된 시간(Timeout) 내에 응답을 완성해서 돌려주지 못했을 때 발생합니다.

  - 사용자가 "최근 10년간의 전사 매출 데이터 통계 내줘"라는 아주 무거운 요청을 보냈을 때, 백엔드 서버가 데이터베이스를 수십 초 동안 끙끙거리며 조회하느라 정해진 타임아웃 시간(예: 30초)을 넘겨버리면 앞단의 Nginx나 AWS 로드밸런서가 기다리다 지쳐 클라이언트에게 이 에러를 내립니다.

<details>
<summary>자주 사용되지 않는 500번대 응답 코드</summary>

- 501 Not Implemented (구현되지 않음)

    - 클라이언트가 요청한 HTTP 메서드나 기능을 서버가 지원하지 않거나, 아직 개발(구현)하지 않아서 요청을 처리할 수 없다는 의미입니다.

    - 사용 예시: 서버가 오직 `GET`과 `POST` 메서드만 처리할 수 있도록 만들어져 있는데, 클라이언트가 `PATCH`나 `OPTIONS` 같은 메서드로 요청을 보냈을 때 "요청은 알아들었지만 우리 서버에는 아직 그 기능을 수행할 코드가 구현되어 있지 않다"며 거부할 때 반환합니다. (500번 에러와 달리 코드가 에러로 터진 게 아니라, 진짜 기능이 없는 상태입니다.)

  - 506 Variant Also Negotiates (변형이 또한 협상됨)

    - 서버 내부 구성 오류로 인해, 클라이언트와 서버 간의 콘텐츠 협상(Content Negotiation) 과정에서 무한 루프(순환 참조)가 발생했을 때 반환하는 매우 희귀한 코드입니다.

    - 클라이언트가 서버에 "알맞은 언어 버전의 페이지를 달라"고 요청했는데, 서버 내부의 리다이렉트 설정이 꼬여서 A 주소는 B를 가리키고 B 주소는 다시 A를 가리키는 식으로 내부 협상 로직이 무한 궤도에 빠졌을 때 서버가 스스로 이를 감지하고 에러를 냅니다.

  - 507 Insufficient Storage (용량 부족 - WebDAV)

    - 요청을 처리하기 위해 필요한 서버의 디스크 공간이나 메모리 등의 저장 용량이 부족할 때 발생합니다.

    - 사용자가 웹 하드나 클라우드 서버에 파일을 업로드(POST)하려고 시도했으나, 서버 컴퓨터의 하드디스크가 100% 꽉 차서 더 이상 파일 시스템에 데이터를 쓸 수 없을 때 시스템이 이 코드를 반환합니다.

  - 508 Loop Detected (루프 감지 - WebDAV)

    - 서버가 요청을 처리하는 과정에서 무한 루프(지속적인 순환 참조)를 감지하여 작업을 강제로 중단했음을 의미합니다.

    - 주로 여러 서버가 복잡하게 얽혀있는 분산 네트워크 환경이나 WebDAV(웹 기반 분산 저작) 환경에서, 리소스 간의 종속성 관계가 서로를 순환 참조하도록 잘못 설정되어 네트워크 패킷이 뱅뱅 돌 때 이를 차단하기 위해 사용합니다.

  - 511 Network Authentication Required (네트워크 인증 필요)

    - 클라이언트가 요청을 보낸 서버에 도달하기 전에, 먼저 네트워크 자체의 인증(로그인 등)을 거쳐야 함을 의미합니다. 서버가 아니라 네트워크 게이트웨이가 던지는 에러입니다.

    - 카페나 공항, 호텔의 공공 와이파이(Wi-Fi)에 처음 연결했을 때 흔히 겪는 상황입니다. 브라우저를 켜고 구글에 접속하려고 하면, 구글 서버까지 가기도 전에 와이파이 공유기(게이트웨이)가 511 코드를 주면서 "이 와이파이를 쓰려면 먼저 호텔 방 번호를 입력하거나 이용 약관에 동의(로그인)하세요"라며 안내 페이지로 가로채갈 때 사용됩니다.
</details>

# 8. 결론

- 일반적으로 실무에서도 모든 것을 외우지는 않기 때문에, 첫 자릿수(1~5)의 규칙과 핵심 코드만 알고 있으면 문제 없음.

- **2xx:** 성공했구나! (조회는 200, 생성은 201)

- **3xx:** 주소가 바뀌었구나! (캐시는 304)

- **4xx:** 클라이언트가 뭔가 잘못 보냈구나! (파라미터 오류는 400, 권한은 401/403, 없는 주소는 404)

- **5xx:** 아, 서버 터졌다! 내 코드나 인프라 문제구나! (500)
