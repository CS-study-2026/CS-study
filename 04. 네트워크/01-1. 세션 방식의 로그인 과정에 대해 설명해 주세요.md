# 1-1. 세션 방식의 로그인 과정에 대해 설명해 주세요.

# **세션 방식의 로그인 과정**

## **1. 핵심 개념**

세션 방식 로그인은 **사용자 로그인 상태를 서버가 저장하는 방식**이다.

클라이언트는 사용자 정보를 직접 들고 있지 않고, 서버가 발급한 **Session ID**만 쿠키에 저장한다.

---

## **2. 로그인 과정**

```plain text
1. 사용자가 아이디/비밀번호 입력
        ↓
2. 클라이언트가 서버에 로그인 요청
        ↓
3. 서버가 회원 정보 검증
        ↓
4. 검증 성공 시 서버에 세션 생성
        ↓
5. 서버가 Session ID를 쿠키로 응답
        ↓
6. 브라우저가 Session ID 쿠키 저장
        ↓
7. 이후 요청마다 쿠키에 Session ID를 담아 전송
        ↓
8. 서버가 Session ID로 세션을 조회해 로그인 여부 확인
```

---

## **3. 예시 흐름**

### **1) 로그인 요청**

```plain text
POST /login HTTP/1.1

username=user1&password=1234
```

---

### **2) 서버에서 사용자 검증**

서버는 DB에서 사용자를 조회하고

비밀번호가 맞는지 확인한다.

```plain text
user1 / 1234 → 검증 성공
```

---

### **3) 세션 생성**

검증에 성공하면 서버는 세션 저장소에 로그인 정보를 저장한다.

```plain text
Session ID: ABC123
저장 데이터: userId=1, role=USER
```

---

### **4) Session ID를 쿠키로 전달**

```plain text
HTTP/1.1 200 OK
Set-Cookie: JSESSIONID=ABC123; HttpOnly; Secure; SameSite=Lax
```

여기서 실제 사용자 정보가 아니라

**Session ID만 클라이언트에게 전달**된다.

---

### **5) 이후 요청**

브라우저는 같은 사이트로 요청할 때 쿠키를 자동으로 함께 보낸다.

```plain text
GET /mypage HTTP/1.1
Cookie: JSESSIONID=ABC123
```

---

### **6) 서버에서 로그인 상태 확인**

서버는 쿠키의 Session ID를 보고 세션 저장소를 조회한다.

```plain text
ABC123 → userId=1, role=USER
```

세션이 존재하면 로그인된 사용자로 처리하고,

없거나 만료되었으면 로그인하지 않은 사용자로 처리한다.

---

## **4. 로그아웃 과정**

로그아웃 시에는 서버의 세션을 삭제한다.

```plain text
1. 클라이언트가 로그아웃 요청
2. 서버가 세션 저장소에서 해당 Session ID 삭제
3. 필요하면 쿠키도 만료 처리
```

예시:

```plain text
Set-Cookie: JSESSIONID=; Max-Age=0
```

---

## **5. 면접 답변 예시**

세션 방식 로그인은 서버가 사용자의 로그인 상태를 관리하는 방식입니다.

사용자가 아이디와 비밀번호로 로그인을 요청하면, 서버는 DB에서 회원 정보를 검증합니다.

검증에 성공하면 서버는 세션 저장소에 사용자 정보를 저장하고, 해당 세션을 식별할 수 있는 Session ID를 생성합니다.

이후 서버는 이 Session ID를 쿠키에 담아 클라이언트에게 전달합니다.

브라우저는 이후 요청마다 Session ID 쿠키를 자동으로 전송하고, 서버는 이 ID로 세션 저장소를 조회하여 로그인 여부를 확인합니다.

로그아웃하거나 세션이 만료되면 서버의 세션 정보가 삭제되어 더 이상 인증된 사용자로 처리되지 않습니다.

---

## **6. 꼬리 질문 대비**

### **Q1. 세션 정보는 어디에 저장되나요?**

보통 서버 메모리, Redis, DB 등에 저장할 수 있다.

단일 서버에서는 메모리에 저장할 수 있지만,

서버가 여러 대라면 Redis 같은 외부 세션 저장소를 많이 사용한다.

---

### **Q2. 왜 쿠키에는 사용자 정보를 저장하지 않나요?**

쿠키는 클라이언트에 저장되기 때문에 사용자가 확인하거나 수정할 수 있다.

그래서 비밀번호, 권한, 개인정보 같은 중요한 정보는 저장하지 않고,

세션을 찾기 위한 **Session ID만 저장**한다.

---

### **Q3. Session ID가 탈취되면 어떻게 되나요?**

공격자가 Session ID를 탈취하면

서버는 공격자를 정상 사용자로 인식할 수 있다.

이를 **세션 하이재킹**이라고 한다.

그래서 보통 다음 옵션을 사용한다.

```plain text
HttpOnly: JavaScript로 쿠키 접근 방지
Secure: HTTPS에서만 쿠키 전송
SameSite: CSRF 위험 완화
```

| **옵션** | **설명** |
| --- | --- |
| **HttpOnly** | JavaScript에서 쿠키에 접근하지 못하도록 막는 옵션. XSS 공격으로 인한 쿠키 탈취를 방지한다. |
| **Secure** | HTTPS 연결에서만 쿠키를 전송하는 옵션. 네트워크에서 쿠키가 평문으로 노출되는 위험을 줄인다. |
| **SameSite** | 다른 사이트에서 발생한 요청에는 쿠키 전송을 제한하는 옵션. CSRF 공격을 완화한다. |

---

### **Q4. 세션 만료는 왜 필요한가요?**

세션을 무한히 유지하면 보안 위험이 커지고 서버 자원도 계속 사용된다.

그래서 일정 시간 동안 요청이 없으면 세션을 만료시킨다.

```plain text
예: 30분 동안 요청이 없으면 세션 만료
```

---

# **한 줄 정리**

세션 방식 로그인은 서버가 로그인 정보를 세션에 저장하고, 클라이언트는 세션을 식별하기 위한 Session ID만 쿠키에 담아 요청마다 전송하는 방식이다.
