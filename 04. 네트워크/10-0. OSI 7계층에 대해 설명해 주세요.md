# 10-0. OSI 7계층에 대해 설명해 주세요.

## OSI 7계층이란?

**OSI(Open Systems Interconnection) 7계층**은 **네트워크 통신 과정을 7개의 역할로 나누어 표준화한 참조 모델**입니다.

쉽게 말하면,

> **"데이터가 한 컴퓨터에서 다른 컴퓨터까지 전달되는 과정을 역할별로 나누어 놓은 설계도"**

라고 생각하면 됩니다.

실제 인터넷은 **TCP/IP 모델**을 사용하지만, **네트워크의 동작 원리를 이해하거나 장애를 분석할 때는 OSI 7계층을 가장 많이 사용합니다.**

- TCP/IP는 일부 계층을 합쳐버림. OSI 7계층은 정석의 설계도, TCP/IP 모델은 실제 건축현장의 설계 느낌.

---

## 왜 굳이 7개의 계층으로 나누었을까?

만약 모든 기능이 하나의 거대한 프로그램 안에 있다면,

- 수정하기 어렵고

- 문제가 발생했을 때 원인을 찾기 어렵고

- 다른 회사의 장비와 호환하기도 어렵습니다.

그래서 역할을 계층별로 분리했습니다.

### 장점

- ✅ 각 계층은 자신의 역할만 수행한다.

- ✅ 특정 계층만 수정해도 다른 계층에는 영향을 거의 주지 않는다.

- ✅ 제조사가 달라도 같은 규칙으로 통신할 수 있다.

- ✅ 문제가 발생한 계층을 쉽게 찾을 수 있다.

---

# OSI 7계층 구조

```plain text
┌────────────────────────────────────────┐
│ 7. Application   사용자와 직접 통신     │
├────────────────────────────────────────┤
│ 6. Presentation  데이터 형식 변환       │
├────────────────────────────────────────┤
│ 5. Session       연결(Session) 관리     │
├────────────────────────────────────────┤
│ 4. Transport     신뢰성 있는 데이터 전송│
├────────────────────────────────────────┤
│ 3. Network       목적지까지 경로 선택   │
├────────────────────────────────────────┤
│ 2. Data Link     같은 네트워크 내 전달  │
├────────────────────────────────────────┤
│ 1. Physical      전기/광 신호 전송      │
└────────────────────────────────────────┘
```

---

# 각 계층의 역할

| 계층 | 핵심 역할 | 대표 프로토콜 / 장비 |
| --- | --- | --- |
| **7. Application** | 사용자에게 네트워크 서비스를 제공 | HTTP, HTTPS, FTP, SMTP, DNS |
| **6. Presentation** | 데이터 형식 변환, 암호화, 압축 | TLS/SSL, JPEG, MPEG |
| **5. Session** | 통신 연결 생성, 유지, 종료 | RPC, NetBIOS |
| **4. Transport** | 신뢰성 있는 데이터 전송 | TCP, UDP |
| **3. Network** | 목적지까지 데이터 전달 | IP, Router |
| **2. Data Link** | 같은 네트워크 내 데이터 전달 | Ethernet, Wi-Fi, Switch |
| **1. Physical** | 데이터를 전기·광 신호로 전송 | 케이블, 허브, 리피터 |

---

## 7. Application Layer (응용 계층)

사용자가 직접 사용하는 **네트워크 서비스**를 제공합니다.

우리가 웹 브라우저를 이용하거나 메일을 보내는 등의 동작은 모두 Application 계층에서 시작됩니다.

예를 들어 브라우저에서

```plain text
<https://google.com>
```

을 입력하면,

Application 계층에서는

- HTTP 요청 생성

- DNS를 이용한 도메인 조회

- 서버에 어떤 데이터를 요청할지 결정

등의 작업을 수행합니다.

### 대표 프로토콜

- HTTP / HTTPS

- FTP

- SMTP

- DNS

---

## 6. Presentation Layer (표현 계층)

송신자와 수신자가 **같은 형태의 데이터를 이해할 수 있도록 변환**하는 역할을 합니다.

대표적으로

- 문자 인코딩(UTF-8 등)

- 데이터 압축

- 암호화/복호화

를 담당합니다.

예를 들어 HTTPS에서는

TLS를 이용하여 데이터를 암호화한 후 전송하고,

서버에서는 다시 복호화하여 원래 데이터를 읽습니다.

### 대표 기능

- 암호화

- 복호화

- 압축

- 데이터 형식 변환

---

## 5. Session Layer (세션 계층)

통신을 위한 **연결(Session)** 을 생성하고 관리하는 계층입니다.

쉽게 말하면

> "언제 연결을 시작하고, 언제 종료할지"

를 관리합니다.

예를 들어

웹 서버와 일정 시간 동안 **연결을 유지**하거나, 통신이 끊어졌을 때 **다시 연결**하는 등의 역할을 수행합니다.

다만 실제 TCP/IP에서는 별도의 Session 계층이 존재하기보다는 Application 계층에서 함께 구현되는 경우가 많습니다.

---

## 4. Transport Layer (전송 계층)

송신자와 수신자 간에 **데이터를 안전하게 전달**하는 계층입니다.

주요 역할은

- 데이터를 작은 단위로 분할

- 순서 보장

- 오류 검출

- 재전송

- 흐름 제어

- 혼잡 제어

입니다.

대표 프로토콜은

- TCP

- UDP

입니다.

예를 들어

10MB 파일을 한 번에 보내는 것이 아니라,

작은 단위(Segment)로 나누어 전송합니다.

---

## 3. Network Layer (네트워크 계층)

데이터가 **목적지까지 어떤 경로로 이동할지 결정**하는 계층입니다.

인터넷에는 수많은 Router가 존재합니다.

Network 계층은 목적지 IP 주소를 보고 가장 적절한 Router를 선택하여 데이터를 전달합니다.

즉,

**"어디로 갈 것인가?"**

를 담당하는 계층입니다.

대표 프로토콜은

- IP

- ICMP

입니다.

---

## 2. Data Link Layer (데이터 링크 계층)

**같은 네트워크(Local Network) 안에서**

데이터를 **다음 장비까지 정확하게 전달**하는 계층입니다.

IP 주소가 아닌 MAC 주소를 이용하여 통신합니다.

> 🚧 

  - **IP 주소** : 데이터를 **최종 목적지**까지 보내기 위한 **논리적인 주소**

  - **MAC 주소** : 같은 네트워크에서 **바로 다음 장치**를 찾기 위한 **물리적인 주소**

| 구분 | IP 주소 | MAC 주소 |
| --- | --- | --- |
| 계층 | Network Layer (3계층) | Data Link Layer (2계층) |
| 의미 | 최종 목적지 주소 | 바로 다음 장치 주소 |
| 사용 범위 | 인터넷 전체 | 같은 LAN |
| 변경 여부 | 변경 가능 | 거의 변경되지 않음 |
| 사용 장비 | Router | Switch |

<details>
<summary>지선생님</summary>

IP 주소가 **변경 가능**하다고 적힌 이유는, IP 주소가 장치 자체에 영구적으로 박혀 있는 값이 아니라 **현재 연결된 네트워크에서 할당받는 논리 주소**이기 때문입니다.

예를 들어 노트북이:

  - 집 공유기에 연결되면 `192.168.0.10`

  - 카페 와이파이에 연결되면 `192.168.1.25`

  - 회사 네트워크에 연결되면 `10.0.0.15`

처럼 접속한 네트워크에 따라 다른 IP 주소를 받을 수 있습니다. 특히 DHCP를 사용하면 연결할 때마다 IP가 달라질 수도 있습니다.

다만 표의 **MAC 주소 설명은 조금 수정해야 합니다.**

| 구분 | IP 주소 | MAC 주소 |
| --- | --- | --- |
| 주소의 성격 | 네트워크에서 할당되는 논리 주소 | 네트워크 인터페이스의 물리 주소 |
| 장치 자체의 주소 변경 | 네트워크에 따라 변경될 수 있음 | 보통 고정되어 있지만 변경·위조도 가능 |
| 패킷 전달 중 주소 | 보통 출발지부터 목적지까지 유지됨 | **라우터를 지날 때마다 변경됨** |

예를 들어 컴퓨터가 다른 네트워크의 서버로 데이터를 보낼 때:

```plain text
컴퓨터 → 공유기 → 인터넷 라우터 → 서버
```

IP의 목적지 주소는 계속 서버의 IP를 가리킵니다. 반면 MAC 주소는 항상 **바로 다음 장치**를 가리키므로 각 구간에서 새롭게 바뀝니다.

즉, 핵심은 다음과 같습니다.

> **IP는 장치가 네트워크를 옮기면 변경될 수 있고, MAC은 패킷이 이동하는 각 구간마다 헤더에서 변경됩니다.**

따라서 원래 표의 `MAC 주소: 거의 변경되지 않음`은 **장치에 설정된 MAC 자체를 말할 때만 어느 정도 맞고**, 네트워크를 통해 전송되는 프레임의 MAC 주소를 말한다면 오히려 IP보다 자주 변경됩니다.
</details>

예를 들어

내 PC에서 공유기까지, 또는 공유기에서 스위치까지 한 홉(Hop)의 통신을 담당합니다.

대표 기술

- Ethernet

- Wi-Fi

대표 장비

- Switch

## 1. Physical Layer (물리 계층)

실제 데이터를

**0과 1의 전기 신호 또는 광 신호로 변환하여 전송**하는 계층입니다.

이 계층은

데이터의 의미를 전혀 알지 못합니다.

단순히

```plain text
010101101011...
```

이라는 비트를

케이블이나 무선을 통해 전달하는 역할만 수행합니다.

대표 장비

- LAN 케이블

- 광케이블

- 허브

- 리피터

# 실제 웹 통신으로 이해하기

브라우저에서 [https://google.com](https://google.com/)에 접속한다고 가정해 보자.

```plain text
브라우저
   │
   ▼
HTTP 요청 생성
(Application)

   ▼
TLS 암호화
(Presentation)

   ▼
연결 유지
(Session)

   ▼
TCP로 데이터 분할
(Transport)

   ▼
IP로 목적지 결정
(Network)

   ▼
MAC 주소로 다음 장비 전달
(Data Link)

   ▼
전기/무선 신호 전송
(Physical)
```

반대로 서버에서는 아래에서 위로 올라오면서 원래의 HTTP 요청을 복원합니다.

# 데이터는 어떻게 내려갈까?

데이터는 송신 측에서 **위에서 아래로** 내려가며 전송됩니다.

```plain text
Application
      ↓
Presentation
      ↓
Session
      ↓
Transport
      ↓
Network
      ↓
Data Link
      ↓
Physical
```

수신 측에서는 **아래에서 위로** 올라오면서 데이터를 해석합니다.

```plain text
Physical
      ↑
Data Link
      ↑
Network
      ↑
Transport
      ↑
Session
      ↑
Presentation
      ↑
Application
```

이 과정에서

- **송신 측**은 각 계층이 필요한 정보를 붙여가며 내려갑니다.
→ **캡슐화(Encapsulation)**

- **수신 측**은 반대로 붙어 있던 정보를 하나씩 제거하며 올라갑니다.
→ **역캡슐화(Decapsulation)**

---

# 실제로는 OSI를 사용할까?

엄밀히 말하면 **아니라고 보는 것이 맞습니다.**

실제 인터넷은 **TCP/IP 모델**을 기반으로 동작합니다.

다만 OSI 7계층은

- 네트워크를 설명하기 쉽고

- 프로토콜의 역할을 구분하기 쉽고

- 장애가 발생한 위치를 찾기 쉽기 때문에

현재도 교육과 실무에서 가장 많이 사용하는 **참조 모델**입니다.

---

# 면접 답변 예시

> OSI 7계층은 네트워크 통신 과정을 7개의 역할로 나누어 표준화한 참조 모델입니다. 각 계층이 독립적인 역할을 수행하기 때문에 유지보수와 장애 분석이 쉬우며, 서로 다른 시스템도 같은 규칙으로 통신할 수 있습니다. 실제 인터넷은 TCP/IP 모델을 사용하지만, 네트워크 구조와 프로토콜의 역할을 이해하기 위해서는 OSI 7계층이 가장 널리 사용됩니다.

# 예상 꼬리 질문

### Q. 실제 인터넷도 OSI 7계층으로 동작하나요?

아닙니다.

실제 인터넷은 **TCP/IP 모델**을 사용하며, OSI 7계층은 **통신 과정을 설명하기 위한 참조 모델**입니다.

| OSI 7계층 | TCP/IP |
| --- | --- |
| Application | Application |
| Presentation | ↑ 포함 |
| Session | ↑ 포함 |
| Transport | Transport |
| Network | Internet |
| Data Link | Network Access |
| Physical | ↑ 포함 |

---

### Q. OSI 7계층을 배우는 이유는 무엇인가요?

- 각 프로토콜의 역할을 이해하기 쉽고

- 네트워크 문제를 계층별로 분석하기 쉽기 때문입니다.

---

### Q. 모든 계층이 항상 구현되어 있나요?

아닙니다.

예를 들어 **Presentation**과 **Session** 계층은 별도의 계층으로 구현되기보다 **Application 계층에 포함되어 구현되는 경우가 많습니다.**
