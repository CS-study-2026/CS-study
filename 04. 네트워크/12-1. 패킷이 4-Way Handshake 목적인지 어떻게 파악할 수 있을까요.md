# 12-1. 패킷이 4-Way Handshake 목적인지 어떻게 파악할 수 있을까요?

## 1. TCP 헤더의 플래그를 본다

4-Way Handshake를 위한 패킷인지 파악하려면 **TCP 헤더의 플래그 필드**를 봐야 합니다.

TCP 헤더에는 연결 제어를 위한 플래그들이 있습니다.

대표적으로 다음과 같습니다.

```plain text
SYN
ACK
FIN
RST
PSH
URG
```

이 중 연결 종료와 직접 관련 있는 것은 `FIN`, `ACK`, 그리고 강제 종료와 관련된 `RST`입니다.

---

## 2. FIN 플래그

`FIN`은 Finish의 의미로, 송신자가 더 이상 보낼 데이터가 없다는 것을 나타냅니다.

```plain text
FIN = 1
```

이면 다음 의미로 볼 수 있습니다.

```plain text
나는 이 방향으로 더 이상 데이터를 보내지 않겠습니다.
```

따라서 4-Way Handshake의 시작은 보통 `FIN` 플래그가 설정된 TCP 세그먼트로 확인할 수 있습니다.

---

## 3. ACK 플래그

`ACK`는 상대방이 보낸 데이터를 어디까지 정상적으로 받았는지 확인하는 플래그입니다.

4-Way Handshake에서도 `FIN`을 받은 쪽은 `ACK`를 보내 종료 요청을 확인합니다.

```plain text
FIN 수신
→ ACK 전송
```

중요한 점은 `ACK`는 평소 데이터 통신 중에도 계속 사용된다는 것입니다.

따라서 `ACK`만 있다고 해서 종료 과정이라고 판단하면 안 됩니다.

종료 과정인지 보려면 보통 다음 흐름을 함께 봐야 합니다.

```plain text
FIN
→ ACK
→ FIN
→ ACK
```

즉, TCP 플래그와 시퀀스 흐름을 함께 봐야 합니다.

---

## 4. FIN도 시퀀스 번호를 소비한다

TCP에서 `FIN`은 단순한 표시만이 아니라 시퀀스 번호를 하나 소비합니다.

즉, 상대방이 `FIN`을 받으면 그 다음 ACK 번호는 보통 다음처럼 증가합니다.

```plain text
상대가 보낸 FIN의 Sequence Number = x

내가 보내는 ACK Number = x + 1
```

예를 들어 클라이언트가 다음과 같은 FIN을 보냈다고 하겠습니다.

```plain text
Client → Server

FIN = 1
Seq = 100
```

서버는 다음과 같이 ACK할 수 있습니다.

```plain text
Server → Client

ACK = 1
Ack Number = 101
```

이렇게 보면 단순히 플래그만이 아니라, ACK 번호를 통해 상대방의 FIN을 확인했는지도 알 수 있습니다.

---

## 5. 패킷 캡처에서 확인하는 방법

Wireshark 같은 도구로 보면 TCP 종료 과정은 대략 다음과 같이 보입니다.

```plain text
Client → Server  [FIN, ACK]
Server → Client  [ACK]
Server → Client  [FIN, ACK]
Client → Server  [ACK]
```

여기서 `[FIN, ACK]`처럼 보이는 이유는 실제 TCP 연결 중에는 대부분 ACK 플래그도 함께 설정되어 있기 때문입니다.

즉, 종료 요청 세그먼트는 보통 순수한 `[FIN]` 하나만 보이기보다 `[FIN, ACK]` 형태로 보이는 경우가 많습니다.

따라서 패킷이 4-Way Handshake 목적이라고 판단하려면 다음을 확인합니다.

```plain text
1. TCP 헤더에 FIN 플래그가 설정되어 있는가?
2. 상대가 그 FIN에 대한 ACK를 보내는가?
3. 반대 방향에서도 FIN이 오는가?
4. 마지막으로 그 FIN에 대한 ACK가 오는가?
5. ACK 번호가 FIN의 시퀀스 번호 + 1을 가리키는가?
```
