# 15-1. CORS 정책이 무엇인가요?

> CORS(Cross-Origin Resource Sharing)는 SOP 때문에 차단되는 교차 출처 요청을 **서버가 응답 헤더를 통해 특정 출처의 접근을 허용하면, 브라우저가 해당 응답을 JavaScript에서 읽을 수 있도록 하는 메커니즘**입니다.

브라우저는 요청을 보내고, 서버가 `Access-Control-Allow-Origin`과 같은 CORS 헤더를 응답하면 해당 리소스의 접근을 허용합니다.

즉, SOP가 기본 정책이라면 CORS는 필요한 경우 안전하게 예외를 허용하는 방법이라고 볼 수 있습니다.

---

## 1️⃣ CORS란?

### 📌 정의

CORS(Cross-Origin Resource Sharing)는

**다른 출처(Cross-Origin)의 리소스 접근을 서버가 허용할 수 있도록 하는 메커니즘**이다.

SOP를 완전히 없애는 것이 아니라, 
필요한 요청만 예외적으로 허용한다.

---

## 2️⃣ 동작 과정

```plain text
Browser

↓

Cross-Origin 요청

↓

Server

↓

Access-Control-Allow-Origin 응답

↓

Browser가 허용 여부 판단
```

브라우저는 응답 헤더를 확인하여
접근 가능 여부를 결정한다.

---

## 3️⃣ 주요 응답 헤더

| 헤더 | 역할 |
| --- | --- |
| Access-Control-Allow-Origin | 허용할 Origin 지정 |
| Access-Control-Allow-Methods | 허용할 HTTP Method |
| Access-Control-Allow-Headers | 허용할 Header |
| Access-Control-Allow-Credentials | 쿠키, 세션, 인증 정보(credentials) 포함 요청 허용 여부 |

---

## 4️⃣ Spring Boot 예시

```java
@CrossOrigin(origins = "<https://example.com>")
@RestController
public class UserController {

}
```

또는

```java
@Configuration
public class CorsConfig implements WebMvcConfigurer {

    @Override
    public void addCorsMappings(CorsRegistry registry) {
        registry.addMapping("/**")
                .allowedOrigins("<https://example.com>")
                .allowedMethods("*");
    }
}
```

---

## 5️⃣ CORS를 사용할 때 주의할 점

```plain text
Access-Control-Allow-Origin: *
```

은 모든 출처를 허용하므로
민감한 API에서는 사용을 지양해야 한다.

특히
Cookie 기반 인증이나 인증 정보를 포함하는 요청에서는 허용 Origin을 명시적으로 설정하는 것이 안전하다.

또한 `Access-Control-Allow-Origin: *`은 `Access-Control-Allow-Credentials: true`와 함께 사용할 수 없으므로, 인증 정보를 포함하는 요청에서는 허용할 Origin을 명시적으로 지정해야 한다.

---

## 📌 핵심 정리

- CORS는 SOP의 예외를 허용하는 메커니즘이다.

- 서버가 응답 헤더를 통해 허용 여부를 알려준다.

- 브라우저가 헤더를 확인하여 접근 가능 여부를 판단한다.

- 민감한 서비스에서는 Origin을 명시적으로 허용하는 것이 좋다.

## 🎯 예상 꼬리 질문

### Q. CORS는 브라우저가 구현한 기능인가요?

네. 서버는 단순히 헤더를 반환할 뿐이며, 실제로 요청을 차단하거나 허용하는 것은 브라우저입니다.

---

### Q. 서버가 CORS를 설정하지 않으면 어떻게 되나요?

브라우저가 응답을 차단하여 JavaScript에서 데이터를 사용할 수 없습니다.

---

### Q. CORS는 요청 자체를 막나요?

아닙니다.

브라우저는 요청을 서버로 전송합니다.

이후 서버의 응답 헤더를 확인하여 JavaScript가 응답 데이터를 읽을 수 있는지 결정합니다.
