# 6-1. HOL Blocking이란 무엇인가요?

## 1. HOL Blocking의 의미

HOL은 `Head Of Line`의 약자입니다. 🤕

HOL Blocking은 처리해야 할 작업들이 한 줄로 대기하고 있을 때, 가장 앞에 있는 작업이 지연되어 뒤의 작업들까지 함께 진행하지 못하는 현상입니다.

```plain text
작업 A → 작업 B → 작업 C
```

A가 막히면 B와 C도 처리할 수 없는 상태가 됩니다.

```plain text
[A 지연] → [B 대기] → [C 대기]
```

중요한 것은 HOL Blocking이 특정 HTTP 버전에만 존재하는 단일 현상이 아니라는 점입니다.

어느 계층에서 순서를 강제하는지에 따라 형태가 달라집니다.

---

# 7. HTTP/1.1의 HOL Blocking

HTTP/1.1 Pipelining에서는 여러 요청을 먼저 보낼 수 있지만, 응답은 요청 순서대로 전송해야 합니다.

```plain text
요청 순서:

A → B → C
```

서버에서 B와 C가 먼저 처리되었더라도 응답 A가 준비되지 않았다면 먼저 전송하기 어렵습니다.

```plain text
서버 처리 완료 순서:

B → C → A

클라이언트에 보내야 하는 순서:

A → B → C
```

따라서 A가 늦어지면 B와 C도 함께 대기합니다.

이 현상은 HTTP 메시지 처리 순서에서 발생하므로 **애플리케이션 계층의 HOL Blocking**이라고 볼 수 있습니다.

HTTP/1.1에서는 이를 완화하기 위해 여러 TCP 연결을 열어 요청을 분산할 수 있습니다.

```plain text
TCP 연결 1 → 요청 A
TCP 연결 2 → 요청 B
TCP 연결 3 → 요청 C
```

그러나 이 방식은 연결 수와 자원 사용량을 증가시킵니다.

# 8. HTTP/2의 HOL Blocking

HTTP/2는 각 요청과 응답을 별도의 스트림으로 구분합니다.

따라서 Stream 1의 응답이 지연되더라도, Stream 3과 Stream 5의 프레임은 먼저 전달할 수 있습니다.

```plain text
Stream 1 → 느린 응답
Stream 3 → 빠른 응답
Stream 5 → 빠른 응답
```

```plain text
Stream 3 DATA 전송
Stream 5 DATA 전송
Stream 1 DATA는 준비되는 대로 전송
```

이로 인해 HTTP/1.1의 애플리케이션 계층 HOL Blocking은 크게 완화됩니다.

하지만 HTTP/2는 TCP 위에서 동작합니다.

TCP는 애플리케이션에 데이터를 **순서가 보장된 하나의 바이트 스트림**으로 제공합니다.

예를 들어 TCP 패킷이 다음과 같이 전송되었다고 하겠습니다.

```plain text
패킷 1 → 도착
패킷 2 → 유실
패킷 3 → 도착
패킷 4 → 도착
```

패킷 3과 4가 이미 도착했더라도 TCP는 유실된 패킷 2가 재전송될 때까지 이후 데이터를 애플리케이션에 순서대로 전달할 수 없습니다.

```plain text
패킷 2 재전송 대기
→ 패킷 3과 4도 전달 대기
```

HTTP/2의 여러 스트림은 하나의 TCP 연결 안에서 프레임을 공유합니다.

따라서 유실된 패킷이 특정 스트림의 데이터만 포함하고 있더라도, TCP 관점에서는 그 뒤의 모든 바이트 전달이 멈출 수 있습니다.

```plain text
TCP 패킷 유실
→ TCP의 순서 복구 대기
→ 같은 TCP 연결의 HTTP/2 스트림들이 함께 정지
```

이것이 HTTP/2에 남아 있는 **TCP 계층의 HOL Blocking**입니다.

---

# 9. 계층별 HOL Blocking 정리

| 구분 | 발생 원인 | 영향 |
| --- | --- | --- |
| HTTP/1.1 HOL Blocking | 요청 순서대로 응답해야 함 | 앞 응답이 늦으면 뒤 응답도 대기 |
| HTTP/2의 TCP HOL Blocking | TCP가 바이트를 순서대로 전달 | 패킷 하나가 유실되면 모든 스트림이 잠시 정지 |
| HTTP/3 | QUIC의 독립 스트림 사용 | 유실된 패킷과 관련된 스트림 위주로 대기 |

HTTP/2는 HOL Blocking을 완전히 해결한 것이 아닙니다.

정확한 표현은 다음과 같습니다.

> HTTP/2는 HTTP/1.1의 애플리케이션 계층 HOL Blocking을 해결했지만, TCP의 순서 보장으로 발생하는 전송 계층 HOL Blocking은 해결하지 못했습니다.
