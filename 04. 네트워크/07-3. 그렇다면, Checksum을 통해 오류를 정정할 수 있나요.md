# 7-3. 그렇다면, Checksum을 통해 오류를 정정할 수 있나요?

## 결론

> **아니요. Checksum은 오류를 '검출'만 할 수 있고, '정정'은 할 수 없습니다.**

---

## 왜 정정할 수 없을까?

Checksum은 데이터 전체를 하나의 작은 값으로 요약한 정보입니다.

예를 들어

```plain text
원본 데이터

Hello

↓

Checksum = 1234
```

전송 중

```plain text
Hella
```

로 바뀌었다면

수신자는

```plain text
Checksum이 다르다.
```

는 사실만 알 수 있습니다.

하지만

- 어느 비트가 잘못되었는지

- 어떻게 원래 데이터로 복원해야 하는지

는 알 수 없습니다.

즉,

```plain text
오류 발생

↓

손상 여부는 확인 가능

↓

원래 데이터는 알 수 없음
```

---

## 그렇다면 TCP는 어떻게 신뢰성을 보장할까?

TCP는 Checksum으로 오류를 검출한 후 **재전송 메커니즘**을 이용합니다.

```plain text
송신

Segment 전송
      │
      ▼
수신

Checksum 검증

오류 발견

↓

세그먼트 폐기

↓

ACK를 보내지 않거나

재전송 요청

↓

송신자가 다시 전송
```

즉,

- Checksum → 오류 검출

- TCP → 재전송을 통해 오류 복구

라는 역할 분담을 합니다.

---

## 오류 정정과 오류 검출의 차이

| 구분 | Checksum |
| --- | --- |
| 오류 검출 | O |
| 오류 위치 확인 | X |
| 오류 수정 | X |

참고로, **ECC(Error Correcting Code)** 와 같은 기술은 일부 오류를 직접 수정할 수 있지만, 이는 TCP Checksum과는 다른 기술입니다.

---

## ECC는 뭔데요?

> **데이터에 추가 정보를 함께 저장하여, 오류를 검출할 뿐만 아니라 일부 오류는 직접 수정할 수 있는 기술**

즉,

- Checksum → 오류를 발견만 한다.

- ECC → 오류를 발견하고 직접 고친다.

---

### 왜 가능한가?

```plain text
데이터

+

오류 수정용 비트(Parity Bit 등)
```

를 함께 저장합니다.

즉

```plain text
10110010

↓

10110010 + ECC 정보
```

처럼 **복원에 필요한 정보를 추가로 저장**합니다.

---

### 예시

원래 데이터

```plain text
1011
```

ECC 정보를 함께 저장하면

```plain text
1011 + ECC
```

가 됩니다.

전송 중

```plain text
1001
```

로 바뀌었다면

ECC 정보를 이용해서

```plain text
3번째 비트가 틀렸구나.

↓

1011
```

처럼 **원래 데이터를 복원할 수 있습니다.**

---

### RAM에서 많이 사용된다

ECC가 가장 많이 사용되는 곳은 **서버용 RAM(ECC Memory)** 입니다.

예를 들어

```plain text
RAM

01010101
```

이

```plain text
01011101
```

로 바뀌더라도

ECC가 있다면

```plain text
비트 하나가 뒤집혔네.

↓

자동 수정
```

을 수행할 수 있습니다.

그래서

- 금융 서버

- 클라우드 서버

- 데이터센터

에서는 ECC RAM을 많이 사용합니다.

---

# Checksum과 ECC의 차이

| 항목 | Checksum | ECC |
| --- | --- | --- |
| 오류 검출 | O | O |
| 오류 수정 | X | O(일부) |
| 추가 정보 저장 | Checksum 값 | 오류 수정 코드 |
| 사용 예 | TCP, UDP | ECC RAM, SSD, 저장장치 |

---

### 그렇다면 TCP는 왜 ECC를 안 쓸까?

가장 큰 이유는 **효율성**입니다.

네트워크에서는

- 수많은 패킷이 실시간으로 오가고,

- 오류 발생 빈도가 비교적 낮습니다.

따라서

```plain text
오류가 거의 안 난다.

↓

오류가 나면

↓

다시 보내는 것이

↓

ECC를 항상 붙여 보내는 것보다 훨씬 효율적
```

입니다.

즉,

TCP는

> **오류를 수정하는 것보다 재전송하는 것이 더 경제적이라고 판단한 것입니다.**

반면 메모리는 상황이 다릅니다.

RAM 안의 데이터는 다시 받을 곳이 없기 때문에

```plain text
오류 발생

↓

직접 고쳐야 함
```

그래서 ECC를 사용합니다.

# **비유로 먼저 이해해보자**

체크섬은 시험을 보고

**“총점이 90점입니다.”**

만 적어놓은 것과 비슷하다.

학생이 시험지를 잃어버리면

  - 총점이 틀렸는지는 알 수 있지만

  - **어느 문제를 틀렸는지는 알 수 없다.**

---

ECC는

**각 문제별 정답 체크표**

를 함께 가지고 있는 것과 비슷하다.

그래서

```plain text
3번 문제가 틀렸네.
```

를 알아낼 수 있다.

---

# **실제로는 무엇을 저장할까?**

대표적인 ECC는 **해밍 코드(Hamming Code)** 를 사용한다.

예를 들어

원본 데이터가

```plain text
1011
```

이라고 하자.

ECC는 여기에

```plain text
P1
P2
P3
```

같은 **패리티 비트(Parity Bit)** 를 추가한다.

즉

```plain text
원본

1 0 1 1

↓

ECC 적용

P1 P2 1 P3 0 1 1
```

처럼 저장된다.

---

# **패리티 비트는 무엇일까?**

패리티 비트는

**특정 위치의 비트들이 짝수 개인지 홀수 개인지 기록하는 비트**

이다.

예를 들어

```plain text
1011
```

에는

```plain text
1의 개수

=3개
```

이다.

ECC는

```plain text
첫 번째 그룹

짝수인가?

두 번째 그룹

짝수인가?

세 번째 그룹

짝수인가?
```

를 각각 저장한다.

즉

```plain text
P1

"1,3,5,7번째 비트 검사"

P2

"2,3,6,7번째 비트 검사"

P3

"4,5,6,7번째 비트 검사"
```

처럼 **여러 개의 검사 그룹**을 만든다.

---

# **왜 이걸로 위치를 찾을 수 있을까?**

예를 들어

원래

```plain text
1011
```

이

```plain text
1001
```

로 바뀌었다고 하자.

수신자는

패리티를 다시 계산한다.

그러면

```plain text
P1

정상

P2

오류

P3

정상
```

처럼 나온다.

이 조합을 보면

```plain text
010

↓

2번째 데이터 비트 오류
```

처럼 **어느 비트가 잘못됐는지 위치를 역으로 계산**할 수 있다.

그 후

```plain text
0

↓

1
```

로 뒤집으면

원래 데이터가 복원된다.

---

# **그림으로 보면**

```plain text
원본

1 0 1 1

↓

ECC 저장

P1 P2 1 P3 0 1 1

↓

전송

↓

P2 검사 실패
P3 검사 성공
P1 검사 성공

↓

"5번째 비트가 틀렸네"

↓

뒤집기

↓

복원 완료
```

---

# **그럼 모든 오류를 고칠 수 있을까?**

아니다.

가장 많이 쓰이는 **SECDED(Single Error Correction, Double Error Detection)** ECC는

  - **1비트 오류 → 수정 가능**

  - **2비트 오류 → 검출만 가능**

  - **3비트 이상 → 경우에 따라 검출이나 수정이 어려울 수 있음**

즉, ECC도 **무한히 강력한 것은 아니다.**

---

# **왜 TCP는 이런 걸 안 쓰는 걸까?**

TCP 세그먼트 하나가 수천 바이트인데, 모든 세그먼트마다 ECC 정보를 붙이면

  - 헤더가 커지고

  - 계산량이 늘고

  - 네트워크 대역폭도 더 사용하게 된다.

반면 네트워크에서는

```plain text
오류 발생

↓

패킷 하나만 다시 보내면 끝
```

이므로 훨씬 효율적이다.

그래서 TCP는

**“오류 위치를 찾는 ECC” 대신 “오류를 발견하는 Checksum + 재전송”** 방식을 선택한 것이다.

---

## **면접에서는 이 정도만 기억하면 충분하다.**

**ECC는 패리티 비트와 같은 중복 정보를 함께 저장하여, 어느 비트에서 오류가 발생했는지 계산할 수 있습니다. 따라서 단순히 오류를 검출하는 Checksum과 달리, 일부 비트 오류는 직접 수정할 수 있습니다. 대표적으로 서버용 ECC 메모리는 1비트 오류를 자동으로 수정하고, 2비트 오류는 검출할 수 있습니다.**

---

## 면접 답변

> 아닙니다. Checksum은 데이터가 손상되었는지를 확인하는 오류 검출 기술일 뿐, 손상된 데이터를 원래대로 복원하거나 수정할 수는 없습니다. TCP는 Checksum으로 오류를 검출한 뒤 재전송 메커니즘을 이용해 올바른 데이터를 다시 받아 신뢰성을 보장합니다.
