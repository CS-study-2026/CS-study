# 7-0. TCP와 UDP의 차이에 대해 설명해 주세요.

# **1. TCP (Transmission Control Protocol)**

1. TCP란?

> Note 데이터가 목적지에** 정확하고 온전하게 도착**하는 것을 최우선으로 하는 프로토콜

1. 3-Way Handshake 방식

> Note 연결 지향형으로 통신을 시작하기 전에 송신자와 수신자 간에 논리적인 연결을 먼저 맺습니다.

1. 특징

> Note 

  - 전송 중 데이터가 유실되거나 손상되면 다시 전송을 요청하여 데이터를 완벽하게 복구합니다.

  - 데이터를 꼼꼼하게 확인하고 연결을 유지하는 과정이 필요하므로 UDP에 비해 상대적으로 처리 속도가 느립니다.

  - 패킷(데이터 조각)이 여러 경로를 통해 도착하더라도 원래 보낸 순서대로 재조립하여 순서를 보장합니다.

1. 주요 사용처 

> Note 데이터의 정확성이 필수적인 서비스 (웹 브라우징, 이메일, 파일 전송 등)

---

# 2. UDP (User Datagram Protocol)

1. UDP란?

> Note 데이터의 정확성이나 순서보다는 **전송 속도**에 초점을 맞춘 프로토콜

1. 비연결형

> Note 사전 연결 작업 없이, 일방적으로 목적지를 향해 데이터를 던지듯이 전송합니다.

1. 특징 

> Note 

  - 전송 과정에서 데이터가 유실되거나 순서가 뒤바뀌어도 재전송을 요구하거나 순서를 맞추지 않으므로 낮은 신뢰성을 가집니다.

  - 데이터 확인이나 연결 유지 과정이 생략되므로 네트워크 부하가 적고 속도가 매우 빠릅니다.

1. 주요 사용처 

> Note 약간의 데이터 손실이 발생하더라도 끊김 없는 실시간 전송이 중요한 서비스 (실시간 동영상 스트리밍, 온라인 게임, 인터넷 전화 등)

# 3. 정리

1. 만약 TCP와 UDP의 차이를 물어본다면?

> Note **TCP와 UDP는 인터넷 환경에서 데이터를 주고받을 때 사용하는 전송 계층의 대표적인 두 가지 프로토콜입니다.**

**TCP는 3-Way Handshake 방식으로 사전 통신 후, 데이터 전송을 진행합니다. 특징으로는 데이터가 유실 및 손상이 된다면 다시 전송 요청을 통해 데이터를 완벽히 복구하므로 높은 신뢰성을 가집니다. 또한 패킷이 여러 경로를 통해 도착하더라도 원래 보낸 순서대로 재조립합니다. 다만 이러한 성질 때문에 속도가 느리다는 단점이 있습니다.**

**UDP는 비연결형 방식으로 사전 연결 없이 목적지를 향해 데이터를 던지듯 전송합니다. 이 과정에서 데이터가 유실되어도 재전송을 요구하지 않고, 순서가 뒤바뀌어도 순서를 맞추지 않습니다. 따라서 TCP와는 반대로 속도 중심의 전달 방법입니다.**

1. 비교 요약

| **구분** | **TCP** | **UDP** |
| --- | --- | --- |
| 통신 방식 | 연결 지향형 | 비연결형 |
| 신뢰성 | 높음 (데이터 유실 시 재전송) | 낮음 (데이터 유실 무시) |
| 전송 속도 | 상대적으로 느림 | 매우 빠름 |
| 데이터 순서 | 완벽하게 보장함 | 보장하지 않음 |
| 헤더 크기 | 상대적으로 큼 (최소 20 바이트) | 작음 (8 바이트 고정) |
| 적합한 서비스 | 파일 다운로드, 웹(HTTP), 이메일 | 스트리밍 영상, VoIP, 온라인 게임 |
