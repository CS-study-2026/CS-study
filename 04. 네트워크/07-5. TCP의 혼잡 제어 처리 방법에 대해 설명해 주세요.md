# 7-5. TCP의 혼잡 제어 처리 방법에 대해 설명해 주세요.

# 1. 혼잡 제어(Congestion Control)

1. 혼잡 제어란?

> Note 혼잡 제어는 수신자의 상태가 아니라, 데이터를 전달하는 **인터넷망 전체(라우터 등)의 트래픽 상태**를 파악하여 송신자가 전송량을 조절하는 메커니즘입니다.

1. 목적

> Note 혼잡 제어를 통해 네트워크 붕괴(Congestion Collapse) 현상을 예방할 수 있습니다.

---

# 2. 주요 알고리즘 4가지

1. 느린 시작(Slow Start)

  - 작동 방식

> Note 통신을 처음 시작할 때는 혼잡 윈도우 크기를 1로 설정하여 조심스럽게 데이터를 보냅니다.

하지만 수신자로부터 정상적으로 응답(ACK)을 받을 때마다 **전송량을 2배씩 매우 빠르게 증가**시킵니다.

  - 목적

> Note 이름은 '느린 시작'이지만, 초기 전송 속도를 최대한 빠르게 끌어올리기 위한 방법입니다.

특정 임계점(ssthresh)에 도달할 때까지 이 방식을 유지합니다.

1. 혼잡 회피(Congestion Avoidance) / AIMD(Additive Increase Multiplicative Decrease)

  - 증가 방식(합산 증가, Additive Increase)

> Note 혼잡 윈도우 크기가 임계점(ssthresh)을 넘어서면, 네트워크가 슬슬 혼잡해질 수 있다고 판단하여 전송량을 2배씩 늘리지 않고 **1씩(선형적으로) 조심스럽게 증가**시킵니다.

  - 감소 방식(곱산 감소, Multiplicative Decrease)

> Note 만약 데이터 유실이 발생하면 네트워크가 혼잡해졌다고 판단하고 전송량을 절반으로 뚝 떨어뜨립니다.

1. 빠른 재전송(Fast Retransmit)

  - 작동 방식

> Note 흐름 제어의 재전송 메커니즘과 같습니다.

수신자로부터 '중복 ACK'를 연속 3번 받게 되면, 타이머가 끝나기 전이라도 패킷이 유실(네트워크 혼잡)되었다고 판단합니다.

  - 효과

> Note 즉시 패킷을 재전송함과 동시에, 혼잡 제어 알고리즘에게 "네트워크가 막히기 시작했으니 전송량을 조절하라"는 신호를 보냅니다.

1. 빠른 회복 (Fast Recovery)

  - 작동 방식

> Note 중복 ACK 3번에 의해 혼잡이 감지되었을 때 사용하는 방법입니다.

혼잡 윈도우 크기를 초기 상태인 1로 완전히 초기화하지 않고, **현재 전송량의 절반으로만 줄인 뒤 그 지점부터 다시 1씩 선형적으로 증가**시킵니다.

  - 효과

> Note 잠깐의 데이터 유실로 인해 통신 속도가 바닥으로 곤두박질치는 것을 막고 안정적인 속도를 유지할 수 있게 해줍니다.

단, 타임아웃으로 인한 심각한 유실이 발생하면 윈도우 크기를 1로 초기화하고 '느린 시작'부터 다시 단계를 밟습니다.

# 3. 임계점(ssthresh, Slow Start Threshold)

1. 임계점이란?

> Note TCP가 과거의 경험(데이터 유실)을 바탕으로 설정한 현재 네트워크의 안전 전송 한계선.

1. 임계점이 변하는 경우

> Note 네트워크에 혼잡이 감지되어 전송량을 조절해야 하는 시점에 변경됩니다.

3연속 중복 ACK가 발생했을 때는 빠른 회복으로 진입, 타임아웃(Timeout)이 발생했을 때는 느린 시작으로 복귀합니다.

1. 어떻게 바뀌는가?

> Note 비상 상황이 터지면 TCP는 "현재 보내고 있던 전송량(혼잡 윈도우 크기, cwnd)의 절반"을 새로운 임계점으로 지정합니다.

단, 최소한의 전송은 유지해야 하므로 아무리 떨어져도 2보다는 작아지지 않도록 하한선이 있습니다.
