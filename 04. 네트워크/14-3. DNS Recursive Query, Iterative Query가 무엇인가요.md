# 14-3. DNS Recursive Query, Iterative Query가 무엇인가요?

# **DNS Recursive Query와 Iterative Query**

## **먼저 DNS 조회 과정을 이해해보자.**

사용자가

```plain text
www.google.com
```

을 입력하면,

내 컴퓨터는 IP 주소를 모르기 때문에 **Local DNS Resolver**(통신사 DNS, Google DNS 등)에게 물어본다.

그런데 Local DNS도 모를 수도 있다.

이때 누가 끝까지 찾아오는지에 따라

- **Recursive Query**

- **Iterative Query**

가 나뉜다.

---

# **1. Recursive Query (재귀 질의)**

**질문을 받은 DNS 서버가 최종 IP 주소를 찾을 때까지 모든 과정을 대신 수행하여 결과만 반환하는 방식이다.**

즉,

클라이언트는

```plain text
"IP만 알려줘."
```

라고 요청하고,

중간 과정은 전혀 신경 쓰지 않는다.

```plain text
Client
    │
    │ google.com IP 알려줘
    ▼
Local DNS
    │
    ├─ Root DNS
    ├─ .com DNS
    ├─ Google DNS
    ▼
최종 IP 획득
    │
    ▼
Client
```

클라이언트는 한 번만 요청하면 된다.

### **특징**

- 클라이언트는 DNS 서버만 믿고 기다린다.

- Local DNS가 끝까지 책임지고 조회한다.

- 우리가 일반적으로 사용하는 방식이다.

---

# **2. Iterative Query (반복 질의)**

**질문을 받은 DNS 서버가 정답을 모르면, 다음에 물어봐야 할 DNS 서버의 정보를 알려주는 방식이다.**

예를 들어

Root DNS는

```plain text
"나는 google.com IP는 모르지만
.com DNS에게 물어봐."
```

라고 답한다.

그 다음

.com DNS는

```plain text
"Google 권한 DNS에게 물어봐."
```

라고 답한다.

```plain text
Local DNS
     │
     ▼
Root DNS
     │
     └── ".com DNS에게 물어봐"

          ▼

.com DNS
     │
     └── "Google DNS에게 물어봐"

          ▼

Google Authoritative DNS
     │
     ▼
최종 IP 반환
```

즉,

각 DNS 서버는

**“나는 모르지만 다음 서버는 알아.”**

라는 식으로 안내만 해준다.

---

# **실제 인터넷에서는 어떻게 사용할까?**

실제로는 **두 방식이 함께 사용된다.**

```plain text
사용자
    │
    │ Recursive Query
    ▼
Local DNS Resolver
    │
    │ Iterative Query
    ▼
Root DNS
    │
    ▼
.com DNS
    │
    ▼
Authoritative DNS
    │
    ▼
IP 획득
    │
    ▼
사용자
```

즉,

### **사용자 ↔ Local DNS**

→ **Recursive Query**

### **Local DNS ↔ Root / TLD / Authoritative DNS**

→ **Iterative Query**

이것이 실제 DNS 동작 방식이다.

---

# **왜 이렇게 설계했을까?**

만약 Root DNS까지 Recursive Query를 수행한다면,

Root DNS가 전 세계 모든 요청을 끝까지 처리해야 하므로 부하가 매우 커진다.

따라서

- Local DNS가 사용자를 대신해 조회를 수행하고,

- Root DNS와 TLD DNS는 **다음 DNS 서버를 알려주는 역할만** 담당한다.

이렇게 역할을 분리해 DNS 시스템의 확장성과 효율성을 높였다.

---

# **한눈에 비교**

| **구분** | **Recursive Query** | **Iterative Query** |
| --- | --- | --- |
| 의미 | DNS 서버가 최종 결과를 찾아 반환 | 다음에 질의할 DNS 서버를 알려줌 |
| 누가 끝까지 조회? | 질의를 받은 DNS 서버 | 질의하는 측(Local DNS) |
| 클라이언트 요청 횟수 | 1번 | 여러 번(각 DNS 서버에 반복 질의) |
| 실제 사용 | 사용자 → Local DNS | Local DNS → Root/TLD/Authoritative DNS |

---

# **기억법**

```plain text
Recursive
= "끝까지 대신 찾아줘."

Iterative
= "다음에 어디 물어볼지 알려줘."
```

---

# **면접 답변**

**Recursive Query는 질의를 받은 DNS 서버가 최종 IP 주소를 찾을 때까지 모든 조회를 대신 수행한 후 결과를 반환하는 방식입니다. 반면 Iterative Query는 DNS 서버가 정답을 모를 경우, 다음에 질의해야 할 DNS 서버의 정보를 반환하는 방식입니다. 실제 DNS에서는 사용자가 Local DNS Resolver에 Recursive Query를 보내고, Local DNS Resolver가 Root DNS, TLD DNS, Authoritative DNS에는 Iterative Query를 수행하여 최종 IP 주소를 조회합니다.**
