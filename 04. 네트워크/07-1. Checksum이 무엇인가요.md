# 7-1. Checksum이 무엇인가요?

## 한 줄 정의

> **Checksum은 데이터가 전송되거나 저장되는 과정에서 손상되었는지 확인하기 위한 오류 검출(Error Detection) 값입니다.**

송신자가 데이터로부터 Checksum을 계산하여 함께 전송하고, 수신자가 동일한 방식으로 다시 계산하여 두 값을 비교합니다.

- 값이 같으면 → 정상 데이터

- 값이 다르면 → 데이터가 손상된 것으로 판단

---

## 왜 필요한가?

데이터는 다음과 같은 이유로 전송 중 또는 저장 과정에서 변형될 수 있습니다.

<details>
<summary>네트워크 노이즈</summary>

> **데이터가 네트워크를 지나가는 동안 전기적·전자기적 간섭으로 일부 비트가 바뀌는 현상**

### **왜 발생할까?**

  - 번개

  - 전자기파

  - 케이블 손상

  - 주변 전자기기의 간섭

과거 구리선(Ethernet)에서는 이런 문제가 더 자주 발생했고, 광케이블에서는 훨씬 적지만 완전히 없어지지는 않는다.
</details>

<details>
<summary>하드웨어 오류</summary>

> **네트워크 장비나 컴퓨터의 물리적인 장치가 오작동하는 경우**

  - 랜카드(NIC)

  - 스위치

  - 공유기

  - CPU

  - 메인보드
</details>

<details>
<summary>메모리 오류</summary>

> **RAM에 데이터를 저장하거나 읽는 과정에서 비트가 바뀌는 현상**

**한 비트가 뒤집히는(Bit Flip)** 경우가 있다.

원인으로는

  - RAM 불량

  - 과열

  - 전압 문제

  - 우주 방사선(Cosmic Ray)
</details>

<details>
<summary>저장 장치 오류</summary>

> **HDD나 SSD에 데이터를 저장하거나 읽을 때 데이터가 손상되는 경우**

  - HDD 배드섹터(Bad Sector)

  - SSD 셀 손상

  - 저장 장치 노후화

  - 갑작스러운 전원 차단
</details>

이러한 오류를 검출하기 위해 Checksum을 사용합니다.

---

## 동작 과정

```javascript
송신자

데이터
   │
   ▼
Checksum 계산
   │
   ▼
[데이터 + Checksum]
        │
        ▼
====================
    네트워크 전송
====================
        │
        ▼
수신자

Checksum 재계산
   │
   ▼
비교

같음 → 정상
다름 → 오류 발생
```

---

## **TCP Checksum은 어떻게 계산할까?**

TCP는 **16비트 1의 보수 합(16-bit One’s Complement Sum)** 이라는 알고리즘을 사용한다.

1. 데이터를 **16비트(2바이트)** 씩 나눈다.

1. 모두 더한다.

1. 오버플로우가 발생하면 다시 더한다.

1. 마지막 결과를 **1의 보수(모든 비트 반전)** 로 바꾼다.

1. 이것이 Checksum이다.

---

## **간단한 예시**

데이터가 있다고 해보자.

```plain text
0000000000000011   (3)
0000000000000101   (5)
```

### **① 더하기**

```plain text
3 + 5 = 8

0000000000001000
```

### **② 1의 보수**

```plain text
0000000000001000

↓

1111111111110111
```

이 값이 Checksum이 된다.

실제 TCP는 훨씬 긴 데이터를 대상으로 같은 방식으로 계산한다.

---

## **수신자는 어떻게 검사할까?**

송신자가

```plain text
데이터
+
Checksum
```

을 보낸다.

수신자는

```plain text
받은 데이터

↓

같은 알고리즘으로 다시 계산

↓

Checksum과 비교
```

한다.

같으면

```plain text
정상
```

다르면

```plain text
데이터 손상
```

으로 판단한다.

---

### **왜 하필 ‘1의 보수’를 사용할까?**

1의 보수 덧셈은

- 계산이 매우 빠르고

- CPU에서 구현하기 쉽고

- 대부분의 단일 비트 오류와 많은 다중 비트 오류를 검출할 수 있기 때문이다.

TCP가 처음 설계되던 시절에는 CPU 성능이 지금보다 훨씬 낮았기 때문에, **빠르게 계산할 수 있는 알고리즘**이 중요했다.

---

## 면접 답변

> Checksum은 데이터가 전송되거나 저장되는 과정에서 손상 여부를 확인하기 위한 오류 검출 값입니다. 송신자가 데이터를 이용해 Checksum을 계산하여 함께 전송하고, 수신자는 동일한 방식으로 다시 계산해 두 값을 비교합니다. 값이 다르면 데이터가 손상된 것으로 판단합니다. TCP에서는 16비트 One's Complement Sum 알고리즘으로 Checksum을 계산합니다.
