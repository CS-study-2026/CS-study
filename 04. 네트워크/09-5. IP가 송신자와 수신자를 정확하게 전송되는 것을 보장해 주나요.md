# 9-5. IP가 송신자와 수신자를 정확하게 전송되는 것을 보장해 주나요?

# 0. 결론

IP(Internet Protocol)는 송신자와 수신자를 식별하고 데이터를 목적지까지 전달하려고 할 뿐,

정확한 전송을 보장하지는 X

---

# 1. IP가 하는 일

IP는 인터넷 계층의 핵심 프로토콜로, 데이터를 패킷으로 분할하고 이를 수신자에게 전달하는 역할

그러나 IP는 비연결형 프로토콜이며, 패킷의 순서 보장, 무결성 검증, 재전송 등을 직접 처리하지 X !

### IP가 하는 일

- 송신자(Source IP)와 수신자(Destination IP) 식별

- 목적지까지 데이터를 전달할 경로를 선택(라우팅)

- 데이터를 패킷 단위로 전송

### IP가 보장하지 않는 것

IP는 **Best-Effort(최선형 서비스)** 방식으로 동작하기 때문에

- 패킷이 반드시 도착하는지

- 패킷이 순서대로 도착하는지

- 패킷이 중간에 손상되지 않았는지

- 중복 전송되지 않았는지

위를 보장하지 X!

즉, IP는 **"최선을 다해 보내지만, 성공 여부는 책임지지 않는다."**

---

# 2. 그럼 누가 보장하나요 ? : TCP

TCP(Transmission Control Protocol)는

- 수신 확인(ACK)

- 오류 검사

- 재전송

- 순서 보장

- 흐름 제어

- 혼잡 제어

등의 기능을 통해 **데이터가 정확하고 순서대로 도착하도록 보장**

### 쉽게 비유하면

- **IP = 택배 기사**

  - 주소를 보고 목적지까지 배송

  - 하지만 택배가 분실되거나 순서가 바뀌는 것까지 책임지지는 X

- **TCP = 배송 확인 시스템**

  - 물건이 제대로 도착했는지 확인

  - 안 왔으면 재전송

  - 여러 개를 보냈다면 순서대로 정리해서 전달

### 정리

- **IP**: 송신자와 수신자를 식별하고 목적지까지 **전달**

- **TCP**: 데이터가 **정확하고 순서대로 도착하도록** 보장

> IP는 송신자와 수신자를 식별하여 데이터를 목적지까지 전달하며, 정확한 전송은 TCP가 보장

---

# 3. 체크섬이란?

→ TCP와 UDP 모두 사용하는 **오류 검출(Error Detection)** 기법이지만,

**체크섬 자체는 오류를 검출만 하고 수정은 하지 못함**

---

# 4. TCP와 UDP 모두 체크섬을 사용하는데, 차이는?

**TCP**

- 체크섬 오류 발생

- 세그먼트 폐기

- ACK가 오지 않음

- 재전송

**UDP**

- 체크섬 오류 발생

- 데이터그램 폐기(재전송 없음)

즉,

> **체크섬은 둘 다 사용하지만, TCP는 재전송을 통해 복구하고 UDP는 복구하지 않는다.**
