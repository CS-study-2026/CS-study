# 14-5. 캐싱된 DNS 쿼리가 잘못 될 수도 있습니다. 이 경우, 어떻게 에러를 보정할 수 있나요?

DNS는 조회 속도를 높이기 위해 **DNS Cache**를 사용한다.

하지만 서버의 IP 주소가 변경되면 캐시에 저장된 정보가 오래되어(Stale Cache) 잘못된 IP를 반환할 수 있다.

이를 방지하기 위해 DNS는 **TTL(Time To Live)**을 사용하여 캐시를 자동으로 갱신한다.

---

# **왜 문제가 발생할까?**

예를 들어

처음에는

```plain text
www.example.com

↓

1.1.1.1
```

이었다.

Local DNS가 이를 캐시에 저장한다.

```plain text
Local DNS Cache

www.example.com

↓

1.1.1.1
```

그런데 서버 이전으로 인해

```plain text
www.example.com

↓

2.2.2.2
```

로 변경되었다.

하지만 캐시는 아직

```plain text
1.1.1.1
```

을 가지고 있다.

그러면

```plain text
사용자

↓

Local DNS

↓

1.1.1.1
```

을 반환하게 되어 잘못된 서버로 접속하게 된다.

---

# **해결 방법 ① TTL(Time To Live)**

가장 중요한 방법이다.

DNS 레코드에는

```plain text
TTL = 300초
```

같은 값이 함께 저장된다.

의미는

**“이 캐시는 300초 동안만 믿어라.”**

이다.

```plain text
Authoritative DNS

www.example.com

↓

2.2.2.2

TTL = 300
```

Local DNS는

```plain text
300초
```

동안만 캐시에 저장한다.

시간이 지나면

```plain text
Cache 삭제

↓

다시 Authoritative DNS 조회
```

한다.

즉

TTL 덕분에 오래된 캐시가 자동으로 제거된다.

---

# **해결 방법 ② 캐시 무효화(Cache Flush)**

운영자가 직접 캐시를 삭제할 수도 있다.

예를 들어

Windows

```bash
ipconfig /flushdns
```

macOS

```bash
sudo dscacheutil -flushcache
```

브라우저도 자체 DNS Cache를 비울 수 있다.

---

# **해결 방법 ③ TTL을 짧게 설정**

서비스 이전이 예정되어 있다면

기존

```plain text
TTL

86400초
```

를

```plain text
300초
```

처럼 줄여 둔다.

그러면

IP 변경 후

금방 새로운 IP가 반영된다.

실제로 서버 이전(Migration) 시 자주 사용하는 방법이다.

---

# **해결 방법 ④ 다시 Authoritative DNS 조회**

TTL이 만료되면

Local DNS는

```plain text
Root

↓

TLD

↓

Authoritative DNS
```

를 다시 조회한다.

최신 IP를 받아

캐시를 갱신한다.

```plain text
오래된 Cache

↓

TTL 만료

↓

Authoritative DNS 조회

↓

새 Cache 생성
```

---

# **DNS Cache의 장점과 단점**

| **장점** | **단점** |
| --- | --- |
| 조회 속도가 빠름 | 오래된 정보가 남을 수 있음 |
| DNS 서버 부하 감소 | 서버 변경이 즉시 반영되지 않을 수 있음 |
| 네트워크 트래픽 감소 | TTL 동안은 이전 IP를 사용할 수 있음 |

---

# **한눈에 보기**

```plain text
Client
   │
   ▼
Local DNS Cache
   │
   ├── TTL 남아 있음
   │       │
   │       ▼
   │   캐시 사용
   │
   └── TTL 만료
           │
           ▼
Authoritative DNS 조회
           │
           ▼
최신 IP 획득
           │
           ▼
Cache 갱신
```

---

# **면접 답변**

**DNS는 조회 성능을 높이기 위해 캐시를 사용하지만, 서버의 IP 주소가 변경되면 오래된 캐시(Stale Cache)로 인해 잘못된 IP를 반환할 수 있습니다. 이를 방지하기 위해 DNS 레코드에는 TTL(Time To Live)이 설정되어 있으며, TTL이 만료되면 캐시를 삭제하고 Authoritative DNS에 다시 질의하여 최신 정보를 가져옵니다. 또한 필요하면 운영자가 DNS 캐시를 직접 비우거나, 서비스 이전 시 TTL을 미리 짧게 설정하여 변경 사항이 빠르게 반영되도록 할 수 있습니다.**

### **면접에서 추가 질문으로 자주 나오는 것**

**Q. TTL을 무조건 짧게 설정하면 더 좋은 것 아닌가요?**

아니다. TTL이 너무 짧으면 캐시가 자주 만료되어 Local DNS가 Authoritative DNS를 더 자주 조회하게 된다. 그 결과 조회 지연이 늘어나고 DNS 서버의 부하도 증가한다. 따라서 **변경이 거의 없는 서비스는 TTL을 길게**, 서버 이전 등 변경이 예정된 경우에는 **일시적으로 TTL을 짧게** 설정하는 것이 일반적인 운영 방식이다.
