- 이번 주제의 핵심은 **전송 계층(L4)**의 대표적인 프로토콜인 `TCP(Transmission Control Protocol)`의 작동 방식

- TCP의 가장 큰 목적은 신뢰성 없는 네트워크 환경에서 **신뢰성 있는 연결**을 만드는 것

## 11. 3-Way Handshake에 대해 설명해 주세요.

> 💡 

### 개념 정의

3-Way Handshake는 TCP 통신을 시작하기 전, 송신측(클라이언트)과 수신측(서버)이 서로가 데이터를 주고받을 준비가 되었는지 확인하고, 가상의 **논리적 통신 채널을 개설**하는 3단계 과정.

이 과정의 본질은 양쪽 컴퓨터가 앞으로 보낼 데이터 조각들의 일련번호인 `시퀀스 번호(Sequence Number)`의 **기준점을 동기화**하고, 운영체제(OS) 내부적으로 데이터를 저장할 메모리 공간인 `버퍼(Buffer)`를 할당하는 데 있습니다.

### 단계별 상세 동작

- 1단계: 클라이언트 ➡️ 서버 (`SYN`)

  - 클라이언트가 서버에 연결 요청 패킷을 보냅니다.

  - 이때 TCP 헤더의 `SYN(Synchronize)` 플래그를 1로 설정합니다.

  - 클라이언트는 자신이 임의로 생성한 초기 시퀀스 번호인 `ISN(Initial Sequence Number)`을 패킷에 담아 보냅니다. (예: `Seq = 1000`)

  - 클라이언트의 상태는 `SYN_SENT`로 변경됩니다.

- 2단계: 서버 ➡️ 클라이언트 (`SYN + ACK`)

  - 서버는 클라이언트의 `SYN` 패킷을 받고, 이에 대한 확인 응답과 동시에 자신도 연결을 요청하는 패킷을 보냅니다.

  - TCP 헤더의 `SYN` 플래그와 `ACK(Acknowledgment)` 플래그를 모두 1로 설정합니다.

  - `Acknowledgment Number(확인 응답 번호)`에는 클라이언트가 보낸 시퀀스 번호에 1을 더한 값(`Ack = 1001`)을 넣습니다. 이는 1000번을 잘 받았으니 다음엔 1001번을 달라는 신호입니다.

  - 동시에 서버도 자신의 초기 시퀀스 번호(`Seq = 5000`)를 새로 생성하여 담아 보냅니다.

  - 서버의 상태는 `SYN_RCVD`로 변경됩니다.

- 3단계: 클라이언트 ➡️ 서버 (`ACK`)

  - 클라이언트는 서버의 `SYN + ACK` 패킷을 받고, 최종 확인 응답 패킷을 서버로 보냅니다.

  - TCP 헤더의 `ACK` 플래그만 1로 설정합니다.

  - 수신한 서버의 시퀀스 번호에 1을 더한 값(`Ack = 5001`)을 담고, 자신의 다음 시퀀스 번호(`Seq = 1001`)를 담아 보냅니다.

  - 이 패킷이 서버에 도착하면 양쪽 컴퓨터의 상태는 모두 `ESTABLISHED(연결됨)`로 변경되며 실제 데이터 전송이 가능해집니다.
