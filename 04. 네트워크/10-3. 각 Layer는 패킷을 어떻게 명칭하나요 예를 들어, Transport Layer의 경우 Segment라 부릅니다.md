# 10-3. 각 Layer는 패킷을 어떻게 명칭하나요? 예를 들어, Transport Layer의 경우 Segment라 부릅니다.

## PDU(Protocol Data Unit)란?

**PDU(Protocol Data Unit)** 는 **각 계층에서 데이터를 부르는 이름**입니다.

데이터가 송신 측에서 아래 계층으로 내려갈수록 각 계층의 헤더(Header)가 추가되며, 그에 따라 데이터의 이름도 달라집니다.

---

# 계층별 PDU

| OSI 계층 | PDU 명칭 |
| --- | --- |
| 7. Application | Data |
| 6. Presentation | Data |
| 5. Session | Data |
| 4. Transport | **Segment (TCP)** / **Datagram (UDP)** |
| 3. Network | **Packet** |
| 2. Data Link | **Frame** |
| 1. Physical | **Bit** |

---

# 왜 이름이 바뀔까?

각 계층은 데이터를 전달하기 위해 **자신에게 필요한 정보(Header)를 추가**합니다.

따라서 계층이 내려갈수록 데이터의 구조가 달라지고, 이를 구분하기 위해 이름도 달라집니다.

예를 들어 HTTP 요청을 보낸다면,

```plain text
Application 

"Data"
(HTTP 요청)

        │
        ▼
Transport

"Segment"
(TCP Header + Data)

        │
        ▼
Network

"Packet"
(IP Header + Segment)

        │
        ▼
Data Link

"Frame"
(Ethernet Header + Packet + Trailer)

        │
        ▼
Physical

"Bit"
(010101...)
```

---

# 각 PDU 설명

## ① Data

Application, Presentation, Session 계층에서는

아직 네트워크 전송을 위한 정보가 붙지 않았기 때문에 단순히 **Data**라고 부릅니다.

예를 들어

- HTTP 요청

- 이미지 파일

- 동영상 데이터

등이 모두 Data입니다.

---

## ② Segment (Transport Layer)

Transport Layer에서는

TCP 헤더를 추가하여 **Segment**를 만듭니다.

TCP 헤더에는

- Port 번호

- Sequence Number

- Checksum

- ACK 번호

등이 포함됩니다.

만약 UDP를 사용한다면 **Datagram**이라고 부릅니다.

---

## ③ Packet (Network Layer)

Network Layer에서는

IP 헤더를 추가합니다.

IP 헤더에는

- 출발지 IP

- 목적지 IP

- TTL

등의 정보가 들어갑니다.

이 상태의 데이터를 **Packet**이라고 합니다.

---

## ④ Frame (Data Link Layer)

Data Link Layer에서는

Ethernet Header와 Trailer를 추가합니다.

| Header | Trailer |
| --- | --- |
| 앞에 붙음 | 뒤에 붙음 |
| 누구에게 보낼지 등 전달 정보 | 데이터가 깨졌는지 검사 |

여기에는

- 출발지 MAC 주소

- 목적지 MAC 주소

- FCS(CRC)

  - FCS(Frame Check Sequence) : 데이터가 전송 중에 손상되었는지 확인하기 위해 프레임 끝에 붙이는 값

  - CRC(Cyclic Redundancy Check) : FCS를 계산하는 알고리즘

등이 포함됩니다.

이 상태를 **Frame**이라고 합니다.

---

## ⑤ Bit (Physical Layer)

Physical Layer에서는

Frame을

```plain text
010101101101...
```

과 같은 전기 신호 또는 광 신호로 변환하여 전송합니다.

이 단계에서는 **Bit**라고 부릅니다.

---

# 데이터 이름이 변하는 과정

```plain text
Application
Data
        │
        ▼
Transport
Segment (TCP)
        │
        ▼
Network
Packet
        │
        ▼
Data Link
Frame
        │
        ▼
Physical
Bit
```

수신 측에서는 반대로

```plain text
Bit
        ▲
Frame
        ▲
Packet
        ▲
Segment
        ▲
Data
```

순서로 원래 데이터를 복원합니다.

---

# 면접 답변 예시

> 각 계층에서는 데이터를 PDU라고 하며, 계층마다 명칭이 다릅니다. Application, Presentation, Session 계층에서는 Data라고 부르고, Transport 계층에서는 TCP의 경우 Segment, UDP의 경우 Datagram이라고 부릅니다. Network 계층에서는 Packet, Data Link 계층에서는 Frame, Physical 계층에서는 Bit라고 부릅니다. 이는 각 계층에서 필요한 헤더가 추가되면서 데이터의 구조가 달라지기 때문입니다.

---

# 예상 꼬리 질문

### Q. 왜 Transport Layer에서는 Segment라고 부르나요?

Transport Layer는 큰 데이터를 전송하기 쉽도록 **작은 단위로 분할(Segmentation)** 합니다.

그래서 TCP에서 사용하는 PDU를 **Segment**라고 부릅니다.

---

### Q. 왜 Network Layer에서는 Packet이라고 하나요?

Network Layer에서는 IP 헤더가 추가되어 **인터넷에서 전달되는 단위**가 되기 때문입니다.

즉, 라우터는 **Packet**을 보고 목적지까지 전달합니다.

---

### Q. Frame에는 무엇이 들어있나요?

Frame은

- Ethernet Header

- Packet

- Trailer(FCS)

로 구성되며,

MAC 주소를 이용한 통신과 오류 검출을 위해 사용됩니다.
