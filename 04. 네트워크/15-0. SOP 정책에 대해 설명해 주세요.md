# 15-0. SOP 정책에 대해 설명해 주세요.

> SOP(Same-Origin Policy)는 브라우저의 기본 보안 정책으로, **동일한 Origin(Protocol, Host, Port)이 아닌 경우 JavaScript가 다른 출처의 응답 데이터를 읽는 것을 제한하는 정책**입니다.

여기서 Origin은 **프로토콜(Protocol), 호스트(Host), 포트(Port)** 세 가지가 모두 동일한 경우를 의미합니다.

SOP는 악성 사이트가 사용자의 인증 정보를 이용해 다른 사이트의 데이터를 탈취하는 것을 방지하기 위해 존재합니다. 만약 다른 출처와 안전하게 통신해야 하는 경우에는 서버가 CORS 헤더를 통해 접근을 허용하거나, Reverse Proxy 또는 서버 간 통신 방식을 사용합니다.

---

## 1️⃣ SOP란?

### 📌 정의

SOP(Same-Origin Policy)는

**브라우저가 다른 출처의 응답(Response)을 읽는 것을 제한하는 보안 정책**이다.

웹 브라우저의 가장 기본적인 보안 정책 중 하나이며,
다른 출처의 데이터 접근을 기본적으로 차단한다.

---

## 2️⃣ Origin(출처)이란?

Origin은 다음 3가지 요소로 구성된다.

- Protocol (http / https)

- Host (도메인)

- Port (80, 443, 8080 ...)

세 가지가 모두 같아야 동일 출처이다.

### 예시

| URL | 동일 출처 여부 |
| --- | --- |
| [https://example.com](https://example.com/) | 기준 |
| [https://example.com/api](https://example.com/api) | ✅ 동일 |
| [http://example.com](http://example.com/) | ❌ Protocol 다름 |
| [https://api.example.com](https://api.example.com/) | ❌ Host 다름 |
| [https://example.com:8080](https://example.com:8080/) | ❌ Port 다름 |

---

## 3️⃣ SOP가 필요한 이유

만약 SOP가 없다면,

사용자가 은행 사이트에 로그인한 상태에서
악성 사이트를 방문했을 때

```plain text
악성 사이트

↓

은행 사이트의 데이터 요청

↓

사용자 정보 탈취
```

가 가능해진다.

SOP는 이러한 **Cross-Origin 공격을 방지**하기 위해 존재한다.

---

## 4️⃣ SOP가 제한하는 것

브라우저에서

다른 출처의

- AJAX(Fetch, XMLHttpRequest)의 응답을 읽는 것

- DOM 접근

등을 제한한다.

단,
이미지, CSS, JavaScript 파일은 HTML 태그를 통해 다른 출처에서도 로드할 수 있지만, JavaScript 코드에서 응답 데이터를 읽는 것은 SOP의 제한을 받을 수 있다.

---

## 5️⃣ SOP를 우회하거나 허용하는 방법

다른 출처의 리소스 접근이 필요한 경우

대표적으로

- CORS

- Reverse Proxy (동일 Origin처럼 보이게 만드는 우회 방식)

- 서버 간 통신(Server to Server)

등을 사용한다.

---

## 📌 핵심 정리

- SOP는 브라우저의 기본 보안 정책이다.

- Origin은 Protocol, Host, Port가 모두 같아야 한다.

- 다른 출처의 응답 데이터를 JavaScript가 읽는 것을 제한하여 사용자 정보를 보호한다.

- Cross-Origin 통신이 필요하면 CORS 등의 예외 정책을 사용한다.

## 🎯 예상 꼬리 질문

### Q. SOP는 브라우저에서만 적용되나요?

네. SOP는 브라우저의 보안 정책입니다.

서버와 서버 간 통신은 SOP의 영향을 받지 않습니다.

---

### Q. Postman에서는 왜 CORS 오류가 발생하지 않나요?

Postman은 브라우저가 아니므로 SOP와 CORS 정책을 적용받지 않습니다.
