# 10-4. 각각의 Header의 Packing Order에 대해 설명해 주세요.

# 0. 들어가기 앞서

정확한 질문의 의도 파악이 어려워

> Note OSI 7계층의 최상단(L7)부터 최하단(L1)까지 데이터가 내려오면서 헤더는 어떤 순서로 덧붙여지는가?

라는 질문을 가정으로 작성함.

---

# 1. 상위 계층 (L7, L6, L5): Data 덩어리의 완성

1. 사용자 데이터가 통신을 위한 준비를 마치는 단계

> Note 

  - **L7 (응용 계층):** 원본 데이터 맨 앞에 통신 방식(예: HTTP)을 담은 **L7 헤더**가 붙습니다.

  - **L6 (표현 계층):** 위에서 내려온 덩어리 맨 앞에 데이터 압축/암호화 정보를 담은 **L6 헤더**가 붙습니다.

  - **L5 (세션 계층):** 위에서 내려온 덩어리 맨 앞에 통신 연결 유지 정보를 담은 **L5 헤더**가 붙습니다.

1. 특징

> Note 

  - 상위 계층에서 생성된 [L5+L6+L7+원본 데이터]의 형태로 L4로 내려갑니다.

  - 네트워크 전송을 담당하는 하위 계층(L4 이하)은 이 내용물을 일일이 뜯어보지 않고, 통째로 하나의 순수한 덩어리(Data 또는 Payload)으로만 취급합니다.

---

# 2. L4 전송 계층: 세그먼트(Segment) 생성

1. 본격적인 네트워크 배달 송장이 붙기 시작하는 단계

> Note 

  - 상위 계층에서 통째로 내려온 거대한 덩어리(Data)의 맨 앞에 **L4 헤더**가 덧붙습니다.

1. L4 헤더 정보

> Note 

  - 출발지와 목적지의 '포트 번호(어떤 프로그램으로 보낼지)'가 기록되어 있습니다.

1. 결과적으로 나오는 것을 ‘세그먼트’라고 합니다.

---

# 3. L3 네트워크 계층: 패킷(Packet) 생성

1. 라우터와 L3 스위치가 활약하는 구간으로, 전 세계 통신망의 경로를 찾습니다.

> Note 

  - 완성된 세그먼트의 맨 앞에 **L3 헤더**가 덧붙습니다.

1. L3 헤더의 정보

> Note 

  - 출발지와 목적지의 'IP 주소'가 기록됩니다.

1. 결과적으로 나오는 것을 ‘패킷’이라고 합니다.

---

# 4. L2 데이터 링크 계층: 프레임(Frame) 생성

1. 물리적으로 직접 연결된 다음 기기(스위치 등)로 데이터를 넘기기 위한 마지막 포장 단계입니다.

> Note 

  - 완성된 패킷의 앞과 뒤를 동시에 포장합니다.

  - 맨 앞에는 **L2 헤더**가, 맨 뒤에는 FCS(Frame Check Sequence, 오류 검출 코드)가 붙습니다.

1. L2 헤더의 정보

> Note 

  - 앞쪽 헤더에는 물리적 주소인 'MAC 주소'가 적힙니다.

  - 뒤쪽 FCS는 전송 중 화물(데이터)이 깨지지 않았는지 무결성을 검증하는 꼬리표 역할을 합니다.

1. 결과적으로 나오는 것을 ‘프레임’이라고 합니다.
