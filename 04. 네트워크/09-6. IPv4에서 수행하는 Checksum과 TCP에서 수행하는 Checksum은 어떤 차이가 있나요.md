# 9-6. IPv4에서 수행하는 Checksum과 TCP에서 수행하는 Checksum은 어떤 차이가 있나요?

> **IPv4의 Checksum과 TCP의 Checksum은 검사 대상과 목적이 다릅니다.**

먼저 IPv4 Checksum은 **IP 헤더(Header)만 검사**합니다. IP 패킷은 라우터를 거칠 때마다 TTL 값이 변경되기 때문에 헤더 정보도 함께 변경되며, 이때 라우터는 Header Checksum을 다시 계산합니다. 반면 Payload까지 검사하면 라우터의 부담이 커지므로, IPv4는 헤더만 검사하여 라우팅 효율을 높입니다.

반면 TCP Checksum은 **TCP 헤더와 Payload 전체**를 검사하며, 출발지와 목적지 IP 정보를 포함한 Pseudo Header도 함께 사용합니다. TCP는 신뢰성 있는 전송을 제공해야 하므로 데이터 손상을 검출하고 필요하면 재전송을 수행합니다.

즉, **IPv4 Checksum은 패킷 전달을 위한 헤더 보호가 목적이고, TCP Checksum은 데이터의 무결성을 보장하기 위한 것**이라는 점이 가장 큰 차이입니다.

## 0️⃣ Checksum이란?

### 📌 정의

Checksum은 **데이터가 전송되는 과정에서 오류가 발생했는지 확인하기 위한 오류 검출(Error Detection) 기법**이다.

송신 측에서 Checksum 값을 계산하여 함께 전송하고,

수신 측에서도 동일한 방식으로 계산하여 비교한다.

- 값이 같으면 → 정상 데이터

- 값이 다르면 → 전송 중 오류 발생

> 💡 Checksum은 **오류를 검출**하는 기능이며, 오류를 **수정(Correction)** 하지는 않는다.

---

## 1️⃣ IPv4 Checksum

### 📌 무엇을 검사할까?

일반적인 패킷의 구성

```javascript
┌──────────────┬──────────────┐
│    Header    │   Payload    │
└──────────────┴──────────────┘
```

- **Header** : 전송에 필요한 제어 정보 (IP 주소, 포트 번호 등)

- **Payload** : 실제 전송하려는 데이터 (HTTP 요청, 파일, 이미지 등)

---

IPv4는 **IP 헤더(Header)만 검사**한다.

```plain text
┌──────────────┬──────────────┐
│  IP Header   │   Payload    │
└──────────────┴──────────────┘
      ▲
      │
 Header Checksum
```

즉,

- IP 주소

- TTL

- 프로토콜 번호

등 **헤더 정보만** 오류를 확인한다.

---

### 📌 왜 헤더만 검사할까?

<details>
<summary>TTL(Time To Live)</summary>

TTL(Time ToLive)은 **IP 패킷이 네트워크에서 무한히 순환하는 것을 방지하기 위한 값**이다.

패킷이 라우터를 하나 지날 때마다 TTL 값은 **1씩 감소**하며, TTL이 0이 되면 해당 패킷은 폐기된다.
</details>

IP 패킷은 라우터를 거칠 때마다

- TTL 감소

- Header Checksum 재계산

이 반복된다.

라우터는 패킷을 빠르게 전달해야 하므로, 매 홉마다 Payload 전체를 검사하면 처리 시간이 크게 증가한다.
따라서 변경되는 Header만 검사하여 라우팅 성능을 높인다.

---

## 2️⃣ TCP Checksum

### 📌 무엇을 검사할까?

TCP는

- TCP Header

- Payload(데이터)

모두 검사한다.

```plain text
┌──────────────┬──────────────┐
│ TCP Header   │   Payload    │
└──────────────┴──────────────┘
      ▲──────────────▲
          Checksum
```

또한 TCP는

**Pseudo Header**(출발지 IP, 목적지 IP 등 일부 IP 정보)를 함께 사용하여 계산한다.

※ Pseudo Header는 실제로 전송되는 데이터는 아니며, TCP 세그먼트가 올바른 출발지와 목적지 사이에서 전달되었는지까지 함께 검증하기 위해 Checksum 계산에만 사용되는 임시 정보이다.

---

### 📌 왜 Payload까지 검사할까?

TCP는 **신뢰성 있는 전송(Reliable Transmission)** 을 제공해야 하기 때문이다.

데이터가 손상되면

- 오류 검출

- 재전송(Retransmission) ← TCP의 신뢰성 매커니즘(ACK, 타임아웃 등)

을 수행하여 정확한 데이터를 전달한다.

---

## 3️⃣ IPv4 Checksum vs TCP Checksum

| 구분 | IPv4 Checksum | TCP Checksum |
| --- | --- | --- |
| 검사 대상 | **IP Header만** | **TCP Header + Payload** |
| 검사 목적 | 패킷 전달을 위한 헤더 보호 | 데이터 무결성 보장 |
| 재계산 여부 | 라우터마다 재계산 | 송신·수신 시만 계산 |
| 계층 | Network Layer (L3) | Transport Layer (L4) |

---

## 4️⃣ IPv6에서는?

IPv6는 **Header Checksum을 제거**하였다.

### 이유

- 라우터의 계산 부담 감소

- 성능 향상

대신 Ethernet의 FCS(L2: 데이터 링크 계층)와 TCP/UDP의 Checksum(L4: 전송 계층)을 통해 오류를 검출한다.

---

## 📌 핵심 정리

- Checksum은 **데이터 오류를 검출**하기 위한 값이다.

- IPv4는 **IP Header만 검사**하여 라우팅 효율을 높인다.

- TCP는 **Header + Payload**를 모두 검사하여 신뢰성 있는 전송을 보장한다.

- IPv6는 Header Checksum을 제거하고 상위 계층의 Checksum을 활용한다.
