# 4-3. SSL과 TLS의 차이는 무엇인가요?

# 1. SSL과 TLS

1. SSL (Secure Sockets Layer)

  - 1990년대 Netscape사(민간기업)에서 처음 개발한 보안 프로토콜입니다.

  - SSL 1.0, 2.0, 3.0 순으로 발전했습니다.

  - 옛날 방식인 RC4, DES 같은 암호화 알고리즘을 사용했는데, 이는 현대의 해킹 기술로 쉽게 복호화가 가능합니다.

  - MAC(Message Authentication Code)이라는 비교적 단순한 알고리즘을 사용했습니다.

1. TLS (Transport Layer Security)

  - SSL 3.0을 기반으로 표준화 기구(IETF)가 공식 표준으로 만들면서 이름을 TLS로 바꿨습니다.

  - TLS 1.0, 1.1, 1.2, 1.3 순으로 발전했습니다.

  - 현대적이고 강력한 고성능 암호화 알고리즘(AES, CHACHA20 등)과 안전한 키 교환 방식(ECDHE 등)을 강제하여 해킹 가능성을 원천 차단합니다.

  - MAC보다 훨씬 강력하고 안전한 해시 기반의 **HMAC**(Hash-based Message Authentication Code)을 사용하여 데이터 위변조를 더 완벽하게 잡아냅니다.


| **구분** | **SSL (Secure Sockets Layer)** | **TLS (Transport Layer Security)** |
| --- | --- | --- |
| **정의** | 넷스케이프(Netscape)사가 개발한 **초기 보안 프로토콜** | IETF가 SSL을 표준화하고 발전시킨 **최신 보안 프로토콜** |
| **현재 상태** | **사용 중단** (취약점이 많아 공식적으로 폐기됨) | **현재 표준** (실제 웹 보안 통신에 사용 중) |
| **역사** | 버전 1.0, 2.0, 3.0까지 출시 | SSL 3.0의 후속 버전이 TLS 1.0으로 명칭 변경 |

---

# 2. 현대의 방식

- 현대에 이르러서는 HTTPS Handshake는 **전부 TLS 방식**으로 진행됩니다.

- 과거의 SSL 시리즈(1.0 ~ 3.0)와 초기 TLS(1.0, 1.1)는 치명적인 보안 취약점이 발견되어 현재 전 세계 모든 웹 브라우저와 서버에서 사용이 금지되었습니다.

---

# 3. 여전히 SSL/TLS라고 부르는 이유

- 인터넷 초기 시절 'SSL'이라는 명칭이 사람들에게 너무나 강하게 각인되었기 때문입니다.

- 기술적으로는 이미 TLS를 쓰고 있지만, 업계 관행상 여전히 **"SSL 인증서"**, "SSL Handshake"라는 표현을 습관적으로 혼용해서 부르고 있습니다.
