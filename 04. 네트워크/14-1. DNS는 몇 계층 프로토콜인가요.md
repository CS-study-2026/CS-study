# 14-1. DNS는 몇 계층 프로토콜인가요?

### 설명하기 전에, DNS가 프로토콜인가?

DNS는 프로토콜이 맞으면서 동시에 거대한 시스템(System). 이것이 DNS라는 이름의 마지막 약자가 Protocol이 아니라 System인 이유.

> 💡 이 두 가지 개념이 어떻게 공존할까?

## 1. DNS의 두 가지 얼굴: 시스템 vs 프로토콜

우리가 DNS를 이야기할 때는 문맥에 따라 **두 가지 의미**를 모두 사용

### 거대한 시스템으로서의 DNS (Domain Name System)

전 세계에 퍼져 있는 루트 네임 서버, TLD 네임 서버, 가비아 같은 권한 있는 네임 서버, 그리고 통신사의 리커시브 리졸버들이 유기적으로 연결되어 작동하는 세계 최대의 분산형 데이터베이스 인프라 그 자체를 의미. 즉, 전 세계 인터넷 주소록을 유지하는 거대한 조직체이자 아키텍처.

### 통신 규약으로서의 DNS (DNS Protocol)

  - 그 거대한 시스템 안에서 컴퓨터들이 서로 대화할 때 사용하는 공용 언어(규약)를 의미.

  - 예시로, 내 브라우저가 통신사 DNS 서버에 주소를 물어볼 때나, 리졸버가 루트 서버에 질의를 던질 때, 아무 문장으로 물어보면 컴퓨터는 이해 불가

  - 패킷의 몇 번째 바이트에는 질의 내용을 넣고, 몇 번째 바이트에는 어떤 플래그를 켜서 보낼지, 응답할 때는 데이터 포맷을 어떻게 맞출지 약속. 이 규격화된 메시지 포맷과 통신 방식이 DNS 프로토콜

## 2. DNS가 프로토콜인 증거: 규격화된 데이터 구조

컴퓨터 과학에서 프로토콜이라고 부르려면 명확한 메시지 헤더 구조와 통신 규칙이 정의되어 있어야 함. DNS 프로토콜은 실제로 다음과 같은 명확한 포맷을 가지고 전송 계층(UDP/TCP 53번 포트) 위에서 움직임.

  - DNS 헤더(Header): 트랜잭션 ID, 플래그(질의인지 응답인지, 데이터가 잘렸는지 등의 정보), 질문 수, 답변 수 등이 적히는 공간

  - 퀘스천(Question): 클라이언트가 찾고 싶어 하는 도메인 이름과 레코드 유형(A, AAAA 등)이 적히는 공간

  - 앤서(Answer): 네임 서버가 찾아낸 실제 IP 주소 정답 데이터가 적히는 공간

우리가 HTTP를 웹 서버와 브라우저가 소통하는 프로토콜이라고 부르는 것처럼, DNS 서버와 클라이언트가 도메인 정보를 주고받기 위해 약속된 데이터 전송 규격을 사용하므로 애플리케이션 계층의 프로토콜이 맞다.

### 📋 한 줄 요약

DNS는 전 세계 네임 서버들이 도메인 정보를 관리하는 시스템의 이름이기도 하지만, 그 서버들이 데이터를 주고받을 때 사용하는 메시지 규격과 통신 규칙을 뜻하는 프로토콜이기도 합니다. 따라서 DNS는 애플리케이션 계층의 프로토콜이라고 표현하는 것이 정답입니다.

DNS는 OSI 7 계층 모델과 TCP/IP 4 계층 모델 모두에서 최상위 계층인 **애플리케이션 계층(Application Layer, L7) 프로토콜**에 해당합니다.

### 이유

하부의 **전송 계층이나 네트워크 계층**은 오직 패킷을 안전하고 정확하게 목적지 IP와 포트 번호로 배달하는 **물리적 전송 인프라 역할만 수행**합니다.

### 반면

- 도메인 문자열 포맷을 파싱하고,

- 주소 레코드 종류(A, AAAA, CNAME, MX 등)를 식별하며,

- 네임 서버 간에 질의 응답 메시지를 규격화하여 비즈니스 로직을 처리하는 주체

이것은 전적으로 **사용자 응용 프로그램 영역**입니다. 따라서 웹 브라우저나 이메일 시스템 등 상위 소프트웨어 인터페이스와 연동되는 애플리케이션 계층에 위치하는 것이 적합합니다.
