# 15-2. Preflight에 대해 설명해 주세요.

> Preflight는 실제 요청을 보내기 전에 브라우저가 서버에 **"이 요청을 보내도 되는지" 미리 확인하는 과정**입니다.

브라우저는 OPTIONS 메서드로 요청을 보내고, 서버가 허용 가능한 Origin, Method, Header 등을 응답하면 그 이후에 실제 요청을 전송합니다.

이를 통해 **브라우저는 서버의 CORS 정책을 확인한 후, 허용된 경우에만 실제 요청을 전송합니다.**

---

## 1️⃣ Preflight란?

### 📌 정의

Preflight는
실제 요청 전에 브라우저가 **OPTIONS 요청**을 보내
해당 요청이 허용되는지 확인하는 과정이다.

---

## 2️⃣ 언제 발생할까?

다음과 같은 **Simple Request****가 아닌 경우** 발생한다.

- PUT

- DELETE

- PATCH

- Authorization Header 사용

- `Content-Type`이 `application/json`처럼 **Simple Request에서 허용되지 않는 값**인 경우

---

## 3️⃣ 동작 과정

```plain text
Browser

↓

OPTIONS 요청

↓

Server

↓

허용 여부 응답

↓

실제 요청(GET, POST, PUT ...)
```

---

## 4️⃣ 예시

브라우저

```plain text
OPTIONS /users

Origin: <https://client.com>

Access-Control-Request-Method: PUT
```

서버

```plain text
Access-Control-Allow-Origin: <https://client.com>

Access-Control-Allow-Methods: PUT
```

허용되면

```plain text
PUT /users
```

실제 요청이 전송된다.

---

## 5️⃣ 왜 필요한가?

브라우저는 Preflight를 통해 서버의 CORS 정책을 미리 확인한다.

허용된 경우에만 실제 요청을 전송하므로,
불필요하거나 허용되지 않은 교차 출처 요청을 사전에 방지할 수 있다.

---

## 6️⃣ Preflight 최적화

브라우저는 `Access-Control-Max-Age` 헤더를 이용하여
일정 시간 동안 Preflight 결과를 캐싱한다.

이를 통해 OPTIONS 요청을 반복하지 않아
성능을 향상시킬 수 있다.

---

## 📌 핵심 정리

- Preflight는 실제 요청 전에 보내는 OPTIONS 요청이다.

- 브라우저가 서버의 허용 여부를 먼저 확인한다.

- 허용되면 실제 요청을 전송한다.

- Access-Control-Max-Age를 이용해 결과를 캐싱할 수 있다.

## 🎯 예상 꼬리 질문

### Q. GET 요청도 Preflight가 발생하나요?

항상 그런 것은 아닙니다.

GET, HEAD, POST 중에서도 Simple Request 조건을 만족하면 Preflight 없이 바로 요청을 보냅니다.

---

### Q. Preflight를 비활성화할 수 있나요?

브라우저의 표준 동작이므로 비활성화할 수 없습니다.

대신 요청을 Simple Request 형태로 변경하거나, Access-Control-Max-Age를 활용해 OPTIONS 요청을 줄일 수 있습니다.
