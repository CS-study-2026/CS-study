# 14-7. 이차원 배열을 가로/세로로 탐색했을 때의 성능 차이에 대해 설명해 주세요.

## 0. 복습

CPU는 메모리에서 데이터를 읽을 때, 데이터 하나를 읽는 게 아니라 공간 지역성 활용을 위해 Cache Line 단위로 읽음

즉 지역성 → Cache Line → 2차원 배열 순회 흐름으로 설명

---

## 1. 2차원 배열은 실제로 어떻게 저장될까?

Row-major Order(행 우선 저장) 된다.

```java
1 2 3
4 5 6
7 8 9
이 아닌,

1 2 3 4 5 6 7 8 9 형식으로 연속적으로 저장(행 우선 저장)
```

---

## 2. 가로탐색과 세로탐색의 성능 차이

### 가로 탐색

```java
for(int i=0;i<N;i++){
    for(int j=0;j<M;j++){
        sum += arr[i][j];
    }
}
```

접근 순서 : `1 → 2 → 3 → …`

→ 메모리 저장 순서와 완전히 동일함

CPU 입장에서는 메모리 저장 순서와 완전 동일하므로, 캐시라인에 1을 읽을 때 `2, 3, 4` 가 모두 캐시 히트

> 

Cache Hit ↑

RAM 접근 ↓

성능 ↑

### 세로 탐색

```java
for(intj=0;j<M;j++){
	for(inti=0;i<N;i++){
		sum+=arr[i][j];
	}
}
```

접근 순서 : `1 → 4 → 7 → ...`

→ 메모리 저장 순서와 다름

CPU 입장에서는 1 읽으면서 `1, 2, 3, 4...` 를 캐시에 올리는데 바로 `4` 로 건너뛰어버림

⇒ 캐시라인에 올려둔 데이터를 제대로 활용하지 못함

> 

Cache Miss 증가

RAM 접근 증가

성능 감소

배열 크기가 작으면 거의 차이가 없지만, 대형 배열에서는 가로 탐색이 수 배 이상 빠른 경우가 많음

`CPU Cache 활용률 차이` 때문에 !
