# 17-4. 페이지 크기가 커지면, 페이지 폴트가 더 많이 발생한다고 할 수 있나요?

페이지 크기와 페이지 폴트 빈도 사이에는 트레이드오프가 있다.

- 공간 지역성이 잘 맞으면 페이지 폴트 횟수가 줄어든다.

- 페이지가 커질수록 페이지 개수가 줄어든다. -> 스래싱 발생 가능성이 커짐

## 결론

> 반드시 그렇다고 할 수 없습니다.

페이지 크기가 커지면 페이지 폴트가 증가할 수도 있고 감소할 수도 있습니다.

따라서 이 질문의 핵심은

> "페이지 폴트 횟수"와 "페이지 폴트 비용"을 구분할 수 있는가

를 확인하는 것입니다.

---

# 먼저 페이지 폴트(Page Fault)란?

## 정의

프로세스가 접근하려는 페이지가 현재 물리 메모리(RAM)에 존재하지 않는 경우 발생하는 예외(Exception)

---

예시

```plain text
프로그램 실행

↓

CPU가 Page 10 접근

↓

RAM에 Page 10 없음

↓

디스크에서 Page 10 읽어옴

↓

프로그램 계속 실행
```

이 과정을

> Page Fault

라고 부른다.

---

## 왜 비싼 연산일까?

RAM 접근 속도

```plain text
약 100ns
```

SSD 접근 속도

```plain text
약 100,000ns
```

이상

---

즉

페이지 폴트 발생 시

```plain text
RAM → Disk
```

접근이 발생하므로 매우 느리다.

---

# 페이지 크기가 커지면 무슨 일이 발생할까?

예를 들어

```plain text
페이지 크기

4KB → 2MB
```

로 증가했다고 가정하자.

---

# 경우 1. 페이지 폴트가 감소할 수 있다

## 지역성(Locality) 때문

---

# 지역성이란?

## 정의

프로그램은 특정 메모리 근처를 반복적으로 사용하는 경향이 있다는 특성

---

### 공간 지역성 (Spatial Locality)

```plain text
배열[0]

↓

배열[1]

↓

배열[2]
```

처럼

인접한 주소를 자주 접근하는 현상

---

## 예시

페이지 크기

```plain text
4KB
```

일 때

```plain text
배열 접근

0KB
4KB
8KB
12KB
```

---

각각 다른 페이지일 수 있음

---

반면

```plain text
2MB 페이지
```

라면

모두 하나의 페이지 안에 존재할 수 있음

---

즉

한 번의 페이지 폴트로

```plain text
필요한 데이터 대부분
```

를 같이 가져온다.

---

결과

```plain text
페이지 폴트 감소
```

가능

---

# 경우 2. 페이지 폴트가 증가할 수 있다

## 메모리 압박(Memory Pressure) 때문

---

# 메모리 압박이란?

## 정의

실제 메모리(RAM)가 부족해지는 상황

---

예시

RAM

```plain text
8GB
```

프로세스가

```plain text
7.8GB 사용
```

중

---

페이지 크기를 크게 하면

필요하지 않은 데이터까지 함께 적재된다.

---

예시

실제 필요한 데이터

```plain text
100KB
```

---

페이지 크기

```plain text
2MB
```

---

실제로는

```plain text
2MB 전체 적재
```

해야 함

---

결과

```plain text
RAM 빨리 소모
```

---

운영체제는

기존 페이지를 쫓아내야 한다.

---

이후

다시 필요해지면

```plain text
Page Fault
```

발생

---

결과적으로

```plain text
페이지 폴트 증가
```

가능

---

# 그래서 중요한 개념

## 페이지 폴트 횟수(Frequency)

와

## 페이지 폴트 비용(Cost)

은 다르다.

---

# 페이지 폴트 횟수

몇 번 발생했는가

---

예시

```plain text
100번 발생
```

---

# 페이지 폴트 비용

한 번 발생했을 때 얼마만큼 비싼가

---

예시

```plain text
4KB 읽기

vs

2MB 읽기
```

---

당연히

```plain text
2MB
```

가 더 비싸다.

---

# 페이지 크기가 커지면?

## 횟수

증가할 수도

감소할 수도

있다.

---

## 비용

거의 항상 증가

한다.

---

왜냐하면

한 번에 더 많은 데이터를 읽어와야 하기 때문이다.

---

# 실제 면접에서 원하는 답

면접관

> 페이지 크기가 커지면 페이지 폴트가 더 많이 발생하나요?

---

좋은 답변

> 반드시 그렇지는 않습니다. 페이지 크기가 커지면 공간 지역성 덕분에 한 번의 페이지 폴트로 더 많은 데이터를 가져올 수 있어 페이지 폴트 횟수는 감소할 수도 있습니다. 하지만 필요하지 않은 데이터까지 함께 적재되기 때문에 메모리 사용량이 증가하고, 메모리 압박이 심해지면 오히려 페이지 교체가 자주 발생하여 페이지 폴트가 증가할 수도 있습니다. 또한 페이지 크기가 커질수록 한 번의 페이지 폴트 비용은 증가합니다.

---

# 자주 나오는 연계 질문

## Q1. 지역성(Locality)이란?

> 프로그램이 특정 메모리 영역을 집중적으로 사용하는 특성입니다.

종류

- 시간 지역성(Temporal Locality)

- 공간 지역성(Spatial Locality)

---

## Q2. 페이지 폴트가 많이 발생하면 왜 느려지나요?

> RAM이 아닌 디스크에서 데이터를 읽어와야 하기 때문입니다.

---

## Q3. 페이지 크기가 커지면 왜 TLB 효율이 좋아지나요?

> 하나의 TLB 엔트리가 더 넓은 주소 공간을 커버할 수 있기 때문입니다.

---

## Q4. 페이지 크기가 커지면 왜 내부 단편화가 증가하나요?

> 실제 필요한 데이터보다 더 큰 페이지를 할당받아 사용하지 않는 공간이 많아지기 때문입니다.

---

# 한 줄 요약

> **페이지 크기가 커진다고 페이지 폴트가 반드시 증가하는 것은 아니다. 공간 지역성으로 인해 감소할 수도 있지만, 메모리 압박으로 인해 증가할 수도 있다. 다만 페이지 폴트가 발생했을 때의 비용은 일반적으로 더 커진다.**
