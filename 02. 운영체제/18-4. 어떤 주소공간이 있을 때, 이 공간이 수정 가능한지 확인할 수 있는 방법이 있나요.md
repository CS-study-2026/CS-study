# 18-4. 어떤 주소공간이 있을 때, 이 공간이 수정 가능한지 확인할 수 있는 방법이 있나요?

### **✅ 한 줄 답변**

> 해당 주소가 속한 **세그먼트 또는 페이지의 접근 권한(Read, Write, Execute)** 을 확인하면 됩니다.

---

## **먼저 왜 이런 질문이 나올까?**

> “메모리 공간마다 접근 권한이 다르다는 것을 알고 있나요?”

---

# **1️⃣ 세그멘테이션 방식**

세그멘테이션은 메모리를 의미 단위로 나눕니다.

```plain text
Code Segment
Data Segment
Heap Segment
Stack Segment
```

각 세그먼트마다 접근 권한(R/W/X)을 가집니다.

예를 들어:

| **Segment** | **권한** | 의미 |
| --- | --- | --- |
| Code | R-X | 읽기, 실행 가능 |
| Data | RW- | 읽기, 쓰기 가능 |
| Heap | RW- | 읽기, 쓰기 가능 |
| Stack | RW- | 읽기, 쓰기 가능 |

따라서 어떤 주소가 수정 가능한지 확인하려면,

**해당 주소가 속한 세그먼트의 Write 권한을 확인**하면 됩니다.

```json
만약 Code Segment라면, 수정이 불가능!
다른 Segment라면 수정 가능하다.
```

---

# **2️⃣ 페이징 방식 (현대 OS)**

페이징은 메모리를 고정 크기의 페이지(Page)로 나눕니다.

각 페이지에 대해 **페이지 테이블(Page Table)**이 존재하며, 여기에 접근 권한이 저장됩니다.

### 📍페이지 테이블 엔트리(PTE) : 페이지 테이블의 한 행

예시:

```plain text
Page 5

Frame Number : 3 (실제 RAM에 어디에 있는지)
Present Bit  : 1 (RAM에 있는지 없는지. 0이라면 page fault)
Read Bit     : 1 (읽기 권한)
Write Bit    : 0 (쓰기 권한) <-- 여기를 확인!
Execute Bit  : 1 (실행 권한)
```

프로세스가 메모리를 수정하려고 하면 CPU는 MMU를 통해 해당 페이지의 PTE를 조회합니다.

```plain text
메모리 쓰기 요청
↓
MMU
↓
페이지 테이블 조회
↓
Write Bit 확인
↓
허용 또는 차단
```

만약 Write Bit가 0인 페이지에 쓰기를 시도하면 운영체제가 이를 차단하고 예외를 발생시킵니다.

---

# **📌 비교 정리**

| **구분** | **세그멘테이션** | **페이징** |
| --- | --- | --- |
| 관리 단위 | Segment | Page |
| 권한 저장 위치 | 세그먼트 정보 | 페이지 테이블 |
| 수정 가능 여부 확인 | Segment의 Write 권한 확인 | Page의 Write Bit 확인 |
| 현대 OS 사용 여부 | 거의 사용 안 함 | 주로 사용 |
