# 17-1. 가상 메모리가 가능한 이유가 무엇일까요?

# 가상 메모리가 가능한 이유는 무엇일까요?

## 한 줄 답변

> **MMU와 페이지 테이블을 이용해 가상 주소를 물리 주소로 변환하고, 필요하지 않은 페이지는 디스크(Swap)에 저장할 수 있기 때문입니다.**

---

# 가상 메모리가 가능한 핵심 이유 1️⃣

## 가상 주소와 물리 주소를 분리했기 때문

프로세스는:

```plain text
0x1000
0x2000
0x3000
```

같은 가상 주소만 사용한다.

---

실제 RAM에서는

```plain text
Frame 3
Frame 8
Frame 1
```

같은 전혀 다른 위치에 저장될 수 있다.

---

이를 연결하는 것이

```plain text
페이지 테이블
```

이다.

예:

```plain text
Page 0 → Frame 3
Page 1 → Frame 8
Page 2 → Frame 1
```

---

즉,

> 프로세스는 실제 위치를 몰라도 되기 때문에

운영체제가 자유롭게 메모리를 배치할 수 있다.

---

# 가상 메모리가 가능한 핵심 이유 2️⃣

## 📍페이지 단위로 관리하기 때문

만약 프로그램 전체를 RAM에 올려야 한다면

```plain text
프로그램 10GB
RAM 8GB
```

→ 실행 불가

---

하지만 페이지 단위로 관리하면

```plain text
Page 0
Page 1
Page 2
...
```

중

현재 필요한 것만 RAM에 올릴 수 있다.

---

예:

```plain text
프로그램 전체 : 10GB

현재 사용 중 :
Page 1
Page 3
Page 5
```

---

RAM

```plain text
Page 1
Page 3
Page 5
```

---

Swap

```plain text
나머지 페이지
```

---

그래서

```plain text
RAM보다 큰 프로그램
```

도 실행 가능하다.

---

# 가상 메모리가 가능한 핵심 이유 3️⃣

## 📍MMU가 주소 변환을 자동으로 수행하기 때문

프로세스는:

```plain text
Page 2 읽어줘
```

만 요청한다.

---

CPU 내부의 MMU가

```plain text
Page 2
↓
Frame 8
```

로 변환한다.

---

RAM에 없으면

```plain text
Page Fault
```

발생

---

운영체제가

```plain text
Swap
↓
RAM
```

으로 가져온다.

프로세스는 이 과정을 전혀 모른다.
