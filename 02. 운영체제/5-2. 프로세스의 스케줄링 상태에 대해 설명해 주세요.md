# **5-2.** 프로세스의 스케줄링 상태에 대해 설명해 주세요.

# 🏦 프로세스 스케줄링과 상태 변화

## 0️⃣ 들어가기 전 필수 용어 정리

- **프로세스(Process):** 실행 중인 프로그램.(손님)

- **CPU:** 실제로 연산을 처리하는 부품. (한 번에 하나의 연산 가능, 은행원)

- **메모리(RAM):** 프로그램이 실행되기 위해 올라가는 공간. (고객들이 들어와서 대기할 수 있는 '은행 건물 내부 공간'입니다.)

  - 모든 상태는 일반적으로(?) RAM에 위치함!

| **구분** | **RAM (주기억장치)** | **HDD / SSD (보조기억장치)** |
| --- | --- | --- |
| **비유** | **공부하는 책상** | **짐을 쌓아두는 창고** |
| **속도** | **빛의 속도** (엄청나게 빠름) | 상대적으로 느림 |
| **용량** | 작음 (보통 8GB ~ 32GB) | **매우 큼** (보통 512GB ~ 수 TB) |
| **가격** | 비쌈 | 저렴함 |
| **전원을 끄면?** | **데이터가 사라짐** (휘발성) | 데이터가 안전하게 보관됨 (비휘발성) |

---

### 1. 생성 상태 (New)

- **의미:** 방금 막 프로그램이 실행되어, 운영체제가 이 프로세스에게 메모리(공간)를 배정해 준 상태.

- **은행 비유:** 고객이 은행 문을 열고 들어와서 **'번호표를 막 뽑은 순간'**

### 2. 준비 상태 (Ready)

- **의미:** CPU를 당장 써도 되는 상태지만, 아직 자기 **차례가 오지 않아** 대기줄(Ready Queue)에서 기다리고 있는 상태.

- **은행 비유:** 번호표를 들고 **'차례를 기다리는 상태'**

### 3. 실행 상태 (Running)

- **의미:** CPU를 할당받아, 실제 코드가 연산되고 있는 상태.

- **은행 비유:** 은행원(CPU) 앞에서 **'내 업무를 처리하고 있는 상태'**

### 4. 대기 상태 (Waiting 또는 Blocked)

- **의미:** 프로세스가 실행되다가, 마우스 입력이나 프린터 출력 같은 **입출력(I/O) 작업**이 필요해져서( ⇒ 트랩, 의도적인 인터럽트 → 소프트웨어 인터럽트) CPU를 잠시 놓고 기다리는 상태. 입출력이 끝나면 다시 '준비 상태(Ready)'로 돌아감.

- **은행 비유:** 은행원이 "고객님, 신분증 복사해 오셔야 해요. 저쪽 복사기 다녀오세요"라고 한 상황. 고객은 은행원 앞(실행)에서 비켜나서, '복사기 앞에서 줄을 서며 대기하는 상태'

### 5. 종료 상태 (Terminated)

- **의미:** 프로세스의 모든 실행이 완료되어, 사용하던 메모리와 자원을 모두 반환한 상태.

- **은행 비유:** 업무를 성공적으로 마치고 '은행 밖으로 나간 상태'

---

이 상태들은 CPU가 언제든 손 뻗으면 닿을 수 있는 거리에 있는 상태

- **생성(New):** 은행 문을 열고 막 들어와서 번호표를 뽑는 중 (**RAM 입성!**)

- **준비(Ready):** 번호표 들고 대기실 의자에 앉아 있음 (**RAM 대기 중**)

- **실행(Running):** 은행원 바로 앞 창구에 앉아 있음 (**RAM에서 작업 중**)

- **대기(Waiting):** 은행 안쪽 복사기 앞에서 줄 서 있음 (**RAM에서 기다리는 중**)

- **종료(Terminated):** 업무 다 보고 짐 싸서 나갈 준비 중 (**RAM에서 나갈 준비**)
