# **21-0. 페이지 교체 알고리즘에 대해 설명해 주세요.**

# 페이지 교체 알고리즘이란?

가상 메모리 환경에서 프로세스가 접근하려는 페이지가 메모리에 없으면 **페이지 폴트(Page Fault)** 가 발생한다.

이때 물리 메모리(RAM)에 빈 공간이 없다면 기존 페이지 중 하나를 제거하고 새로운 페이지를 적재해야 한다.

→ **어떤 페이지를 제거할지 결정하는 알고리즘**을 페이지 교체 알고리즘이라고 한다.

### 목적

<details>
<summary>페이지 폴트(Page Fault) 최소화</summary>

## 페이지 폴트란?

프로세스가 어떤 페이지에 접근하려고 했는데, 해당 페이지가 물리 메모리(RAM)에 없는 상황을 말합니다.

```plain text
CPU가 페이지 접근
↓
페이지 테이블 확인
↓
해당 페이지가 RAM에 없음
↓
Page Fault 발생
```

페이지 폴트가 발생하면 운영체제는 다음 작업을 수행합니다.

```plain text
1. 현재 프로세스 실행 중단
2. 필요한 페이지가 디스크 어디에 있는지 확인
3. 디스크에서 페이지를 RAM으로 가져옴
4. 메모리에 빈 공간이 없으면 기존 페이지 교체
5. 페이지 테이블 갱신
6. 중단된 명령어 다시 실행
```

즉, 페이지 폴트는 단순한 오류가 아니라 **운영체제가 개입해야 하는 비싼 이벤트**입니다.

## 왜 최소화해야 할까?

페이지 폴트가 자주 발생하면 CPU는 계속 기다리게 됩니다.

```plain text
정상 메모리 접근
→ RAM 접근
→ 빠름

페이지 폴트 발생
→ 디스크 접근
→ 매우 느림
```

RAM 접근은 매우 빠르지만, 디스크 접근은 상대적으로 훨씬 느립니다.

따라서 페이지 폴트가 많아지면 CPU는 연산을 하지 못하고 I/O 완료를 기다리는 시간이 증가합니다.
</details>

<details>
<summary>디스크 I/O 감소</summary>

## 페이지 폴트와 디스크 I/O의 관계

페이지 폴트가 발생하면 필요한 페이지를 디스크에서 읽어와야 합니다.

또한 교체 대상 페이지가 수정된 상태라면, 즉 Dirty Page라면 디스크에 다시 써야 합니다.

```plain text
새 페이지 적재
→ 디스크 Read 발생

교체할 페이지가 Dirty Page
→ 디스크 Write 발생
```

즉, 페이지 교체 한 번이 단순히 메모리 내부 작업으로 끝나는 것이 아니라, 디스크 읽기와 쓰기를 동반할 수 있습니다.

## Clean Page와 Dirty Page

### Clean Page

메모리에 올라온 뒤 수정되지 않은 페이지입니다.

교체할 때 디스크에 다시 쓸 필요가 없습니다.

```plain text
Clean Page 제거
→ 그냥 버려도 됨
```

### Dirty Page

메모리에 올라온 뒤 수정된 페이지입니다.

디스크에 있는 원본과 내용이 다르기 때문에 교체 전에 반드시 디스크에 기록해야 합니다.

```plain text
Dirty Page 제거
→ 디스크에 Write 필요
→ 비용 증가
```

## 왜 디스크 I/O를 줄여야 할까?

디스크 I/O는 CPU 연산이나 RAM 접근보다 훨씬 느립니다.

페이지 교체 알고리즘이 좋지 않으면 다음과 같은 문제가 생깁니다.

```plain text
자주 쓰는 페이지 제거
↓
곧 다시 필요해짐
↓
다시 디스크에서 읽음
↓
또 다른 페이지 제거
↓
반복
```

이렇게 되면 시스템은 계산보다 페이지를 읽고 쓰는 데 시간을 더 많이 쓰게 됩니다.

이를 **스래싱(Thrashing)** 이라고 합니다.
</details>

<summary>메모리 활용도 향상</summary>

## 메모리 활용도란?

한정된 RAM 공간에 **앞으로 사용할 가능성이 높은 페이지를 최대한 유지하는 것**을 의미합니다.

물리 메모리는 제한되어 있습니다.

```plain text
프로세스가 필요로 하는 전체 페이지 수 > 실제 RAM에 올릴 수 있는 페이지 수
```

따라서 모든 페이지를 메모리에 올릴 수 없습니다.

결국 중요한 것은 다음 질문입니다.

> 제한된 메모리 공간에 어떤 페이지를 남겨둘 것인가?

## 좋은 페이지 교체 알고리즘의 기준

좋은 알고리즘은 앞으로 다시 사용할 가능성이 낮은 페이지를 제거합니다.

```plain text
다시 사용할 가능성 높은 페이지
→ 메모리에 유지

다시 사용할 가능성 낮은 페이지
→ 교체 대상
```

예를 들어 LRU는 시간 지역성을 이용합니다.

```plain text
최근에 사용한 페이지
→ 다시 사용할 가능성 높음

오랫동안 사용하지 않은 페이지
→ 다시 사용할 가능성 낮음
```

즉, LRU는 메모리를 단순 저장 공간이 아니라 **가치 있는 페이지를 선별해서 보관하는 캐시 공간**처럼 활용합니다.
</details>

<details>
<summary>시스템 성능 향상</summary>

## 성능 저하의 흐름

페이지 교체 알고리즘이 나쁘면 다음 흐름이 발생합니다.

```plain text
잘못된 페이지 교체
↓
페이지 폴트 증가
↓
디스크 I/O 증가
↓
CPU 대기 시간 증가
↓
처리량 감소
↓
응답 시간 증가
↓
전체 시스템 성능 저하
```

## 성능 향상의 흐름

반대로 좋은 페이지 교체 알고리즘은 다음 효과를 냅니다.

```plain text
재사용 가능성 높은 페이지 유지
↓
페이지 폴트 감소
↓
디스크 I/O 감소
↓
CPU 대기 시간 감소
↓
처리량 증가
↓
응답 시간 감소
↓
시스템 성능 향상
```

즉, 페이지 교체 알고리즘은 메모리 관리 정책이지만, 실제로는 CPU 활용률, 응답 시간, 처리량까지 영향을 줍니다.
</details>

# 대표적인 페이지 교체 알고리즘

## 1. FIFO (First In First Out)

### 개념

가장 먼저 메모리에 들어온 페이지를 교체

```plain text
A → B → C → D

페이지 교체 필요
↓
A 제거
```

### 장점

- 구현이 매우 간단

- Queue 자료구조 활용 가능

### 단점

- 자주 사용하는 페이지도 제거될 수 있음

- Belady's Anomaly 발생 가능

---

## 2. OPT (Optimal)

### 개념

앞으로 가장 오랫동안 사용되지 않을 페이지를 교체

```plain text
A B C D

미래 참조 순서 확인
↓
가장 늦게 사용될 페이지 제거
```

### 장점

- 페이지 폴트 횟수 최소

- 이론적으로 최적

### 단점

- 미래의 참조 정보를 알아야 함

- 실제 구현 불가능

> 주로 다른 알고리즘 성능 비교 기준(Baseline)으로 사용

---

## 3. LRU (Least Recently Used)

### 개념

가장 오랫동안 사용되지 않은 페이지를 교체

```plain text
최근 사용
A → B → C

오랫동안 사용 안 됨
D

↓

D 제거
```

### 장점

- 실제 프로그램 특성을 잘 반영

- OPT에 근접한 성능

### 단점

- 사용 시간을 계속 추적해야 함

- 구현 비용 증가

---

## 4. LFU (Least Frequently Used)

### 개념

참조 횟수가 가장 적은 페이지를 교체

```plain text
A : 10회
B : 7회
C : 2회

↓

C 제거
```

### 장점

- 자주 사용하는 페이지 유지 가능

### 단점

- 과거에 많이 사용됐지만 앞으로 사용되지 않을 수도 있음

---

## 5. Clock (Second Chance)

### 개념

LRU를 근사적으로 구현한 알고리즘

페이지마다 Reference Bit를 둔다.

```plain text
Reference Bit = 1
→ 최근 사용됨

Reference Bit = 0
→ 최근 사용 안 됨
```

### 동작

```plain text
포인터 순환

비트 = 1
↓
0으로 변경 후 통과

비트 = 0
↓
교체
```

### 장점

- LRU보다 구현이 단순

- 실제 OS에서 많이 사용
