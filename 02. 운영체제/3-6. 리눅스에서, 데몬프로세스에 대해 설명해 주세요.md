# **3-6.** 리눅스에서, 데몬프로세스에 대해 설명해 주세요.

## 1️⃣ 데몬 프로세스란?

👉 **백그라운드에서 계속 실행되면서 시스템 작업을 수행하는 프로세스**

- 사용자와 직접 상호작용 ❌

- 시스템 또는 서버 기능을 담당 ⭕

예: 웹 서버, DB 서버, 스케줄러 등

---

## 2️⃣ 특징

### ✔️ 1. 백그라운드 실행

- 터미널과 분리되어 실행됨

- 사용자가 로그인/로그아웃과 무관하게 동작

---

### ✔️ 2. 장시간 실행 (Long-lived)

- 대부분 **시스템 시작 시 실행**

- 필요할 때까지 계속 살아있음

---

### ✔️ 3. 독립적인 환경

- 일반적으로:

  - 부모 프로세스와 분리됨

  - 터미널 없음 (TTY 없음) → **터미널과 완전히 연결이 끊어진 상태**

    - 키보드 입력 X 화면 출력 X 사용자와 직접 상호작용 X

    - 그냥 뒤에서 혼자 계속 동작하는 프로세스

> 🧠 

### TTY란?

---

👉 **터미널(사용자 입력/출력 창)을 의미하는 개념**

  - 키보드 입력 받음

  - 화면에 출력 보여줌

예:

  - 우리가 사용하는 터미널 창 (bash, zsh)

  - SSH 접속 화면

👉 이걸 OS에서는 **TTY (Teletype)** 라고 부름

---

### ✔️ 4. 이름 특징

- 리눅스에서 보통 이름 끝에 `d`가 붙음

예:

- `sshd` (SSH 서버)

- `httpd` (웹 서버)

- `crond` (스케줄러)

---

## 3️⃣ 대표적인 데몬 예시

- sshd
→ 원격 접속 처리

- crond
→ 예약 작업 실행

- httpd
→ 웹 요청 처리

- mysqld
→ DB 관리

---

## 4️⃣ 데몬 프로세스는 어떻게 만들어질까?

👉 핵심: **터미널로부터 완전히 분리된 프로세스 만들기**

일반적인 과정:

1. `fork()`
→ 부모 종료 → 자식이 백그라운드로

1. `setsid()`
→ 새로운 세션 생성 (터미널과 완전히 분리)

1. 작업 디렉토리 변경 (`/`)

1. 파일 디스크립터 정리 (stdin, stdout, stderr 닫기)

👉 이렇게 하면 완전한 데몬 프로세스가 됨

---

## 5️⃣ 고아 프로세스와의 관계

👉 데몬 프로세스는 보통 생성 과정에서 부모가 종료됨

→ 결과적으로

**init (Unix process) 또는 systemd에게 입양된 고아 프로세스 형태**

✔️ 즉,

- 고아 프로세스가 항상 데몬은 아니지만

- 데몬은 보통 고아 프로세스 형태로 존재

---

## 6️⃣ 한눈에 정리

- 데몬 = **백그라운드에서 계속 돌아가는 시스템 서비스 프로세스**

- 터미널 없음 / 사용자 입력 없음

- 시스템 기능 수행 (서버, 스케줄링 등)

- 대부분 init/systemd가 관리

---

## 🎯 한 줄 핵심

👉 **데몬 프로세스는 "사용자와 상관없이 뒤에서 계속 일하는 시스템 서비스"다**
