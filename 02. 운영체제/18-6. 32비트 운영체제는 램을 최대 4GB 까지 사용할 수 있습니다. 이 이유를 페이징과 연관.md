# 18-6. 32비트 운영체제는 램을 최대 4GB 까지 사용할 수 있습니다. 이 이유를 페이징과 연관 지어서 설명해 주세요.

> **페이징은 주소를 변환하는 기법이지 주소 공간을 확장하는 기법이 아니다.**

## 1️⃣ 주소 비트 수와 주소 공간

비트 수가 n이라면

표현 가능한 주소 개수는 `2ⁿ`개

---

32bit

→ `2³² = 4,294,967,296`개 주소

---

각 주소가 1Byte를 가리키므로

```plain text
2³² Byte = 4GB
```

따라서 하나의 프로세스가 사용할 수 있는 가상 주소 공간의 최대 크기는 4GB

---

## 2️⃣ 페이징과의 관계

페이징은 가상 주소를

```plain text
[ Page Number | Offset ]
```

으로 나누어 관리한다.

페이지 테이블은 Page Number를 이용하여 가상 주소를 물리 주소로 변환한다.

---

## 3️⃣ 왜 4GB를 넘을 수 없는가?

중요한 점은

> 페이지 테이블은 주소를 변환할 뿐, 주소 비트 수를 늘리지는 못한다.

는 것이다.

32비트 주소 체계에서는 가상 주소 자체가 32비트로 고정되어 있으므로
표현 가능한 주소 범위는 최대 4GB이다.

따라서 페이지를 아무리 많이 만들거나 페이지 크기를 변경하더라도
전체 가상 주소 공간은 4GB를 초과할 수 없다.

---

## 4️⃣ 예시

페이지 크기가 4KB라면

```plain text
Offset = 12bit
Page Number = 20bit
```

가 된다.

즉,

```plain text
2²⁰ Pages × 4KB
=
2³² Bytes
=
4GB
```

결국 페이지 크기가 달라져도 전체 주소 공간은 항상 4GB로 제한된다.

---

## 5️⃣ 결과

따라서 32비트 운영체제는 물리 메모리(RAM)가 8GB 이상 설치되어 있더라도

주소 공간 한계 때문에 전체 RAM을 직접 활용하지 못하며,

일반적으로 약 3~4GB 범위만 사용할 수 있다.
