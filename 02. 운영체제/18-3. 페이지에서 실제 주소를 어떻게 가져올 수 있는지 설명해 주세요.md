# 18-3. 페이지에서 실제 주소를 어떻게 가져올 수 있는지 설명해 주세요.

## 1️⃣ 페이징(Paging)

### 📌 왜 필요한가?

프로세스의 논리 주소 공간(Logical Address Space)과 실제 물리 메모리(Physical Memory)를 분리하기 위해 사용한다.

---

### 📌 구성 요소

- Page : 프로세스를 일정 크기로 나눈 단위

- Frame : 물리 메모리를 같은 크기로 나눈 단위

```plain text
가상 메모리

Page 0
Page 1
Page 2
Page 3

↓

물리 메모리

Frame 5
Frame 2
Frame 9
Frame 1
```

---

## 2️⃣ 논리 주소(Logical Address)

CPU가 생성하는 주소

논리 주소는 두 부분으로 구성된다.

```plain text
Logical Address

[ Page Number | Offset ]
```

| 구성 요소 | 역할 |
| --- | --- |
| Page Number | 페이지 번호 |
| Offset | 페이지 내부 위치 |

---

## 3️⃣ 주소 변환 과정

예시)

페이지 크기 = 4KB (→ 비트수 4096(4 × 2¹⁰))

논리 주소 = 8200

---

### Step 1. Page Number 계산

```plain text
8200 ÷ 4096 = 2
```

Page Number = 2

---

### Step 2. Offset 계산

```plain text
8200 mod 4096 = 8
```

Offset = 8

---

따라서

```plain text
Logical Address

(Page 2, Offset 8)
```

---

### Step 3. 페이지 테이블 조회

페이지 테이블

| Page | Frame |
| --- | --- |
| 0 | 5 |
| 1 | 3 |
| 2 | 10 |
| 3 | 7 |

---

Page 2

↓

Frame 10

---

### Step 4. 물리 주소 계산

```plain text
Physical Address

= Frame 시작 주소 + Offset

= 10 × 4096 + 8

= 40968
```

---

## 4️⃣ MMU의 역할

### MMU (Memory Management Unit)

CPU가 생성한 논리 주소를

물리 주소로 변환하는 하드웨어

---

동작 과정

```plain text
CPU
 ↓
Logical Address
 ↓
MMU
 ↓
Page Table 조회
 ↓
Physical Address
 ↓
Memory Access
```

---

## 📌 핵심 정리

- 논리 주소는 Page Number + Offset으로 구성

- MMU가 페이지 테이블을 조회

- Page Number를 Frame Number로 변환

- 최종적으로 Physical Address를 계산하여 접근
