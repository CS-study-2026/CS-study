# 22-1. I-Node가 무엇인가요?

> I-Node는 파일의 메타데이터를 저장하는 자료구조입니다. 파일 크기, 권한, 소유자 정보, 데이터 블록 위치 등을 저장하지만 파일 이름은 저장하지 않습니다. 파일 이름은 디렉터리 엔트리에 저장되며, 디렉터리는 파일명과 inode 번호를 매핑합니다. 따라서 운영체제는 파일명을 통해 inode를 찾고, inode를 통해 실제 데이터 블록에 접근합니다.

## 1️⃣ I-Node란?

### 📌 정의

I-Node(Index Node)는
파일의 메타데이터와 실제 데이터 위치를 저장하는 자료구조이다.

---

중요한 점
👉 I-Node에는 파일 이름이 없다.

파일 이름은
디렉토리 엔트리에 저장된다.

---

## 2️⃣ I-Node가 필요한 이유

디스크에는 수많은 파일이 존재한다.

운영체제는

- 파일 크기

- 권한

- 위치

등을 알아야 한다.

이 정보를 저장하는 것이 I-Node이다.

---

## 3️⃣ I-Node가 저장하는 정보

### 포함

- 파일 크기

- 소유자(User)

- 그룹(Group)

- 접근 권한(rwx)

- 생성 시간

- 수정 시간

- 데이터 블록 위치

### 포함하지 않는 것

❌ 파일 이름

---

## 4️⃣ [구조](/p/37d4f7753cf280adac82ff4b17746334#3814f7753cf2804f8622e218301be851)

예시

```plain text
test.txt
```

---

디렉토리

```plain text
test.txt
   ↓

```

inode 135

```plain text

데이터 블록
 ↓
120
121
122
```

---

실제 데이터

```plain text
Block 120
Block 121
Block 122
```

에 저장

## 5️⃣ 파일 접근 과정

사용자

```plain text
cat test.txt
```

실행

---

### Step 1

디렉토리 검색

```plain text
test.txt
↓
inode 135
```

---

### Step 2

inode 조회

```plain text
inode 135
↓
블록 위치 확인
```

---

### Step 3

실제 데이터 읽기

```plain text
Block 120
Block 121
Block 122
```

---

## 6️⃣ Hard Link와의 관계

Linux에서

```bash
ln file1 file2
```

---

실행 시

```plain text
file1
file2
```

둘 다
같은 inode 참조

---

즉

```plain text
file1
   ↘
    inode 135
   ↗
file2
```

그래서 Hard Link는 실제로 같은 파일이다.

---

## 7️⃣ 왜 중요한가?

파일 시스템 성능과 직결

운영체제는
파일 이름이 아니라 inode를 통해
실제 데이터를 찾는다.

즉,
inode는
파일 시스템의 핵심 인덱스 역할을 수행한다.

---

## 결론

- **파일 디스크립터**: 프로세스가 열린 파일을 참조하기 위한 인덱스

- **아이노드**: 파일 시스템이 파일 자체를 식별하기 위한 인덱스

- 둘 다 번호를 통해 대상을 찾는다는 점에서는 “인덱스 역할”을 하지만, **FD는 프로세스 수준의 인덱스이고 inode는 파일 시스템 수준의 인덱스**이다.

---

## 📌 핵심 정리

- I-Node는 파일 메타데이터를 저장하는 자료구조

- 파일 이름은 저장하지 않음

- 실제 데이터 블록 위치를 관리

- 파일 접근 시 디렉토리 → inode → 데이터 블록 순으로 탐색
