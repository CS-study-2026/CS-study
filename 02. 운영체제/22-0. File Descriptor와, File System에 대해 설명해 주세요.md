# 22-0. File Descriptor와, File System에 대해 설명해 주세요.

> 

File System은 운영체제가 디스크에 저장된 파일과 디렉터리를 관리하는 구조입니다. 단순한 바이트 저장 공간인 디스크 위에서 파일의 위치, 크기, 권한, 디렉터리 구조 등의 정보를 관리하여 사용자가 파일을 효율적으로 사용할 수 있도록 합니다.

File Descriptor는 프로세스가 열린 파일이나 소켓, 파이프 같은 I/O 자원에 접근하기 위해 사용하는 정수 형태의 식별자입니다. 프로세스가 파일을 열면 운영체제가 File Descriptor를 생성하고, 이후에는 파일 이름이 아니라 해당 번호를 이용해 읽기·쓰기 작업을 수행합니다.

예를 들어 Java에서 FileInputStream을 생성하면 내부적으로는 운영체제의 open 시스템 콜이 호출되어 File Descriptor가 생성됩니다. 또한 File Descriptor는 Open File Table과 I-Node를 통해 실제 파일 정보와 연결되며, 이를 통해 운영체제가 파일을 효율적으로 관리합니다.

## 1️⃣ File System이란?

### 📌 정의

파일 시스템(File System)은
운영체제가 파일을 저장하고 관리하기 위한 구조이다.

즉, 디스크(HDD, SSD)에 데이터를 저장 · 조회 · 수정 · 삭제할 수 있도록 관리하는 체계이다.

---

### 📌 왜 필요한가?

디스크는 단순히 수많은 바이트들의 집합이다.

만약 파일 시스템이 없다면

```plain text
000101101010101...
```

어디가 파일인지
어디가 빈 공간인지 알 수 없다.

---

따라서 파일 시스템은

- 파일 이름

- 파일 위치

- 파일 크기

- 접근 권한

등을 관리한다.

---

## 2️⃣ File Descriptor란?

### 📌 정의

운영체제가 열린 파일(Open File)을 관리하기 위해 부여하는 정수 번호

즉,
👉 프로세스가 파일을 직접 다루는 것이 아니라
File Descriptor(FD)를 통해 접근한다.

---

### 예시

<details>
<summary>운영체제가 파일을 어떻게 관리하는가를 설명하기 위해서는 C 예시가 일반적</summary>

☕ Java에서는 File Descriptor를 직접 사용할까?

Java 개발자는 일반적으로 File Descriptor를 직접 다루지 않는다.

예시

```java
FileInputStream fis =
        new FileInputStream("test.txt");
```

---

하지만 내부적으로는

```java
FileInputStream
    ↓
JVM
    ↓
OS System Call(open)
    ↓
File Descriptor 생성
```

과정을 거친다.

즉,
Java가 File Descriptor를 숨겨줄 뿐
실제로 운영체제는 여전히 File Descriptor를 사용하여 파일을 관리한다.
</details>

open(): 파일을 열고 파일 디스크립터를 얻음

```c
int fd = open("/home/users/test.txt", O_RDONLY);
```

<details>
<summary>open() 시스템콜의 핵심 흐름</summary>

1. 경로 탐색(path lookup)
"/"
 ↓
"home"
 ↓
"user"
 ↓
"test.txt"

  1. 각 디렉터리의 dentry를 조회

  1. 최종적으로 test.txt의 inode 획득

  1. inode를 기반으로 open file 객체 생성

  1. 프로세스 FD 테이블에 등록

  1. FD 번호 반환
</details>

---

실행 결과

```c
fd = 3
```

가 반환될 수 있다.

---

### 의미

프로세스

| FD | 목적 | POSIX 이름 | stdio 스트림 |
| --- | --- | --- | --- |
| 0 | 표준 입력 | STDIN_FILENO | stdin |
| 1 | 표준 출력 | STDOUT_FILENO | stdout |
| 2 | 표준 에러 | STDERR_FILENO | stderr |
| 3 | test.txt 파일 참조 |   |   |

프로세스는
파일 이름이 아니라
FD 번호를 이용하여 파일을 읽고 쓴다.

cf) 프로세스는 최소한 0, 1, 2 세 가지 파일 디스크립터를 열어둠

---

## 3️⃣ 왜 File Descriptor를 사용할까?

### 이유 1

파일 이름 검색 비용 제거

매번 `test.txt`를 찾아가는 것이 아니라
이미 열린 파일 정보를 참조

---

### 이유 2

파일과 장치를 동일하게 관리 가능

Linux 철학 : `Everything is a File` 
→ 장치, 프로세스, 네트워크까지 모두 파일처럼 다룬다.

예시)

- 일반 파일

- 키보드

- 터미널

- 소켓

모두 FD로 관리

---

## 4️⃣ 파일 읽기 과정

예시

```c
fd = open("test.txt");
read(fd, buffer, 100);
```

---

동작 과정

```plain text
프로세스
 ↓
File Descriptor : 프로세스가 사용하는 번호
 ↓
Open File Table : 열린 파일 상태 정보(inode 포인터, offset, mode)
 ↓
I-Node : 파일 메타데이터
 ↓
Disk(Data Block): 실제 파일 내용
```

즉
FD는 실제 파일을 가리키는 "참조 번호" 역할을 한다.

---

## 5️⃣ File Descriptor 특징

### 프로세스마다 독립적

```plain text
Process A

FD 3

Process B

FD 3
```

가능

⇒ FD 숫자가 같아도 실제 파일은 다를 수 있다.

---

### 파일 오픈 시 생성

```c
open()
```

---

### 파일 종료 시 제거

`fd`에 연관된 파일과의 맵핑 해제

```c
close()
```

---

## 📌 핵심 정리

- File System은 파일을 저장·관리하는 운영체제 구조

- File Descriptor는 열린 파일을 가리키는 정수 번호

- 프로세스는 파일 이름이 아닌 FD를 이용해 파일 접근

- Linux에서는 파일·소켓·터미널 등을 모두 FD로 관리
