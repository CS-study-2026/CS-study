# **12-4.** Thread Safe를 구현하기 위해 반드시 락을 사용해야 할까요? 그렇지 않다면, 어떤 다른 방법이 있을까요?

**Thread Safe 구현을 위해 반드시 락(Lock)을 사용할 필요는 없다.**

락은 오버헤드와 컨텍스트 스위칭 비용을 유발할 수 있으므로, 다음과 같은 비잠금 방식이 활용된다.

---

# 🔧 보강 추가 버전 (완성형)

락을 **직접 사용하지 않는** Thread Safe 구현 방법만 정리하면 이렇습니다.

---

## 1. Atomic 연산 사용

```java
AtomicInteger count = new AtomicInteger(0);
count.incrementAndGet();
```

단순 증가, 감소, 상태 변경처럼 작은 단위 연산에 사용합니다.

👉 CAS(Compare-And-Swap)를 기반으로, **현재 값과 예상 값을 비교하여 일치할 때만 갱신하는 방식**으로 원자성을 보장합니다.

---

## 2. Thread-safe 자료구조 사용

```java
ConcurrentHashMap<String, Integer> map = new ConcurrentHashMap<>();
```

내부적으로 동시성 처리가 되어 있는 자료구조를 사용합니다.

예:

```plain text
ConcurrentHashMap
BlockingQueue
ConcurrentLinkedQueue
CopyOnWriteArrayList
```

👉 내부적으로 **CAS나 세분화된 락(lock striping 등)**을 사용하여

개발자가 직접 락을 사용하지 않고도 Thread Safe를 보장합니다.

---

## 3. Immutable 객체 사용

객체를 수정하지 못하게 만듭니다.

```java
final class User {
    private final String name;

    public User(String name) {
        this.name = name;
    }
}
```

공유하더라도 값이 바뀌지 않으므로 안전합니다.

👉 **“공유는 하되 변경하지 않는다”**는 방식입니다.

---

## 4. Thread-local 사용

각 스레드가 자기만의 데이터를 갖게 합니다.

```java
ThreadLocal<Integer> localValue = ThreadLocal.withInitial(() -> 0);
```

공유 자원 자체를 없애는 방식입니다.

👉 스레드 간 간섭이 원천적으로 발생하지 않습니다.

---

## 5. Message Passing

공유 데이터를 직접 접근하지 않고 메시지로 전달합니다.

```plain text
Thread A → Queue → Thread B
```

Actor Model, 이벤트 큐, 작업 큐 방식이 여기에 해당합니다.

👉 **공유 메모리를 사용하지 않고 통신으로 해결**합니다.

---

## 6. CAS / Lock-free 방식

CPU의 원자적 명령을 사용합니다.

```java
AtomicInteger count = new AtomicInteger(0);

count.compareAndSet(0, 1);
```

락 없이 값을 비교하고, 예상한 값일 때만 변경합니다.

👉 충돌 시 재시도(spin) 방식으로 동작합니다.

<details>
<summary>ㅋ</summary>

| 구분 | Atomic 연산 | CAS / Lock-free |
| --- | --- | --- |
| 수준 | 고수준 (API) | 저수준 (CPU/알고리즘) |
| 사용 난이도 | 쉬움 | 어려움 |
| 구현 여부 | 이미 구현됨 | 직접 구현 |
| 내부 동작 | CAS 기반 | 직접 CAS 사용 |
| 예 | AtomicInteger | compareAndSet |
</details>

---

## 🔥 한 줄 정리 (업그레이드)

👉 **Lock 없이 Thread Safe를 구현하려면 공유 자원을 제거하거나, 불변으로 만들거나, 원자적 연산(CAS)과 메시지 기반 구조를 활용한다.**
