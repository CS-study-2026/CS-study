# **4-7.** IPC의 Shared Memory 기법은 프로세스 주소공간의 어디에 들어가나요? 그런 이유가 있을까요?

# 1. IPC(Inter-Process Communication)란?

- 컴퓨터 안에서 실행 중인 각각의 프로그램 단위를 프로세스라고 부릅니다.

- 원래 프로세스들은 서로의 영역을 절대 침범할 수 없도록 운영체제가 튼튼한 벽을 세워 보호하고 있습니다.

- A라는 게임 프로그램이 B라는 메신저 프로그램의 정보를 마음대로 읽거나 수정하면 보안과 안정성에 큰 문제가 생기기 때문입니다.

- 하지만 때로는 프로세스들끼리 서로 데이터를 주고받아야 할 때가 있습니다.

- 이때 운영체제가 제공하는 특별한 통로를 이용해 데이터를 주고받는 것을 IPC(프로세스 간 통신)라고 합니다.

---

# 2. Shared Memory(공유 메모리) 기법이란?

- 공유 메모리는 IPC의 여러 방법 중 가장 속도가 빠른 방법입니다.

- 중간에 데이터를 복사해서 전달하는 과정이 없기 때문에 모든 IPC 기법 중에서 가장 속도가 빠릅니다.

- 원래는 프로세스마다 자기만의 메모리 공간을 가지지만, 운영체제에게 부탁해서 여러 프로세스가 함께 사용할 수 있는 공통적인 메모리 영역을 하나 만드는 것입니다.

- 작동 방식

  1. 운영체제가 메모리의 특정 부분을 공유 영역으로 지정합니다.

  1. 이 영역에 접근 권한이 있는 프로세스들은 마치 자기 자신의 메모리를 사용하는 것처럼 이 공간에 데이터를 쓰고 읽습니다.

---

# **3. Shared Memory는 어디에 들어가나요?**

- 프로세스의 주소 공간은 크게 코드(Code), 데이터(Data), 힙(Heap), 스택(Stack) 영역으로 나뉩니다.

- 공유 메모리는 이 일반적인 영역이 아니라, 힙과 스택 사이의 빈 공간인 메모리 매핑 영역(Memory Mapped Region)에 위치하게 됩니다.

- 예를 들어, 1~10000까지 메모리가 있을 때, 힙은 101~1000, 스택은 9001~10000까지 메모리를 차지하고 있다면 1001~9000까지 메모리 중에서 일부 공간을 메모리 매핑 영역으로 사용하게 됩니다.

---

# **4. 왜 그곳에 위치하나요?**

- **유연한 크기 조절:** 힙은 아래에서 위로 커지고, 스택은 위에서 아래로 커집니다. 그 사이의 넓은 빈 공간을 활용하면 공유 메모리의 크기를 필요에 따라 유연하게 할당하기 좋습니다.

- **독립성 유지:** 프로세스가 기본적으로 사용하는 데이터나 스택 영역을 침범하지 않으면서도, 여러 프로세스가 공통적으로 접근할 수 있는 '별도의 방'을 만드는 것과 같습니다.

- **효율적인 매핑:** 운영체제는 물리적인 메모리를 프로세스의 가상 주소 공간에 연결(매핑)해 주는데, 이 작업을 수행하기 가장 적합한 설계 장소가 바로 메모리 매핑 영역입니다.

- **면접용 답변**

  - 힙과 스택이 서로 반대 방향으로 자라나며 남겨둔 '넉넉한 빈터'를 활용함으로써, 기존 메모리 구조를 방해하지 않고 여러 프로세스가 안전하게 데이터를 공유하기 위해서입니다.
