# **2-3.** HW / SW 인터럽트에 대해 설명해 주세요.

# ⚡ HW 인터럽트 / SW 인터럽트

## 1️⃣ 인터럽트란 무엇인가

인터럽트(Interrupt)는 **CPU가 실행 중인 작업을 잠시 중단하고 특정 이벤트를 처리하도록 만드는 메커니즘**이다.

CPU는 기본적으로 프로그램의 명령어를 순차적으로 실행한다.

```plain text
명령어 실행 → 다음 명령어 실행 → 다음 명령어 실행
```

하지만 외부 장치나 프로그램에서 중요한 이벤트가 발생하면

```plain text
현재 작업 중단
↓
인터럽트 처리 루틴 실행
↓
원래 작업으로 복귀
```

이 과정을 통해 CPU는 **이벤트 기반(Event-driven) 방식으로 동작**할 수 있다.

---

## 2️⃣ HW 인터럽트 (Hardware Interrupt)

### 📌 개념

HW 인터럽트는 **하드웨어 장치가 CPU에게 신호를 보내 발생하는 인터럽트**이다.

즉,

👉 **외부 장치에서 발생하는 인터럽트**

CPU가 모든 장치 상태를 계속 확인하면 비효율적이기 때문에

장치가 이벤트 발생 시 **CPU에게 직접 알리는 방식**을 사용한다.

---

### 📌 분류

- **전원 이상 인터럽트 (Power fail Interrupt)**

  - 정전, 전압 이상 등

  - 시스템 보호 목적

- **기계 착오 인터럽트 (Machine Check Interrupt)** : CPU나 하드웨어 내부 오류

- **외부 신호 인터럽트 (External Interrupt)** : CPU 외부 장치에서 발생

  - 타이머 인터럽트(자원이 할당된 시간이 다 끝난 경우)

  - 키보드 인터럽트(Control+Alt+Delete)

- **입출력 인터럽트 (I/O Interrupt)** : 입출력 장치가 작업 완료나 요청을 알림

  - 키보드 입력, 마우스 클릭, 디스크 I/O 완료, 네트워크 패킷 수신 등

🔽

I/O interrupt, timer interrupt, hardware failure

---

### 📌 특징

- **비동기적 발생** (예측 어려움)

- 외부 장치에서 발생

- I/O 처리에 사용

- 인터럽트 컨트롤러를 통해 CPU에 전달

---

## 3️⃣ SW 인터럽트 (Software Interrupt)

### 📌 개념

SW 인터럽트는 **프로그램 실행 중 CPU 내부에서 발생하는 인터럽트**이다.

즉,

👉 **소프트웨어가 CPU에게 인터럽트를 요청**

대표적인 예가 **시스템 콜(System Call)**이다.

사용자 프로그램이 운영체제 기능을 사용하려 할 때 SW 인터럽트가 발생한다.

---

### 📌 분류

- **예외상황 (Exception)** ≈ 프로그램 검사 인터럽트 (Program Check Interrupt) : 프로그램 실행 중 오류

  - 0으로 나눈 경우 (Division by Zero)

  - Overflow/Underflow

  - 잘못된 명령어 사용

  - page fault

- **시스템 콜 (System Call)** ≈ SVC (Supervisor Call) : 사용자 프로그램이 OS 기능을 요청할 때 발생

  - 파일 읽기/쓰기

  - 프로세스 생성

  - 입출력 요청

---

### 📌 특징

- **동기적 발생** (프로그램 실행 흐름에 의해 발생)

- 프로그램이 직접 요청

- 운영체제 기능 사용 목적

- 커널 모드 전환과 관련

---

## 4️⃣ HW 인터럽트 vs SW 인터럽트 비교

| 구분 | HW 인터럽트 | SW 인터럽트 |
| --- | --- | --- |
| 발생 주체 | 하드웨어 장치 | 프로그램 |
| 발생 방식 | 외부 이벤트 | 프로그램 호출 |
| 발생 시점 | 비동기적 | 동기적 |
| 주요 목적 | I/O 이벤트 처리 | 운영체제 서비스 요청 |
| 대표 예 | 키보드 입력 | 시스템 콜 |

---

## 📌 핵심 정리

- 인터럽트는 **CPU 실행 흐름을 변경하여 이벤트를 처리하는 메커니즘**

- HW 인터럽트는 **하드웨어 장치가 발생시키는 인터럽트**

- SW 인터럽트는 **프로그램이 의도적으로 발생시키는 인터럽트**

- 대표적인 SW 인터럽트 예시는 **시스템 콜**

[과거] HW Interrupt vs SW Interrupt(원인 기준)
→
[현대] Interrupt vs Exception(동기성 기준)

## CPU 내부 예외 분류 체계

### 전체 구조

```plain text
CPU 이벤트
│
├ Interrupt (비동기)-하드웨어
│
└ Exception (동기)-소프트웨어
     ├ Fault
     ├ Trap
     └ Abort
```

이 구조가 **현대 CPU (특히 x86 계열)**에서 사용하는 개념입니다.

대표적으로 Intel CPU에서 사용합니다.

---

### 1️⃣ Interrupt

### 특징

  - **비동기 발생**

  - 외부 장치가 발생

  - 현재 명령어와 관계 없음

예

  - 키보드 입력

  - 타이머 인터럽트

  - 디스크 I/O 완료

---

### 2️⃣ Exception

### 특징

  - **동기 발생**

  - 현재 실행 중인 명령어 때문에 발생

예

  - divide by zero

  - page fault

  - invalid instruction

Exception은 다시 **3가지로 나뉩니다.**

---

### 2️⃣-1. Fault

### 특징

  - **명령어 실행 중 발생**

  - **복구 가능**

  - 해결 후 **같은 명령어 다시 실행**

예

  - page fault

과정

```plain text
메모리 접근
→ 페이지 없음
→ page fault
→ OS가 페이지 로드
→ 명령어 다시 실행
```

---

### 2️⃣-2. Trap

### 특징

  - **명령어 실행 후 발생**

  - 의도적으로 발생시키도 함

대표 예

  - **system call**

즉

```plain text
프로그램
→ system call 실행
→ trap 발생
→ OS 실행
```

옛 OS 교재에서 말하는 **SVC**도 여기에 해당합니다.

---

### 2️⃣-3. Abort

### 특징

  - **치명적인 오류**

  - 복구 불가능

예

  - hardware failure

  - severe CPU error

보통 프로그램을 **즉시 종료**합니다.

---

### 📌 시험용 핵심 정리

운영체제 시험에서는 보통 이렇게 정리합니다.

```plain text
Interrupt
→ 비동기
→ 외부 장치

Exception
→ 동기
→ 명령어 실행 중 발생

Exception 종류
- Fault : 복구 가능 (재실행)
- Trap : 의도적 발생
- Abort : 치명적 오류
```
