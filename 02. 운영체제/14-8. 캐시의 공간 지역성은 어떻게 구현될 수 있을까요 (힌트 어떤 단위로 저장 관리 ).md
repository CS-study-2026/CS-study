# 14-8. 캐시의 공간 지역성은 어떻게 구현될 수 있을까요? (힌트: 어떤 단위로 저장/관리?)

정답 : "캐시 라인(Cache Line) 단위로 데이터를 저장하고 관리합니다."

## 0. 공간 지역성

특정 메모리 위치에 접근하면 그 주변에 있는 데이터도 가까운 미래에 접근할 가능성이 높다는 특성

인접한 메모리 주소의 데이터가 함께 사용되는 경향을 의미하며, CPU는 이를 활용해 캐시라인 단위로 주변     데이터까지 함께 적재

---

## 1. Caching Line

**CPU는 데이터를 Byte 단위로 저장하지 않고, Cache Line 단위로 관리**

⇒ 캐시에 데이터를 저장할 때, **특정 자료구조를 사용해 묶음으로 저장**하게 되는데 이를 캐싱라인이라고 함

캐시 라인이란, 캐시가 데이터를 저장하는 최소 단위로 현대 CPU는 대부분 `64Byte` 단위의 캐시라인을 사용

예시 :

```java
int[] arr = new int[100];

int = 4 Byte

64 / 4 = 16

즉, arr[0] ~ arr[15]를 한 번에 캐시에 적재하는 방식.
int 기준 배열 16개 원소를 한번에 가져옴
```

---

## 2. 하드웨어 프리페처(Prefetcher)

조금 더 깊게 들어가면, 현대 CPU는 여기서 더 나아간다.

단순히 캐시라인만 가져오는 것이 아니라 미래 접근을 예측한다.

예시 :

```java
for(int i=0;i<10000;i++)
{
    sum += arr[i];
}

1. arr[0] 읽음
2. CPU는 0, 1, 2, ... 순으로 접근한다는 패턴 감지
3. CPU가 프로그램이 요청하기도 전에, arr[16]~arr[31]을 미리 가져옴
```

> 💡 즉, 공간 지역성을 활용하는 방법은 크게 Cache Line, Prefetching 두 가지로 볼 수 있음

---

## 3. 캐시라인 정렬(Cache Line Alignment)

성능 최적화 영역에서는, 데이터를 캐시라인 경계에 맞춰 배치하는 전략을 사용하기도 함

예시 :

```java
64 Byte 캐시라인을 사용하는 CPU에서
객체가 60 Byte 라면?

다음 객체 일부가 같은 캐시라인에 섞여서 들어갈 수 있음
```

→ 이 경우, 멀티스레드 환경에서는 `False Sharing` 문제가 발생 가능

> 💡 False Sharing 이란?

실제로는 서로 다른 변수를 저장하는데, CPU 입장에서는 같은 캐시라인에 들어있기 때문에 서로 간섭하는 현상

예를 들어 캐시라인 크기가 64 Byte고 객체가 이렇게 생기면

```java
class Counter {
	volatile long a;
	volatile long b;
}

메모리상
|-------- Cache Line (64B) --------|
|    a(8B)    |    b(8B)           |
a와 b가 같은 캐시라인 안에 들어있다.

Thread1 ->a증가
Thread2 ->b증가 수행 시,
```

개발자 입장 : a와 b는 서로 다른 변수자나

CPU 입장 : CPU 캐시는 변수 단위 X,  캐시라인 단위 O

---

CPU1

```plain text
a 수정
```

↓

```plain text
캐시라인 전체 변경
```

↓

```plain text
다른 CPU의 동일 캐시라인 무효화
```

---

CPU2

```plain text
b 수정
```

↓

```plain text
캐시라인 전체 변경
```

↓

```plain text
CPU1 캐시 무효화
```

---

계속 반복된다.

```plain text
CPU1 수정
→ CPU2 캐시 무효화

CPU2 수정
→ CPU1 캐시 무효화

CPU1 수정
→ CPU2 캐시 무효화
```

---

결과

```plain text
메모리 동기화 폭증
캐시 미스 증가
성능 급락
```

# 왜 False(가짜) Sharing인가?

실제로는

```plain text
Thread1 -> a
Thread2 -> b
```

라서

데이터를 공유하지 않는다.

그런데 같은 캐시라인에 들어있다는 이유만으로CPU는 공유한다고 판단한다.

그래서 가짜 공유(False Sharing) 라고 부른다.

### 해결 방법

1. Padding : 사이에 빈 공간을 넣어서 서로 다른 캐시라인에 위치하도록 하는 방식

```java
| a | padding ......... |

| b | padding ......... |
```

1. `@Contended` JVM이 알아서 a(Padding)을 넣어주는 방식으로, 내부적으로 각 변수 주변에 패딩 삽입

```java
import jdk.internal.vm.annotation.Contended;

class Counter {

    @Contended
    volatile long a;

    @Contended
    volatile long b;
}
```
