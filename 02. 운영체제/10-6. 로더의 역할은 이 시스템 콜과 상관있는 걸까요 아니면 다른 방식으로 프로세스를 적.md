# **10-6.** 로더의 역할은 이 시스템 콜과 상관있는 걸까요? 아니면 다른 방식으로 프로세스를 적재할 수 있는 건가요?

# **10-6.** 우리는 흔히 fork(), exec() 시스템 콜을 사용하여 프로세스를 적재할 수 있다고 배웠습니다. 로더의 역할은 이 시스템 콜과 상관있는 걸까요? 아니면 다른 방식으로 프로세스를 적재할 수 있는 건가요?

# 🧠 fork(), exec()와 로더(Loader)의 관계

## 1️⃣ 핵심 질문 정리

👉 “프로세스를 생성할 때 사용하는 fork(), exec()와

OS의 로더(Loader)는 어떤 관계가 있는가?”

---

## 2️⃣ 결론 먼저

👉 **로더는 exec()와 직접적으로 깊은 관계가 있다**

👉 fork()는 “복제”, exec()는 “교체”, loader는 “적재 담당”

즉,

```plain text
fork() → 프로세스 복사
exec() → 새로운 프로그램으로 덮어쓰기 (이때 Loader 동작)
```

---

### 3️⃣ 각 역할 분리

## 1) fork()

### 📌 정의

- 현재 프로세스를 그대로 복제

- 새로운 PID 생성

---

### 📌 특징

- 부모 프로세스와 동일한 메모리 구조

- Copy-on-Write 방식 사용

---

### 📌 역할

👉 “프로세스 복사”

```plain text
부모 → 자식 프로세스 생성
```

---

## 2) exec()

### 📌 정의

- 현재 프로세스를 새로운 프로그램으로 교체

---

### 📌 특징

- 기존 코드, 데이터 모두 제거

- 새로운 실행 파일 로드

---

### 📌 핵심

👉 여기서 **Loader가 동작**

---

## 3) Loader (로더)

### 📌 정의

👉 실행 파일을 메모리에 올리는 OS 구성 요소

---

### 📌 역할

- 실행 파일(.exe, ELF 등) 로드

- 코드/데이터를 메모리에 배치

- Stack, Heap 초기화

- 프로그램 시작 주소 설정

---

# 4️⃣ 전체 흐름 (fork + exec)

```plain text
1. fork()
   ↓
프로세스 복제

2. exec()
   ↓
기존 프로세스 내용 삭제

3. Loader 동작
   ↓
새 프로그램 메모리에 적재

4. CPU 실행 시작
```

---

# 5️⃣ Loader는 exec() 내부에서 동작한다

## 📌 중요한 포인트

👉 Loader는 독립적으로 실행되는 개념이 아니라

👉 **exec() 시스템 콜 내부에서 호출되는 OS 기능**

---

### 📌 즉 구조

```plain text
exec()
 └── Loader
      ├── ELF 분석
      ├── 메모리 적재
      └── 실행 준비
```

---

# 6️⃣ 왜 fork()와 exec()를 나눠 쓰는가

## 1. 유연성

- fork() → 상태 복제

- exec() → 프로그램 교체

👉 둘을 분리해서 다양한 실행 모델 구현 가능

---

## 2. Shell 구조

예:

```bash
ls
```

실제 내부 동작:

```plain text
fork()
exec("ls")
```

---

## 3. Copy-on-Write 최적화

- fork 후 exec 하면 메모리 낭비 최소화

---

# 7️⃣ 다른 방식으로 프로세스 적재 가능?

## 📌 가능 여부

👉 “직접 Loader 없이 실행?” → 불가능

---

## 📌 이유

프로세스 실행에는 반드시 필요:

- 코드 적재

- 메모리 배치

- 초기화

👉 이 역할이 Loader

---

## 📌 다만 형태는 다양함

| 방식 | 설명 |
| --- | --- |
| exec() | 표준 방식 (OS 제공 Loader 사용) |
| LoadLibrary (Windows) | DLL 동적 로딩 |
| mmap() | 메모리 직접 매핑 |

---

👉 하지만 공통점:

**결국 Loader 기능을 간접적으로 사용**

---

# 8️⃣ 핵심 구조 정리

```plain text
fork() → 프로세스 생성
exec() → 프로그램 교체
Loader → 실제 실행 파일 메모리 적재
```

---

# 📌 핵심 요약

- fork(): 프로세스 복제

- exec(): 프로그램 교체

- Loader: 실행 파일을 메모리에 적재

- Loader는 exec() 내부에서 동작

- 프로세스 실행에는 반드시 Loader가 필요
