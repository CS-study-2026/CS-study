# 17-0. 가상 메모리란 무엇인가요?

# 가상 메모리(Virtual Memory)란 무엇인가요?

## 한 줄 정의

> **프로세스가 실제 물리 메모리(RAM)보다 더 큰 메모리를 사용하는 것처럼 보이게 만드는 메모리 관리 기법**입니다.

---

# 왜 필요할까?

예를 들어,

```plain text
RAM : 8GB
실행하려는 프로그램 : 20GB
```

물리 메모리만 사용한다면 실행 불가.

하지만 **가상 메모리**를 사용하면 운영체제가:

> 📢 

  - 현재 **필요한 데이터만 RAM**에 올리고

  - **나머지는 디스크(Swap 영역)에 저장**

하여 프로그램이 실행될 수 있도록 한다.

> ❓ 

  <details>
  <summary>디스크? Swap?</summary>

> **Swap 영역은 RAM이 부족할 때 사용하지 않는 메모리 데이터를 임시로 저장하는 SSD/HDD의 일부 공간이다.**

### 동작 과정

```plain text
RAM 부족
↓
사용하지 않는 페이지를 Swap으로 이동
↓
나중에 필요하면 다시 RAM으로 복구
```

### 왜 필요한가?

    - RAM보다 큰 프로그램도 실행 가능

    - 일시적인 메모리 부족 상황 완화

### 단점

    - SSD/HDD는 RAM보다 훨씬 느림

    - Swap 사용이 많아지면 성능이 크게 저하됨
  </details>

---

# 가상 메모리의 핵심 아이디어

> 가상 메모리는 **각 프로세스에게 독립적이고 연속된 메모리 공간을 가진 것처럼 보이게 하는 기술**이다.

즉, 실제 RAM은 여러 프로세스가 나눠 쓰고 있지만, 각 프로세스는 마치 이렇게 생각한다.

```plain text
“이 메모리 공간은 전부 내 것이다.”
```

---

# 1. 프로세스는 가상 주소를 사용한다

프로그램이 실행되면 프로세스가 된다.

이때 프로세스는 실제 RAM 주소를 직접 사용하지 않는다.

```plain text
실제 RAM의 주소 = 물리 주소
프로세스가 사용하는 주소 = 가상 주소🌟
```

예를 들어 프로세스 A가 다음 주소에 접근한다고 하자.

```plain text
0x1000
```

이 주소는 실제 RAM의 0x1000번지를 의미하는 것이 아니다.

프로세스 A 입장에서는 `0x1000`이지만, **운영체제와 하드웨어가 이 가상 주소를 실제 물리 주소로 바꿔준다**.

---

# 2. 주소 변환이 필요하다

프로세스가 가상 주소를 사용하기 때문에 CPU가 RAM에 접근하려면 **주소 변환**이 필요하다.

```plain text
가상 주소
↓
주소 변환
↓
물리 주소
↓
RAM 접근
```

이 주소 변환은 주로 **MMU**와 **페이지 테이블**을 통해 이루어진다.

```plain text
프로세스
  ↓ 가상 주소
CPU / MMU
  ↓ 페이지 테이블 참고
물리 주소
  ↓
RAM
```

> ❓ 

  <details>
  <summary>MMU? </summary>

## 한 줄 정의

> **가상주소를 물리주소로 변환해주는 하드웨어 장치 (Memory Management Unit)**

---

CPU 내부(정확히는 CPU와 매우 밀접한 하드웨어)에 존재한다.

동작 흐름:

```plain text
CPU
↓
가상주소 생성
↓
MMU
↓
물리주소 변환
↓
RAM 접근
```

---

# 그런데 MMU는 어떻게 변환할까?

여기서 등장하는 게

> 페이지 테이블(Page Table)

이다.
  </details>

  <details>
  <summary>페이지 테이블?</summary>

## 한 줄 정의

> **가상 페이지와 물리 프레임의 매핑 정보를 저장하는 테이블**

---

예를 들어:

### 가상 메모리

```plain text
Page 0
Page 1
Page 2
Page 3
```

---

### 물리 메모리(RAM)

```plain text
Frame 5
Frame 1
Frame 8
Frame 2
```

---

페이지 테이블은

```plain text
Page 0 → Frame 5
Page 1 → Frame 1
Page 2 → Frame 8
Page 3 → Frame 2
```

를 저장한다.

---

# 🌟 실제 주소 변환 예시

프로세스가:

```plain text
가상주소 0x1234
```

에 접근했다고 하자.

---

## 1단계

가상주소를 나눈다.

```plain text
[페이지 번호] [오프셋]
```

예시:

```plain text
Page 2
Offset 34
```

---

## 2단계

MMU가 페이지 테이블 조회

```plain text
Page 2 → Frame 8
```

발견

---

## 3단계

물리주소 생성

```plain text
Frame 8 + Offset 34
```

---

결과:

```plain text
물리주소 0x8234
```
  </details>

---

# 3. 프로세스마다 같은 가상 주소를 가질 수 있다

가상 메모리의 중요한 특징은 **프로세스마다 독립적인 주소 공간을 가진다**는 것이다.

예를 들어 프로세스 A와 B가 모두 `0x1000`이라는 주소를 사용할 수 있다.

```plain text
프로세스 A의 0x1000 → RAM의 0x5000
프로세스 B의 0x1000 → RAM의 0x9000
```

겉으로는 둘 다 `0x1000`을 사용하지만, 실제로는 서로 다른 물리 메모리에 연결된다.

그래서 프로세스 A가 자기 메모리를 수정해도 프로세스 B의 메모리가 바뀌지 않는다.

---

# 4. 그래서 메모리 보호가 가능하다

가상 메모리가 없으면 한 프로세스가 다른 프로세스의 메모리를 잘못 건드릴 위험이 커진다.

하지만 가상 메모리에서는 운영체제가 각 프로세스의 주소 공간을 분리한다.

```plain text
프로세스 A → A의 가상 주소 공간만 접근 가능
프로세스 B → B의 가상 주소 공간만 접근 가능
```

만약 프로세스 A가 허용되지 않은 주소에 접근하면 운영체제가 막는다.

대표적으로 이런 에러가 발생할 수 있다.

```plain text
Segmentation Fault
: 프로세스가 접근 권한이 없거나 존재하지 않는 메모리에 접근하려고 할 때 운영체제가 프로그램을 강제 종료시키는 오류
```

---

# 5. 실제 RAM보다 큰 메모리를 쓰는 것처럼 보일 수 있다

가상 메모리는 RAM에 모든 데이터를 항상 올려두지 않는다.

**현재 필요한 부분만 RAM에 올리고, 당장 필요하지 않은 부분은 디스크의 Swap 영역에 둘 수 있다.**

```plain text
프로세스 전체 메모리
├─ 자주 쓰는 부분 → RAM
└─ 당장 안 쓰는 부분 → Swap
```

프로세스 입장에서는 전체 메모리가 있는 것처럼 보이지만, 실제로는 일부만 RAM에 올라와 있다.

---

# 6. 페이지 단위로 관리한다

가상 메모리는 보통 메모리를 일정한 크기의 조각으로 나누어 관리한다.

이 조각을 **페이지(Page)** 라고 한다.

> ❓ 

  <details>
  <summary>페이지?</summary>

## 한 줄 정의

> **가상 메모리를 일정한 크기로 잘라놓은 조각**

예를 들어 운영체제가:

```plain text
1 Page = 4KB
```

로 정했다고 가정하자.

---

프로세스가 사용하는 가상 메모리

```plain text
16KB
```

가 있으면

이걸 이렇게 나눈다.

```plain text
가상 메모리

Page 0 (4KB)
Page 1 (4KB)
Page 2 (4KB)
Page 3 (4KB)
```

즉,

> 페이지 = 메모리 관리 단위

라고 생각하면 된다.

---

# 왜 굳이 페이지로 나눌까?

    - 바이트로 관리하면 매우 비효율적이니까 .. 묶어서 관리하자!

---

그래서 운영체제는

```plain text
4KB 단위
```

같은 큰 덩어리로 묶는다.

```plain text
[4KB]
[4KB]
[4KB]
[4KB]
```

이 조각이 페이지다.

---
  </details>

```plain text
가상 메모리
├─ Page 0
├─ Page 1
├─ Page 2
└─ Page 3
```

물리 메모리도 비슷하게 **프레임(Frame)** 이라는 단위로 나뉜다.

```plain text
RAM
├─ Frame 0
├─ Frame 1
├─ Frame 2
└─ Frame 3
```

운영체제는 페이지와 프레임을 매핑한다. (`MMU`와 `페이지테이블`로!)

```plain text
Page 0 → Frame 3
Page 1 → Frame 7
Page 2 → Swap
Page 3 → Frame 1
```

즉, 가상 주소 공간은 연속되어 보이지만 실제 RAM에서는 흩어져 있을 수 있다.

---

# 7. 페이지 폴트가 발생할 수 있다

프로세스가 어떤 페이지에 접근했는데 그 페이지가 RAM에 없고 Swap에 있다면 바로 실행할 수 없다.

이때 **Page Fault**가 발생한다.

```plain text
프로세스가 Page 2 접근
↓
Page 2가 RAM에 없음
↓
Page Fault 발생 🚨
↓
OS가 Swap에서 Page 2를 RAM으로 가져옴
↓
다시 실행
```

Page Fault 자체는 정상적인 가상 메모리 동작의 일부다.

다만 너무 자주 발생하면 성능이 크게 떨어진다.

---

# 8. 정리하면

가상 메모리의 핵심은 다음과 같다.

```plain text
프로세스는 가상 주소를 사용한다.
운영체제와 MMU가 가상 주소를 물리 주소로 변환한다.
각 프로세스는 독립적인 주소 공간을 가진다.
실제 RAM에는 필요한 부분만 올라간다.
부족한 부분(페이지 폴트)은 Swap을 활용할 수 있다.
```
