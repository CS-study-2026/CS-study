# 18-1. 페이지와 프레임의 차이에 대해 설명해 주세요.

> 💡 이 두 가지는 앞서 설명한 **외부 단편화** 문제를 **하드웨어적**으로 해결하기 위해 고안된 **페이징(Paging)** 기법의 핵심 단위들.

  - 페이징은 불연속 할당

메모리를 물리적, 논리적으로 어떻게 바라보느냐에 따라 이름이 다르다.

### 프레임 (Frame) - 물리

- **정의**

  - 실제 하드웨어인 물리적 메모리(RAM)를 일정한 크기(고정 크기)로 일률적으로 쪼개어 놓은 물리적 블록 단위.

- **특징**

  - 보통 4KB 크기를 많이 사용. RAM에 4KB 크기의 격자눈금을 그려놓은 물리적인 칸 하나하나가 프레임.

<details>
<summary>그럼 연속 할당 방식인 고정 분할인가요?</summary>

아뇨? `연속 할당`인 `고정 분할 방식`은 프로세스가 들어왔을 때 한 번에 넣을 수 있는 파티션을 찾아야 하지만, 프레임은 프로세스가 들어왔을 때 크기가 맞지 않는다면 연속성을 파괴하고 쪼개서 넣어버립니다.
</details>

### 페이지 (Page) - 논리

- **정의**

  - 프로세스가 사용하는 가상 메모리(논리적 메모리)를 프레임과 완전히 동일한 크기로 쪼개어 놓은 논리적 블록 단위.

- **특징**

  - CPU가 다루는 프로세스의 코드가 4KB 단위로 잘려진 조각입니다.

# 🪄 가상 메모리 (Virtual Memory): "속이는 자와 속는 자"

## 1. 도입: 왜 이런 마술이 필요할까?

질문자님의 컴퓨터 RAM이 **16GB**라고 가정해 보겠습니다.
그런데 배틀그라운드 같은 고사양 게임은 용량이 **50GB**가 넘습니다. 게다가 게임을 켜둔 채로 디스코드(메신저)도 하고 유튜브도 봅니다.

상식적으로 16GB짜리 방에 50GB가 넘는 짐이 들어갈 수 없는데, 컴퓨터는 안 터지고 잘 돌아갑니다. 어떻게 가능할까요? 바로 **운영체제가 프로그램들을 완벽하게 '속이고 있기' 때문**입니다.

## 2. 가상 메모리의 개념

가상 메모리란, **실제 RAM 용량과 상관없이 프로세스(프로그램)에게 "너 혼자 쓸 수 있는 엄청나게 크고 독립적인 메모리 공간이 있어!"**라고 환상을 만들어주는 기술입니다.

프로세스 입장에서는 "오, 나한테 100GB짜리 텅 빈 메모리가 주어졌네? 마음껏 써야지!" 하고 짐을 마구 풉니다. 하지만 실제로는 그렇지 않죠.

## 3. 어떻게 속이는 걸까? (동작 원리)

운영체제는 RAM(빠르지만 비싸고 좁음)과 하드디스크/SSD(느리지만 싸고 아주 넓음)를 합쳐서 하나의 메모리처럼 사용합니다. 하드디스크의 일부분을 메모리처럼 빌려 쓰는 이 공간을 '스왑 영역(Swap Space)'이라고 부릅니다.

아까 우리가 배운 '페이징(Paging)'을 여기서 써먹습니다.

  - **50GB짜리 게임을 켤 때:** 운영체제는 50GB를 4KB짜리 '페이지'로 다 조각냅니다.

  - **올려놓기:** 그리고 50GB 전체를 RAM에 올리지 않습니다! **"당장 지금 캐릭터가 서 있는 마을 주변의 데이터(페이지)" 몇 개만 RAM의 프레임에 올려놓습니다.**

  - **숨겨두기:** 당장 안 쓰는 나머지 99%의 페이지들(저 멀리 있는 다른 마을 데이터, 엔딩 크레딧 등)은 전부 하드디스크(스왑 영역)에 잠재워 둡니다.

## 4. 핵심 메커니즘: 스와핑(Swapping)과 페이지 부재(Page Fault)

캐릭터가 텔레포트를 해서 다른 마을로 이동했다고 해봅시다.

  1. **페이지 부재 (Page Fault 발생!):** CPU가 "새로운 마을 데이터(페이지) 가져와!" 했는데, RAM(책상)을 뒤져보니 없습니다. (이 상황을 페이지 부재라고 합니다.)

  1. **스왑 아웃 (Swap-out):** RAM도 꽉 찼습니다. 그래서 당장 안 쓸 것 같은 아까 전 마을 데이터를 하드디스크로 쫓아냅니다. _(이때 누구를 쫓아낼지 결정하는 게 아까 캐시에서 배운 LRU, FIFO 같은 교체 알고리즘입니다!)_

  1. **스왑 인 (Swap-in):** 방금 비워진 RAM의 빈 프레임에 하드디스크에서 자고 있던 새로운 마을 데이터를 불러와서 끼워 넣습니다.
</details>

### 페이지와 프레임의 관계 (매핑)

- **크기 일치**

  - 페이지 1개의 크기 = 프레임 1개의 크기 (예: 둘 다 4KB)

- **동작 원리**

  - CPU가 프로세스를 실행하려면, 논리적인 '페이지' 조각들을 실제 RAM의 빈 '프레임' 칸에 끼워 넣어야 합니다.

  - 페이지 크기와 프레임 크기가 완벽하게 같아서, RAM에 빈 프레임만 있다면 순서에 상관없이 여기저기 흩어져서 들어갈 수 있습니다.

- **결과**

  - 빈 공간을 찾아 연속적으로 넣을 필요가 없으므로 외부 단편화 문제가 100% 해결됩니다.
