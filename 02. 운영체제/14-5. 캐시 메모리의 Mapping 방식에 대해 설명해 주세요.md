# 14-5. 캐시 메모리의 Mapping 방식에 대해 설명해 주세요

# 14-5. 캐시 메모리의 Mapping 방식에 대해 설명해 주세요

## 1. 캐시 Mapping이란?

CPU가 메모리의 어떤 데이터를 가져올 때, 그 데이터는 캐시에 저장될 수 있어.

그런데 캐시는 RAM보다 훨씬 작기 때문에 모든 데이터를 다 담을 수 없어.

그래서 중요한 질문이 생긴다.

> 메인 메모리의 특정 블록을 캐시의 어느 위치에 저장할 것인가?

이 규칙을 **캐시 매핑 방식**이라고 해.

---

## 2. 캐시는 보통 블록 단위로 관리된다

캐시는 데이터를 1바이트씩 저장하는 게 아니라 보통 **캐시 라인**, 또는 **블록** 단위로 저장해.

예를 들어 캐시 라인 크기가 64바이트라면, 메모리에서 어떤 주소 하나를 가져올 때 그 주변 64바이트를 함께 캐시에 올려.

```plain text
메모리 주소 하나 접근
→ 해당 주소가 포함된 64바이트 블록을 캐시에 적재
```

이게 공간 지역성과 연결돼.

---

## 3. 주소는 보통 세 부분으로 나뉜다

캐시에서 주소를 찾을 때 메모리 주소는 보통 이렇게 나뉘어.

```plain text
| Tag | Index | Offset |
```

각각의 의미는 이렇다.

| 구분 | 의미 |
| --- | --- |
| Tag | 캐시에 들어온 블록이 어느 메모리 블록인지 식별 |
| Index | 캐시의 어느 위치, 또는 어느 set을 볼지 결정 |
| Offset | 캐시 라인 안에서 몇 번째 바이트인지 결정 |

예를 들어 CPU가 어떤 주소에 접근하면:

```plain text
1. Index로 캐시의 특정 위치 또는 set을 찾음
2. Tag를 비교해서 원하는 데이터인지 확인
3. 맞으면 cache hit
4. 틀리면 cache miss
5. Offset으로 캐시 라인 내부의 실제 데이터를 선택
```

---

# 4. 캐시 Mapping 방식 3가지

캐시 매핑 방식은 크게 세 가지가 있어.

```plain text
1. Direct Mapping
2. Fully Associative Mapping
3. Set Associative Mapping
```

---

# 1. Direct Mapping

## 개념

**메인 메모리의 각 블록이 캐시의 정확히 한 위치에만 들어갈 수 있는 방식**이야.

즉, 메모리 블록 번호를 캐시 라인 수로 나눈 나머지로 위치가 정해진다.

```plain text
캐시 위치 = 메모리 블록 번호 % 캐시 라인 수
```

예를 들어 캐시 라인이 4개라고 하자.

```plain text
메모리 블록 0 → 캐시 라인 0
메모리 블록 1 → 캐시 라인 1
메모리 블록 2 → 캐시 라인 2
메모리 블록 3 → 캐시 라인 3
메모리 블록 4 → 캐시 라인 0
메모리 블록 5 → 캐시 라인 1
```

여기서 메모리 블록 0과 4는 둘 다 캐시 라인 0에만 들어갈 수 있어.

---

## 장점

| 장점 | 설명 |
| --- | --- |
| 구조가 단순함 | 위치 계산이 쉬움 |
| 빠름 | 비교해야 할 후보가 적음 |
| 하드웨어 구현 비용이 낮음 | 회로가 단순함 |

---

## 단점

**충돌 miss가 많이 발생할 수 있어.**

예를 들어 메모리 블록 0과 4를 번갈아 접근한다고 해보자.

```plain text
블록 0 접근 → 캐시 라인 0에 저장
블록 4 접근 → 캐시 라인 0에 저장, 블록 0 제거
블록 0 접근 → 다시 miss
블록 4 접근 → 다시 miss
```

실제로 캐시의 다른 라인은 비어 있어도, 두 블록이 같은 라인에만 들어갈 수 있기 때문에 계속 서로 밀어낸다.

이런 걸 **conflict miss**라고 해.

---

## 발표용 문장

> Direct Mapping은 메모리 블록이 캐시의 특정 한 위치에만 매핑되는 방식입니다. 구현이 단순하고 빠르지만, 서로 같은 캐시 라인에 매핑되는 블록들을 번갈아 접근하면 conflict miss가 많이 발생할 수 있습니다.

---

# 2. Fully Associative Mapping

## 개념

**메인 메모리의 어떤 블록이든 캐시의 어느 위치에나 들어갈 수 있는 방식**이야.

```plain text
메모리 블록 0 → 캐시 어느 라인이든 가능
메모리 블록 1 → 캐시 어느 라인이든 가능
메모리 블록 2 → 캐시 어느 라인이든 가능
```

즉, 위치 제한이 없어.

---

## 장점

충돌 miss가 가장 적어.

Direct Mapping에서는 특정 위치가 겹치면 계속 충돌이 났지만, Fully Associative에서는 빈 곳이 있으면 어디든 넣을 수 있어.

```plain text
블록 0 → 캐시 라인 0
블록 4 → 캐시 라인 1
```

이런 식으로 둘 다 저장 가능해.

---

## 단점

찾을 때 비용이 크다.

왜냐하면 원하는 블록이 캐시의 어느 위치에든 있을 수 있으니까, 모든 캐시 라인의 Tag를 비교해야 해.

```plain text
캐시 전체 라인의 Tag를 동시에 비교해야 함
```

그래서 하드웨어 비용이 크고, 캐시가 클수록 구현이 부담스러워.

또 어디든 넣을 수 있으므로, 캐시가 꽉 찼을 때 어떤 블록을 제거할지 결정하는 replacement policy가 필요해.

예를 들어:

```plain text
LRU
FIFO
Random
```

같은 정책을 사용할 수 있어.

---

## 발표용 문장

> Fully Associative Mapping은 메모리 블록이 캐시의 어느 위치에나 들어갈 수 있는 방식입니다. 충돌 miss를 줄일 수 있지만, 캐시 전체에서 Tag를 비교해야 하므로 하드웨어 비용이 크고 구현이 복잡합니다.

---

# 3. Set Associative Mapping

## 개념

**Direct Mapping과 Fully Associative Mapping의 절충 방식**이야.

캐시를 여러 개의 set으로 나누고, 메모리 블록은 특정 set에만 들어갈 수 있어.

다만 그 set 안에서는 여러 위치 중 하나에 들어갈 수 있어.

예를 들어 **2-way set associative cache**라고 하자.

```plain text
각 set마다 캐시 라인 2개
```

캐시가 총 8라인이고 2-way라면:

```plain text
총 캐시 라인: 8개
한 set당 라인: 2개
set 개수: 4개
```

메모리 블록은 특정 set으로 매핑된다.

```plain text
set 번호 = 메모리 블록 번호 % set 개수
```

그리고 해당 set 안의 2개 라인 중 하나에 저장될 수 있어.

---

## 예시

캐시가 2-way이고 set이 4개라고 하자.

```plain text
Set 0: line 0, line 1
Set 1: line 2, line 3
Set 2: line 4, line 5
Set 3: line 6, line 7
```

메모리 블록 0과 4는 둘 다 Set 0에 들어간다.

```plain text
블록 0 → Set 0
블록 4 → Set 0
```

하지만 Set 0 안에는 line이 2개 있으므로 둘 다 같이 들어갈 수 있다.

```plain text
Set 0:
line 0: 블록 0
line 1: 블록 4
```

Direct Mapping보다 충돌이 줄어든다.

---

## N-way의 의미

```plain text
2-way set associative
→ 한 set에 캐시 라인 2개

4-way set associative
→ 한 set에 캐시 라인 4개

8-way set associative
→ 한 set에 캐시 라인 8개
```

way 수가 커질수록 Fully Associative에 가까워지고, 충돌 miss는 줄어든다.

하지만 그만큼 set 안에서 비교해야 할 Tag 수가 늘어나서 하드웨어 비용과 지연이 증가할 수 있어.

---

## 장점

| 장점 | 설명 |
| --- | --- |
| Direct보다 충돌 miss가 적음 | 한 set 안에 여러 블록 저장 가능 |
| Fully보다 구현 비용이 낮음 | 전체 캐시가 아니라 set 내부만 비교 |
| 실제 시스템에서 많이 사용 | 성능과 비용의 균형이 좋음 |

---

## 단점

| 단점 | 설명 |
| --- | --- |
| Direct보다 구조가 복잡함 | 여러 way의 Tag 비교 필요 |
| Fully보다는 충돌 가능성이 있음 | set은 고정되어 있음 |
| replacement policy 필요 | set 안에서 어떤 라인을 제거할지 결정해야 함 |

---

## 발표용 문장

> Set Associative Mapping은 캐시를 여러 set으로 나누고, 메모리 블록은 특정 set에 매핑되지만 그 set 안에서는 여러 way 중 하나에 저장될 수 있는 방식입니다. Direct Mapping보다 conflict miss를 줄이고, Fully Associative보다 구현 비용이 낮기 때문에 실제 캐시에서 많이 사용되는 절충 방식입니다.

---

# 5. 세 방식 비교

| 방식 | 저장 위치 | 장점 | 단점 |
| --- | --- | --- | --- |
| Direct Mapping | 정해진 한 라인 | 빠르고 단순함 | conflict miss가 많을 수 있음 |
| Fully Associative | 캐시 어디든 가능 | conflict miss가 가장 적음 | 전체 Tag 비교 필요, 비용 큼 |
| Set Associative | 정해진 set 안의 여러 way | 성능과 비용의 균형 | set 내부 replacement 필요 |

---

# 6. Cache Miss 종류와 연결

캐시 miss는 보통 세 가지로 나눠서 설명할 수 있어.

| Miss 종류 | 의미 |
| --- | --- |
| Compulsory miss | 처음 접근해서 발생하는 miss |
| Capacity miss | 캐시 용량 자체가 부족해서 발생하는 miss |
| Conflict miss | 매핑 위치가 겹쳐서 발생하는 miss |

Mapping 방식은 특히 **conflict miss**와 관련이 깊어.

```plain text
Direct Mapping
→ conflict miss 발생 가능성 큼

Fully Associative
→ conflict miss 거의 없음

Set Associative
→ conflict miss를 줄이는 절충안
```
