# **2-4.** 동시에 두 개 이상의 인터럽트가 발생하면, 어떻게 처리해야 하나요?

# ⚡ 동시에 두 개 이상의 인터럽트가 발생하면 어떻게 처리할까

## 1️⃣ 문제 상황

컴퓨터 시스템에서는 여러 장치가 동시에 이벤트를 발생시킬 수 있다.

예를 들어

- 키보드 입력 발생

- 네트워크 패킷 도착

- 디스크 I/O 완료

이러한 이벤트들은 **각각 인터럽트를 발생시킨다.**

즉,

```plain text
CPU 실행 중
↓
인터럽트 A 발생
↓
인터럽트 B 발생
```

이때 CPU는 **어떤 인터럽트를 먼저 처리해야 하는지 결정해야 한다.**

운영체제와 하드웨어는 이를 해결하기 위해 **인터럽트 우선순위와 인터럽트 중첩 구조**를 사용한다.

---

## 2️⃣ 인터럽트 우선순위 (Interrupt Priority)

각 인터럽트에는 **우선순위(priority)**가 존재한다.

CPU는 동시에 여러 인터럽트가 발생하면

**가장 우선순위가 높은 인터럽트부터 처리한다.**

처리흐름

```javascript
여러 인터럽트 발생
↓
인터럽트 우선순위 비교
↓
가장 높은 인터럽트 먼저 처리
↓
나머지 인터럽트는 대기
```

**인터럽트 우선순위는 절대적인 표준이 있는 게 아니라, CPU/OS/설정에 따라 다르다**

→ 일반적으로 이해하는 우선순위

```javascript
[최우선]

전원 이상 / 하드웨어 오류

↓

타이머 인터럽트

↓

네트워크 / 중요 I/O

↓

일반 I/O

↓

SW 인터럽트 (system call)

[최하]
```

예시

```plain text
타이머 인터럽트
디스크 I/O 인터럽트
전원 이상 인터럽트
```

동시에 발생하면

```plain text
전원 이상 → 타이머 → I/O
```

순서로 처리된다.

---

## 3️⃣ 인터럽트 처리 방식 (두 가지)

## ① 인터럽트 중첩 (Interrupt Nesting)

인터럽트 처리 중에도 **더 높은 우선순위 인터럽트가 발생할 수 있다.**

이 경우

👉 현재 인터럽트 처리를 **일시 중단하고 더 높은 인터럽트를 먼저 처리한다.**

예

```plain text
Disk 인터럽트 처리 중
↓
Timer 인터럽트 발생 (더 높은 우선순위)
↓
Timer 먼저 처리
↓
Disk 인터럽트 처리로 복귀
```

이를 **인터럽트 중첩(Interrupt Nesting)** 이라고 한다.

---

## ② 인터럽트 마스킹 (Interrupt Masking)

특정 상황에서는 **인터럽트를 일시적으로 비활성화해야 할 수도 있다.**

예

- 커널의 중요한 코드 실행 중

- 데이터 구조 수정 중

👉 현재 인터럽트를 처리하는 동안 **특정 우선순위 이하 인터럽트를 막는다.**

즉,

```plain text
특정 인터럽트 비활성화
↓
중요 작업 수행
↓
인터럽트 다시 활성화
```

이를 통해 시스템 안정성을 유지한다.

---

## 4️⃣ 실제 하드웨어 처리 방식 (Interrupt Controller)

현대 컴퓨터에서는 **인터럽트 컨트롤러**가 인터럽트를 관리한다.

대표적인 예

- **PIC (Programmable Interrupt Controller)**

- **APIC (Advanced Programmable Interrupt Controller)**

이 장치는

- 인터럽트 신호 수집

- 우선순위 결정

- CPU 전달

역할을 수행한다.

---

# 📌 핵심 정리

- 동시에 여러 인터럽트가 발생하면 **우선순위 기반으로 처리**

- 인터럽트는 **인터럽트 큐에 저장 후 순차 처리**

- 더 높은 우선순위 인터럽트가 발생하면 **인터럽트 중첩 발생**

- 필요 시 **인터럽트 마스킹**으로 일부 인터럽트 비활성화 가능

- 실제 시스템에서는 **인터럽트 컨트롤러**가 이를 관리

- 인터럽트 컨트롤러가 인터럽트 우선순위를 관리하고
CPU는 가장 높은 우선순위 인터럽트를 선택하여 처리한다.
