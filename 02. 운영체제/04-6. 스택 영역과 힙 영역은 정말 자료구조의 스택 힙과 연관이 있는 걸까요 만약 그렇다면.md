# 4-6. "스택"영역과 "힙"영역은 정말 자료구조의 스택/힙과 연관이 있는 걸까요? 만약 그렇다면, 각 주소공간의 동작과정과 연계해서 설명해 주세요.

> 

**Stack 영역 → 자료구조 Stack과 “강하게 관련 있음” (거의 동일한 동작)
Heap 영역 → 자료구조 Heap과 “거의 관련 없음” (이름만 유사)**

---

# ✅ 1. Stack 영역 vs 자료구조 Stack

> **거의 동일한 개념이다 (확실함)**

---

## 🔹 공통점 (핵심)

| 특징 | 메모리 Stack | 자료구조 Stack |
| --- | --- | --- |
| 구조 | LIFO | LIFO |
| 연산 | push / pop | push / pop |
| 접근 | top만 가능 | top만 가능 |

---

## 🔹 실제 동작 과정 (주소 공간 기준)

### 📌 함수 호출

```plain text
voidA() {B(); }
voidB() {C(); }
voidC() {}
```

---

### 🔹 실행 흐름

```plain text
Stack

[A]
[A, B]
[A, B, C]
```

---

### 🔹 반환 과정

```plain text
[A, B]
[A]
[]
```

👉 **가장 나중에 들어온 C가 가장 먼저 나감**

👉 완벽한 LIFO 구조

---

## 🔥 핵심

👉 Stack 영역은 단순히 이름만 같은 게 아니라

> **실제로 자료구조 Stack처럼 동작하도록 설계된 메모리 영역**

---

# ✅ 2. Heap 영역 vs 자료구조 Heap

> **거의 관련 없음**

---

## 🔹 자료구조 Heap

- 완전 이진 트리

- 우선순위 큐

- 정렬 구조

---

## 🔹 메모리 Heap

👉 실제 모습:

```plain text
[사용][빈][사용][사용][빈]
```

👉 특징:

- 구조 없음

- 정렬 없음

- 트리 구조 아님

---

## 🔹 실제 동작 과정

### 📌 malloc 호출

```c
int *p = malloc(100);
```

---

### 🔹 내부 동작 (개념적으로)

1. Heap에서 빈 공간 탐색

1. 적절한 크기 블록 선택

1. 필요하면 분할

1. 주소 반환

---

👉 이 과정에서 사용하는 것:

- free list

- buddy system

- slab allocator

# ✅ 전체 한 줄 요약

    - **free list** → “빈 공간 목록 관리”

    - **buddy system** → “2의 거듭제곱 단위로 쪼개고 합치는 방식”

    - **slab allocator** → “같은 크기 객체를 빠르게 재사용”

---

# ✅ 1. free list

## 🔹 개념

👉 **현재 힙에서 “비어 있는 메모리 블록들”을 리스트로 관리하는 방식**

---

## 🔹 구조

```plain text
[사용][빈][사용][빈][빈]
        ↑    ↑    ↑
     free list에 등록
```

👉 빈 공간들만 따로 연결 리스트로 관리

---

## 🔹 동작

### 📌 malloc

    1. free list에서

    1. 조건 맞는 블록 탐색 (First Fit 등)

    1. 필요하면 분할

    1. 반환

---

### 📌 free

    1. 해당 블록을 free list에 추가

    1. 주변이 비어 있으면 병합 (coalescing)

---

## 🔥 특징

    - 구현 간단

    - 유연함

    - ❗ 단점: **단편화 발생**

---

# ✅ 2. Buddy System

## 🔹 개념

👉 **메모리를 2의 거듭제곱 단위로 나눠 관리하는 방식**

---

## 🔹 구조 예시

전체 1024 byte:

```plain text
1024
├── 512
│   ├── 256
│   ├── 256
├── 512
```

---

## 🔹 동작

### 📌 malloc(100)

    - 100을 담을 수 있는 최소 2^n → 128

    - 1024 → 512 → 256 → 128로 계속 분할

---

### 📌 free

👉 “짝(buddy)” 블록이 비어 있으면 합침

```plain text
[128][128] → 256
```

---

## 🔥 특징

    - 빠른 할당/해제

    - 병합 쉬움

    - ❗ 단점: **내부 단편화 발생**

      - 100 요청 → 128 할당 (28 낭비)

---

# ✅ 3. Slab Allocator

## 🔹 개념

👉 **같은 크기의 객체를 미리 만들어두고 재사용하는 방식**

---

## 🔹 왜 등장했나?

👉 free list / buddy는:

    - 매번 할당/해제 비용 발생

    - fragmentation 문제

---

👉 그래서:

> **“자주 쓰는 객체는 미리 만들어두자”**

---

## 🔹 구조

예: 프로세스 구조체 저장

```plain text
Slab
[객체][객체][객체][객체]
```

---

## 🔹 동작

### 📌 할당

    - 빈 객체 하나 꺼내서 사용

---

### 📌 해제

    - 다시 slab으로 반환

---

## 🔥 특징

    - 매우 빠름 (거의 O(1))

    - fragmentation 거의 없음

    - 캐시 친화적

    - ❗ 단점: 다양한 크기 대응 어려움

---

# ✅ 4. 한 번에 비교

| 방식 | 특징 | 장점 | 단점 |
| --- | --- | --- | --- |
| free list | 빈 공간 리스트 | 유연 | 외부 단편화 |
| buddy system | 2^n 분할 | 병합 쉬움 | 내부 단편화 |
| slab allocator | 객체 재사용 | 매우 빠름 | 유연성 낮음 |
  </details>

👉 **이진 힙(Binary Heap) 사용 안 함**

---

## 🔥 핵심 

> Heap 영역은 **자료구조 Heap처럼 정렬/트리 구조를 가지지 않는다**

---

# ✅ 3. 왜 이름이 헷갈리게 같을까?

- Stack → “쌓다” → LIFO 구조

- Heap → “마구 쌓아둔 더미”

👉 즉,

- Stack → **규칙적으로 쌓는 구조**

- Heap → **무작위로 쌓인 공간**

---

# ✅ 4. 주소 공간 동작과 연결해서 정리

## 📌 Stack 영역

👉 동작:

- 함수 호출 → push

- 함수 종료 → pop

👉 특징:

- 항상 top에서만 변화

- 중간 접근 없음

- 단편화 없음

👉 → 자료구조 Stack과 동일

---

## 📌 Heap 영역

👉 동작:

- malloc → 임의 위치 할당

- free → 임의 위치 해제

👉 특징:

- 위치 랜덤

- 크기 가변

- 단편화 발생

👉 → 자료구조 Heap과 무관

---

# 🎯 최종 한 줄 정리

👉 **Stack 영역은 실제로 자료구조 Stack처럼 LIFO 방식으로 동작하지만, Heap 영역은 단순한 동적 메모리 공간일 뿐 자료구조 Heap과는 구조적으로 관련이 없다.**
