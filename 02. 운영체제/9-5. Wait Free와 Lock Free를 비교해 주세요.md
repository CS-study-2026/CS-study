# **9-5.** Wait Free와 Lock Free를 비교해 주세요.

# ⚡ Wait-Free vs Lock-Free

> Lock-Free는 “전체 진행”(누군가는 진행됨), Wait-Free는 “개별 스레드 진행”(모두가 반드시 완료됨)을 보장

## 1️⃣ 배경: 왜 Lock-Free 계열이 필요한가

멀티스레드 환경에서 공유 자원에 접근할 때 보통 **Lock(Mutex, synchronized)**을 사용한다.

하지만 Lock 기반 방식은 다음 문제가 있다.

- 스레드 대기 발생 (Blocking)

- Deadlock 가능성

- 우선순위 역전

- 성능 저하 (컨텍스트 스위칭 증가)

👉 이를 해결하기 위해 등장한 개념이 **Non-blocking 알고리즘**

---

## 2️⃣ Non-blocking 알고리즘이란

👉 다른 스레드의 **중단/지연 때문에 전체 진행이 멈추지 않는** 알고리즘

즉, **lock을 잡고 있는 스레드가 멈춰도 시스템이 멈추지 않음**

대표 종류

- Wait-Free

- Lock-Free

<details>
<summary>Obstruction-Free</summary>

- 경쟁이 없으면(progress in isolation) 완료 보장

  - 하지만 경쟁이 있으면 보장 없음 → 그래서 실무에서는 거의 안 씀
</details>

---

# 3️⃣ Lock-Free

## 📌 개념

Lock-Free는
👉 **전체 시스템이 항상 진행됨(progress)을 보장하는 알고리즘**

즉, 여러 스레드 중 **적어도 하나는 계속 성공적으로 작업 수행**

---

## 📌 특징

- 일부 스레드는 실패하고 재시도(retry) 가능

- 하지만 **전체 시스템은 멈추지 않음(global progress)**

- 주로 CAS(Compare-And-Swap) 사용

---

## 📌 예시 (CAS 기반)

→ 현재값==예상값 ? 교체 : 실패

```java
while (true) {
    int current = value.get();
    int next = current + 1;

    if (value.compareAndSet(current, next)) {
        break;
    }
}
```

👉 실패하면 재시도 (Spin)

---

## 📌 장점

- Deadlock 없음

- 높은 성능

- Lock 오버헤드 없음

---

## 📌 단점

- 특정 스레드는 계속 실패 가능 (Starvation)

- 구현 난이도 높음

---

# 4️⃣ Wait-Free

## 📌 개념

Wait-Free는
👉 **모든 스레드가 유한한 시간 내에 작업을 완료함을 보장**

---

## 📌 특징

- 어떤 스레드도 무한 대기하지 않음

- 각 연산이 **bounded step(정해진 횟수)** 안에 끝남
⇒ 최악의 경우 시간까지 예측 가능 → 실시간 시스템에서 중요

---

## 📌 핵심

👉 “모든 스레드 성공 보장”

---

## 📌 장점

- Starvation 없음

- 가장 안정적인 방식

---

## 📌 단점

<details>
<summary>구현 매우 어려움</summary>

**Helping**: 빠른 스레드가 느린 스레드의 작업을 대신 처리해줌

  1. 남의 작업 건드려야 함 → 각 스레드 작업 상태 공유 필요 → **상태 관리 복잡도 증가**

  1. **작업 순서 보장 문제**: linearizability (선형화), 정확한 commit 시점 필요

  1. **중복 실행 방지:** “이미 처리됨” 표시, CAS로 단 한 번만 성공하도록 제어

  1. **메모리 / 상태 폭발:** 각 스레드마다 요청기록, 완료여부, 결과를 저장 → 자료구조 커지고 복잡해짐

  1. **성능 역설:** 느린 스레드 때문에 빠른 스레드가 추가 작업 수행 → 전체 성능 떨어짐
</details>

- 오버헤드 큼(스레드 수에 비례해서 비용 증가 가능)

- 실무에서 거의 사용되지 않음

---

# 5️⃣ Wait-Free vs Lock-Free 비교

| 구분 | Lock-Free | Wait-Free |
| --- | --- | --- |
| 진행 보장 | 일부 스레드 | 모든 스레드 |
| Starvation | 가능 | 없음 |
| 성능 | 높음 | 상대적으로 낮음 |
| 구현 난이도 | 어려움 | 매우 어려움 |
| 사용 빈도 | 높음 | 매우 낮음 |

---

# 6️⃣ 직관적 이해

## Lock-Free

```plain text
여러 명이 문을 통과하려고 시도
→ 누군가는 계속 통과함
→ 하지만 어떤 사람은 계속 실패 가능
```

---

## Wait-Free

```plain text
모든 사람이 반드시 일정 시간 내 통과
→ 누구도 무한 대기하지 않음
```

---

# 7️⃣ 언제 사용하는가

## ✔️ Lock-Free

- 고성능 시스템

- 멀티코어 환경

- CAS 기반 자료구조

예

<details>
<summary>ConcurrentQueue</summary>

.NET에 있는 클래스
소속: `System.Collections.Concurrent`

특징

  - Thread-safe

  - Lock-Free 기반 (주로 CAS 사용)

  - FIFO 큐
</details>

<details>
<summary>Atomic 연산(원자적 연산)</summary>

- 정의: 연산이 중간에 끼어들 수 없이 한 번에 실행되는 변수

- 특징

  - 읽기 + 쓰기가 **쪼개지지 않음**

  - 다른 스레드가 중간에 개입 불가

- 예시: AtomicInteger(Java), Interlocked(C#)

- Atomic VS Lock

| 구분 | Atomic | Lock |
| --- | --- | --- |
| 방식 | CPU 명령 | 경우에 따라 커널 개입
(유저 모드(spin)/커널 모드(block)) |
| 속도 | 매우 빠름 | 느림 |
| 블로킹 | 없음 | 있음 |
| 난이도 | 높음 | 쉬움 |
</details>

---

## ✔️ Wait-Free

- 실시간 시스템

- 지연(latency)이 절대적으로 중요한 환경

예

- 금융 시스템

- 항공/임베디드 시스템

---

# 📌 핵심 요약

- 둘 다 Non-blocking 알고리즘

- Lock-Free → 시스템 전체 진행 보장(starvation 가능)

- Wait-Free → 모든 스레드 완료 보장(starvation 없음)

- Wait-Free가 더 강한 개념이지만 구현이 매우 어려움
