# **12-2.** Peterson's Algorithm 이 무엇이며, 한계점에 대해 설명해 주세요.

_두 개의 프로세스(또는 스레드)_가 **임계 구역(Critical Section)**에 동시에 들어가지 않도록 보장하는 **소프트웨어 기반 동기화 알고리즘**

※ Critical-section problem 의 **예전 버전** 해결 방법이다.

예전 버전이므로 현대 버전에 적용되는 것이 보장 되지 않지만 알고리즘 자체가 동기화 문제 해결 방법 들의 기반이 된다.

**1. 상호 배제 (Mutual Exclusion)**

: 한 번에 하나의 프로세스만이 임계 구역에 들어갈 수 있어야 합니다.

**2. 진행 (Progress)**

: 임계 구역에 들어가려는 프로세스가 없을 때, 어느 프로세스도 임계 구역에 들어갈 수 있어야 합니다.

**3. 한정 대기 (Bounded Waiting)**

: 각 프로세스는 임계 구역에 들어가기 위해 무한정 기다리지 않아야 합니다.

⇒ 위와 같은 요구사항을 만족해야

### 핵심 아이디어

공유 변수 2개를 사용하여  두 프로세스가 임계 영역에 동시에 진입(즉 경쟁 상태 발생)하는 것을 방지:

- `flag[i]` : i번 프로세스가 들어가고 싶은지 표시

- `turn` : 누구 차례인지

### 동작 흐름

1. 나 들어갈게 → `flag[i] = true`

1. 상대 먼저 해 → `turn = j`

1. 상대도 들어가고 싶고(turn이 상대라면) → 기다림

1. 아니면 진입

👉 즉, **서로 양보하면서 충돌을 방지**

**둘 다 들어가려 하면 → 서로 양보 → 마지막으로 양보한 사람이 기다린다**

```javascript
// 변수 선언
boolean flag[2] = {false, false};
int turn;

function process0() {
    while (true) {
        /* 1. 임계 구역 진입 요청 : 프로세스가 임계 구역(critical section)에 들어가고자 할 때, 
        자신의 flag를 true로 설정하여 진입 의사를 표시합니다.*/

        flag[0] = true;
        
      
        // 2. 양보 설정 :: 프로세스는 turn 변수를 상대방 프로세스의 번호로 설정하고, 
        //이를 통해 상대방 프로세스에게 양보할 의사를 나타냅니다.
        turn = 1;
        
        // 대기 상태: 프로세스는 상대방 프로세스의 flag가 true이고, 
        //turn이 상대방 프로세스의 번호인 동안 계속해서 기다립니다
        //(상대방 프로세스가 임계 구역에 들어가고자 할 경우 상대방에게 우선권을 주기 위함)
        while (flag[1] == true && turn == 1) {
            // busy-wait
        }
        
        // 4. 임계 구역 진입
        // 임계 구역에서 수행할 작업
        //: 상대방 프로세스가 임계 구역에 들어가고자 하지 않거나, 
        //turn이 자신의 번호로 설정될 때까지 기다린 후 임계 구역에 진입합니다.


        print("Process 0 in critical section")

        // 5. 임계 구역 종료 : 임계 구역에서의 작업을 마치면, 
        //자신의 flag를 false로 설정하여 임계 구역에서 나왔음을 알립니다.

        flag[0] = false;

        // 6. 비임계 구역 작업
        // 비임계 구역에서 수행할 작업
        print("Process 0 in non-critical section")
    }
}

function process1() {
    while (true) {
        // 1. 임계 구역 진입 요청
        flag[1] = true;
        
        // 2. 양보 설정
        turn = 0;
        
        // 3. 대기 상태
        while (flag[0] == true && turn == 0) {
            // busy-wait
        }

        // 4. 임계 구역 진입
        // 임계 구역에서 수행할 작업
        print("Process 1 in critical section")

        // 5. 임계 구역 종료
        flag[1] = false;

        // 6. 비임계 구역 작업
        // 비임계 구역에서 수행할 작업
        print("Process 1 in non-critical section")
    }
}
```

### 장점

- **Mutual Exclusion 보장** (동시에 못 들어감)

- **Deadlock 없음**

- **Bounded Waiting 보장**

---

### ❗ 한계점

1. **2개 프로세스만 가능**

  - 3개 이상이면 못 씀 (확장 어려움-  2개보다 많은 프로세스를 다룰 경우 알고리즘을 확장해야 하지만, 코드가 복잡해지고 효율성이 떨어질 수 있)

1. **Busy Waiting (Spin Lock)**

  - 계속 while 돌면서 CPU 낭비

1. **현대 CPU에서 안전하지 않을 수 있음**

👉 **메모리 재정렬 (Memory Reordering)** 문제

  - CPU / 컴파일러가 명령 순서를 바꿀 수 있음

  - 의도한 순서 보장이 깨짐

    - **Instruction Reordering (명령어 재배치)**:
현대 CPU와 컴파일러는 성능 최적화를 위해 코드의 실행 순서를 바꿉니다. 피터슨 알고리즘은 `flag`를 먼저 올리고 `turn`을 바꾸는 **순서**가 생명인데, CPU가 "어차피 상관없겠지?" 하고 순서를 바꿔버리면 상호 배제가 깨질 수 있습니다.

    - **Memory Wall**
CPU 캐시 메모리 때문에 `flag` 값이 즉시 메인 메모리에 반영되지 않아, 상대방 프로세스가 최신 상태를 읽지 못하는 
**메모리 가시성(Visibility) **문제가 발생합니다.

1. **실제 OS에서는 거의 사용 안 함**

  - 비효율적 (spin)

  - 확장성 부족

  - 대신 mutex, semaphore 같은 하드웨어/OS 지원 사용

**🛠️ 피터슨 알고리즘 vs 현대적 대안**
현재는 피터슨 알고리즘의 아이디어를 하드웨어 수준에서 구현한 방식들을 주로 사용합니다

| **비교 항목** | **피터슨 알고리즘** | **빵집 알고리즘** | **세마포어 / 뮤텍스** |
| --- | --- | --- | --- |
| **대상** | 2개 프로세스 | $N$개 프로세스 | $N$개 프로세스 |
| **기반** | 순수 소프트웨어 | 순수 소프트웨어 | **H/W 지원 + OS 커널** |
| **대기 방식** | Busy Waiting | Busy Waiting | **Block & Wakeup (Sleep)** |
| **가장 큰 차이** | 논리적 완결성 증명 | 다중 프로세스 확장 | **효율성 및 실용성 최우선** |

| **구분** | **피터슨 알고리즘 (Software)** | **현대적 대안 (Hardware/OS)** |
| --- | --- | --- |
| **대기 방식** | **Busy Waiting** (CPU 계속 점유) | **Sleep/Wakeup** (대기 큐로 이동) |
| **도구** | 공유 변수 (`flag`, `turn`) | **Mutex, Semaphore, Monitor** |
| **하드웨어 지원** | 없음 | **Atomic Instructions** (TSL, CAS) |

### **N개 프로세스로의 확장: 램포트의 빵집 알고리즘 (Bakery Algorithm)**

피터슨 알고리즘이 "양보"를 기반으로 한다면, **빵집 알고리즘**은 우리가 은행이나 빵집에서 뽑는 **'번호표'** 시스템을 활용합니다.
• **핵심 원리**:
    1. 임계 구역에 들어가려는 프로세스는 번호표를 받습니다.
    2. 번호표 숫자가 **가장 작은(먼저 온)** 프로세스가 먼저 진입합니다.
    3. 만약 번호표 숫자가 같다면, 프로세스 ID(PID)가 낮은 쪽이 우선권을 가집니다.
• **특징**: 하드웨어의 도움 없이 $N$개의 프로세스에 대해 상호 배제를 완벽하게 구현할 수 있습니다.

**🔥 Peterson vs Dekker vs Bakery 비교**

| 구분 | Dekker | Peterson | Bakery |
| --- | --- | --- | --- |
| 프로세스 수 | 2개 | 2개 | N개 |
| 복잡도 | 높음 | 낮음 | 중간 |
| 핵심 아이디어 | flag + turn | flag + turn | 번호표 |
| busy waiting | 있음 | 있음 | 있음 |
| 실사용 | ❌ | ❌ | ❌ |
| 의의 | 최초 구현 | 가장 간단 | 확장 가능 |

# 🧠 1️⃣ Dekker’s Algorithm

## ✔ 개념

👉 **최초의 소프트웨어 기반 상호배제 알고리즘 (2개 프로세스용)**

    - Peterson보다 이전

    - lock 없이 mutual exclusion 보장

---

## ⚙️ 핵심 아이디어

```plain text
flag[i]  → 나 들어갈게
turn     → 양보 개념
```

👉 Peterson이랑 비슷하지만

👉 **훨씬 복잡하게 제어함**

---

## 🔁 동작 느낌

```plain text
1. 나 들어갈게 (flag = true)
2. 상대도 원하면
    → turn 확인
    → 내가 양보면 flag 내리고 기다림
3. 들어감
4. 끝나면 turn 넘김
```

---

## ❗ 특징

    - busy waiting 있음

    - Peterson보다 구현 복잡

    - 그래도 **이론적으로 완전한 상호배제 최초 구현**

---

# 🧠 2️⃣ Bakery Algorithm (Lamport)

## ✔ 개념

👉 **여러 프로세스(N개)를 위한 상호배제 알고리즘**

👉 이름 이유:

> 빵집에서 번호표 뽑는 방식 🍞

---

## ⚙️ 핵심 아이디어

```plain text
1. 번호표 뽑음
2. 번호 작은 사람부터 실행
3. 번호 같으면 ID로 순서 결정
```

---

## 🔁 동작 흐름

```plain text
choosing[i] = true
number[i] = max(number) + 1
choosing[i] = false

다른 프로세스들:
    번호 비교해서 나보다 먼저면 기다림
```

---

## 🎯 특징

✔ Mutual Exclusion 보장

✔ Bounded Waiting 보장

✔ N개 프로세스 지원

---

## ❗ 한계

    - 여전히 busy waiting

    - number 배열 → 메모리 비용

    - 성능 비효율
