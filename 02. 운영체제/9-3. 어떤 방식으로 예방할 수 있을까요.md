# **9-3.** 어떤 방식으로 예방할 수 있을까요?

> 예방(prevention)은 이 중 하나라도 “의도적으로 깨버리는 전략”입니다.

### 1️⃣ 상호 배제 깨기 (Mutual Exclusion 제거)

: 자원을 공유 가능하게 만들기

예: read-only 파일 → 여러 프로세스 동시에 접근 가능

하지만…

현실적으로 **프린터, DB 락 등은 공유 불가**
👉 그래서 **거의 사용 못하는 방법**

### 2️⃣ 점유 대기 제거 (Hold and Wait 방지) ⭐ 중요

: “자원을 한 번에 다 요청하게” 만들기

- 방식

  - 실행 전에 필요한 자원 전부 요청

  - 없으면 아예 시작 안 함

- 장점: Deadlock 완전 차단

- 단점:

  - 자원 낭비 심함 (비효율)

  - 대기 시간 증가

👉 현실에서는 **부분적으로만 적용**

### 3️⃣ 비선점 제거 (Preemption 허용)

: 자원을 강제로 뺏을 수 있게 함

- 방식

  - 프로세스가 요청 실패하면 → 가진 자원 반납

  - OS가 강제로 회수

- 예:

  - CPU 스케줄링 (time slice)

  - 트랜잭션 롤백

👉 **운영체제 + DB에서 자주 쓰는 방식**

### 4️⃣ 순환 대기 제거 (Circular Wait 방지) 

**: 자원에 “순서”를 부여해서 요청하게 함**

- 예:

```plain text
R1 → R2 → R3 순서로만 요청 가능
```

- 그러면:

  - R3 → R1 이런 역방향 요청 불가능

  - 👉 사이클 자체가 안 생김

👉 **가장 현실적이고 많이 쓰는 방법**

## 정리

| 방법 | 핵심 아이디어 | 현실성 |
| --- | --- | --- |
| 상호배제 제거 | 공유 자원 만들기 | ❌ 거의 불가능 |
| 점유대기 제거 | 한 번에 요청 | ⚠️ 비효율 |
| 비선점 허용 | 강제로 뺏기 | ✅ 자주 사용 |
| 순환대기 제거 | 자원 순서 부여 | ⭐ 가장 실용적 |
