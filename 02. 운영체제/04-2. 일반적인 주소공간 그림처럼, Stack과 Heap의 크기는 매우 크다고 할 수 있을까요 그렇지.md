# 4-2. 일반적인 주소공간 그림처럼, Stack과 Heap의 크기는 매우 크다고 할 수 있을까요? 그렇지 않다면, 그 크기는 언제 결정될까요?

---

# 4-2. Stack / Heap 크기 크냐?

이거 많이 헷갈리는데

**"그림이 크다고 실제로 큰 게 아님"**

👉 현실은:

- Stack: 보통 몇 MB

- Heap: 상황에 따라 커지지만 무한 아님

---

## ❗ 언제 크기 결정됨?

### Stack

- **프로그램 시작할 때 고정됨**

- OS가 정해줌 (예: 1MB ~ 8MB)

👉 그래서 재귀 깊으면 터짐 (Stack overflow)

---

### Heap

- 실행 중에 계속 커짐

- 필요할 때 OS에 요청 (`malloc`, `new`)

👉 대신 한계 있음 (메모리 부족)

---

👉 정리하면

| 구분 | 크기 |
| --- | --- |
| Stack | 시작할 때 정해짐 |
| Heap | 실행 중 동적으로 증가 |

방금 답변 방향 좋다. 딱 본질 잡았어.

그럼 BSS 제대로 파보자. 이건 면접에서도 꽤 잘 꼬는 포인트다.

---

## 📌 1. BSS가 뭐냐 (정확한 정의)

👉 **초기화되지 않은 전역 변수 / static 변수 저장 영역**

```c
int a;          // BSS
static int b;   // BSS
```

---

## 📌 2. 근데 중요한 질문

👉 “초기화 안 했는데 왜 값이 0이냐?”

이게 핵심이다.

---

## 🔥 답

👉 **OS가 실행할 때 전부 0으로 밀어버림**

- 프로그램 실행 시

- BSS 영역을 **zero-fill** 한다

👉 그래서 결과적으로는:

```c
int a;
printf("%d", a);  // 0
```

---

## 📌 3. Data 영역이랑 뭐가 다르냐?

이거 헷갈리면 끝까지 헷갈린다.

---

## Data vs BSS

```c
int a = 10;   // Data
int b;        // BSS
```

---

## 차이 핵심

| 구분 | Data | BSS |
| --- | --- | --- |
| 초기값 | 있음 | 없음 |
| 파일에 저장됨? | O | ❌ |
| 실행 시 초기화 | 그대로 로드 | 0으로 채움 |

---

👉 여기 진짜 중요한 포인트 하나

### 💣 BSS는 실행 파일 크기를 줄이기 위해 존재함

---

## 예시

```c
int arr[1000000];  // 초기화 안함
```

👉 이걸 Data에 넣으면?

- 파일에 0이 백만 개 들어감

- 실행 파일 엄청 커짐

---

👉 그래서 BSS는:

```plain text
"이건 그냥 0으로 채우면 되니까 저장 안 해"
```

👉 실행 파일에는 “크기 정보만” 있음

---

## 📌 4. 동작 흐름 (진짜 이해 포인트)

프로그램 실행 시:

1. Code 영역 로드

1. Data 영역 로드

1. BSS 영역 → **0으로 초기화**

👉 이 순서

---

## 📌 5. 왜 따로 분리했냐?

이건 그냥 설계 철학이다

---

## 이유 3개

### 1) 실행 파일 크기 절약

- 불필요한 0 저장 안함

---

### 2) 초기화 비용 줄이기

- OS가 한 번에 0으로 밀면 끝

---

### 3) 의미 구분

- “값 있는 변수” vs “없는 변수”

---

## 📌 6. 헷갈리는 포인트 정리

---

## ❗ 지역 변수는 BSS 아니다

```c
void func() {
    int a;  // Stack (쓰레기값)
}
```

👉 초기화 안 하면 쓰레기값 나옴

---

👉 BSS는 오직

- 전역 변수

- static 변수

---

---

## ❗ static 지역 변수는 BSS 갈 수도 있음

```c
void func() {
    static int a;  // BSS
}
```

👉 이유:

- static → 프로그램 전체에서 유지됨

---

## 📌 7. 한 줄 핵심

👉 **“BSS = 값 없는 전역 변수들을 위한 ‘0 전용 공간’”**

---

### 👉 “왜 지역 변수는 0으로 초기화 안 해줄까?”

📌 결론부터 말하면

👉 **“안 해도 되니까 안 하는 거다” + “속도 때문”**

---

### 📌 1. 지역 변수는 왜 초기화 안 해주냐

이유 1️⃣ 성능

스택은 함수 호출 때마다 계속 생겼다 사라진다.

```c
void func() {
    int a;
}
```

이게 한두 번이 아니라

👉 수천, 수만 번 호출됨

---

만약 매번:

```plain text
"스택 영역 전부 0으로 초기화"
```

👉 그냥 쓸데없이 CPU 낭비

---

👉 그래서:

  - 초기화 안 하고

  - 그냥 이전 값 그대로 둠 (쓰레기값)

---

📌 2. 진짜 중요한 포인트

👉 지역 변수는 **반드시 개발자가 초기화해야 하는 대상**

---

```c
int a;
printf("%d", a);  // 쓰레기값
```

👉 이건 OS 잘못이 아니라

👉 **코드 잘못**

---

### 📌 3. 그럼 BSS는 왜 해주냐?

여기서 비교가 핵심이다.

---

BSS (전역/static)

  - 한 번만 초기화하면 됨

  - 프로그램 전체에서 사용

👉 비용 거의 없음

---

Stack (지역 변수)

  - 함수마다 계속 생성

  - 호출 횟수 엄청 많음

👉 초기화 비용 누적됨

---

👉 그래서 결론:

| 구분 | 초기화 |
| --- | --- |
| BSS | 자동 0 초기화 |
| Stack | 안 해줌 (개발자 책임) |

---

### 📌 4. 한 단계 더 들어가면

👉 사실 스택은 “재사용”된다

```plain text
func1 실행 → 스택 사용
func1 끝 → 스택 비워짐 (실제로는 그대로 남아있음)
func2 실행 → 같은 자리 재사용
```

👉 그래서 이전 값이 그대로 남아 있음 = 쓰레기값

---

### 📌 5. 근데 언어마다 다르다 (중요)

---

## C / C++

👉 초기화 안 해줌 (빠름, 위험)

---

## Java

👉 자동 초기화

```java
int a;  // 클래스 변수 → 0
```

👉 대신 성능 약간 희생

---

👉 왜?

  - 안전성 vs 성능 트레이드오프

---

### 📌 6. 핵심 정리

👉 지역 변수 초기화 안 하는 이유

  1. 성능 (매번 초기화 비용 큼)

  1. 어차피 짧게 쓰고 사라짐

  1. 개발자 책임 영역

---

## 🔥 한 줄 핵심

👉 **“Stack은 속도를 위해 안전을 일부 포기한 구조”**

---

### 👉 “그럼 Java는 왜 지역 변수는 자동 초기화 안 해줄까?” (클래스 변수는 해주는데?)

응, 크게는 그 방향이 맞아.

근데 그 말만 하면 조금 부족하고, **자바가 왜 “지역 변수는 자동 초기화 안 함”을 선택했는지**를 두 가지로 나눠서 봐야 해.

---

# 결론

👉 **성능 때문도 맞고, 더 중요한 건 “실수를 컴파일 단계에서 막기 위해서”야.**

즉 자바는

  - **자동 초기화 비용도 아끼고**

  - 동시에

  - **초기화 안 된 지역 변수를 아예 못 쓰게 막아버림**

이렇게 간 거야.

---

# 1. C랑 자바의 차이부터 봐야 함

## C

```c
void func() {
    int a;
    printf("%d", a); // 가능, 쓰레기값
}
```

C는 초기화 안 해도 그냥 쓴다.

빠르지만 위험하지.

---

## Java

```java
void func() {
    int a;
    System.out.println(a); // 컴파일 에러
}
```

자바는 아예 **컴파일 오류** 낸다.

즉 자바는

> “자동으로 0 넣어줄게”

이게 아니라

“초기화 안 했으면 쓰지 마”

이 방식이야.

---

# 2. 왜 자동 초기화를 안 했을까?

네 말대로 첫 번째 이유는 맞아.

## ① 비용 대비 이점이 크지 않음

지역 변수는 메서드 호출 때마다 계속 생기고 사라진다.

매번 기본값으로 초기화하면 비용이 쌓인다.

특히 지역 변수는 보통 바로 값 대입해서 쓰는 경우가 많아.

```java
int sum = 0;
int n = sc.nextInt();
```

이런 식으로 대부분 개발자가 직접 넣는다.

그러면 JVM이나 컴파일러 입장에서는

> “어차피 곧 값 넣을 건데 왜 미리 0으로 채움?”

이 되는 거지.

---

## ② 자바는 안전을 다른 방식으로 확보함

이게 더 중요하다.

자바는 지역 변수를 자동 초기화하지 않는 대신

**반드시 값이 들어간 뒤에만 사용 가능**하게 강제한다.

이걸 흔히

**definite assignment**

라고 봐.

즉,

```java
int a;
a를 쓰기 전에 반드시 어떤 경로에서든 값이 대입되어 있어야 함
```

그래서 자바는

  - C처럼 쓰레기값 문제 없음

  - 그렇다고 매번 자동 초기화 비용도 없음

둘 다 잡으려 한 거야.

---

# 3. 그럼 왜 필드(멤버 변수)는 자동 초기화해?

이것도 같이 연결해서 봐야 이해된다.

## 멤버 변수

```java
class A {
    int x; // 자동으로 0
}
```

이건 객체의 상태라서

초기값이 없으면 의미가 애매해진다.

그리고 멤버 변수는 지역 변수처럼 엄청 자주 생겼다 사라지는 값이 아니라

**객체의 일부**라서 기본 상태를 주는 게 더 자연스럽다.

즉,

  - **지역 변수**: 잠깐 쓰는 작업용 → 개발자가 직접 초기화

  - **멤버 변수**: 객체 상태 표현용 → 언어가 기본값 제공

---

# 4. 네 말 보완해서 더 정확히 말하면

네 문장을 조금 다듬으면 이렇게 돼:

> 자바는 지역 변수를 자동 초기화하는 비용이 크다고 봤고,

그 대신 초기화되지 않은 지역 변수는 컴파일 단계에서 사용하지 못하게 막아서

성능과 안전성을 둘 다 확보했다.

이렇게 말하면 훨씬 정확하다.

---

# 5. 한 줄 요약

👉 **자바는 지역 변수를 자동 초기화하지 않는 대신, 초기화 전 사용을 금지해서 안전을 확보한다.**
