# 18-0. 세그멘테이션과 페이징의 차이점은 무엇인가요?

### 18. 세그멘테이션과 페이징의 차이점은 무엇인가요?

- 공통점

  - 프로세스를 메모리에 올릴 때 잘라서 올리겠다는 목적

- 차이점

  - **자르는 기준**

### 1. 페이징 (Paging) 기법

- 자르는 기준

  - 하드웨어적 크기 (보통 4KB 고정 크기)

- 동작 방식

  - **프로세스의 내용에 관계없이**(이게 코드인지 데이터인지) 무조건 4KB씩 자름

- 장점

  - **외부 단편화 0%**. 남는 프레임(RAM 공간)에 페이지를 순서 없이 넣으면 되기 때문.

- 단점

  - **내부 단편화 발생**. 프로세스 크기가 4KB의 배수로 딱 떨어지지 않으면 마지막 페이지는 공간 발생. (예: 10KB 프로세스는 4KB 페이지 3개가 필요하며, 마지막 페이지에 2KB의 내부 단편화 발생)

### 2. 세그멘테이션 (Segmentation) 기법

- 자르는 기준

  - 논리적 의미와 기능 (가변 크기)

- 동작 방식

  - 프로세스를 크기가 아닌 의미 있는 논리적 단위인 세그먼트(Segment)로 자름.

  - 대표적으로 프로세스는 코드가 들어있는 Code 영역, 전역 변수가 있는 Data 영역, 동적 할당을 위한 Heap 영역, 함수 호출을 관리하는 Stack 영역으로 나뉨.

- 장점

  - 보호(Protection)와 공유(Sharing)에 매우 유리.

  - 예를 들어 "Code 영역은 읽기 전용으로 설정해", "이 Data 영역은 다른 프로세스랑 공유해" 같은 권한 설정을 **논리적 덩어리 단위**로 아주 정교하게 부여 가능.(영역마다 설정 가능)

- 단점

  - 세그먼트마다 크기가 제각각(어떤 건 1MB, 어떤 건 500KB)이므로, 메모리에 적재하고 해제하는 과정에서 크기가 다른 빈 공간들이 흩어지는 외부 단편화가 필연적으로 발생.

### 한눈에 보는 비교 정리 표

| **구분** | **페이징 (Paging)** | **세그멘테이션 (Segmentation)** |
| --- | --- | --- |
| 분할의 기준 | 물리적 고정 크기 (하드웨어 관점) | 논리적 기능 단위 (사용자/프로그램 관점) |
| 분할 단위의 명칭 | 논리: 페이지 (Page)
물리: 프레임 (Frame) | 논리: 세그먼트 (Segment) |
| 단위의 크기 | 모두 동일함 (예: 4KB) | 각기 다름 (가변적) |
| 발생하는 단편화 | 내부 단편화 발생 | 외부 단편화 발생 |
| 주요 장점 | 메모리 공간 관리 효율성 극대화 (외부 단편화 제거) | 의미 단위의 접근 제어 및 메모리 공유에 유리함 |

실제 현대의 운영체제(Windows, Linux 등)는 페이징의 하드웨어적 효율성과 세그멘테이션의 논리적 보호 기능을 결합한 세그먼티드 페이징(Segmented Paging) 기법을 혼합하여 사용하고 있습니다.

(의미 단위로 먼저 자른 뒤, 그것을 다시 동일한 크기의 페이지로 잘라서 메모리에 올리는 방식)
