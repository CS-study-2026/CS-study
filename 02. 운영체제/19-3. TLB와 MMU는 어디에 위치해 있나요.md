# 19-3. TLB와 MMU는 어디에 위치해 있나요?

## 1. MMU는 어디에 있나요?

**MMU는 CPU 내부에 있는 하드웨어 장치**야.

예전에는 별도 칩처럼 설명하기도 하지만, 현대적인 CPU에서는 보통 CPU 내부, 더 정확히는 **각 코어 내부의 주소 변환 경로에 포함된 하드웨어**라고 보면 돼.

MMU의 역할은 이거야.

```plain text
가상 주소를 물리 주소로 변환한다.
```

예를 들어 CPU가 이런 명령을 실행한다고 하자.

```plain text
가상 주소 0x1000에 있는 값을 읽어라
```

그러면 CPU는 바로 RAM의 0x1000에 접근하지 않아.

먼저 MMU가 페이지 테이블을 참고해서 이 가상 주소가 실제 RAM의 어느 물리 주소에 대응되는지 찾는다.

```plain text
가상 주소 0x1000
      ↓ MMU
물리 주소 0xA300
```

그다음 실제 RAM에 접근해.

---

## 2. TLB는 어디에 있나요?

**TLB도 CPU 내부에 있어.**

더 정확히는 보통 **각 CPU 코어 내부에 존재하는 작은 고속 캐시**야.

TLB는 일반 데이터 캐시처럼 데이터를 저장하는 게 아니라, **주소 변환 결과**를 저장해.

```plain text
TLB에 저장되는 것:

가상 페이지 번호 → 물리 프레임 번호
```

예를 들어:

```plain text
Virtual Page 10 → Physical Frame 52
Virtual Page 11 → Physical Frame 80
Virtual Page 12 → Physical Frame 7
```

이런 식으로 최근에 사용한 주소 변환 결과를 저장해두는 거야.

---

## 3. 왜 TLB가 CPU 내부에 있어야 하나?

주소 변환은 메모리 접근마다 필요해.

CPU가 메모리에서 값을 읽거나 쓸 때마다:

```plain text
가상 주소 생성
→ 물리 주소 변환
→ RAM 접근
```

이 과정이 필요해.

만약 주소 변환을 할 때마다 RAM에 있는 페이지 테이블을 매번 읽어야 한다면 너무 느려.

그래서 CPU 내부에 매우 빠른 TLB를 두고, 최근 주소 변환 결과를 바로 찾는 거야.

```plain text
TLB hit
→ 페이지 테이블을 보지 않고 바로 물리 주소 획득

TLB miss
→ 페이지 테이블을 찾아서 변환
→ 결과를 TLB에 저장
```

---

## 4. 코어마다 TLB가 있나요?

보통은 **각 코어마다 독립적인 TLB를 가진다**고 이해하면 돼.

예를 들어 4코어 CPU라면:

```plain text
Core 0 → TLB 0
Core 1 → TLB 1
Core 2 → TLB 2
Core 3 → TLB 3
```

각 코어가 자기 TLB를 사용해서 주소 변환을 빠르게 처리한다.

물론 실제 CPU 구조는 더 복잡할 수 있어.

예를 들어 명령어용 TLB와 데이터용 TLB가 나뉘기도 해.

```plain text
ITLB: Instruction TLB
- 명령어 fetch 주소 변환용

DTLB: Data TLB
- 데이터 load/store 주소 변환용
```

또 L1 TLB, L2 TLB처럼 계층 구조를 갖는 경우도 있어.

하지만 면접/스터디 수준에서는 이렇게 말하면 충분해.

> TLB와 MMU는 CPU 내부, 보통 각 코어 내부의 주소 변환 경로에 위치합니다. MMU는 가상 주소를 물리 주소로 변환하고, TLB는 그 변환 결과를 캐싱해서 주소 변환 속도를 높입니다.
