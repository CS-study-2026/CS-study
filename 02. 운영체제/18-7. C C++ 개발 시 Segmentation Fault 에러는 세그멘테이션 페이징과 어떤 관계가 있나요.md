# 18-7. C/C++ 개발 시 Segmentation Fault 에러는 세그멘테이션/페이징과 어떤 관계가 있나요?

# **1️⃣ C/C++에서 Segmentation Fault는 무엇인가?**

## **한 줄 정의**

> **프로세스가 ****허용되지 않은 메모리 영역에 접근****하거나, ****접근 권한을 위반****했을 때 발생하는 오류**이다.

---

## **대표적인 발생 사례**

### **1. NULL 포인터 접근**

```c
int *ptr = NULL; // 포인터가 아무것도 가리키지 않고 있음
*ptr = 10; // 거기에 10을 저장하래! (❌)
```

→ Segmentation Fault 발생

---

### **2. 배열 범위 초과 접근**

```c
int arr[10];
arr[100000] = 1; // 할당받지 않은 메모리에 접근
```

→ Segmentation Fault 발생 가능

---

### **3. 읽기 전용 영역 수정**

```c
char *str = "hello"; // 문자열은 읽기 전용 영역에 저장.
str[0] = 'H';        // 그런데 변경하려고 함 ;
```

→ Segmentation Fault 발생

---

## **왜 C/C++에서 자주 발생할까?**

C/C++은

```plain text
포인터
메모리 주소
동적 메모리
```

를 직접 다루기 때문이다.

반면 Java는 JVM이 대부분의 메모리 접근을 관리하므로 보통

```plain text
NullPointerException
ArrayIndexOutOfBoundsException
```

과 같은 예외가 먼저 발생한다.

---

## **한 줄 정리**

> **Segmentation Fault는 잘못된 메모리 접근으로 인해 운영체제가 프로그램 실행을 중단시키는 오류이다.**

---

# **2️⃣ Segmentation Fault는 Segmentation / Paging과 어떤 관계가 있는가?**

## **Segmentation과의 관계**

과거 세그멘테이션 방식에서는

```plain text
Code Segment
Data Segment
Stack Segment
```

등의 영역이 존재했다.

프로세스가

```plain text
허용되지 않은 세그먼트 접근
세그먼트 범위 초과
```

를 시도하면 예외가 발생했다.

이 때문에 지금도 이름이

```plain text
Segmentation Fault
```

로 남아 있다.

---

## **Paging과의 관계**

현대 운영체제는 대부분 페이징 기반으로 동작한다.

메모리 접근 시

```plain text
프로세스
↓
MMU
↓
페이지 테이블 조회
```

를 수행한다.

이때

### **존재하지 않는 페이지 접근**

```plain text
유효한 페이지 없음
```

또는

### **권한 위반**

```plain text
Write Bit = 0

그런데 쓰기 시도
```

가 발생하면

운영체제가 접근을 차단한다.

↓

Segmentation Fault 발생

---

## **Page Fault와의 차이**

많이 헷갈리는 부분

### **Page Fault**

```plain text
페이지가 RAM에 없음
```

↓

OS가 디스크(Swap)에서 가져옴

↓

실행 계속

즉, 정상 동작

---

### **Segmentation Fault**

```plain text
존재하지 않는 주소 접근

또는

권한 없는 접근
```

↓

OS가 차단

↓

프로세스 종료

즉, 오류

---

## **🎯 최종 한 줄 정리**

**Segmentation Fault는 세그멘테이션에서 유래한 이름이지만, 현대 OS에서는 페이지 테이블의 메모리 보호 규칙(존재 여부, 접근 권한)을 위반했을 때 발생하는 메모리 접근 오류이다.**
