# 15-2. 성능이 가장 좋은 알고리즘은 무엇일까요?

> 👉 일반적으로 **First Fit이 가장 좋은 성능**을 보인다.

# 2️⃣ 왜 First Fit이 좋은가

## 📌 탐색 비용이 적음

처음 맞는 공간을 발견하면

즉시 종료

---

예

```plain text
Hole

100KB
400KB
600KB
800KB

프로세스 = 350KB
```

---

First Fit

```plain text
400KB 발견
→ 바로 종료
```

---

Best Fit

```plain text
전체 탐색 필요
```

---

Worst Fit

```plain text
전체 탐색 필요
```

---

# 3️⃣ 실제 연구 결과

운영체제 교과서

### Operating System Concepts

실험 결과

- First Fit

- Best Fit

- Worst Fit

비교 시

👉 First Fit이 가장 좋은 평균 성능

---

# 4️⃣ Best Fit이 항상 좋은 것은 아니다

직관적으로는

"빈 공간을 최소화하니까 좋아 보임"

---

하지만

```plain text
300KB 공간
250KB 할당

남은 공간
50KB
```

---

이런 작은 Hole이 계속 생성

→ 외부 단편화 증가

---

# 5️⃣ Worst Fit도 좋은 선택은 아닌기라 - 아까 말했제?(지우버전)

큰 Hole만 계속 사용

결국

- 큰 공간 소모

- 탐색 비용 증가

---

# 6️⃣ 현대 OS 관점

사실 현대 운영체제는

```plain text
Contiguous Allocation
↓
Paging
↓
Virtual Memory
```

구조를 사용

---

그래서

First Fit / Best Fit / Worst Fit은

운영체제 역사와 메모리 관리 개념을 이해하기 위한 내용으로 더 자주 등장한다.

---

# 📌 면접 답변 포인트

질문:

"성능이 가장 좋은 알고리즘은?"

답변:

👉 일반적으로 First Fit이 가장 좋은 평균 성능을 보입니다.

이유는 탐색 비용이 가장 적고, 실제 연구에서도 Best Fit이나 Worst Fit보다 전체 성능이 우수한 경우가 많기 때문입니다.

---

# 📌 핵심 정리

- 평균 성능 기준으로 First Fit이 가장 우수

- Best Fit은 작은 Hole을 많이 생성

- Worst Fit은 큰 Hole을 빠르게 소모

- 현대 OS는 Paging 기반이라 직접 사용 빈도는 낮음
