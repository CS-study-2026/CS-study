# **20-0. 동기화를 구현하기 위한 하드웨어적인 해결 방법에 대해 설명해 주세요.**

# 동기화의 기본적인 해결방법

> 임계 영역으로의 진입 가능성을 확인하고 진입을 원자적으로 처리해야 한다.
경쟁 조건이 발생하지 않도록 해야하고 진입하게 되면 임계 영역으로 잠궈야 한다.(Lock)

### 하드웨어적 해결 방법

CPU가 직접

> "야, 한 명만 들어가!"

라고 관리해주는 특별한 명령어를 제공함.

### 1. Test-and-Set (TSL)

CPU가 제공하는 특수 명령어로, 변수 값을 읽고 동시에 1로 설정하는 작업을 한 번에 수행

```c
booleanTestAndSet(boolean*lock){
booleanold=*lock;
*lock=true;
returnold;
}
```

사용 예시

```c
while(TestAndSet(&lock))
    ;// 대기

// Critical Section

lock=false;
```

- 원자적으로 수행됨

- 동시에 여러 스레드가 접근해도 하나만 락 획득 가능

- 단점: Busy Waiting(Spin Lock) 발생

문 앞에 "사용 중" 표시를 붙이는 것과 같음.

```plain text
문 확인
↓

사용 중 아니네?
↓

내가 사용 중 표시 붙임
↓

들어감
```

이 과정을 CPU가 **한 번에(원자적으로)** 처리함.

그래서 다른 스레드는 끼어들 수 없음.

---

### Compare-and-Swap(CAS)

현재 값이 예상 값과 같으면 새로운 값으로 변경하는 원자적 연산

- 현대 CPU에서 널리 사용

- Java Atomic 클래스, Lock-Free 자료구조의 기반

이건

```plain text
현재 값이 0이면
→ 1로 바꿔라
```

라는 명령.

예를 들어

```plain text
lock = 0 (사용 가능)
```

일 때

스레드 A

```plain text
0 확인
→ 1로 변경 성공
```

스레드 B

```plain text
이미 1임
→ 실패
```

그래서 A만 임계영역(Critical Section)에 들어감.

---

### 3. Swap 명령어

메모리 값과 레지스터 값을 원자적으로 교환

- lock 획득 여부를 안전하게 확인 가능

- 역시 Busy Waiting 발생

---

### 핵심

하드웨어적 동기화 방법은

> CPU가 제공하는 특별한 원자적 명령어를 사용해서 여러 스레드가 동시에 공유 자원에 접근하지 못하게 하는 방법이다.

대표적으로

- Test-and-Set

- Compare-and-Swap(CAS)

- Swap

이 있으며, 이를 기반으로 Mutex와 Semaphore가 구현된다.

### 공통적인 한계

위 방법들은 모두 **상호 배제(Mutual Exclusion)** 는 보장하지만,

- Busy Waiting 발생

- CPU를 계속 점유하며 반복 확인

- 대기 시간이 길어질수록 비효율적

이라는 문제가 있습니다.

그래서 실제 운영체제에서는 이러한 하드웨어 명령어를 기반으로 **세마포어(Semaphore)**, **뮤텍스(Mutex)**, **모니터(Monitor)** 같은 소프트웨어적 동기화 기법을 구현합니다.
