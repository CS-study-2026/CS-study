# 22-2. 프로그래밍 언어 상에서 제공하는 파일 관련 함수는 어떤 방식으로 읽어들이나요?

> **프로그래밍 언어에서 제공하는 파일 읽기 함수(****`fread`****, ****`BufferedReader`****, ****`FileInputStream`****, ****`read()`**** 등)는 결국 운영체제가 제공하는 시스템 콜을 통해 파일을 읽어옵니다.**

### 동작 과정

1. **애플리케이션이 파일 읽기 함수 호출**

```java
BufferedReader.readLine()
```

또는

```c
fread()
```

1. **언어의 라이브러리가 시스템 콜 호출**

시스템 콜이란 ? 프로그램은 하드웨어에 직접 접근 못 함 ⇒사용자 프로그램이 운영체제의 기능을 사용하기 위한 인터페이스

  - Linux: `read()`

  - Windows: `ReadFile()`

1. **커널 모드로 전환**

운영체제는 보안을 위해 CPU 실행 권한을 두 개로 나눔.

  - CPU가 User Mode → Kernel Mode로 변경

  - 운영체제가 요청 처리

1. **파일 시스템 확인**

  - 파일 디스크립터(File Descriptor) 확인

  - 파일의 위치, 권한, 블록 정보 조회

1. **페이지 캐시(Page Cache) 확인**

  - 이미 메모리에 있으면 디스크 접근 없이 바로 반환

  - 없으면 디스크(I/O) 접근

페이지 캐시는 운영체제가 사용하는 버퍼 ⇒ 페이지 캐시는 운영체제가 파일 데이터를 메모리에 저장해두는 공간입니다. 동일한 파일을 다시 읽을 경우 디스크 접근 없이 메모리에서 데이터를 제공하여 성능을 향상

처음 읽을 때

```plain text
test.txt

SSD
 ↓
Page Cache
 ↓
프로그램
```

---

두 번째 읽을 때

```plain text
Page Cache
 ↓
프로그램
```

SSD 안 감.

1. **디스크에서 데이터 읽기**

  - SSD/HDD에서 필요한 블록을 메모리로 로드

  - 페이지 캐시에 저장

1. **커널 버퍼 → 사용자 버퍼 복사**

  - 페이지 캐시는 커널 영역에 존재하므로 사용자 프로그램이 직접 접근할 수 없음.  ⇒ 운영체제는 페이지 캐시의 데이터를 사용자 영역 버퍼로 복사한 후 반환합니다.

```plain text
SSD
 ↓
Page Cache(커널)
 ↓
User Buffer(프로세스)
```

1. **애플리케이션에 데이터 반환**

> 프로그래밍 언어의 파일 읽기 함수는 직접 디스크를 읽는 것이 아니라, 내부적으로 운영체제의 파일 관련 시스템 콜을 호출하며, 운영체제는 페이지 캐시를 확인한 뒤 필요 시 디스크에서 데이터를 읽어 사용자 프로세스의 버퍼로 복사하여 전달합니다.

---

**Q. 파일을 읽을 때 왜 User Mode에서 바로 디스크 접근을 못 하나요?**

A.

> 디스크와 같은 하드웨어 자원은 보호가 필요하기 때문에 운영체제만 접근 권한을 가지며, 사용자 프로그램은 시스템 콜을 통해서만 간접적으로 접근할 수 있습니다.

### Q. BufferedReader와 Page Cache의 차이는?

  - Page Cache = 운영체제가 관리하는 커널 영역 캐시

  - BufferedReader = JVM이 관리하는 사용자 영역 버퍼

```plain text
SSD
 ↓
Page Cache (OS)
 ↓
BufferedReader Buffer (JVM)
 ↓
내 코드
```

이렇게 **캐시가 2단계**로 존재함.

왜 둘 다 있어야 할까 ?

Page Cache만 있다고 가정하면  SSD는 안 가지만 시스템 콜은 계속 발생.

| 구분 | Page Cache | BufferedReader |
| --- | --- | --- |
| 관리 주체 | 운영체제(OS) | JVM(Java) |
| 위치 | Kernel Space | User Space |
| 목적 | 디스크 I/O 감소 | 시스템 콜 감소 |
| 대상 | 모든 프로세스 공유 | 해당 프로세스만 사용 |
| 생명주기 | OS가 관리 | 객체가 살아있는 동안 |

### BufferedReader vs FileInputStream

### FileInputStream

```plain text
FileInputStreamfis
```

  - 바이트 단위 읽기

  - 바이너리 파일

예)

```plain text
jpg
png
mp4
```

---

### BufferedReader

```plain text
BufferedReaderbr
```

  - 문자 단위 읽기

  - 내부 버퍼 사용

  - readLine 제공

예)

```plain text
txt
csv
json
```

---

> FileInputStream은 바이트 단위로 데이터를 읽는 스트림이고, BufferedReader는 문자 단위 읽기와 버퍼링 기능을 제공하여 텍스트 파일 처리에 적합합니다.
