# 15-1. worst-fit 은 언제 사용할 수 있을까요?

## 1️⃣ Worst Fit이란?

### 📌 정의

가장 큰 빈 공간(Hole)에 프로세스를 배치하는 방식

---

예

```plain text
Hole

100KB
300KB
800KB

프로세스 = 200KB
```

→ 800KB 공간 사용

---

# 2️⃣ Worst Fit의 아이디어

핵심 철학은

👉 "큰 공간을 계속 크게 유지하자"

---

Best Fit

```plain text
800KB → 그대로 유지
300KB → 사용
```

---

Worst Fit

```plain text
800KB → 사용

남은 공간
600KB
```

---

즉

작은 조각 대신

상대적으로 큰 Hole 유지

---

# 3️⃣ 언제 사용할 수 있을까?

## 📌 큰 프로세스가 자주 들어오는 환경

예

- 대용량 데이터 처리

- 과학 계산

- HPC(고성능 컴퓨팅)

---

큰 공간을 유지해야

향후 큰 프로세스 적재 가능

---

## 📌 작은 프로세스가 많은 경우

오히려 비효율

---

예

```plain text
800KB
→ 700KB
→ 600KB
→ 500KB
→ ...
```

결국 큰 Hole만 계속 잘림

---

# 4️⃣ 왜 실제로 잘 사용되지 않을까

연구 결과

Worst Fit은

- 탐색 비용 큼

- 단편화 감소 효과 미미

- First Fit보다 성능 우수하지 않음

---

따라서

실제 OS에서는 거의 사용되지 않는다.

---

# 📌 핵심 정리

- Worst Fit은 가장 큰 Hole에 할당

- 큰 프로세스가 자주 들어오는 환경에 적합

- 실제 성능 이점이 크지 않아 현대 OS에서는 거의 사용되지 않음
