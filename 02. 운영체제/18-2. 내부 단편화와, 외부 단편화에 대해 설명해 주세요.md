# 18-2. 내부 단편화와, 외부 단편화에 대해 설명해 주세요.

> 💡 사전 지식

### 핵심 하드웨어 3대장

  1. CPU (Central Processing Unit, 중앙 처리 장치)

설명: 컴퓨터의 두뇌로, 프로그램의 명령어(연산, 데이터 읽기/쓰기 등)를 실제로 실행하는 부품입니다.

특징: CPU는 물리적인 메모리(RAM)의 실제 위치를 모릅니다. CPU는 오직 논리 주소(Logical Address, 가상 주소)라는 0부터 시작하는 일련의 번호만 생성하고 다룹니다.

  1. RAM (Random Access Memory, 주기억장치 / 메인 메모리)

설명: 실행 중인 프로그램(프로세스)의 데이터와 코드가 실제로 적재되는 물리적 하드웨어 공간입니다.

특징: 전원이 꺼지면 데이터가 날아가는 휘발성이며, 물리 주소(Physical Address)라는 실제 하드웨어적인 위치값을 가집니다.

  1. MMU (Memory Management Unit, 메모리 관리 장치)

설명: CPU와 RAM 사이에 위치한 아주 작은 하드웨어 칩입니다.

역할: CPU가 "100번지 논리 주소 데이터 가져와!"라고 명령하면, MMU가 이를 중간에서 가로채서 "아, 그건 실제 RAM의 5000번지 물리 주소에 있어"라고 변환해 주는 주소 변환기 역할을 합니다. 페이징과 세그멘테이션 모두 이 MMU 하드웨어의 지원 없이는 불가능합니다.

# **단편화(Fragmentation)란?**

메모리 공간이 조각조각 나뉘어 있어서, 총 빈 공간은 충분하지만 실제로는 사용할 수 없는 낭비되는 메모리 공간이 발생하는 현상을 말합니다.

# 📌 내부 단편화

할당받은 메모리 공간 내부에서 사용되지 않고 낭비되는 공간

즉, **프로세스에게 메모리를 너무 크게 할당해서 발생하는 낭비**

---

발생 원인:

주로 **고정 분할 방식(Fixed Partition)** 에서 발생

프로세스 크기보다 큰 파티션에 할당될 경우 남은 공간을 다른 프로세스가 사용할 수 없음

---

ex)

100MB 파티션
프로세스 크기 = 70MB

```plain text
┌───────────────┐
│ 프로세스 70MB │
├───────────────┤
│ 낭비 30MB     │
└───────────────┘
```

→ 30MB가 파티션 내부에서 낭비

---

특징:

- 할당은 성공

- 공간은 남아 있음

- 하지만 다른 프로세스는 사용 불가

---

해결 방법:

- 가변 분할 방식 사용

- Paging 사용

---

# 📌 외부 단편화

총 빈 공간은 충분하지만 연속된 공간이 부족하여 프로세스를 적재하지 못하는 현상

즉, **빈 공간이 여기저기 흩어져 발생하는 낭비**

---

발생 원인:

주로 **가변 분할 방식(Variable Partition)** 에서 발생

가변 분할 방식은 파티션이 고정되어있지 않음. 고정 분할은 항상 파티션의 크기가 유지되기에 작은 홀이 생길 일이 거의 없지만, 가변 분할은 작은 프로세스가 종료되면 작은 홀이 생겨 외부 단편화가 발생하는 것.

프로세스 **생성과 종료가 반복**되면서 중간중간 Hole(빈 공간)이 생성됨

---

ex)

```plain text
┌─────┬──────┬─────┬──────┬─────┐
│ P1  │10MB  │ P2  │20MB  │ P3  │
└─────┴──────┴─────┴──────┴─────┘
          ↑           ↑
         Hole        Hole
```

총 빈 공간

```plain text
10MB + 20MB = 30MB
```

---

새로운 프로세스

```plain text
25MB 필요
```

⇒

결과: ❌ 적재 불가

이유: 연속된 25MB 공간은 없음

---

특징:

- 총 여유 공간은 충분

- 연속 공간 부족

- 가변 분할에서 자주 발생

---

## 해결 방법:

### 1️⃣ 압축(Compaction)

프로세스를 한쪽으로 몰아서

빈 공간을 하나로 합침

```plain text
Before

P1 | Hole | P2 | Hole | P3

After

P1 | P2 | P3 | Large Hole
```

단점

- 비용 매우 큼(오버헤드 겁나 심함)

---

### 2️⃣ Paging

물리 메모리를 고정 크기 Frame으로 분할

→ 연속 공간이 필요 없음

→ 외부 단편화 제거

---

## 📌 한눈에 비교

| 구분 | 내부 단편화 | 외부 단편화 |
| --- | --- | --- |
| 의미 | 할당된 공간 내부 낭비 | 빈 공간이 흩어져 발생 |
| 발생 원인 | 고정 분할 | 가변 분할 |
| 공간 상태 | 공간이 너무 큼 | 공간이 조각남 |
| 해결 방법 | 가변 분할, Paging | Compaction, Paging |
