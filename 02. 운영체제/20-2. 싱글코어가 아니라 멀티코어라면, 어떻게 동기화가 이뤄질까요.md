# 20-2. 싱글코어가 아니라 멀티코어라면, 어떻게 동기화가 이뤄질까요?

싱글코어에서는 한 순간에 하나의 스레드만 실행되므로 공유 자원 접근을 비교적 쉽게 제어할 수 있다.

하지만 멀티코어 환경에서는 여러 코어가 동시에 실행되면서 같은 메모리 영역에 접근할 수 있기 때문에 동기화 문제가 더욱 중요해진다.

---

## 1. 캐시 일관성(Cache Coherence)

멀티코어 CPU는 각 코어가 자체 캐시를 가지고 있다.

```plain text
Core1 Cache
      ↓
 Main Memory
      ↑
Core2 Cache
```

예를 들어 Core1이 변수 값을 수정하더라도 Core2는 자신의 캐시에 저장된 이전 값을 계속 사용할 수 있다.

이러한 문제를 **캐시 일관성 문제(Cache Coherence Problem)** 라고 한다.

이를 해결하기 위해 CPU는 캐시 일관성 프로토콜을 사용한다.

대표적으로 **MESI 프로토콜**이 있다.

### MESI 프로토콜

캐시 데이터를 다음 네 가지 상태로 관리한다.

- Modified : 수정됨

- Exclusive : 독점 상태

- Shared : 여러 코어가 공유

- Invalid : 무효화

어떤 코어가 데이터를 수정하면 다른 코어의 해당 캐시 라인을 Invalid 상태로 만들어 최신 데이터를 다시 읽도록 한다.

이를 통해 모든 코어가 동일한 데이터를 보도록 보장한다.

---

## 2. 원자적 연산(Atomic Operation)

멀티코어에서는 단순한 읽기와 쓰기 사이에 다른 코어가 개입할 수 있다.

예를 들어

```plain text
if(lock == 0)
    lock = 1;
```

와 같은 코드는

```plain text
읽기(Read)
쓰기(Write)
```

사이에 다른 코어가 끼어들 수 있다.

이를 해결하기 위해 CPU는 다음과 같은 원자적 명령어를 제공한다.

- Test-And-Set

- Compare-And-Swap(CAS)

- Swap

원자적 연산은 여러 코어가 동시에 실행하더라도 하나의 연산처럼 수행되어 경쟁 상태(Race Condition)를 방지한다.

---

## 3. 메모리 장벽(Memory Barrier)

CPU는 성능 향상을 위해 명령어 재정렬(Instruction Reordering)을 수행한다.

예를 들어

```plain text
A = 1;
B = 2;
```

를 내부적으로 다른 순서로 실행할 수도 있다.

하지만 동기화가 필요한 구간에서는 실행 순서가 매우 중요하다.

이를 위해 CPU는 **메모리 장벽(Memory Barrier 또는 Memory Fence)** 을 제공한다.

메모리 장벽은

- 이전 메모리 연산이 완료될 때까지

- 이후 메모리 연산이 실행되지 않도록

보장한다.

즉, 메모리 접근 순서를 강제하여 스레드 간 일관된 결과를 얻도록 한다.

---

## 4. 메모리 모델(Memory Model)

멀티코어 환경에서는 CPU와 컴파일러가 다양한 최적화를 수행한다.

따라서 프로그래머가 작성한 순서와 실제 실행 순서가 다를 수 있다.

이를 제어하기 위해 각 시스템은 메모리 모델을 정의한다.

메모리 모델은

- 어떤 연산이 다른 연산보다 먼저 수행되어야 하는지

- 어떤 시점에 다른 코어가 변경 사항을 볼 수 있는지

를 규정한다.

대표적으로

- x86 Memory Model

- ARM Memory Model

- Java Memory Model(JMM)

등이 있다.

---

## 정리

멀티코어 환경에서는 각 코어가 독립적인 캐시를 사용하기 때문에 캐시 일관성 문제가 발생한다.

이를 해결하기 위해

1. MESI와 같은 캐시 일관성 프로토콜

1. CAS, Test-And-Set 같은 원자적 연산

1. Memory Barrier를 통한 실행 순서 보장

1. Memory Model을 통한 일관성 규칙 제공

이 함께 동작하여 동기화를 구현한다.
