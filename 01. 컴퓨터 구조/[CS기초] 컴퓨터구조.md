# [CS기초] 컴퓨터구조

[출처 - 이것이 ~~다 시리즈 CS책 수기 정리내역 README 형식 변환본]

## 1. 컴퓨터 구조의 큰 그림

### 컴퓨터가 이해하는 정보

- **데이터(정적 정보)**: 명령어에 종속적인 정보, 데이터/명령어 모두 **0과 1**로 표현됨

- **명령어(동적 정보)**: `수행할 동작 + 수행할 대상`

- **CPU**: 명령어를 **실행하는 주체**

---

## 2. 핵심 부품

### 2.1 CPU

- 데이터와 명령어를 **읽고(Fetch) → 해석(Decode) → 실행(Execute)** 하는 부품

- 구성: **ALU / CU / Register**

### ALU (산술논리연산장치)

- 산술/논리 연산 수행

### CU (제어장치)

- 명령어 해석 → **제어 신호(전기 신호)** 생성 → 각 부품 작동 지시

### Register (레지스터)

- CPU 내부의 작은 임시 저장장치

- 처리 중간값 저장

- ✅ _CPU가 처리하는 명령어는 반드시 레지스터에 저장됨_

---

### 2.2 메인 메모리(주기억장치)

- **현재 실행 중인 프로그램의 데이터/명령어** 저장

- 특징

  - **휘발성**: 전원 OFF 시 정보 소멸

  - 주소 기반 접근 (CPU가 원하는 정보에 접근 가능)

  - CPU-메모리 사이에 **캐시**가 존재해 접근 속도 보조

- 구성: **RAM / ROM**

---

### 2.3 캐시 메모리

- CPU-메모리 속도 차이를 줄이기 위한 고속 저장장치

- L1/L2/L3 캐시 구조 (보통 L1/L2는 코어 내부, L3는 공유)

---

### 2.4 보조기억장치

- **보관용 프로그램/데이터** 저장

- 특징

  - **비휘발성**

  - CPU는 보조기억장치의 프로그램을 **메모리로 복사**한 후 실행

- 예시: HDD, SSD, USB, SD 카드 등

---

### 2.5 입출력장치(I/O)

- 컴퓨터 외부와 정보 교환

- 예시

  - 입력: 키보드, 마우스

  - 출력: 모니터, 스피커, 프린터

---

### 2.6 메인보드와 버스

- **메인보드**: 핵심 부품들을 고정/연결하는 기판

- **버스**: 부품 간 정보를 주고받는 통로

- **시스템 버스**: 핵심 부품(CPU/메모리/I/O 등)을 연결하는 버스

---

## 3. 저장장치 계층 구조

- CPU에 가까울수록 **빠르고 용량 작음**

- 순서

`레지스터 → 캐시(L1→L2→L3) → 메인메모리 → 보조기억장치`

---

# 컴퓨터가 이해하는 정보

## 4. 비트/바이트/단위

- **bit**: 0 또는 1 (가장 작은 단위)

  - N비트 → `2^N`개 정보 표현 가능

- **byte**: 8bit (= 256가지 표현)

- **KB~TB**: 이전 단위를 1,000개 묶은 단위(실무에서 흔히 사용)

---

## 5. 0과 1로 숫자 표현 (데이터)

### 5.1 2진수 / 16진수

- CPU는 내부적으로 **2진법** 사용

- **16진수** 활용 예: MAC 주소, IPv6

### 5.2 부동소수점(IEEE 754)

- 소수점 위치가 고정되지 않고 이동 가능한 표현

- 형태: `가수 × 2^지수`

- 오차 발생 이유: 10진 소수 → 2진 소수로 변환 시 **무한소수**가 되는 경우가 많고 저장공간 한계로 일부 생략

### 표현 구조(단정도 예시)

- `부호(1) - 지수(8) - 가수(23)`

  - 부호: 0 양수 / 1 음수

  - 지수: 제곱수 정보

  - 가수: `1.xxx`에서 `xxx`의 소수 부분

---

## 6. 0과 1로 문자 표현 (데이터)

### 인코딩/디코딩

- **인코딩**: 문자 → 0/1 코드 변환

- **디코딩**: 0/1 코드 → 문자 변환

### 유니코드(Unicode)

- 다양한 언어/기호/이모지까지 통일된 문자 집합

- UTF-8/16/32 등 (UTF-8은 대표적인 가변 길이 인코딩)

### Base64

- 이미지/파일 등을 **문자 형태**로 표현하는 64진 인코딩 기법

---

# 명령어

## 7. 명령어 구성

- **연산 코드(opcode)**: 수행할 동작

- **오퍼랜드(operand)**: 동작 대상(데이터 또는 데이터 위치)

✅ 보통 오퍼랜드에는 “값”보다 “위치(주소/레지스터)”가 들어감

→ 메모리 주소라면 **추가 메모리 접근**이 필요할 수 있음

---

## 8. 대표 명령어 유형

### 데이터 전송

- MOVE, STORE, LOAD(FETCH), PUSH, POP

### 산술/논리 연산

- ADD, MULTIPLY, DIVIDE, INCREMENT, AND, OR, NOT, COMPARE

### 제어 흐름 변경

- JUMP, CALL, RETURN

### 입출력 제어

- READ, WRITE, START, TEST

---

## 9. 기계어 & 어셈블리어

- **기계어**: 0과 1 그대로의 언어

- **어셈블리어**: 기계어를 사람이 읽기 쉽게 번역한 형태

- ⚠️ CPU마다 이해하는 명령어가 다를 수 있음

---

## 10. 명령어 사이클

- 프로그램은 메모리에 저장되고 여러 명령어로 구성됨

- CPU는 다음 사이클을 반복하며 실행

### (1) FETCH (인출)

- PC(프로그램 카운터) 값(다음 명령어 주소) 참조

- 명령어를 메모리에서 읽어 **IR(명령어 레지스터)** 에 저장

- PC를 다음 주소로 업데이트(+1 개념)

### (2) EXECUTION (실행)

- 명령어 해독 및 실행

- 연산/메모리 접근/I/O/분기 처리

### (3) INDIRECT (간접)

- 오퍼랜드가 메모리 주소인 경우 → 해당 주소의 데이터를 가져오기 위해 **추가 접근**

### (4) INTERRUPT (인터럽트)

- 예외, I/O 요청, 타이머 등 외부 이벤트 처리

---

# CPU

## 11. 레지스터 종류

- **PC(프로그램 카운터)**: 다음에 실행할 명령어 주소

- **IR(명령어 레지스터)**: 현재 해석할 명령어 저장

- **범용 레지스터**: 데이터/명령어/주소 저장 가능

- **플래그 레지스터**: 연산 결과/CPU 상태 저장

- **SP(스택 포인터)**: 스택 최상단 위치

### 플래그 예시

- 부호 / 제로 / 캐리 / 오버플로우

- 인터럽트 플래그 / 슈퍼바이저 플래그(커널 모드 여부)

---

## 12. 인터럽트

- CPU 작업을 방해하는 신호

### 12.1 동기 인터럽트(= 예외)

- CPU 내부에서 발생

- 종류

  - **폴트(Fault)**: 예외 처리 후 **발생한 명령어부터** 재개

  - **트랩(Trap)**: 예외 처리 후 **다음 명령어부터** 재개(디버깅 등에 활용)

  - **중단(Abort)**: 심각한 오류 → 강제 중단

  - **소프트웨어 인터럽트**: 시스템 콜 등

### 12.2 비동기 인터럽트

- 입출력 장치에 의해 발생

- CPU가 I/O 완료 여부를 계속 확인(낭비)하지 않게 해줌

### 12.3 인터럽트 처리 흐름

1. 장치가 CPU에 인터럽트 요청

1. CPU는 실행 사이클 후 인출 사이클 전 인터럽트 확인

1. 인터럽트 플래그로 수용 여부 확인

1. 현재 작업 백업(보통 스택)

1. **인터럽트 벡터** 참조 → **ISR(인터럽트 서비스 루틴)** 실행

1. ISR 종료 → 복구 후 실행 재개

- NMI(무시 불가, 우선순위 높음)도 존재

---

## 13. CPU 성능 향상 설계

### 13.1 클럭 속도

- 클럭: 부품을 움직이는 시간 단위(Hz)

- 클럭↑ → 명령어 사이클 반복 속도↑

### 13.2 멀티코어

- 코어: 명령어를 실행하는 단위(내부에 ALU/CU/Register 포함)

### 13.3 멀티스레드

- 하드웨어 스레드(논리 프로세서): 한 코어가 동시에 처리하는 단위 → **병렬성**

- 소프트웨어 스레드: 프로그램의 실행 단위 → **동시성**

---

## 14. 파이프라이닝(명령어 병렬 처리)

- `인출-해석-실행-저장` 단계가 겹치지 않으면 동시에 처리 가능

### CISC vs RISC

- **CISC(인텔 계열)**: 명령어 수 적지만 수행시간 들쑥날쑥 → 파이프라이닝 비효율 가능

- **RISC(예: Apple M1)**: 단순 명령어(1클럭 내외) 지향 → 파이프라이닝 최적화

### 파이프라인 위험

- **데이터 위험**: 데이터 의존성

- **제어 위험**: JUMP/인터럽트로 PC 급변

- **구조적 위험**: 자원 경쟁(ALU/레지스터 등)

# 메모리

## 15. RAM

- CPU가 실행할 대상 저장(휘발성)

- RAM이 크면 보조기억장치에서 미리 가져올 수 있어 실행 시간 단축 가능

- 임의 접근(Random Access): 어느 주소든 접근 시간 비슷

### RAM 종류

- **DRAM**: 시간이 지나면 데이터 소멸 → 주기적 재저장 필요(대용량)

- **SRAM**: 유지되지만 전원 OFF 시 소멸(빠름, 캐시 등에 사용)

- **SDRAM**: 클럭과 동기화된 DRAM

- **DDR SDRAM**: 대역폭 확대 → 속도 향상

---

## 16. 엔디안(Endianness)

- CPU가 워드 단위로 메모리에 쓰는 순서

- **빅 엔디안**: 낮은 주소에 상위 바이트부터 저장(사람이 읽기 편함)

- **리틀 엔디안**: 낮은 주소에 하위 바이트부터 저장(연산/시스템에서 흔함)

---

## 17. 캐시 메모리 상세

### 캐시 히트/미스

- **캐시 히트**: 예측한 데이터가 실제로 쓰임

- **캐시 미스**: 예측 실패 → 메모리 직접 접근

- 적중률: 대략 85~95% 수준

### 참조 지역성

- 시간 지역성: 최근 접근한 곳 다시 접근(변수)

- 공간 지역성: 근처 주소 접근(배열)

### 쓰기 정책 & 일관성

- **즉시 쓰기(Write-through)**: 캐시+메모리 동시 반영(느림)

- **지연 쓰기(Write-back)**: 캐시에만 반영 후 나중에 메모리에 반영(빠르나 일관성 관리 필요)

---

# 보조기억장치 & 입출력

## 18. RAID

- 여러 저장장치를 하나처럼 사용해 안정성/성능 확보

- **RAID0**: 분산 저장(성능↑, 안정성↓)

- **RAID1**: 미러링(안정성↑, 용량↓, 쓰기 느림)

- **RAID4**: 패리티 전용 디스크(병목 가능)

- **RAID5**: 패리티 분산(병목 완화)

- **RAID6**: 패리티 2개(안정성↑, 쓰기 느림)

---

## 19. 입출력 기법

### 장치 컨트롤러 / 드라이버

- **장치 컨트롤러**: CPU와 I/O 장치 연결(내부에 작은 RAM 존재)

- **장치 드라이버**: 컨트롤러를 제어하는 소프트웨어(대개 OS 포함)

### 프로그램 입출력

- 명령어로 직접 I/O 수행

- 고립형 I/O / 메모리 맵 I/O

### 인터럽트 기반 입출력

- 다중 인터럽트 상황에서 우선순위 처리(PIC 등)

### DMA 입출력

- CPU를 거치지 않고 DMA 컨트롤러가 메모리에 직접 접근

- CPU는 시작 지시 후 다른 작업 가능

- 버스는 공용자원 → DMA가 사용하면 CPU 입장에서는 “사이클 스틸”처럼 보일 수 있음

---

## 20. GPU

- 코어 수가 매우 많아 **병렬 처리**에 강함

- CPU: 범용 연산, 메모리 접근 최소화 지향

- GPU: 대역폭 확대, 많은 코어에 많은 작업 분배 지향

---

# 운영체제

## 21. 운영체제의 큰 그림

### 커널 / 사용자 영역

- **커널 영역**: OS 핵심 기능 수행, 커널이 적재되어 실행됨

- **사용자 영역**: 응용프로그램이 실행되는 영역(자원 직접 접근 불가)

### 시스템 콜(System Call)

- 응용프로그램이 OS 기능을 사용하기 위한 호출

- 예시

  - 프로세스: fork/execve/exit/waitpid

  - 파일: open/close/read/write/stat

  - 디렉토리: chdir/mkdir/rmdir

  - 파일시스템: mount/umount

✅ 흐름: 응용프로그램 → (시스템콜) → 커널 코드 실행(인터럽트) → 사용자 영역 복귀

- 사용자 모드: 자원 직접 접근 불가

- 커널 모드: 자원 접근/제어 가능

---

## 22. 운영체제 역할 요약

1. 자원 할당/관리(CPU/메모리/파일시스템 등)

1. 프로세스/스레드 관리

1. 동기화 및 교착상태 관리

---

# 프로세스 & 스레드

## 23. 프로세스 메모리 구조

- **커널 영역**: PCB(프로세스 제어 블록), 프로세스 테이블

  - PID, 레지스터 값, 상태, 스케줄링 정보, 메모리 위치, I/O 정보 등

- **사용자 영역**

  - 동적: 스택(지역변수/매개변수/복귀주소), 힙(동적 할당)

  - 정적: 데이터(전역/정적), 코드(명령어)

### 좀비 프로세스

- 자원은 회수됐는데 PCB가 남아있는 상태

---

## 24. 프로세스 상태

- NEW → READY → RUNNING → BLOCKED → TERMINATED

- 타이머 인터럽트/입출력 요청에 의해 상태 전이 발생

### 문맥 교환(Context Switch)

- 프로세스 A 실행 중 타이머 인터럽트 → 문맥(PC/레지스터/메모리 등) 백업 → B 복구

- 잦으면 캐시 미스↑ → 오버헤드↑

---

## 25. 멀티프로세스 vs 멀티스레드

- **멀티프로세스**

  - 주소공간 독립, 자원 공유 적음 → 안정성↑

- **멀티스레드**

  - 코드/데이터/힙 공유, 협력 쉬움 → 위험도↑(프로세스 전체 영향 가능)

---

## 26. IPC(프로세스 간 통신)

- 공유 메모리(빠르나 레이스 위험)

- 메시지 전달(커널 경유, 파이프/시그널/소켓/RPC 등)

---

# 동기화 & 교착 상태

## 27. 임계 구역과 레이스 컨디션

- 임계 구역: 공유자원 접근 코드

- 레이스 컨디션: 동시에 실행되어 일관성 깨짐

### 동기화 목표

1. 실행 순서 제어

1. 상호 배제

---

## 28. 동기화 기법

- **뮤텍스 락**: 1개 공유자원 상호배제

- **세마포어(카운팅)**: 여러 공유자원도 관리 가능(S로 개수 관리)

- **모니터 + 조건변수**: 상호배제 + 실행순서 제어까지 가능

  - 예: Java `synchronized`

### 스레드 안전(Thread Safety)

- 멀티스레드 동시 접근에서도 문제 없는 상태

  - 예: Java Vector(동기화 컬렉션)

---

## 29. 교착상태(Deadlock)

- 서로 자원을 기다리며 무한 대기

### 발생 조건(4가지 모두 만족 시)

1. 상호배제

1. 점유와 대기

1. 비선점

1. 원형 대기

### 해결

- 예방: 조건 중 하나 깨기(자원에 번호 부여 후 오름차순 할당 등)

- 회피: 은행원 알고리즘(안전 상태 판단)

- 검출 후 회복: 자원 선점/강제 종료

---

# CPU 스케줄링

## 30. 스케줄링 개념

- OS가 프로세스/스레드에 CPU 사용을 배분하는 정책

### CPU 버스트 / I/O 버스트

- CPU 집중 프로세스: 연산 많음

- I/O 집중 프로세스: 입출력 대기 많음

→ I/O 집중을 빨리 실행시키면 전체 효율↑

### 스케줄링 큐

- 준비 큐: CPU 기다림

- 대기 큐: I/O 완료 기다림

### 선점 vs 비선점

- 선점형: OS가 강제로 뺏음(공정, 오버헤드↑)

- 비선점형: 끝날 때까지 못 뺏음(오버헤드↓, 대기↑)

---

## 31. 스케줄링 알고리즘

- FCFS(선입선처리): 호위효과 가능

- SJF(최단 작업 우선)

- RR(라운드 로빈): 타임슬라이스 기반

- SRT: 남은 시간 최소 우선

- 우선순위: 아사 가능 → 에이징으로 완화

- 다단계 큐 / 다단계 피드백 큐

### 리눅스

- RT 스케줄러(실시간 프로세스)

- CFS(공정성 지향, vruntime 기반)

---

# 가상 메모리

## 32. 물리주소 vs 논리주소

- 프로세스는 논리주소 사용

- MMU가 논리주소 → 물리주소 변환

---

## 33. 스와핑 & 연속 할당

- 스와핑: 실행 안 하는 프로세스를 스왑 영역으로 이동

- 연속 할당: 연속된 공간에 프로세스 적재

- 문제: 외부 단편화 + 큰 프로세스 실행 제약

---

## 34. 페이징

- 논리공간: **페이지**, 물리공간: **프레임**

- 페이지는 메모리에 불연속 배치 가능

- 장점: 외부 단편화 없음

- 단점: 내부 단편화 가능

### 페이지 테이블

- 페이지 번호 ↔ 프레임 번호 매핑

- 주요 비트

  - 유효 비트(0이면 페이지 폴트)

  - 보호 비트(R/W/X)

  - 참조 비트(접근 여부)

  - 수정 비트(변경 여부)

### TLB

- 페이지 테이블의 캐시 → 메모리 접근 횟수 감소

---

## 35. 페이지 교체 알고리즘

- 요구 페이징: 필요한 페이지만 적재

- FIFO / OPT(최적) / LRU

---

# 파일 시스템 & 부팅

## 36. 파일/디렉토리

- 파일: 이름 + 메타데이터 + 데이터

- 파일 디스크립터: 파일 식별자(0/1/2는 표준 입출력/에러)

- 디렉토리: 트리 구조(`/` 루트)

- 블록 단위 저장(보통 4096바이트)

- 아이노드(색인 블록): 블록 주소를 모아 파일 접근

### 링크

- 하드 링크: 같은 아이노드 공유(원본 삭제해도 접근 가능)

- 심볼릭 링크: 원본 경로만 가리킴(원본 삭제 시 불가)

### 마운트

- 다른 파일시스템을 특정 경로에 연결

---

## 37. 부팅 흐름

1. 전원 인가

1. ROM(비휘발성)에서 BIOS 실행

1. 보조기억장치 MBR의 부트로더가 커널 위치 확인

1. 커널을 메모리에 적재 → OS 시작
