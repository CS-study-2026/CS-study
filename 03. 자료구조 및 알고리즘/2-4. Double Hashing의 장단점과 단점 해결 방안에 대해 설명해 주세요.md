# **2-4.** Double Hashing의 장단점과 단점 해결 방안에 대해 설명해 주세요.

# 🧮 Double Hashing

## 1️⃣ 개념

- **Open Addressing 기반 해시 충돌 해결 기법**

- 두 개의 해시 함수 사용

  - h_1(k) → 초기 위치

  - h_2(k) → 탐사 간격

- 탐사 공식

| 기호 | 의미 |
| --- | --- |
| k | 키 |
| i | 충돌 횟수 |
| m | 테이블 크기 |
| h_1(k) | 기본 해시 |
| h_2(k) | 보조 해시 (step size) |

➡️ 즉, 충돌할 때마다 **일정 간격이 아니라 키마다 다른 간격으로 이동 ⇒ 충돌 분산 효과**

---

## 2️⃣ 장점

### ✅ 1. 군집화 최소화

- Primary / Secondary Clustering 거의 발생하지 않음

- 데이터 분포가 가장 균등

### ✅ 2. 평균 성능 우수

- Load Factor가 높아도 성능 유지

- 평균 탐색/삽입: **O(1)**

### ✅ 3. 메모리 효율적

- 체이닝보다 추가 포인터 필요 없음

### ✅ 4. 이론적으로 가장 이상적인 Open Addressing

- 균등 해싱(uniform hashing)에 가장 근접

## 3️⃣ 단점

---

### ⚠️ 1. 해시 함수 설계가 어려움

- h_2(k)가 잘못 설계되면 전체 버킷을 탐색하지 못함

- 특정 버킷만 반복 방문 가능

👉 예: h_2(k) = 0 이면 무한 루프

### ⚠️ 2. 계산 비용 증가

- 해시 함수 2번 계산 필요

### ⚠️ 3. 삭제 처리 복잡

- 단순 삭제 시 탐색 경로 단절

### ⚠️ 4. 캐시 지역성 낮음

- Linear probing 대비 메모리 접근 패턴 분산

---

## 4️⃣ 단점 해결 방안

### 🛠️ 1. h_2(k) 설계 규칙

- 절대 0이 되지 않도록 설계

- 테이블 크기와 서로소 관계 유지

대표 설계 방법
h_2(k) = R - (k \bmod R)

R = m보다 작은 소수

### 🛠️ 2. 테이블 크기를 소수로 설정

이유

➡️ 모든 버킷을 순회 가능

➡️ 탐사 주기 문제 방지

### 🛠️ 3. Load Factor 관리

- 보통 0.5 ~ 0.75 유지

- 초과 시 Resize + Rehash

➡️ 탐사 길이 증가 방지

### 🛠️ 4. Tombstone 사용

삭제 시

- 실제 삭제 ❌

- “삭제됨” 표시

➡️ 탐색 경로 유지

---

## 5️⃣ 언제 사용하면 좋은가

✔️ 메모리 오버헤드를 줄이고 싶을 때

✔️ 충돌이 많은 환경

✔️ 높은 성능이 필요한 시스템

✔️ 해시 함수 설계가 가능한 경우

---

## 📌 핵심 정리

- Double Hashing은 **두 번째 해시 값으로 탐사 간격을 결정하는 충돌 해결 기법**

- Open Addressing 중 **군집화가 가장 적음**

- 평균 성능은 매우 좋지만
👉 해시 함수 설계가 핵심 난이도

- 소수 크기 테이블 + 적절한 h_2 설계가 필수
