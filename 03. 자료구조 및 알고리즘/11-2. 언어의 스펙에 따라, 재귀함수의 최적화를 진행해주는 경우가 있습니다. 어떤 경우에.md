# **11-2.** 언어의 스펙에 따라, 재귀함수의 최적화를 진행해주는 경우가 있습니다. 어떤 경우에 재귀함수의 최적화가 가능하며, 이를 어떻게 최적화 할 수 있을지 설명해 주세요.

# ⚙️ 재귀 함수 최적화 (Tail Call Optimization)

## 1️⃣ 재귀 최적화가 필요한 이유

재귀 함수는 가독성과 문제 표현에 유리하지만

👉 호출마다 **새로운 Stack Frame 생성**

따라서

- 메모리 사용 증가

- 호출 깊이가 깊어지면 **Stack Overflow 위험**

- 반복문 대비 성능 손실 발생

➡️ 이를 해결하기 위한 기법이 **재귀 최적화**

---

## 2️⃣ 재귀 최적화가 가능한 경우

## 📌 Tail Recursion (꼬리 재귀)

함수의 **마지막 연산이 재귀 호출인 경우**

즉,

👉 재귀 호출 이후에 추가 계산이 없음

### 형태

```java
return recursive_call(...);
```

> 재귀 호출의 결과를 그대로 반환하거나, 결과를 누적하는 인자를 통해 다음 호출로 넘기는 방식이 대표적

### 최적화 가능 이유

- 이전 스택 프레임을 유지할 필요 없음

- 현재 프레임을 재사용 가능

➡️ 컴파일러가 반복문처럼 변환 가능 ⇒ Tail Call Optimization

---

## 3️⃣ Tail Recursion vs 일반 재귀

### 일반 재귀 (최적화 불가)

```java
public static int factorial(int n) {
    if (n == 1) return 1;
    return n * factorial(n - 1); // 호출 후 곱셈 연산 존재
}
```

❌ 재귀 호출 후 곱셈 수행

→ 이전 스택 유지 필요

---

### Tail Recursion (최적화 가능)

```java
public static int factorialTail(int n, int acc) {
    if (n == 1) return acc;
    return factorialTail(n - 1, n * acc);
}
```

✔️ 마지막 연산이 재귀 호출

✔️ 추가 계산 없음

➡️ Tail Call Optimization 가능

<details>
<summary>⚠️ 단, Java는 TCO를 공식적으로 지원하지 않음
(그래서 실제로는 스택이 증가함)</summary>

Java는

  - 디버깅 스택 추적 유지 필요

  - JVM 스펙상 TCO 보장하지 않음

따라서

👉 실무에서는 **반복문으로 변환**하는 것이 일반적
</details>

---

## 4️⃣ Tail Call Optimization (TCO) 동작 원리

### 일반 재귀

```plain text
main()
 └ factorial(5)
    └ factorial(4)
       └ factorial(3)
          └ factorial(2)
             └ factorial(1)
```

➡️ 호출 깊이만큼 스택 증가

---

### TCO 적용 시

```plain text
Single Stack Frame 재사용
```

➡️ 메모리 사용 O(n) → O(1)

➡️ 함수 호출 오버헤드 감소

---

## 5️⃣ 어떤 언어에서 지원하는가

### ✔️ TCO 지원 언어

- Scheme

- Haskell

- Scala

- Kotlin (부분 지원(tailrec 키워드))

### ❌ 기본적으로 지원하지 않는 언어

- Java(JVM 스펙상 보장하지 않음)

- Python

- JavaScript (표준 명세는 있으나 대부분 엔진 미지원)

👉 따라서 실무에서는 반복문으로 변환하는 경우 많음

---

## 6️⃣ 재귀 최적화 방법

## 🛠️ 방법 1. Tail Recursion으로 리팩토링

핵심

👉 누적 변수(accumulator) 사용

- 중간 계산을 미리 수행

- 마지막 호출만 남기기

---

## 🛠️ 방법 2. 반복문으로 변환

재귀 호출을 명시적 루프로 변경

### 예

```java
public static int factorialIter(int n) {
    int result = 1;
    while (n > 1) {
        result *= n;
        n--;
    }
    return result;
}
```

✔️ 스택 사용 없음

✔️ 성능 안정적

---

## 🛠️ 방법 3. 명시적 스택 사용

```java
Stack<Node> stack = new Stack<>();
stack.push(root);

while (!stack.isEmpty()) {
    Node node = stack.pop();
    // 처리 로직
}
```

👉 Call Stack 대신 자료구조 스택 사용

➡️ 메모리 제어 가능

---

## 7️⃣ 재귀 최적화의 효과

| 항목 | 개선 효과 |
| --- | --- |
| 성능 | 함수 호출 오버헤드 감소 |
| Stack Overflow | 방지 |
| 안정성 | 깊은 재귀에서도 안전 |

---

## 8️⃣ 언제 고려해야 하는가

✔ 재귀 깊이가 매우 깊어질 수 있는 경우
✔ Stack Overflow 위험이 있는 경우
✔ 성능 튜닝 상황
✔ 언어가 TCO를 지원하는 경우

---

## 📌 핵심 정리

- 재귀 최적화는 **Tail Recursion에서 가능**

- 마지막 연산이 재귀 호출이면 스택 재사용 가능

- 이를 **Tail Call Optimization (TCO)** 라고 함

- 누적 변수 사용으로 Tail Recursion으로 변환 가능

- TCO 미지원 언어에서는 반복문 변환이 실무적 해결책
