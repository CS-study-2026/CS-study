# 2-1. 충돌이 최대한 적은 해시 함수 설계 방법

# 2-1. 충돌이 최대한 적은 해시 함수 설계 방법

## 현실 체크

- 입력 공간(키)이 해시값 공간보다 크면 충돌은 필연

- 목표는 충돌 0이 아니라:

  - 균등 분포(uniformity)로 충돌 “확률”을 낮추기

  - 패턴/공격 입력에도 한쪽 버킷으로 몰리지 않게 하기

---

## 좋은 해시의 핵심 성질 3가지

1. **Avalanche effect**

  - 입력 1비트 변화 → 출력 비트가 대폭 변화

1. **Uniformity (균등성)**

  - 버킷 0..M-1에 거의 동일 확률로 분포

1. **Mixing(구조 파괴)**

  - 연속 숫자/규칙 문자열 등 “패턴 키”도 잘 섞이게

---

## 해시 함수만큼 중요한 것: 테이블 인덱싱

- 해시테이블 크기 `M`이 2의 거듭제곱이면

인덱스 계산이 보통 `h & (M-1)`

→ 이 경우 하위 비트 품질이 매우 중요

- 로드팩터(α = n/M)가 높아지면 충돌 급증

→ 리사이징 정책도 충돌/성능에 큰 영향

# 2-1 예시코드(Java)

---

## 1) 64-bit 믹서(mix64): 정수 키를 균등하게 섞기

```java
/**
 * mix64: 입력(long)을 고르게 섞는(비트 혼합) 함수
 * - 목적: 연속 키(1,2,3,4...)나 규칙 키도 출력이 균등하게 퍼지도록
 * - 특징: XOR shift + 곱셈으로 avalanche를 유도
 *
 * ※ 이 믹싱은 "해시 테이블 인덱스"로 쓰기 전에 한 번 거치는 전처리라고 생각하면 됨.
 */
static long mix64(long z) {
    z ^= (z >>> 33);
    z *= 0xff51afd7ed558ccdL;
    z ^= (z >>> 33);
    z *= 0xc4ceb9fe1a85ec53L;
    z ^= (z >>> 33);
    return z;
}
```

---

## 2) 정수 키 → 버킷 인덱스 (M이 2의 거듭제곱일 때)

```java
/**
 * M은 2의 거듭제곱(예: 1024, 2048...)이라고 가정.
 * index = (int)h & (M-1) 형태는 빠르지만,
 * 하위 비트 품질이 안 좋으면 충돌이 급증함.
 *
 * 그래서 key를 바로 쓰지 말고 mix64로 섞은 뒤 하위 비트를 사용.
 */
static int indexForIntKey(int key, int tableSizePowerOfTwo) {
    long h = mix64((long) key);
    return (int) h & (tableSizePowerOfTwo - 1);
}
```

- `key % M`은 규칙성이 강한 키에서 충돌이 커질 수 있음

- `mix64`로 섞고 하위 비트를 쓰면 분포가 훨씬 안정적

## 3) 문자열 해시 + 믹싱 적용

문자열은 보통 검증된 해시를 쓰는 게 안전

```java
/**
 * 문자열을 64-bit로 누적해 만든 뒤 mix64로 마무리.
 * - 누적 단계: 문자열 전체를 반영 (순서 민감)
 * - 마무리 mix: 패턴을 더 강하게 분산
 *
 * 주의: 이 코드는 교육용. 실무는 xxHash/Murmur/SipHash 등을 권장.
 */
static long hashString64(String s) {
    long h = 1469598103934665603L; // 임의의 offset basis (예: FNV 계열 느낌)
    for (int i = 0; i < s.length(); i++) {
        h ^= s.charAt(i);
        h *= 1099511628211L; // 큰 홀수 곱으로 섞기
    }
    return mix64(h);
}

static int indexForStringKey(String s, int tableSizePowerOfTwo) {
    long h = hashString64(s);
    return (int) h & (tableSizePowerOfTwo - 1);
}
```

## 4) 복합키 해싱

```java
/**
 * 복합 키를 섞는 방법:
 * - hash(a), hash(b)를 단순 덧셈하면 충돌이 쉽게 생김 (교환법칙/선형성 문제)
 * - rotate + xor + mix로 비선형성을 부여
 */
static long hashPair64(long a, long b) {
    long ha = mix64(a);
    long hb = mix64(b);

    // rotl: 비트를 회전시켜 서로 다른 위치에 영향 주기
    long combined = ha ^ Long.rotateLeft(hb, 27);

    // 마지막에 한 번 더 mix로 마무리
    return mix64(combined);
}

static int indexForPair(long a, long b, int tableSizePowerOfTwo) {
    long h = hashPair64(a, b);
    return (int) h & (tableSizePowerOfTwo - 1);
}
```

## 5) 충돌 줄이는 체크리스트

- 해시 함수:

  - 입력 패턴을 깨는 mixing이 있는가?

  - 출력이 균등하게 분포하는가?

- 해시테이블:

  - 테이블 크기 `M`과 인덱싱 방식이 해시 품질과 맞는가?

  - 로드팩터가 높아지면 리사이징하는가?

- 보안/공격 고려:

  - 외부 입력을 받는 서비스면 seed(랜덤 시드) 고려
