# **16-2.** 그렇다면, 동적 계획법으로 풀 수 있는 모든 문제는 재귀로 변환하여 풀 수 있나요?

# 1. DP과 재귀 함수

## 1) DP의 재귀 변환 가능 여부?

- 이론적으로 동적 계획법으로 풀 수 있는 모든 문제는 재귀로 변환하여 풀 수 있다.

## 2) DP의 풀이 방식

- 상향식 (Bottom-Up): 반복문을 사용하여 작은 문제부터 차례대로 표를 채워나가는 타뷸레이션(Tabulation) 기법을 활용.

- 하향식 (Top-Down): 재귀 함수를 사용하며, 이미 계산한 결과는 저장해두는 메모이제이션(Memoization) 기법을 활용.

- 즉,  DP 문제의 하향식 접근법이 바로 재귀를 이용한 풀이를 의미한다.

# 2. DP를 재귀 함수로 변환 시 주의할 점

## 1) 중복 계산

- 단순 재귀로만 풀면 동일한 작은 문제를 반복해서 계산하게 되어 시간 복잡도가 기하급수적으로 늘어날 수 있다.

- 따라서 반드시 메모이제이션을 결합해야 DP로서의 효율이 생긴다.

## 2) **스택 오버플로우(Stack Overflow)**

- 재귀의 깊이가 너무 깊어지면(N이 매우 커지면) 시스템의 콜 스택 한계를 초과하여 프로그램이 강제 종료될 수 있다.

- 이럴 경우, 반복문을 사용하는 상향식(Bottom-Up) 방식이 더 안전하다.

# 3. 요약

| **구분** | **재귀 (with Memoization)** | **반복문 (Tabulation)** |
| --- | --- | --- |
| **방식** | 큰 문제 → 작은 문제 (Top-Down) | 작은 문제 → 큰 문제 (Bottom-Up) |
| **장점** | 가독성이 좋고 점화식을 그대로 옮기기 쉬움 | 스택 오버플로우 걱정이 없고 속도가 미세하게 빠름 |
| **단점** | 재귀 깊이 제한에 걸릴 수 있음 | 문제의 의존 관계에 따라 구현 순서가 복잡할 수 있음 |
