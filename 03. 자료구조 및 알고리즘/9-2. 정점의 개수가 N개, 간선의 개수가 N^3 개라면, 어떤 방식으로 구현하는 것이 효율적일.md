# **9-2.** 정점의 개수가 N개, 간선의 개수가 N^3 개라면, 어떤 방식으로 구현하는 것이 효율적일까요?

# 1. 인접 행렬과 인접 리스트 비교

| **구분** | **인접 행렬 ** | **인접 리스트 ** | **비고** |
| --- | --- | --- | --- |
| **간선 존재 확인** | **O(1)** | O(N^3)  | **행렬 승** |
| **이웃 노드 탐색** | O(N) | O(N^3) | **행렬 승** |
| **공간 복잡도** | **O(N^2)** | O(N^3) | **행렬 승** |

# 2. 접근 속도

- 간선이 너무 많으면 인접 리스트의 각 연결 리스트 길이가 매우 길어진다.

- 특정 간선의 존재를 확인할 때 인접 리스트는 매우 느려지지만, 인접 행렬은 여전히 O(1)이다.

# 3. 공간 효율성

- 인접 행렬 : 항상 O(N^2)의 공간을 사용한다. 간선이 아무리 많아져도 행렬의 크기는 변하지 않는다.

- 인접 리스트 : 간선 하나당 하나의 노드 객체(또는 연결 리스트의 요소)를 생성해야 하므로, 간선이 N^3개라면 공간 복잡도는 O(N^3)이 된다.

- 즉, 인접 리스트가 인접 행렬보다 메모리를 훨씬 더 많이 사용하게 된다.

# 4. 요약

- 간선의 개수가 정점의 제곱(N^2)을 초과할 정도로 많은 극단적인 밀집 그래프 환경에서는 인접 행렬을 사용하는 것이 공간과 시간 모든 측면에서 효율적이다.

- 따라서 인접 행렬은 간선이 많을 때, 인접 리스트는 간선이 적을 때 빛을 발하는 방식이다.
