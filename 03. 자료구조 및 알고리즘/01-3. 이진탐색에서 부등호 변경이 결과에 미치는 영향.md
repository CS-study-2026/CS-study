# 1-3. 이진탐색에서 부등호 변경이 결과에 미치는 영향

# 1-3. 이진탐색에서 `<=` → `<`로 바꾸면 결과가 달라질까?

- 달라질 수 있다(거의 항상)

- 특히 중복 값이 있는 정렬 배열에서 결과가 크게 달라짐

- 이유: 부등호는 단순 조건이 아니라 어떤 **경계**를 찾는가를 정의함

---

## 이진탐색은 보통 3종류로 나뉜다

### 1) 존재 여부

- `a[mid] == x`면 return

- 구현에 따라 `<`/`<=` 바꾸면 루프 종료 조건이 깨질 수도 있음

### 2) lower_bound(x)

- **처음으로 ****`a[i] >= x`** 를 만족하는 i

### 3) upper_bound(x)

- **처음으로 ****`a[i] > x`** 를 만족하는 i

> lower_bound와 upper_bound의 차이는 **부등호 하나(>= vs >)**

---

## lower_bound vs upper_bound

정렬 배열: `a = [1, 2, 2, 2, 3]`, `x = 2`

- `lower_bound(2)` = **1** (첫 번째 2의 위치)

- `upper_bound(2)` = **4** (마지막 2 다음 위치)

⇒  **부등호를 ****`<=`****에서 ****`<`****로 바꾸면**

의도치 않게 lower ↔ upper가 뒤집히는 효과가 나올 수 있음

---

## 안전한 표준 패턴 

### lower_bound 구현 불변식

- 구간 `[lo, hi)` 에서

- 답은 항상 이 구간에 존재

```java
// lower_bound: 첫 번째 a[i] >= x
static int lowerBound(int[] a, int x) {
    int lo = 0, hi = a.length; // [lo, hi)
    while (lo < hi) {
        int mid = (lo + hi) >>> 1;
        if (a[mid] < x) lo = mid + 1;
        else hi = mid;
    }
    return lo;
}
```

### upper_bound 구현 불변식

```java
// upper_bound: 첫 번째 a[i] > x
static int upperBound(int[] a, int x) {
    int lo = 0, hi = a.length; // [lo, hi)
    while (lo < hi) {
        int mid = (lo + hi) >>> 1;
        if (a[mid] <= x) lo = mid + 1;
        else hi = mid;
    }
    return lo;
}
```
